# 9장. 해시테이블로 데이터 저장하고 찾기

표를 준비하면 배열 전체를 매번 확인하지 않고 저장한 데이터를 찾을 수 있다. 직통 주소 테이블에서 시작해 큰 키와 음수 키, 충돌을 처리하는 고정 크기 해시테이블로 나아간다. 완성한 표는 마지막에 두 수의 합을 찾는 문제에 응용한다.

## 논리적으로 생각해 보기

### 배열에서 원하는 값을 어떻게 찾을까?

정렬되지 않은 배열에서는 원하는 값이 나오거나 모든 항목을 확인할 때까지 하나씩 살펴본다. 값이 없으면 배열 전체를 확인해야 할 수 있다. 같은 배열에서 여러 번 찾아야 한다면, 어디를 볼지 알려 주는 표를 미리 준비할 수 있을까?

### 직통 주소 테이블은 무엇일까?

찾으려는 값을 두 번째 배열의 인덱스로 쓰고, 그 칸에 원래 입력 위치를 저장한다. 찾을 값은 **키**이고, 이렇게 만든 두 번째 배열을 **직통 주소 테이블**이라고 한다. 키가 작고 음수가 아닌 인덱스 범위에 들어갈 때 쓸 수 있다.

`nums = {2,5,6}`에서는 일곱 칸의 표에 각 값의 입력 위치를 저장한다. 나머지 칸에는 -1을 둔다.

| 입력 위치 | 값 | 표의 항목 |
| ---: | ---: | --- |
| 0 | 2 | `table[2] = 0` |
| 1 | 5 | `table[5] = 1` |
| 2 | 6 | `table[6] = 2` |

5를 찾으려면 `table[5]`를 읽는다. 저장된 위치 1로부터 `nums[1]`이 5임을 알 수 있다. `table[4]`는 -1이므로 4는 없다. 표의 인덱스는 키이고, 저장한 항목은 그 키에 연결된 데이터이며 여기서는 입력 위치이다.

### 큰 키나 음수 키도 작은 표로 찾으려면 어떻게 할까?

직통 주소 테이블은 값이 몇 개뿐이어도 가장 큰 키까지 담을 공간이 필요하다. 음수 키도 배열 인덱스로 바로 쓸 수 없다. 대신 고정 크기 표 안에 들어가는 인덱스를 계산한다.

**해시함수**는 같은 키에 언제나 같은 표의 위치를 대응시킨다. 이 위치를 **버킷**이라고 한다. **해시테이블**은 이 계산으로 키와 연결된 데이터를 저장하고 찾을 위치를 고른다. 현재 실습은 버킷 열다섯 개를 예약한다. 서로 다른 키도 같은 버킷을 고를 수 있으므로, 버킷을 골랐다는 사실만으로 찾는 키가 있다고 할 수는 없다. 후보를 남겨 두고 키 전체를 비교해야 한다.

### 음수 키는 어느 버킷을 고를까?

실습 표에는 버킷 위치가 열다섯 개 있다. `TABLE_CAPACITY`로 나눈 C의 나머지를 구하고, 나머지가 음수일 때만 용량을 더한다. 음수인 배수의 나머지는 이미 0이다. 가장 작은 부호 있는 정수도 유효한 버킷 인덱스로 바뀐다.

### 충돌한 키는 어디에 저장할까?

서로 다른 키가 같은 버킷을 고르는 일을 **충돌**이라고 한다. 이런 레코드를 버킷마다 정수 노드 인덱스와 `next`로 연결한 하나의 체인에 두는 방법을 **별도 체인(separate chaining)**이라고 한다. 버킷에는 첫 노드의 인덱스만 저장한다. 새 노드는 기존 첫 노드 앞에 붙이고, 탐색에서는 체인의 키 전체를 비교한다.

### 키와 함께 저장한 데이터는 어떻게 다를까?

해시 계산과 같은지 비교하는 데에는 `key`를 쓴다. 별도의 `data` 필드에는 그 키와 관련된 정보를 둔다. `find`는 노드 인덱스를 반환하므로 -1인지 먼저 확인한 뒤 데이터를 읽는다. 중복 키도 새 노드를 사용하며, 기존 항목을 고치는 대신 가장 최근의 일치 노드를 찾는다.

### 노드 열 개로 버킷 열다섯 개를 어떻게 사용할까?

두 배열의 역할은 다르다. `hnodes_unused`는 할당한 노드 수이면서 다음에 쓸 인덱스이다. 노드 공간이 모두 차도 빈 버킷은 남을 수 있다. 표를 직접 쓰기 전에는 `initialize()`를 호출한다. 모든 첫 노드와 카운터를 초기화하지만 이전 노드 필드는 남긴다. 자유 리스트나 7장에서 가져오는 풀은 없다.

### 다른 충돌 해결법은 무엇이 다를까?

개방 주소 방식은 표의 칸에 항목을 두고 이미 차 있으면 정해진 탐사 규칙에 따라 다른 칸을 찾는다. 로빈 후드 해싱은 원래 위치에서 더 멀리 온 항목에 자리를 양보할 수 있다. 예를 들어 더 멀리 이동한 새 항목이 자리를 차지하면 기존 항목은 탐사를 계속한다. 비교를 위한 개념이며 실습은 별도 체인을 쓴다.

### 응용: 어떤 두 위치의 합이 목표가 될까?

이제 완성한 표를 알고리즘에 써 보자. 합이 목표값이 되는 서로 다른 두 입력 위치를 찾아야 한다. 같은 값도 서로 다른 위치에 있으면 별개의 선택이다. 무차별 대입은 현재 위치를 정하고 가장 가까운 이전 위치부터 하나씩 확인한다. 해시테이블을 쓰면 앞선 값을 다른 방법으로 찾을 수 있다.

### 현재 값에는 어떤 이전 키가 필요할까?

필요한 값은 목표값에서 현재 입력값을 뺀 보수이다. 앞서 읽은 입력값을 키로, 그 입력 위치를 데이터로 저장한다. 보수 키를 찾으면 그 노드의 데이터에서 이전 위치를 구할 수 있다.

### 왜 현재 위치를 넣기 전에 찾아볼까?

반복을 시작할 때 저장된 위치는 모두 현재 위치보다 앞선다. 먼저 찾고 실패했을 때만 현재 위치를 넣으면 자기 자신을 짝으로 고를 수 없다. 성공해서 반환하면 이전 레코드는 관찰할 수 있게 남고, 다음 해시 방식 호출에서 표를 다시 초기화한다.

### 두 가지 짝 찾기는 어떻게 다를까?

두 방법 모두 `i`를 늘리면서 가장 최근의 일치하는 이전 `j`를 골라 `{j,i}`를 쓴다. 무차별 대입은 `j`를 줄이고, 해시 체인은 앞에 붙였기 때문에 최근의 일치 키부터 만난다. 없으면 `{-1,-1}`을 쓴다. 아래 예제는 실습의 기본 배열과 별도의 실험 배열을 구분하며 실습 소스를 바꾸지 않는다.

제공된 구현은 음수를 포함한 입력을 쓰고, 이전 위치를 큰 인덱스부터 작은 인덱스 순서로 확인한다.

## 효율 계산해 보기

### 체인 하나를 찾는 데 얼마나 걸릴까?

해시 계산, 노드 할당과 앞에 붙이기는 일정한 작업이다. 노드가 `k`개인 체인은 키를 최대 `k`번 비교한다. 기본 배열의 목표 0 해시 추적은 저장된 키를 한 번 비교한다. 그 앞의 보수 버킷은 비어 있다. 빈 버킷을 확인하는 데에도 일정한 작업은 필요하다.

### 초기화와 예약 공간의 비용은 얼마일까?

초기화는 모든 버킷의 첫 노드를 쓰지만 이전 체인을 따라가지는 않으므로 일반화한 시간은 `Θ(b)`이다. 실제 소스는 정수 첫 노드 열다섯 개와 정수 필드 세 개씩인 레코드 열 개를 예약한다. 노드 공간이 `p`개라면 표 공간은 `Θ(b+p)`이다. 무차별 대입의 추가 공간은 일정하지만 해시 방식은 표를 유지한다.

### 무차별 대입은 몇 쌍을 비교할까?

입력 열 개에서 끝까지 못 찾으면 `0+1+...+9 = 45`쌍을 확인한다. 기본 배열의 목표 0에서는 `i=5,j=4`가 첫 일치이다. 앞선 반복에서 열 번, 현재 반복에서 한 번으로 총 열한 번이다. 길이 `n`으로 일반화하면 실패할 때 `n(n-1)/2`쌍이므로 시간은 이차로 증가한다.

### 해시 방식은 언제 평균적으로 선형일까?

항목 `n`개가 버킷 `b`개에 고르게 퍼지면 기대 탐색 비용은 `O(1+n/b)`이다. 버킷 수가 입력 길이에 비례하고 노드 용량도 충분하면 전체 해시 짝 찾기는 기대 `O(n)`이다. 충돌이 많으면 전체 탐색이 이차가 될 수 있다. 버킷 열다섯 개를 고정한 채 입력만 늘리면서 항상 선형이라고 할 수는 없다.

## 용어 정리

### 키

버킷을 고르고 같은지 비교하는 수이다.

### 연관 데이터

`data`에 저장하는 연관 정보이며, 짝 찾기에서는 이전 입력 위치이다.

### 버킷

체인의 첫 노드 인덱스 또는 -1을 저장하는 표의 위치이다.

### 충돌

서로 다른 키가 같은 버킷을 고르는 일이다.

### 별도 체인

한 버킷에 배정된 항목을 연결 체인에 모두 남기는 방법이다.

### 노드 인덱스

`hnodes` 안의 위치이며 버킷이나 입력 인덱스와 다르다.

### 보수

현재 입력에 필요한 `target - nums[i]` 값이다.

### 할당 카운터

`hnodes_unused`는 할당한 칸 수이자 다음에 쓸 인덱스이다.

### 앞에 붙이기

새 노드가 기존 첫 노드를 가리키게 한 다음 새 첫 노드를 기록하는 일이다.

### 특별한 표시값

각 필드에서 -1은 빈 첫 노드, 체인 끝, 못 찾은 노드 또는 할당 실패를 뜻한다. 키나 연관 데이터로는 유효한 값일 수 있다.

### 중복 키

같은 키의 다른 레코드이며, 실습에서는 별도 할당하고 가장 최근의 일치를 찾는다.

### 상태와 인덱스

`insert`는 상태 0/-1, `find`와 `new_hnode`는 노드 인덱스/-1을 반환한다.

## 규칙

### 올바른 표는 어떤 규칙을 지킬까?

도달 가능한 노드 인덱스는 할당한 앞부분 안에 있고, 모든 체인은 -1로 끝나며 서로 겹치거나 순환하지 않는다. 각 키의 해시값은 자신이 속한 버킷과 같다. 짝 찾기에서 저장된 위치는 모두 현재 `i`보다 앞선다.

### 규칙을 지키면 무엇이 보장될까?

탐색은 가능성 있는 후보만 확인하고 체인 끝에서 멈춘다. 별도 키를 사용하면 저장한 위치와 값을 혼동하지 않는다. 이전 위치 규칙은 반환한 두 입력 위치가 다름을 보장한다.

### 규칙을 깨면 무엇이 잘못될까?

키 대신 데이터를 비교하면 올바른 보수를 놓칠 수 있다. 찾기 전에 넣으면 자기 자신을 짝으로 고를 수 있다. 할당 카운터만 초기화하면 이전 첫 노드가 재사용한 칸을 계속 가리킨다. 잘못된 체인이나 인덱스의 실행 실험은 하지 않는다.

### 실습 코드는 규칙을 어떻게 지킬까?

모든 첫 노드와 카운터를 함께 초기화한다. 새 첫 노드를 공개하기 전에 할당하고 성공 여부를 확인한다. 유효한 링크만 따라가고 키 전체를 비교하며 현재 위치를 넣기 전에 찾는다. 실패한 추가는 표 상태를 바꾸지 않는다.

## 코딩 계획

### 두 배열의 역할 나누기

노드 용량, 버킷 용량과 key/data/next 레코드를 정한다. 한 배열에는 노드를, 다른 배열에는 체인의 첫 인덱스를 둔다. 실습의 할당 카운터 이름을 그대로 사용하고 직접 연산하기 전에 초기화한다.

### 해시 계산하고 할당하고 넣고 찾기

나머지를 정규화하고 노드 용량을 확인한 다음 새 노드의 모든 필드를 쓴다. 추가할 때는 할당 성공까지 기존 첫 노드를 보존한다. 찾을 때는 선택한 체인을 따라가며 처음 일치한 키의 노드 인덱스를 반환한다.

### 앞선 위치를 두 방법으로 찾기

먼저 감소하는 안쪽 반복으로 이전 위치를 나열한다. 다음에는 반복 탐색을 보수 키 조회와 입력 인덱스 데이터로 바꾼다. 두 방법 모두 이전 위치를 현재 위치보다 먼저 기록하고, 없으면 두 정답 칸 모두 -1로 쓴다.

### 정답뿐 아니라 상태도 검사하기

별도의 단언 검사 드라이버에서 실습 소스를 한 번 포함한다. 충돌, 키와 데이터의 구별, 중복 키, 소진 실패의 상태 보존, 초기화와 재사용, 실패한 탐색, 자기 짝 방지와 반복 호출을 검사한다. 계산은 모두 `int` 범위에 두고 제공된 실습 소스는 바꾸지 않는다.

## 새로운 C 문법 설명

### 정수 상수와 용량 식

`enum`으로 컴파일 시 정수 상수에 이름을 붙일 수 있다. `NODES_CAPACITY * 3 / 2`는 정수 연산이다. `NUMS_SIZE`도 노드 용량을 사용하므로 정상적인 전체 탐색에서 각 입력을 저장할 공간이 충분하다.

### 음수 정수의 나머지

C 정수 나눗셈은 0 방향으로 버리므로 음수를 나누면 나머지가 음수일 수 있다. 조건에 따른 한 번의 덧셈으로 키의 부호를 뒤집지 않고 정규화하므로 가장 작은 `int`에도 쓸 수 있다.

### 인덱스를 쓰고 나서 늘리기

`int i = hnodes_unused++;`에서는 증가 전 카운터 값이 `i`에 들어간 뒤 카운터가 늘어난다. 용량은 먼저 확인한다. 반환한 칸 인덱스와 추가 성공 상태는 둘 다 우연히 0일 수 있어도 의미가 다르다.

### 이전 위치를 거꾸로 방문하는 반복

안쪽 반복은 `i - 1`에서 시작하고 `j >= 0`인 동안 `j`를 줄인다. 부호 있는 `int`이므로 첫 바깥 반복에서는 -1에서 시작해 안쪽 반복을 건너뛴다. 인덱스 0을 검사한 뒤 감소하면 조건이 거짓이 된다.

### 반환값을 확인한 뒤 멤버 읽기

`hnodes[node].data`의 점은 배열 원소를 고른 다음 구조체 멤버를 선택한다. 먼저 `node != -1`인지 확인해야 한다. 두 정답 원소에 -1을 대입하면 실패를 나타내며, 성공한 짝을 쓴 뒤의 `return`은 함수를 바로 끝낸다.

## C 코드

### 노드 용량과 레코드

키와 데이터를 구분하고 노드 공간 열 개를 예약한다.

```c
/* 키와 데이터를 구분하고 노드 공간 열 개를 예약한다. */
/* NODES_CAPACITY > 0 */
enum { NODES_CAPACITY = 10, TABLE_CAPACITY = NODES_CAPACITY * 3 / 2 };

struct hnode {
    int key;
    int data;
    int next;
};
struct hnode hnodes[NODES_CAPACITY];
int hnodes_unused = 0;
```

### 다음 미사용 노드 할당하기

카운터나 필드를 바꾸기 전에 용량을 확인한다.

```c
/* 카운터나 필드를 바꾸기 전에 용량을 확인한다. */
int new_hnode(int _key, int _data, int _next) {
    if (hnodes_unused >= NODES_CAPACITY) {
        return -1;
    }
    int i = hnodes_unused++;
    hnodes[i].key = _key;
    hnodes[i].data = _data;
    hnodes[i].next = _next;
    return i;
}
```

### 음수 키 정규화하기

나머지와 조건부 덧셈으로 열다섯 버킷 중 하나를 고른다.

```c
/* 나머지와 조건부 덧셈으로 열다섯 버킷 중 하나를 고른다. */
int hash_func(int key) {
    int hash = key % TABLE_CAPACITY;
    if (hash < 0) {
        hash += TABLE_CAPACITY;
    }
    return hash;
}
```

### 첫 노드와 카운터 초기화하기

노드 필드나 정답을 지우지 않고 이전 체인에 도달할 수 없게 만든다.

```c
/* 노드 필드나 정답을 지우지 않고 이전 체인에 도달할 수 없게 만든다. */
int hashtable[TABLE_CAPACITY];

void initialize(void) {
    hnodes_unused = 0;
    for (int i = 0; i < TABLE_CAPACITY; i++) {
        hashtable[i] = -1;
    }
}
```

### 기존 첫 노드 앞에 추가하기

할당이 성공한 경우에만 새 첫 노드를 기록한다.

```c
/* 할당이 성공한 경우에만 새 첫 노드를 기록한다. */
int insert(int k, int d) {
    int hash = hash_func(k);
    int old_head = hashtable[hash];
    int node = new_hnode(k, d, old_head);
    if (node == -1) {
        return -1;
    }
    hashtable[hash] = node;
    return 0;
}
```

### 키 전체로 노드 찾기

일치한 노드 인덱스로 호출자가 연관 데이터를 읽을 수 있다.

```c
/* 일치한 노드 인덱스로 호출자가 연관 데이터를 읽을 수 있다. */
int find(int k) {
    int hash = hash_func(k);
    int node = hashtable[hash];
    while (node != -1) {
        if (hnodes[node].key == k) {
            return node;
        }
        node = hnodes[node].next;
    }
    return -1;
}
```

### 이전 위치의 쌍 비교하기

이전 인덱스를 감소시키며 첫 유효한 순서쌍을 반환한다.

```c
/* 이전 인덱스를 감소시키며 첫 유효한 순서쌍을 반환한다. */
enum { NUMS_SIZE = NODES_CAPACITY };

int nums[NUMS_SIZE] = {-16, -8, -4, -2, -1, 1, 2, 4, 8, 16};
int answer[2] = {-1, -1};

void two_sum_bf(int target) {
    for (int i = 0; i < NUMS_SIZE; i++) {
        for (int j = i - 1; j >= 0; j--) {
            if (nums[i] + nums[j] == target) {
                answer[0] = j;
                answer[1] = i;
                return;
            }
        }
    }
    answer[0] = answer[1] = -1;
}
```

### 추가 전에 보수 찾기

찾지 못한 경우에만 입력값을 키로, 그 위치를 데이터로 저장한다.

```c
/* 찾지 못한 경우에만 입력값을 키로, 그 위치를 데이터로 저장한다. */
void two_sum_ht(int target) {
    initialize();
    for (int i = 0; i < NUMS_SIZE; i++) {
        int complement = target - nums[i];
        int node = find(complement);
        if (node != -1) {
            int j = hnodes[node].data;
            answer[0] = j;
            answer[1] = i;
            return;
        }
        if (insert(nums[i], i) == -1) {
            break;
        }
    }
    answer[0] = answer[1] = -1;
}
```
