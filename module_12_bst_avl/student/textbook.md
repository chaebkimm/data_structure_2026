# Chapter 12. 순서를 지키며 검색 경로 줄이기

## Thinking Logically

### 찾을 문자가 어느 쪽에 있는가?

정렬된 명단에서는 찾는 이름이 현재 이름보다 앞서는지 비교할 수 있다.
뒤쪽 이름만 모인 부분은 더 살펴보지 않아도 된다.
트리에도 같은 조건을 둘 수 있다.
작은 문자는 왼쪽 부분에 모은다.
큰 문자는 오른쪽 부분에 모은다.
한 노드와 그 아래 전체가 이 조건을 지키는 구조가
이진 검색 트리(Binary Search Tree, BST)다.
비교에 쓰는 값은 키(key)다.

이번 장은 완성된 [lab.c](lab.c)를 읽는다.
Module 2의 `nodes[10]`을 그대로 사용한다.
`nodes[i].data`는 문자 키다.
`i`는 노드가 저장된 배열 인덱스다.
`left`와 `right`에는 키가 아니라 자식 인덱스를 저장한다.
없는 자식은 `-1`로 표시한다.

### 한쪽을 건너뛰면 항상 빠른가?

같은 키도 들어온 순서에 따라 다른 모양을 만든다.
A부터 G까지 차례로 넣으면 새 키는 계속 오른쪽으로 간다.
G를 찾으려면 일곱 노드를 모두 비교한다.
H가 없다는 사실을 확인할 때도 일곱 노드를 비교한다.
없는 링크에 도달한 순간에는 키 비교를 추가하지 않는다.

같은 키를 D, B, F, A, C, E, G 순서로 넣어 보자.
첫 키 D의 양쪽으로 키가 나뉜다.

```text
        D
       / \
      B   F
     / \ / \
    A  C E  G
```

G를 찾는 경로는 D, F, G다.
H를 찾을 때도 D, F, G를 거친 뒤 끝난다.
키의 집합과 비교 규칙은 같다.
입력 순서가 경로 길이를 바꿨다.

### 가장 긴 경로는 어떻게 셀까?

링크가 하나 늘어나면 검색에서 한 노드를 더 거친다.
노드에서 가장 먼 leaf까지 링크 수를 세면 모양을 비교할 수 있다.
이 수가 간선 높이(edge height)다.
이번 장에서 빈 부분의 높이는 -1이다.
자식이 없는 leaf의 높이는 0이다.

A부터 G까지 이어진 트리의 높이는 6이다.
D를 root로 둔 두 번째 트리의 높이는 2다.
부모 높이는 두 자식 높이 중 큰 값에 1을 더한 값이다.
두 자식이 모두 없으면 `max(-1,-1)+1 == 0`이다.

### 어느 한쪽만 길어지는 것을 어떻게 막을까?

매번 전체 높이를 재면 이미 있는 노드를 반복해서 방문한다.
각 노드의 정확한 높이를 따로 기록해 두자.
이 값이 저장 높이(stored height)다.
노드 구조체를 바꾸지 않고 같은 인덱스의 `height[10]`에 저장한다.

왼쪽 높이에서 오른쪽 높이를 빼면 기울어진 곳을 찾을 수 있다.
이 값이 균형 인수(balance factor)다.
모든 노드에서 이 값이 -1, 0, 1 중 하나여야 한다.
이 조건을 지키는 검색 트리가 AVL 트리(AVL tree)다.

삽입 전 트리가 올바르다면 새 leaf 하나로 부분 높이는 최대 1만 커진다.
복구가 필요한 노드의 균형 인수는 2 또는 -2다.
아래쪽부터 복구하면 부모는 복구된 자식 높이를 읽는다.

### 순서를 지키며 root를 바꿀 수 있는가?

새 키 때문에 길어진 부분만 연결을 바꿔 보자.
C, B, A를 넣으면 C 아래에서 왼쪽 경로가 두 번 이어진다.
B를 올리고 C를 B의 오른쪽으로 내리면 경로가 짧아진다.

```text
      C                 B
     /                 / \
    B         ->      A   C
   /
  A
```

inorder는 바꾸기 전과 후에 모두 A, B, C다.
작은 부분의 링크를 바꾸면서 inorder를 보존하는 동작을 회전(rotation)이라 한다.
노드의 인덱스와 키는 그대로다.
부모와 자식 관계만 바뀐다.

길어진 두 방향에 따라 네 경우로 나눈다.
L은 왼쪽, R은 오른쪽이다.

| 경우 | 입력 순서 | 호출하는 함수 | 최종 root 키 |
| --- | --- | --- | --- |
| LL | C, B, A | `rotate_ll` | B |
| RR | A, B, C | `rotate_rr` | B |
| LR | C, A, B | `rotate_lr` | B |
| RL | A, C, B | `rotate_rl` | B |

LL과 RR은 한 번의 기하학적 회전이다.
LR과 RL은 두 번의 회전에 해당한다.
이번 코드는 LR과 RL도 하나의 함수에서 필요한 링크를 직접 바꾼다.

### 중간에 있던 노드는 어디로 가는가?

세 노드 그림에서는 옮길 중간 부분이 비어 있다.
더 큰 트리에서는 그 부분도 보존해야 한다.
LL 복구 직전의 root를 `i`, 왼쪽 자식을 `l`이라 하자.
`l`의 오른쪽 부분은 `l`보다 크고 `i`보다 작다.
따라서 회전 뒤에는 `i`의 왼쪽으로 가야 한다.

```text
        i                       l
       / \                     / \
      l   R         ->        L   i
     / \                         / \
    L  lr                       lr  R
```

`lr`는 링크를 덮어쓰기 전에 저장한 인덱스다.
`rotate_ll`는 먼저 `nodes[i].left = lr`를 수행한다.
다음으로 `nodes[l].right = i`를 수행한다.
중간 부분은 새 root에서 계속 도달할 수 있다.

이 배열에서 링크를 잃어도 노드 메모리가 해제되지는 않는다.
노드는 여전히 배열 안에 있다.
문제는 검색과 순회가 해당 노드에 도달하지 못한다는 점이다.
동적 할당을 쓰는 별도 참고 코드의 메모리 누수와 구별한다.

### 높이는 왜 아래쪽부터 바꿀까?

회전 뒤에는 자식 높이도 바뀐다.
LL에서는 내려간 `i`의 높이를 먼저 계산한다.
그다음 새 root `l`의 높이를 계산한다.
세 키 예에서는 C의 높이가 0으로 바뀐다.
B는 자식 A와 C의 높이 0을 읽어 높이 1을 저장한다.

회전 함수는 링크만 바꾼다.
높이 갱신은 호출한 `_add`가 맡는다.
필요한 순서는 다음과 같다.

| 경우 | 높이를 갱신하는 노드 순서 |
| --- | --- |
| LL | `i`, `l` |
| RR | `i`, `r` |
| LR | `i`, `l`, `lr` |
| RL | `i`, `r`, `rl` |

LR의 두 하위 노드 `i`와 `l` 사이에는 높이 의존 관계가 없다.
둘을 갱신한 뒤 새 root `lr`를 갱신해야 한다.
RL도 같은 원리다.

### 반환한 인덱스는 왜 다시 저장할까?

빈 링크에 도달하면 준비된 새 노드를 연결한다.
`_add(-1,new_node)`는 leaf 높이를 0으로 정하고 새 인덱스를 반환한다.
부모는 반환된 인덱스를 자식 링크에 저장한다.
아래에서 회전했다면 이전 자식 인덱스와 다를 수 있다.

`l = nodes[i].left = _add(l,new_node)`는 두 곳을 갱신한다.
트리에 남는 실제 링크를 바꾼다.
이번 호출에서 균형 계산에 쓸 지역 변수 `l`도 바꾼다.
오른쪽 삽입도 대칭이다.

회전이 없으면 `root = i`가 유지된다.
회전하면 `root`는 회전 함수가 돌려준 인덱스가 된다.
가장 바깥 호출도 `root = _add(root,new_node)`로 결과를 저장한다.

### 같은 문자를 두 번 저장하면 어떻게 될까?

같은 키를 가진 서로 다른 레코드도 저장할 수 있다.
`<=` 비교 때문에 새 키는 같은 키의 왼쪽으로 내려간다.
B를 가진 새 노드 세 개를 넣으면 LL 회전이 일어난다.
가운데 노드가 올라가고 같은 B를 가진 노드가 오른쪽에도 남는다.

따라서 같은 키가 반드시 왼쪽에만 있다고 가정하면 안 된다.
전체 왼쪽 부분의 키는 현재 키 이하일 수 있다.
전체 오른쪽 부분의 키는 현재 키 이상일 수 있다.
inorder는 같은 값을 허용하는 비내림차순이다.
같은 키를 새 ID로 넣는 것과 이미 연결된 ID를 다시 넣는 것은 다르다.
이미 연결된 ID의 재삽입은 올바른 호출이 아니다.

### 코드를 호출하기 전에 무엇을 준비할까?

사용할 인덱스는 0부터 9까지다.
새 ID는 아직 트리에 없어야 한다.
키를 정하고 양쪽 자식을 -1로 초기화한다.
기존 트리의 링크와 저장 높이도 정확해야 한다.
`alphabet_init()`는 A부터 J까지 키와 링크를 준비한다.
새 트리의 별도 root는 -1로 시작한다.

`nodes_size`는 이 초기화에서 10이 된다.
선택한 root가 도달하는 노드 수라는 뜻은 아니다.
높이는 새 노드를 삽입할 때 설정된다.

원본은 잘못된 ID나 열한 번째 노드를 검사하지 않는다.
할당하거나 삭제하는 함수도 없다.
검색, 일반 BST 비교, 독립 검사는 테스트 드라이버가 제공한다.
모든 기대 ID의 도달 여부, 중복 방문, inorder, 높이, 균형을 함께 검사한다.
실제 높이를 잴 때는 `height[]`를 신뢰하지 않고 링크를 따라간다.

## Calculating Efficiency

### 같은 일곱 키에서 몇 번 비교할까?

검색에서 방문한 노드 수를 세면 작업량이 보인다.
한 방문을 한 번의 키 비교로 센다.
빈 링크 도착은 비교에 넣지 않는다.
내림차순의 누락 키 @는 이번 문자 환경에서 A보다 작다.

| 구조와 입력 | 높이 | 존재 키와 비교 수 | 누락 키와 비교 수 |
| --- | ---: | --- | --- |
| 일반 BST, ABCDEFG | 6 | G: 7 | H: 7 |
| 일반 BST, GFEDCBA | 6 | A: 7 | @: 7 |
| 일반 BST, DBFACEG | 2 | G: 3 | H: 3 |
| AVL, ABCDEFG | 2 | G: 3 | H: 3 |
| AVL, GFEDCBA | 2 | A: 3 | @: 3 |
| AVL, DBFACEG | 2 | G: 3 | H: 3 |

세 AVL 결과는 모두 D를 root로 둔다.
다른 모든 입력 순서도 같은 최종 모양을 만든다는 주장은 아니다.
같은 키를 저장해도 모양에 따라 실제 비교 횟수가 달라진다.

### 회전은 얼마나 많은 링크를 바꿀까?

대입 수는 트리 전체 크기에 따라 늘어나지 않는다.
LL과 RR은 자식 링크 두 개를 바꾼다.
LR과 RL은 자식 링크 네 개를 바꾼다.
각 복구는 두 개 또는 세 개 노드의 높이를 갱신한다.
자식 높이는 배열에서 바로 읽는다.
이 고정된 작업을 `O(1)`이라 쓴다.

### 검색과 삽입은 어느 길을 지날까?

검색은 한 경로를 내려간다.
삽입은 내려가고 돌아오면서 높이를 복구한다.
높이가 `h`면 빈 경우까지 포함해 `O(h + 1)` 작업이다.
일반 BST가 `n`개 노드의 사슬이면 높이는 `n-1`이다.
최악의 작업은 `O(n)`이다.

AVL은 모든 위치에서 양쪽 높이 차이를 제한한다.
그 조건을 지키며 높이를 한 단계 늘리려면 더 많은 노드가 필요하다.
노드 수가 커져도 높이는 로그 규모로 증가한다.
그래서 일반화된 구현의 검색과 삽입은 `O(log n)`이다.
로그 표기는 노드 수 증가보다 경로 증가가 훨씬 느리다는 뜻이다.
열 칸의 실제 코드와 용량을 늘린 설계의 분석을 구별한다.

### 저장 공간과 검사 비용은 같은가?

기존 `nodes[10]`과 추가 `height[10]`은 항상 열 칸을 예약한다.
실제 코드의 예약 공간은 고정되어 있다.
용량을 `N`으로 늘리면 두 배열은 `O(N)` 공간이다.
활성 재귀 호출은 root에서 새 leaf까지의 경로를 따른다.
높이가 `h`면 `O(h + 1)` 호출 공간이다.

전체 검사는 모든 도달 노드를 방문한다.
고정 ID 환경에서는 방문 표시를 배열로 관리할 수 있다.
노드마다 한 번 처리하는 검사와 실제 높이 측정은 `O(n)`이다.
테스트에서 매 삽입 뒤 검사하는 비용은 `_add` 자체의 비용과 분리한다.
별도 포인터 참고 구현의 검사 비용도 현재 드라이버와 구별한다.

### 짧은 경로가 무엇을 보장할까?

입력 순서를 정할 수 있는 상대는 일반 BST를 사슬로 만들 수 있다.
유효한 입력으로 예상보다 많은 계산을 시키는 문제를
알고리즘 복잡도에 의한 서비스 거부(algorithmic-complexity denial of service)라 한다.
일곱 키 실험은 작업 증가를 보여 주는 모형이다.
실제 서비스 중단을 입증한 실험은 아니다.

유효한 노드를 더 많이 비교하는 일과 잘못된 메모리를 읽는 일은 다르다.
자원이 모두 소진되었다는 주장도 별도 근거가 필요하다.
높이 제한은 입력 검사나 접근 권한 검사를 대신하지 않는다.
Heap은 부모 우선순위를 지킨다.
BST는 전체 부분 트리의 키 순서를 지킨다.
AVL은 그 순서에 높이 제한을 더한다.

## Glossary

문제에서 사용한 개념을 이름과 연결한다.
배열 인덱스와 키를 구별해 읽는다.

| 이름 | 뜻 |
| --- | --- |
| 이진 검색 트리 | 왼쪽과 오른쪽 부분 전체가 정해진 키 순서를 지키는 트리 |
| 키 | `nodes[i].data`에 저장된 비교 기준 문자 |
| 간선 높이 | 노드에서 가장 먼 leaf까지 링크 수, 빈 부분은 -1 |
| 저장 높이 | 실제 간선 높이를 따로 저장한 `height[i]` |
| 균형 인수 | 왼쪽 높이에서 오른쪽 높이를 뺀 값 |
| AVL 트리 | 모든 균형 인수를 -1, 0, 1로 유지하는 검색 트리 |
| 회전 | inorder를 보존하며 작은 부분의 링크를 바꾸는 동작 |
| 중간 부분 트리 | 회전 때 두 키 사이에서 기존 root 쪽으로 옮겨 연결하는 부분 |
| 비내림차순 | 같은 값을 허용하며 다음 값이 작아지지 않는 순서 |

## Coding Plan

준비된 ID를 연결하고 돌아오면서 필요한 부분만 복구한다.
원본을 다시 작성하는 과제는 아니다.
상태를 예측하고 원본을 실행하는 테스트로 확인한다.

1. Module 2의 노드를 준비한다. 새 root는 -1로 둔다.
2. 높이 보조 함수의 빈 부분 -1, leaf 0 기준을 확인한다.
3. 네 회전에서 인수로 저장한 중간 링크가 어디로 가는지 추적한다.
4. 재귀 결과를 실제 링크와 지역 자식 변수에 함께 저장한다.
5. 균형 범위이면 높이를 갱신한다.
6. 불균형이면 회전하고 하위 노드부터 새 root까지 높이를 갱신한다.
7. 반환한 root를 저장한다. 독립 테스트로 링크, 순서, 높이, 균형을 검사한다.

### 노드를 준비한다

다음 준비는 main 안에서 수행한다.

```c
alphabet_init();

```

### 높이 기준을 읽는다

먼저 빈 자식과 실제 자식을 구별해야 한다.
원본의 세 보조 함수는 다음과 같다.

```c
int get_height(int i) {
    if (i == -1) {return -1;}
    else {return height[i];}
}
int get_balance(int l, int r) {
    return get_height(l) - get_height(r);
}
void set_height(int i, int l, int r) {
    int h_l = get_height(l);
    int h_r = get_height(r);
    height[i] = (h_l > h_r ? h_l : h_r) + 1;
}
```

### 저장한 중간 링크를 연결한다

덮어쓸 링크는 인수로 이미 보존했다.
다음 함수는 높이를 바꾸지 않는다.

```c
int rotate_ll(int i, int l, int lr) {
    nodes[i].left = lr;
    nodes[l].right = i;
    return l;
}

int rotate_lr(int i, int l, int lr, int lrl, int lrr) {
    nodes[l].right = lrl;
    nodes[i].left = lrr;
    nodes[lr].left = l;
    nodes[lr].right = i;
    return lr;
}
```

`rotate_rr`와 `rotate_rl`은 반대쪽 인덱스를 같은 원리로 연결한다.
`_add`의 LL 분기는 회전한 뒤 자식부터 높이를 계산한다.

```c
root = rotate_ll(i, l, lr);
set_height(i, lr, r);
set_height(l, ll, i);
```

### 재귀 결과와 새 root를 저장한다

반환된 부분 트리 root는 부모 링크를 대체한다.
다음 줄은 원본 `_add`의 왼쪽 재귀 분기다.

```c
l = nodes[i].left = _add(l, new_node);
```

완전한 작은 실행은 별도 `main`에서 확인한다.
이 드라이버는 C, B, A를 넣는다.
초기 문자 ID는 A=0, B=1, C=2다.

```c
#include <assert.h>
#include "module_12_bst_avl/student/lab.c"

int main(void) {
    alphabet_init();
    int root = -1;
    int order[] = {2, 1, 0};
    for (int k = 0; k < 3; ++k) {
        root = _add(root, order[k]);
    }

    assert(root == 1);
    assert(nodes[root].data == 'B');
    assert(nodes[root].left == 0);
    assert(nodes[root].right == 2);
    assert(nodes[0].left == -1 && nodes[0].right == -1);
    assert(nodes[2].left == -1 && nodes[2].right == -1);
    assert(height[0] == 0 && height[1] == 1 && height[2] == 0);
    return 0;
}
```

`A,B,C`, `C,A,B`, `A,C,B`도 매번 초기화한 상태에서 검사한다.
더 큰 예에서는 모든 기대 ID의 도달 여부와 실제 높이도 검사한다.
