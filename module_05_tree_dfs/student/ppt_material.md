- 데이터를 처리할 타이밍
- preorder: 자식 노드들 방문 전
- inorder: 자식 노드들 방문 도중
- postorder: 자식 노드들 방문 후

# 스택으로 이진 트리 탐색하기

- 재귀 호출 대신 스택에 저장한다.
- 탑 노드를 한 단계 처리한다.
- 1. preorder 처리, 왼쪽 자식 노드 추가
- 2. inorder 처리, 오른쪽 자식 노드 추가
- 3. postorder 처리, 현재 노드 제거

# 트리 탐색에 따른 스택의 변화

- 처음에 루트가 추가된다.
- 이어서 루트의 왼쪽 자식이 추가된다.
- 왼쪽 자식의 왼쪽 자식이 추가된다.
- 리프 노드도 없는 자식의 인덱스 -1을 추가한다. 다음 단계에서 -1을 바로 제거한다.
- 리프 노드는 두 자식 처리가 끝나면 postorder 방문 후 제거된다.
- 부모 노드의 오른쪽 자식이 추가된다.
- 오른쪽 자식의 왼쪽 자식이 추가된다...

# 스택에 있는 노드 처리 규칙

- 노드별로 현재 진행 상황을 기록해 둔다.
- 스택의 탑 노드에서 다음 단계를 실행하고 진행 상황을 업데이트한다.
- 스택에서 탑을 새로 읽고 반복한다.
- 스택이 비면 반복을 종료한다.

# postfix에서 수식 트리 만들기

- 수식 트리에서 숫자는 리프 노드, 연산자는 자식이 두 개인 내부 노드다.
- postorder에서 연산자 앞에는 오른쪽 서브트리가 있고, 그 앞에는 왼쪽 서브트리가 있다.

- postorder: 123*+
- lab.c의 postfix는 처음에 빈 문자열이다. 변환하거나 유효한 postfix를 먼저 넣는다.
- build_tree_from_postfix()는 스택에 노드 인덱스를 저장한다.
- 숫자는 스택에 추가한다.
- 연산자는 오른쪽 루트부터 꺼내고 왼쪽 루트를 꺼내 자식으로 붙인 후 새 노드의 인덱스를 추가한다.
- 모두 읽으면 스택에 루트만 남게 된다.
- build_tree_from_postfix()의 마지막 pop()은 루트 인덱스를 반환하고 스택을 비운다.

# 수식 트리를 inorder로 읽기

- inorder로 읽으면 infix 수식이 나온다.
- 루트에서 시작해서 왼쪽 리프에 도달하면 첫 번째 숫자가 나온다.
- 그 다음에는 첫 번째 숫자의 부모 연산자 노드가 나온다.
- 그리고 오른쪽 서브트리를 처리한다.

- inorder로 쓰면 연산자의 왼쪽에는 왼쪽 피연산자에 해당하는 서브트리가 수식으로 쓰인다. 연산자의 오른쪽에는 오른쪽 피연산자에 해당하는 서브트리가 수식으로 쓰인다.

# inorder에 괄호 추가하기

- 현재 _write_infix()는 우선순위에 따라 괄호를 쓰며 트리의 묶음을 유지한다.
- 12+3*의 출력은 (1+2)*3이고 123--의 출력은 1-(2-3)이다.

- prec2()로 현재 연산자와 자식의 우선순위를 비교한다.
- 왼쪽 피연산자에 우선순위가 더 낮은 연산자가 있으면, 괄호를 친다.
- 오른쪽 피연산자에 우선순위가 같거나 더 낮은 연산자가 있으면, 괄호를 친다.
- 숫자에는 괄호를 치지 않는다.
- prec2()는 숫자에 3을 반환한다. 나머지는 Chapter 4의 prec()를 사용하며 * / %는 2, + -는 1이다. 숫자는 모든 지원 연산자보다 우선순위가 높으므로 괄호가 붙지 않는다.
- 괄호를 쳐야 할 경우에는, 서브트리에 재귀 호출을 하기 전에 먼저 괄호를 열고, 재귀 호출이 끝난 후에 괄호를 닫는다.

# lab.c의 실행 상태와 용량

- tree_traversal_proceed(int i)는 전달받은 탑 노드 인덱스의 작업 하나를 실행한다. 래퍼는 tree_traversal_proceed(peek())로 호출한다.
- tree_traversal_with_stack()은 top만 초기화하며 progress는 초기화하지 않는다.
- 한 번 방문한 노드의 progress는 3이다. 두 번째 순회 전에 모두 0으로 초기화해야 한다. 새 트리를 만들 때도 progress는 남아 있다.
- write_infix()는 전체 쓰기 시작에서 infix_pos를 0으로 초기화한다. 보조 함수 호출 뒤 write_char('\0')로 문자열을 끝낸다.
- write_char(c)는 현재 위치에 쓰고 infix_pos를 증가시킨다. 자식 호출에서는 같은 위치를 공유하며 초기화하지 않는다.
- 반복 전체 쓰기는 첫 칸부터 다시 시작한다. 1+2*3의 종료 문자는 인덱스 5에 있으며 마지막 infix_pos는 6이다.
- _write_infix()는 음수 루트에서 반환한다. write_infix(-1)은 빈 문자열을 만들지만 연산자의 자식 누락은 검증하지 않는다.
- postfix[8]에는 최대 7개의 토큰과 '\0'이 들어간다. 입력은 한 자리 숫자와 이항 연산자로 된 유효한 수식이라고 가정한다.
- 괄호를 쓴 1+(2+(3+4))는 '\0'까지 12칸이 필요하며 현재 infix[20]에 들어간다. 입력이나 용량은 검사하지 않는다.
- 10개 노드가 일렬로 연결된 트리를 순회하면 -1까지 스택 11칸이 필요하다. 용량을 늘리거나 없는 자식은 추가하지 않는 방식으로 확장한다.

# 선택 연습 — A 루트 트리에서 노드가 방문되는 순서

- ((D)-(B)-(E))-(A)-((F)-(C)-(G))
- preorder: ABDECFG
- inorder: DBEAFCG
- postorder: DEBFGCA

# 노드 방문 순서에서 트리 재구성 (선택 연습)

- 노드의 값이 모두 다르다고 가정한다.
- 각 inorder 구간의 크기로 해당 preorder 구간을 나눈다.
- 이 예제의 루트는 A이며, lab.c에서 tree_connect()가 만드는 F 루트 트리와 다르다.
- 재구성은 개념 연습이며 lab.c에는 구현되어 있지 않다.

- (DBE)-(A)-(FCG)
- preorder: ['A'BDECFG]
- inorder: [DBE'A'FCG]
- preorder의 첫 번째 노드 A는 루트
- inorder에서 A 왼쪽은 왼쪽 서브트리, A 오른쪽은 오른쪽 서브트리.

- ((D)-(B)-(E))-(A)-(FCG)
- preorder: A['B'DE]CFG
- inorder: [D'B'E]AFCG
- preorder의 첫 번째 노드 B가 루트
- inorder에서 B 왼쪽은 왼쪽 서브트리, B 오른쪽은 오른쪽 서브트리.

- ((D)-(B)-(E))-(A)-((F)-(C)-(G))
- preorder: ABDE['C'FG]
- inorder: DBEA[F'C'G]
- preorder의 첫 번째 노드 C가 루트
- inorder에서 C 왼쪽은 왼쪽 서브트리, C 오른쪽은 오른쪽 서브트리.
