# 11장. 이진 힙

우선순위 큐의 값을 우선순위 순서로 저장하면 다음 값을 바로 꺼낼 수 있다. 그런데 새 값이 맨 앞에 들어가면 기다리던 값을 모두 옮겨야 한다. 트리를 사용해 다음에 꺼낼 값을 맨 위에 두고, 한 경로에 있는 값만 옮겨 보자. 그런 다음 값이 아무 순서로 들어 있는 트리를 힙으로 만들고, 그 힙으로 정수를 정렬해 본다.

## 논리적으로 생각해 보기

### 다음에 꺼낼 값을 정하려면 어디까지 순서를 맞춰야 할까?

값을 정렬하면 어느 두 값을 골라도 그 사이의 순서가 정해져 있다. 우선순위 큐에서는 우선순위가 가장 높은 값이 root에 있으면 된다. 부모의 우선순위를 각 자식의 우선순위보다 높거나 같게 둔다. 어느 값에서든 부모를 따라 올라가면 우선순위는 높아지거나 그대로이므로 root의 우선순위가 가장 높다. 형제 사이의 순서는 자유롭다.

### 다음 리프는 어디에 놓을까?

한 층을 다 채운 뒤에 다음 층을 시작하고, 같은 층에서는 왼쪽부터 채운다. root에 두 자식이 생기면 다음 리프는 왼쪽 자식 아래의 왼쪽 자리에 놓는다.

### 값을 올릴 때 넣을 자리를 어떻게 찾을까?

새 값을 따로 보관하고 빈자리에서 시작한다. 부모 값의 우선순위가 새 값의 우선순위보다 낮으면 부모 값을 한 층 아래의 빈자리로 복사한다. 이제 부모가 있던 자리가 비었다. root에 도달하거나 새 값과 우선순위가 같거나 더 높은 부모를 만날 때까지 반복한다. 마지막 빈자리에 새 값을 넣는다.

### 값을 내릴 때는 어느 자식을 올릴까?

두 자식 중 우선순위가 더 높은 자식을 고른다. 한 층 올라간 자식이 다른 자식의 부모가 되기 때문이다. 고른 자식의 우선순위가 따로 보관한 값의 우선순위보다 높으면 그 자식 값을 한 층 위의 빈자리로 복사하고, 그 자식이 있던 자리에서 계속한다. 보관한 값과 우선순위가 같으면 자식은 그대로 둬도 된다. 왼쪽 자식만 있으면 그 자식과 비교한다. 리프에 도달하면 탐색을 마친다. 마지막 빈자리에 보관한 값을 넣는다.

### 힙에 새 값을 어떻게 넣을까?

다음 리프가 들어갈 자리를 비워 두고, 거기서부터 새 값을 올리며 알맞은 자리를 찾는다. 그 리프에서 root까지의 경로에 있는 부모 값만 움직일 수 있고, 움직이는 값은 한 층씩 내려간다. 새 리프가 그 자리를 채우므로 트리는 완전 이진 트리의 모양을 유지하고, 힙에 든 값은 하나 늘어난다.

### root에서 꺼낸 값의 자리는 어떤 값으로 채울까?

root 값을 꺼내면 그 자리가 빈다. 자식 값을 올리기만 하면 빈자리가 아래로 옮겨 갈 뿐이어서 한 층의 중간에 빈자리가 남을 수 있다. 마지막 리프의 값을 따로 보관하고 그 리프를 없애면 트리는 완전 이진 트리의 모양을 유지한다. 보관한 값이 들어갈 자리는 root에서부터 내려가며 찾는다. 그 경로에 있는 자식 값만 한 층씩 올라가고, 힙에 든 값은 하나 줄어든다.

### 주어진 트리를 어떻게 힙으로 만들까?

값이 하나뿐인 트리는 이미 힙이다. root에서 시작해 값을 하나씩 넣으며 힙을 키울 수 있다. 새 값은 올라가면서 자기 자리를 찾는다. 리프에서 시작할 수도 있다. 각 리프는 값 하나짜리 힙이다. 부모 값을 내려 알맞은 자리를 찾아 주면 자식 힙들이 하나로 합쳐진다. 이렇게 root를 향해 올라간다.

### 자식 힙을 합치면 왜 하나의 힙이 될까?

리프에서 root 쪽으로 올라가면 각 부모 차례가 되기 전에 그 아래의 값을 모두 처리했으므로 자식 트리들은 이미 힙이다. root에서 값을 꺼낸 뒤와 마찬가지로 맨 위의 값만 제자리를 벗어나 있을 수 있다. 그 값을 따로 보관하고 자식 중 우선순위가 가장 높은 값을 고른다. 고른 값의 우선순위는 두 자식 트리의 어느 값보다도 높거나 같다. 보관한 값보다 우선순위가 높으면 그 자식 값을 한 층 위의 빈자리로 복사하고, 보관한 값이 들어갈 자리를 찾을 때까지 계속 내려간다. 같은 값 내리기를 root부터 시작하면 아직 힙이 되지 않은 자식 트리로 값을 내릴 수 있어서, 끝까지 진행해도 트리 전체가 힙이 된다는 보장이 없다.

### root에서 하나씩 꺼내면 어떻게 정렬될까?

앞에서처럼 힙을 만든 뒤 root에서 값을 하나 꺼내 보자. 기다리던 값 중 우선순위가 가장 높은 값이 나오고, 남은 값들은 다시 힙을 이룬다. 힙이 빌 때까지 반복하면 모든 값이 우선순위 순서로 나온다. 꺼낸 순서대로 값을 모으면 정렬이 끝난다.

### 배열의 어느 자리에 트리를 저장할까?

트리를 채우는 순서대로 각 자리에 번호를 붙인다. root의 인덱스는 0, 두 자식의 인덱스는 1과 2다. 그다음 층의 자리는 3부터 6까지다.

### 각 층은 어느 인덱스에서 시작하고 끝날까?

root를 0층으로 두면 d층의 첫 인덱스는 2ᵈ − 1이다. 그 위의 층에 1 + 2 + … + 2ᵈ⁻¹ = 2ᵈ − 1개의 값이 있기 때문이다. d층을 다 채웠을 때 마지막 인덱스는 다음 층인 d + 1층이 시작되기 바로 전인 2ᵈ⁺¹ − 2다.

### 자식은 어느 자리에 있을까?

d층의 인덱스 i 앞에는 같은 층의 값이 i − (2ᵈ − 1)개 있다. 다음 층은 인덱스 2ᵈ⁺¹ − 1에서 시작하고, 앞선 값 하나마다 자식 자리 두 개를 건너뛴다. 따라서 인덱스 i의 왼쪽 자식 자리는 2ᵈ⁺¹ − 1 + 2(i − 2ᵈ + 1) = 2i + 1이고, 오른쪽 자식 자리는 바로 다음인 2i + 2다.

### 부모는 어느 자리에 있을까?

root가 아닌 자식의 인덱스가 c라면 부모의 인덱스는 (c − 1) / 2에서 소수 부분을 버린 값이다. c에 왼쪽 자식의 인덱스 2i + 1을 넣어도, 오른쪽 자식의 인덱스 2i + 2를 넣어도 부모의 인덱스 i가 나온다.

## 효율 계산해 보기

### 값을 하나 넣거나 꺼낼 때 작업량은 얼마나 될까?

값을 넣거나 꺼낼 때는 리프와 root를 잇는 한 경로에서만 값을 옮긴다. 경로를 한 층 지날 때마다 부모나 자식 값 하나를 빈자리로 옮긴다. 마지막 층을 제외한 모든 층이 가득 차 있고, 한 층에 들어갈 수 있는 값의 수는 바로 위층의 두 배다. 따라서 값이 n개인 힙은 n ≥ 1일 때 ⌊log₂ n⌋ + 1개의 층을 차지한다. 올라갈 때는 층마다 부모 값 하나와 비교한다. 내려갈 때는 두 자식 중 우선순위가 더 높은 쪽을 골라 보관한 값과 비교한다. 어느 쪽이든 한 층에서 하는 일이 일정하므로 최악의 경우 작업량은 log₂ n에 비례한다.

### root에서 시작해 힙 전체를 만드는 작업량은 얼마나 될까?

값을 하나씩 넣어 힙을 키울 때, 새 값의 우선순위가 지금까지 넣은 값 중 가장 높으면 그 값은 root까지 올라간다. 새 값이 매번 root까지 올라간다고 해 보자. 아래쪽 두 층에 전체 값의 절반 이상이 들어가므로 많은 값이 트리의 높이만큼 올라가야 한다. 그래서 최악의 경우 전체 작업량은 n log₂ n에 비례한다.

### 리프에서 시작해 힙 전체를 만드는 작업량은 얼마나 될까?

리프에서 시작해 힙을 합칠 때, 리프는 그 자체로 힙이므로 리프에서 값을 내릴 일은 없다. 다만 부모 값을 내릴 때 리프의 값이 위로 올라갈 수 있다. 부모 값을 내릴 때도 그 자리 아래에 있는 층만큼만 내려갈 수 있다. 한 층 이상 내려갈 수 있는 시작 자리는 전체의 절반 이하이고, 두 층 이상은 4분의 1 이하, 세 층 이상은 8분의 1 이하다. 각 층을 한 번 내려가는 것을 한 번으로 세어 모두 더하면 비어 있지 않은 힙에서는 n번보다 적다. 각 부모를 한 번씩 방문하는 일까지 합쳐도 전체 작업량은 n에 비례한다.

### 힙으로 정렬하는 작업량은 얼마나 될까?

비어 있지 않은 힙을 리프에서부터 합쳐 만들면 한 층씩 내려가는 횟수를 모두 더해도 n번보다 적다. 그런 다음 root에서 값을 n번 꺼낸다. 한 번 꺼낼 때마다 값은 한 경로를 따라 최대 ⌊log₂ n⌋층을 내려간다. 꺼낼수록 힙이 작아지지만, 처음 절반을 꺼내는 동안에는 적어도 n/2개의 값이 남아 있다. 최악의 경우에는 이 중 일정 비율의 호출에서 값이 힙의 높이에 가까운 거리만큼 내려간다. 따라서 정렬의 전체 작업량은 n log₂ n에 비례한다.

### 저장 공간은 얼마나 필요할까?

힙에는 값을 하나씩 담을 배열과 현재 값의 개수를 기록할 변수 하나가 필요하다. 배열에 마련한 자리 수가 힙에 넣을 수 있는 값의 최대 개수다. 부모와 자식의 위치는 계산으로 구하므로 포인터를 저장할 공간은 필요 없다. 값을 넣거나 꺼내거나 힙 전체를 만들 때는 따로 보관한 값과 빈자리의 위치처럼 몇 개의 변수만 더 쓴다. 이 장의 정렬 방법은 꺼낸 값을 두 번째 배열에 모으므로 값이 n개면 n개의 자리가 더 필요하다. 값을 하나 꺼낼 때마다 힙의 마지막 자리가 비므로 꺼낸 값을 그 자리에 쓸 수도 있다. 최소 힙에서는 작은 값부터 배열 뒤쪽에 쓰게 되므로 결과는 내림차순이 된다.

## 용어 정리

### 완전 이진 트리

위층부터 차례로 채우고, 같은 층에서는 왼쪽부터 채우는 이진 트리다. 마지막 층만 일부가 비어 있을 수 있다.

### 이진 힙

각 부모의 우선순위가 어느 자식보다도 높거나 같은 완전 이진 트리다.

### 최소 힙

작은 값의 우선순위가 더 높은 힙이다. 비어 있지 않으면 root에 최솟값이 있다.

### 최대 힙

큰 값의 우선순위가 더 높은 힙이다. 비어 있지 않으면 root에 최댓값이 있다.

### 빈자리

원래 있던 값을 다른 자리에 복사해 두었거나 아직 값을 넣지 않아서 새 값을 써도 되는 자리다. 마지막 빈자리에 따로 보관한 값을 넣는다.

### 데이터 올리기 (Sift-up)

따로 보관한 값보다 우선순위가 낮은 부모 값을 한 층씩 내리며, 보관한 값이 들어갈 자리를 찾는 것이다.

### 데이터 내리기 (Sift-down)

따로 보관한 값보다 우선순위가 높은 자식 값을 한 층씩 올리며, 보관한 값이 들어갈 자리를 찾는 것이다.

### 힙 만들기 (Heapify)

주어진 트리를 힙으로 만드는 것이다. 마지막 부모부터 root까지 거슬러 올라가며 각 부모의 값을 내려 제자리를 찾는다.

### 힙 정렬

힙이 빌 때까지 root에서 값을 하나씩 꺼내 정렬하는 방법이다. 이 장의 코드에서는 힙을 먼저 만든 뒤 `heap_sort`를 호출한다.

## 규칙

### 어떤 자리를 항상 사용하고 있을까?

연산과 연산 사이에는 값들이 인덱스 0부터 `size - 1`까지 빈틈없이 들어 있고, `size`는 그 값의 개수다. 값을 올리거나 내리는 동안에는 한 자리를 비워 두고 값 하나를 배열 밖에 따로 보관한다. 연산을 마칠 때는 빈자리를 다시 채운다. 인덱스 `size`부터는 예전 값이 남아 있어도 힙에 속하지 않는다.

### 한 경로만 고쳐도 힙의 순서가 유지되는 이유는 무엇일까?

값을 넣거나 꺼내기 전에는 트리가 이미 힙이다. 값은 빈자리가 움직이는 경로를 따라서만 복사하므로 경로 밖의 부모와 자식은 원래 순서를 유지한다. 아래로 복사한 값은 원래 자기 아래에 있던 값들 위에 놓인다. 위로 복사한 값은 새 자리 아래에 있는 어느 값보다도 우선순위가 높거나 같다. 이제 따로 보관한 값을 빈자리에 놓아도 되는지만 확인하면 된다. 올라갈 때는 바로 위의 부모와, 내려갈 때는 우선순위가 가장 높은 자식과 비교한다. 더 비교할 값이 없거나 두 값의 순서가 맞으면 멈춘다.

### 힙을 만들 때 한 부모의 차례가 오면 무엇이 이미 참일까?

인덱스 `i`를 처리할 차례가 되면 `i`보다 뒤에 있는 각 자리를 root로 하는 트리는 이미 힙이다. 마지막 부모 뒤에는 리프만 있으므로 처음부터 이 조건이 성립한다. `i`의 자식은 모두 `i`보다 뒤에 있으므로 `i`의 값을 내리기 시작할 때는 양쪽 자식 트리가 이미 힙이다.

## 코딩 계획

### 우선순위 큐에는 어떤 데이터가 필요할까?

기다리는 정수는 `pq[CAPACITY]`에 담고 개수는 `size`에 둔다. 처음에는 개수를 0으로 설정한다. `compare(x, y)`는 `x < y`일 때 참을 반환한다. 같은 값은 우선순위도 같다. 큐가 가득 찼는지, 비었는지 검사하는 코드는 없으므로 호출하는 쪽에서 가득 찬 큐에 값을 넣거나 빈 큐에서 값을 꺼내지 않도록 한다.

### 값을 올릴 때 우선순위가 낮은 조상의 값은 어떻게 옮길까?

주어진 자리를 빈자리로 보고, 따로 보관한 값이 들어갈 곳을 찾는다. 빈자리가 root가 아니고 부모의 우선순위가 보관한 값보다 낮으면 부모 값을 빈자리로 한 층 내린다. 부모가 있던 자리가 새 빈자리가 되므로 거기서 같은 비교를 반복한다. 마지막 빈자리의 인덱스를 반환하면 호출한 쪽에서 보관한 값을 그 자리에 넣는다.

### 값을 내릴 때 우선순위가 높은 자손의 값은 어떻게 옮길까?

주어진 자리를 빈자리로 보고, 따로 보관한 값이 들어갈 곳을 찾는다. 빈자리에 자식이 있고 고른 자식의 우선순위가 보관한 값보다 높으면 그 자식 값을 빈자리로 한 층 올린다. 자식이 있던 자리가 새 빈자리가 되므로 거기서 같은 비교를 반복한다. 마지막 빈자리의 인덱스를 반환하면 호출한 쪽에서 보관한 값을 그 자리에 넣는다. 어느 자식을 고를지는 다음 절에서 살펴본다.

### 실제로 있는 자식을 어떻게 고를까?

자식 인덱스가 현재 값의 개수보다 작아야 그 자리에 자식이 있다. 자식이 둘이면 우선순위가 높은 쪽을 고르고, 우선순위가 같으면 왼쪽을 고른다. 왼쪽 자식만 있으면 그 자식을 고른다. 자식이 없으면 호출한 쪽에 멈춰야 한다고 알린다.

### 값을 넣으려면 무엇을 해야 할까?

사용하지 않는 첫 자리의 인덱스는 현재 값의 개수와 같다. 그 자리에서 시작해 새 값을 올린다. 반환된 자리에 새 값을 넣고 개수를 하나 늘린다.

### 값을 꺼내려면 무엇을 해야 할까?

먼저 root 값을 보관한다. 개수를 하나 줄이면 마지막 리프가 힙에서 빠진다. 그 리프의 값을 따로 들고 root에서부터 내린다. 반환된 자리에 그 값을 넣고, 처음에 보관한 root 값을 반환한다.

### 힙 만들기는 어디서 시작할까?

마지막 값의 부모에서 시작한다. 그보다 뒤에 있는 자리에서는 자식 인덱스가 마지막 값의 인덱스를 넘으므로, 이 부모가 자식을 둔 마지막 자리다. 거기서 root까지 인덱스를 하나씩 줄인다. 각 자리의 값을 따로 보관하고, 그 값을 내려 알맞은 자리를 찾은 다음 그 자리에 넣는다.

### 정렬할 때 반복문은 몇 번 실행해야 할까?

이미 만들어진 힙에서 시작한다. 처음 값의 개수를 따로 저장하고 그만큼 반복한다. 값을 꺼낼 때마다 개수가 하나씩 줄어들므로 줄어드는 개수와 반복 횟수를 비교하면 절반쯤 꺼내고 멈추게 된다. 매번 root에서 값을 하나 꺼내 두 번째 배열의 앞에서부터 차례로 쓴다. 그러면 값들이 우선순위 순서대로 저장된다.

## 새로운 C 문법 설명

### 정수 나눗셈으로 어떻게 부모 인덱스를 구할까?

인덱스 `i`의 두 자식은 `2*i + 1`과 `2*i + 2`다. 어느 쪽이든 1을 빼고 2로 나눈다. 음이 아닌 정수끼리 나눌 때 C는 소수 부분을 버리므로 두 경우 모두 `i`가 나온다. 이 결과는 부모가 있는 자리에서만 쓴다. root에는 부모가 없다.

```c
int parent(int i) { return (i - 1) / 2; }
```

### 자식 자리의 값을 언제 읽어도 될까?

`c < size && compare(pq[c], data)`에서 C는 왼쪽 조건을 먼저 검사한다. 인덱스가 힙의 범위 안에 있을 때만 오른쪽 비교를 실행한다. 마찬가지로 `r < size && compare(pq[r], pq[l])`에서는 오른쪽 자식이 있는지 확인한 뒤에만 두 값을 읽는다.

### 인덱스에서 먼저 1을 빼면 어느 값을 읽을까?

`--size`는 먼저 `size`를 하나 줄이고 그 결과를 인덱스로 쓴다. 크기가 5였다면 마지막 값이 있던 `pq[4]`를 읽는다. 인덱스 0부터 3까지의 자리가 힙에 남는다.

```c
int data = pq[--size];
```

## C 코드

### 힙으로 우선순위 큐 구현하기

#### 값을 저장하고 우선순위 비교하기

```c
/* No full or empty checks: never enqueue into a full queue,
 * never dequeue from an empty queue. */
enum { CAPACITY = 5 };

int pq[CAPACITY];
int size;

void init_pqueue(void) { size = 0; }

/* The smaller value has higher priority, so this is a min-heap */
int compare(int x, int y) { return x < y; }
```

#### 부모를 찾아 더 큰 부모 내리기

```c
/* Positions go level by level from 0, so the children of i are 2i + 1
 * and 2i + 2, and (i - 1) / 2 rounds down to i's parent from either. */
int parent(int i) { return (i - 1) / 2; }

/* Moves lower-priority parents down a level each and returns the
 * position where data belongs. The caller stores data there. */
int sift_up(int i, int data) {
	int p = parent(i);
	while (i > 0 && compare(data, pq[p])) {
		pq[i] = pq[p];
		i = p;
		p = parent(i);
	}
	return i;
}
```

#### 우선순위가 높은 자식 고르기

```c
int left(int i) { return i * 2 + 1; }
int right(int i) { return i * 2 + 2; }

int priority_child(int i) {
	int l = left(i);
	int r = right(i);
	int child;
	if (r < size && compare(pq[r], pq[l])) {
		child = r;
	} else {
		child = l;
	}
	return child;
}
```

#### 더 작은 자식 올리기

```c
/* Moves higher-priority children up a level each and returns the
 * position where data belongs. The caller stores data there. */
int sift_down(int i, int data) {
	int c = priority_child(i);
	while (c < size && compare(pq[c], data)) {
		pq[i] = pq[c];
		i = c;
		c = priority_child(i);
	}
	return i;
}
```

#### 힙에 값 넣기

```c
void enqueue(int data) {
	int pos = sift_up(size, data);
	pq[pos] = data;
	size++;
}
```

#### 힙에서 root 값 꺼내기

```c
int dequeue(void) {
	int root = pq[0];
	int data = pq[--size];
	int pos = sift_down(0, data);
	pq[pos] = data;
	return root;
}
```

### 힙 만들기와 정렬

#### 마지막 부모부터 힙 만들기

```c
/* Positions after parent(size - 1) are leaves, already heaps. Going
 * backwards, both subtrees of i are heaps when sift_down(i, data) runs. */
void heapify(void) {
	for (int i = parent(size - 1); i >= 0; i--) {
		int data = pq[i];
		int pos = sift_down(i, data);
		pq[pos] = data;
	}
}
```

#### 꺼낸 root 값을 출력 배열에 쓰기

```c
/* pq must already be a heap. Each root fills sorted from the front,
 * so the order is ascending. pq ends empty. */
void heap_sort(int sorted[]) {
	int old_size = size;
	for (int i = 0; i < old_size; i++) {
		sorted[i] = dequeue();
	}
}
```

#### 힙을 만들고 두 값을 넣어 다섯 값 정렬하기

```c
int main(void) {
	pq[0] = 9;
	pq[1] = 6;
	pq[2] = 5;
	size = 3;
	heapify(); /* pq is now 5 6 9: 9 moved down 1 level */

	enqueue(3); /* pq is now 3 5 9 6: 3 moved up 2 levels */
	enqueue(1); /* pq is now 1 3 9 6 5: 1 moved up 2 levels */

	int sorted[CAPACITY];
	/* Heap sort: empty the heap into sorted */
	heap_sort(sorted); /* sorted is now 1 3 5 6 9, and pq is empty */

	return 0;
}
```
