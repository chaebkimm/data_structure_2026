# 제3장. data를 그래프로 연결하기

항목들을 양방향으로 이동할 수 있는 간선으로 연결한다. 그런 다음 연결을 따라 그룹을 찾고, 가지에서 더 일찍 발견한 정점에 도달할 수 있는지를 기록한다.

## 논리적으로 생각해 보기

### 연결된 data는 어떤 모습일까?

노드로 항목을 나타내고 간선으로 연결한다. 이 구조를 그래프라고 한다. 그래프의 노드는 정점이라고도 부른다. 무방향 그래프에서는 각 간선을 양쪽 방향으로 따라갈 수 있다.

간선 하나로 직접 연결된 정점은 서로 이웃이다. 연속된 간선을 따라가면 경로가 된다. 여기서 다루는 그래프에는 자기 자신을 잇는 간선이나 중복 간선이 없다. 이러한 그래프에서 사이클은 정점 세 개 이상을 거쳐, 출발점 이외의 정점을 반복하지 않고 출발점으로 돌아오는 길이다. 제2장의 트리와 달리 그래프에는 사이클과 서로 떨어진 그룹이 있을 수 있다.

### 배열의 위치를 어떻게 그래프로 연결할까?

배열에 있는 다른 노드의 인덱스를 이웃 링크로 사용한다. 트리 노드에는 자식 링크가 두 개 있었다. 여기서는 각 노드가 이웃 인덱스의 목록을 저장한다. 이 목록을 인접 리스트라고 한다.

노드 배열에는 열 노드를 저장할 공간이 있고, `nodes_size`는 사용 중인 노드 수를 기록한다. 각 노드에도 이웃 인덱스 열 개를 저장할 공간이 있다. `adj_size`는 그중 사용 중인 항목 수를 기록한다. 빈 리스트의 크기는 0이다. 저장된 이웃 인덱스가 0이면 첫 번째 노드를 가리킨다.

### 두 정점을 어떻게 연결할까?

각 정점의 인덱스를 상대 정점의 이웃 리스트에 추가한다. 두 끝점이 `u`와 `v`이면 `u`의 리스트에 `v`를, `v`의 리스트에 `u`를 추가하고 각 리스트의 크기를 1씩 늘린다. 간선은 양방향으로 이동할 수 있으므로 두 항목 모두 필요하다.

간선을 추가하기 전에 이웃 리스트를 빈 상태로 초기화한다. 여기서는 자기 자신을 잇는 간선이나 중복 간선이 없는 그래프를 사용한다. 각 끝점은 사용 중인 노드여야 하며, 두 이웃 리스트 모두 빈칸이 있어야 한다.

### 연결된 정점을 어떻게 방문할까?

한 정점에서 시작해 이웃을 따라가고, 새로 발견한 정점마다 같은 과정을 반복한다. 사이클을 따라 같은 정점을 끝없이 다시 방문할 수 있으므로, 이웃을 확인하기 전에 각 정점에 양수인 방문 번호를 부여한다. 방문 번호가 0이면 아직 발견하지 않았다는 뜻이다.

각 이웃의 방문 번호를 확인한다. 0이면 그 이웃을 재귀적으로 탐색한다. 호출이 끝나면 현재 정점의 이웃 리스트를 계속 확인한다. 이미 번호가 있는 이웃은 건너뛴다.

새 이웃의 탐색을 끝낸 뒤 현재 정점의 리스트를 계속 확인하는 방법이 깊이 우선 탐색(DFS)이다. 이 방법으로 시작 정점과 연결된 모든 정점에 도달한다. 시작점에서 경로가 없는 정점은 미방문 상태로 남는다. 인덱스는 정점이 저장된 위치를, 방문 번호는 정점을 발견한 순서를 나타낸다.

### 연결된 그룹을 모두 어떻게 찾을까?

연결 요소는 경로로 연결된 정점들을 빠짐없이 모은 그룹이다. 그 그룹 밖의 정점으로 이어지는 경로는 없다.

사용 중인 노드를 차례로 확인한다. 미방문 정점을 찾을 때마다 그룹 번호를 늘리고 그 정점에서 탐색을 시작한다. 해당 탐색으로 도달하는 모든 정점에 같은 그룹 번호를 부여한다. 사용 중인 모든 노드에 번호가 붙을 때까지 확인한다. 이웃이 없는 정점도 혼자서 하나의 연결 요소를 이룬다.

### 어떤 간선이 탐색 트리에 속할까?

새 정점을 처음 발견할 때 사용하는 간선이 트리 간선이다. 현재 정점은 DFS 트리에서 새 정점의 부모가 된다. 부모를 따라 올라가며 만나는 정점은 조상이고, 아래에 있는 정점은 자손이다.

이 무방향 DFS에서 부모 이외의 이미 발견한 조상으로 이어지는 간선은 빽 간선이다. 나중에 그 조상이 같은 간선을 확인하면 이미 발견한 자손을 만나게 된다. 이러한 역할은 탐색 과정에서 정해진다. 시작점이나 이웃을 확인하는 순서가 달라지면 역할도 달라질 수 있다.

### 한 가지에서 얼마나 일찍 발견한 정점까지 돌아갈 수 있을까?

빽 번호는 트리 간선을 따라 아래로 0번 이상 내려간 뒤, 빽 간선을 최대 한 번 사용해 조상에 도달할 때 얻을 수 있는 가장 작은 발견 번호다. 현재 정점에 머물러 자기 번호를 유지하는 경우도 포함한다.

`back[i]`를 `visit_num[i]`로 시작한다. 그런 다음 각 이웃을 처리한다.

| 이웃 | 빽 번호를 갱신하는 방법 |
|---|---|
| 새 자식 | 먼저 재귀 호출한다. 호출이 끝난 뒤 자식의 빽 번호가 더 작으면 사용한다. |
| 부모 | 건너뛴다. 도착할 때 사용한 간선을 반대 방향에서 확인한 것이기 때문이다. |
| 부모 이외의 이미 발견한 조상 | 조상의 방문 번호가 더 작으면 사용한다. |
| 이미 발견한 자손 | 자손의 방문 번호는 더 크므로 현재 값을 낮추지 못한다. |

계산이 끝난 값은 들어온 간선을 되짚지 않고 이 가지에서 얼마나 일찍 발견한 정점까지 도달할 수 있는지를 나타낸다. 이 값은 배열 인덱스가 아니라 발견 번호다. 이번 탐색이 도달하지 않은 정점의 방문 번호와 빽 번호는 초기값인 0으로 남는다.

## 효율 계산해보기

### 저장할 때의 메모리 효율

노드는 `char` 하나, 이웃 인덱스 열 개, 이웃 수 하나를 저장한다. 노드 배열은 일부 칸만 사용하더라도 열 칸 모두의 공간을 확보한다. 각 무방향 간선은 이웃 항목 두 개를 사용하며, 사용하지 않는 칸의 공간도 그대로 확보되어 있다.

### 순회할 때의 메모리 효율

방문 번호, 그룹 번호, 빽 번호, 부모는 각각 별도의 배열에 저장한다. 각 배열은 확보한 노드마다 항목 하나를 가진다. 각 재귀 호출도 자식 호출이 실행되는 동안 자신의 임시 상태를 보관한다. 동시에 유지되는 호출 수는 현재 DFS 경로의 정점 수와 같다. 이 경로에 한 연결 요소의 모든 정점이 포함될 수도 있다.

### 항목 하나를 만들거나 추가하는 효율

노드 하나의 문자와 이웃 수를 초기화하는 데는 상수 시간이 든다. 두 이웃 리스트에 빈칸이 있으면 간선 하나를 추가하는 데도 상수 시간이 든다. 인덱스 두 개를 추가하고 개수 두 개를 늘리면 된다. 끝점이 유효하고 중복 간선이 없다고 가정한다. 추가 연산 자체가 중복 여부를 검색하지는 않는다.

### 항목을 순회하는 효율

각 탐색의 작업량은 도달한 정점 수와 그 정점들에 저장된 이웃 항목 수의 합에 비례한다. 도달한 정점은 각각 한 번씩 발견하며, 각 무방향 간선은 양 끝에서 확인한다. 모든 연결 요소를 찾을 때는 고립 정점을 포함해 사용 중인 노드를 모두 확인한다.

## 용어 정리

### 정점 또는 노드 (Vertex, Node)

그래프의 항목 하나. 여기서는 문자, 이웃 인덱스, 사용 중인 이웃 항목 수를 저장한다.

### 간선 (Edge)

두 정점을 직접 연결하는 것.

### 무방향 그래프 (Undirected Graph)

각 간선을 양쪽 방향으로 따라갈 수 있는 그래프.

### 이웃 (Neighbor)

다른 정점과 간선 하나로 직접 연결된 정점.

### 인접 리스트 (Adjacency List)

한 정점에 저장한 이웃 목록. 여기서는 이웃의 배열 인덱스를 저장한다.

### 경로 (Path)

연속된 간선으로 이어지는 정점들의 순서.

### 사이클 (Cycle)

자기 연결과 중복 간선이 없는 이 그래프에서, 정점 세 개 이상을 거쳐 출발점 이외의 정점을 반복하지 않고 출발점으로 돌아오는 길.

### 연결 요소 (Connected Component)

경로로 연결된 정점들을 빠짐없이 모은 그룹. 그룹 밖의 정점으로 이어지는 경로는 없다.

### 고립 정점 (Isolated Vertex)

이웃이 없는 정점. 혼자서 하나의 연결 요소를 이룬다.

### 깊이 우선 탐색 (Depth-First Search, DFS)

새로 발견한 이웃의 탐색을 끝낸 뒤 현재 정점의 리스트를 계속 확인하는 탐색.

### 방문 번호 (Visit Number)

발견 순서를 나타내는 양수 번호. 0은 현재 탐색에서 아직 발견하지 않은 정점을 나타낸다.

### 트리 간선 (Tree Edge)

새 정점을 처음 발견하여 DFS 트리의 자식으로 만드는 간선.

### 빽 간선 (Back Edge)

이 무방향 DFS에서 한 정점과 조상을 연결하는, 트리 간선이 아닌 간선.

### 빽 번호 (Back Number)

트리 간선을 따라 아래로 내려간 뒤 빽 간선을 최대 한 번 사용해 조상에 도달할 때 얻을 수 있는 가장 작은 방문 번호. 현재 정점에 머무르는 경우도 포함한다.

## 규칙

### 이 자료구조의 규칙은 무엇일까?

- `nodes_size`와 각 `adj_size`는 0부터 10 사이를 유지한다. 해당 크기보다 앞에 있는 칸만 사용한다.
- 저장된 모든 이웃 인덱스는 0부터 `nodes_size - 1` 사이에 있다.
- 각 무방향 간선은 양 끝점의 리스트에 한 번씩 나타난다. 자기 자신을 잇는 간선과 중복 간선은 없다.
- 탐색 중에는 각 정점의 이웃을 확인하기 전에 방문 번호를 부여한다. 미방문 이웃에 대해서만 재귀 호출한다.
- 빽 번호 탐색에서 root의 부모는 `-1`이다. 새 자식의 부모는 재귀 호출 전에 설정한다.

### 규칙을 지키면 무엇이 좋을까?

크기와 인덱스가 유효하면 저장된 이웃만 정확히 읽을 수 있다. 재귀 호출 전에 방문을 기록하면 사이클이 있어도 도달 가능한 각 정점을 한 번씩 탐색한다. 부모 링크를 통해 들어온 간선을 되짚는 경우와 조상으로 이어지는 다른 경로를 구분할 수 있다.

### 규칙이 깨지면 어떻게 될까?

잘못된 크기나 인덱스는 사용하지 않는 칸이나 배열 밖의 메모리에 접근하게 한다. 반대 방향의 항목이 빠지면 간선이 한쪽 방향으로만 작동한다. 방문 기록이 없으면 재귀가 끝나지 않을 수 있고, 부모가 잘못 기록되면 빽 번호가 틀릴 수 있다.

### 규칙을 어떻게 지킬까?

간선을 추가하기 전에 이웃 수를 초기화한다. 인덱스가 유효하고 빈칸이 있을 때만 양 끝점에 항목을 추가한다. 독립된 탐색을 시작할 때마다 방문 기록을 비운다. 자식을 탐색하기 전에 부모를 설정하고, 자식 호출이 끝난 뒤 완성된 빽 번호를 사용한다.

## 코딩 계획

### 노드 설계하기

`struct GraphNode`에 `data`, `adj_list`, `adj_size`를 두고, 공유 배열에 노드 열 개를 저장한다. `nodes_size`는 사용 중인 노드 수, `adj_size`는 한 노드의 이웃 수로 사용한다.

### 그래프 준비하기

1. 배열 용량 안에서 사용할 노드 수를 정한다.
2. 노드의 data를 초기화하고 이웃 수를 모두 0으로 설정한다.
3. 각 간선의 양 끝점을 상대 정점의 리스트에 추가한다.

### 발견 순서 기록하기

`save_visit_num`에서 현재 정점에 다음 양수 번호를 부여한다. 각 이웃 인덱스를 읽고, 방문 번호가 0일 때만 재귀 호출한다.

### 연결 요소에 번호 붙이기

`mark_group`에서 방문 번호와 `current_group`을 함께 기록한다. `mark_all_groups`에서 사용 중인 모든 노드를 확인한다. 미방문 노드를 찾을 때마다 그룹 번호를 늘리고 `mark_group`을 시작한다.

### 빽 번호 기록하기

`save_back`에서 현재 정점의 방문 번호를 부여하고, 그 값을 빽 번호의 초기값으로 사용한다. 새 자식의 부모를 설정한 뒤 재귀 호출하고, 호출이 끝나면 자식의 완성된 빽 번호를 비교한다. 이미 방문한 이웃이 부모가 아니면 그 이웃의 방문 번호를 비교한다.

### 독립된 탐색 준비하기

독립된 탐색을 시작하기 전에 `visit_num`을 비우고 `visit_time`을 0으로 되돌린다. 연결 요소에 번호를 붙이기 전에는 `group`도 비우고 `current_group`을 0으로 되돌린다. 빽 번호를 계산하기 전에는 `back`을 비우고 모든 `parent` 항목을 `-1`로 설정한다.

준비가 끝나면 유효한 정점 인덱스에서 한 연결 요소를 탐색하거나, `mark_all_groups()`를 호출해 그래프 전체를 탐색한다. `save_back`은 자신의 방문 번호를 직접 부여하므로 발견 순서를 기록하는 탐색을 먼저 실행할 필요가 없다. 이전 방문 번호가 남아 있으면 새 탐색에서 정점을 건너뛰게 된다.

## 새로운 C 문법 설명

### `struct` 안의 배열

`int adj_list[10];`은 각 노드 안에 이웃 인덱스 열 개의 공간을 확보한다. `nodes[i].adj_list[j]`는 `i`번 노드를 선택한 뒤 그 노드의 이웃 리스트에서 `j`번 위치를 선택한다. 저장된 값은 다른 노드의 인덱스다.

### 중괄호로 배열 초기화하기

`int visit_num[10] = {0};`은 모든 원소를 0으로 설정한다. 첫 원소는 명시한 값으로, 나머지 원소는 자동으로 0으로 초기화된다. 이는 초기화할 때 일어나는 일이며, 탐색할 때마다 자동으로 반복되지는 않는다.

### prefix와 postfix 증가 연산자

`++visit_time`은 값을 사용하기 전에 카운터를 늘리므로 첫 발견 번호가 1이 된다. `nodes[u].adj_size++`는 증가 전 크기를 다음 빈 위치로 사용한 뒤 크기를 늘린다.

### `else if`와 `&&`

`else if`는 앞의 `if` 조건이 거짓일 때만 확인한다. `adj != parent[i] && back[i] > visit_num[adj]`에서는 두 조건이 모두 참이어야 한다. 이웃이 부모가 아니어야 하고, 이웃의 방문 번호가 현재 빽 번호보다 작아야 한다.

## C 코드

아래 함수들은 노드를 초기화하고 간선을 하나씩 추가한 뒤, 만들어진 그래프를 탐색한다. 탐색 이름은 [ppt_day_c_code.md](ppt_day_c_code.md)를 따른다. 별도의 [lab.c](lab.c)에서는 `back`과 `save_back`을 각각 `back_num`과 `save_back_num`이라는 이름으로 사용한다.

### 노드 저장 공간

```c
struct GraphNode {
        char data; // 문자를 저장한다. 방문 번호가 아니다.
        int adj_list[10]; // 이웃의 문자가 아닌 이웃 인덱스를 저장한다.
        int adj_size; // 사용 중인 이웃 항목 수다.
};
struct GraphNode nodes[10];
int nodes_size = 0; // 고립 정점을 포함한 사용 중인 노드 수다.
```

### 노드 초기화하기

```c
void graph_init(int size) {
        // size는 0부터 10 사이여야 한다. 간선을 추가하기 전에 초기화한다.
        nodes_size = size;
        for (int i = 0; i < nodes_size; i++) {
                nodes[i].data = 0; // 아직 문자 이름을 부여하지 않았다.
                // 빈 리스트의 크기는 0이다. 0은 여전히 유효한 노드 인덱스다.
                nodes[i].adj_size = 0;
        }
}
```

### 두 정점 연결하기

```c
void add_edge(int u, int v) {
        // 서로 다른 사용 중인 끝점, 새로운 간선, 두 리스트의 빈칸을 가정한다.
        // 사용 크기를 늘리기 전에 각각의 다음 빈 위치를 저장한다.
        int u_adj_end = nodes[u].adj_size++;
        int v_adj_end = nodes[v].adj_size++;
        // 무방향 간선 하나를 양쪽 방향으로 저장한다.
        nodes[u].adj_list[u_adj_end] = v;
        nodes[v].adj_list[v_adj_end] = u;
}
```

### 발견 순서 기록하기

```c
int visit_num[10] = {0};
int visit_time = 0;

void save_visit_num(int i) {
        // 유효한 미방문 정점에서 시작한다. 간선을 따라가기 전에 방문을 기록한다.
        visit_num[i] = ++visit_time;
        for (int j = 0; j < nodes[i].adj_size; j++) {
                int adj = nodes[i].adj_list[j]; // 이웃의 인덱스다.
                if (visit_num[adj] == 0) {
                        // 이 이웃의 탐색 전체를 끝낸 뒤 다음 j를 처리한다.
                        save_visit_num(adj);
                }
        }
}
```

### 연결 요소 하나에 번호 붙이기

```c
int group[10] = {0};
int current_group = 0;

void mark_group(int i) {
        visit_num[i] = ++visit_time;
        group[i] = current_group; // 이 탐색의 모든 정점에 같은 그룹 번호를 부여한다.
        for (int j = 0; j < nodes[i].adj_size; j++) {
                int adj = nodes[i].adj_list[j];
                if (visit_num[adj] == 0) {
                        mark_group(adj);
                }
        }
}
```

### 모든 연결 요소 찾기

```c
void mark_all_groups() {
        // 방문 기록을 비우고 current_group을 0으로 설정한 상태여야 한다.
        for (int i = 0; i < nodes_size; i++) {
                if (visit_num[i] == 0) {
                        // 고립 정점도 새 그룹을 시작한다.
                        current_group++;
                        mark_group(i);
                }
        }
}
```

### 빽 번호 기록하기

```c
int back[10] = {0};
int parent[10]; // 이 탐색을 시작하기 전에 모든 항목을 -1로 설정한다.

void save_back(int i) {
        // 이번 탐색에서 발견 번호를 직접 부여한다.
        visit_num[i] = ++visit_time;
        back[i] = visit_num[i];
        for (int j = 0; j < nodes[i].adj_size; j++) {
                int adj = nodes[i].adj_list[j];
                if (visit_num[adj] == 0) {
                        parent[adj] = i; // 재귀 호출 전에 들어온 간선을 기록한다.
                        save_back(adj);
                        // 자식의 빽 번호는 호출이 끝난 뒤에야 완성된다.
                        if (back[i] > back[adj]) {
                                back[i] = back[adj];
                        }
                }
                else if (adj != parent[i]
                        && back[i] > visit_num[adj]) {
                        // 부모는 건너뛰고, 방문한 이웃의 방문 번호를 비교한다.
                        // 자손의 더 큰 방문 번호는 back[i]를 낮추지 못한다.
                        back[i] = visit_num[adj];
                }
        }
}
```
