# 제2장. 데이터에 계층을 부여하기

## 논리적으로 생각해 보기

### 데이터에 계층이 있으면 무엇이 좋을까?

수식 `1 + 2 * 3`에서의 연산자 우선순위와 같이 구조적인 정보도 저장할 수 있다.

### 우선순위 정보를 어떻게 저장할까?

수식 `2 * 3`에서는 `*`가 `2`와 `3`을 곱하므로 왼쪽에 `2`를, 오른쪽에 `3`을 저장한다. 수식 `1 + 2 * 3`에서는 `+`가 `1`과 `*`의 결과를 더하므로, 왼쪽에 `1`을, 오른쪽에 `*`를 저장한다.

### 계층적으로 저장된 수식은 어떻게 계산할까?

수식 `2 * 3`에서는 `*` 노드를 계산하는 함수가 `2`와 `3`을 곱한 결과인 `6`을 반환한다. 수식 `1 + 2 * 3`에서는 `+` 노드를 계산하는 함수가 `1`과 `6`을 더한 결과인 `7`을 반환한다. 노드에 저장된 연산자와 자식 인덱스는 바뀌지 않는다.

### 계층적으로 저장된 수식에 어떻게 접근할까?

수식 `2 * 3`에서 `*` 연산자가 `2`와 `3`에 대한 정보를 저장하므로, `*` 연산자를 통해 전체 수식에 접근한다. 수식 `1 + 2 * 3`에서 `+` 연산자는 `1`과 `*` 연산자에 대한 정보를 저장하고, `*` 연산자는 `2`와 `3`에 대한 정보를 저장한다. 따라서 `+` 연산자를 통해 전체 수식에 접근한다.

### 각 연산자나 숫자에 대해 무엇을 저장할까?

`1`이나 `*`같은 데이터에 더불어 연산자의 경우 왼쪽과 오른쪽에 무엇이 있는지에 대한 정보도 저장한다.

### 이 자료구조에 새로운 데이터를 어떻게 연결할까?

자료구조에 있는 연산자의 왼쪽이나 오른쪽에 데이터를 연결할 수 있다. 자료구조에 접근하는 데 쓰이는 루트를 새로운 연산자의 왼쪽이나 오른쪽에 연결할 수도 있다.

### 이 자료구조에 저장된 수식을 어떻게 계산할까?

`1`이나 `2` 같은 숫자의 경우, 계산 결과는 해당 정수값과 같다. `+`나 `*` 같은 연산자의 경우, 먼저 왼쪽과 오른쪽의 결과를 계산한 다음 그 값들로 연산을 수행한다.

### 단순한 예제

한 자리 숫자와 `+`, `*` 연산자로만 구성된 올바른 수식을 생각해보자. 숫자로 시작하고, 각 연산자 뒤에 숫자 하나가 이어진다. 공백이나 괄호 없이 최대 19개의 문자를 사용하여 `eq[20]`에 문자열의 끝을 나타내는 `\0`을 저장할 공간을 남긴다. 모든 중간 계산 결과와 최종 결과가 `int` 범위 안에 있다고 가정한다. 이 예제는 이러한 입력 조건을 검사하지 않는다.

### 0개 이상의 `*`가 있는 항의 계층 구조는 어떤 특징이 있을까?

`1 * 2 * 3`과 같은 수식은 왼쪽부터 묶어 `(1 * 2) * 3`으로 나타낸다. 첫 번째 `*` 노드는 두 번째 `*` 노드의 왼쪽 자식이 된다. 더 긴 수식에서도 새로운 `*` 노드가 지금까지 만든 항의 부모가 된다.

### 0개 이상의 `*`가 있는 항의 계층 구조를 어떻게 만들까?

계층 구조를 만드는 동안 여기에 접근하게 해주는 루트를 추적하면 된다. 처음에는 첫 번째 숫자가 루트가 된다. 다음에 `*`가 있으면, 이전 루트는 `*`의 왼쪽이 되고, 다음 숫자는 `*`의 오른쪽이 되며, `*`가 새로운 루트가 된다. 뒤에 이어서 나오는 모든 `*`에 대해 반복한다.

### `*`와 `+`가 있는 수식의 계층 구조는 어떻게 만들까?

여러 항들의 합계라고 생각하면 된다. 처음에는 첫 번째 항이 루트가 된다. 다음에 `+`가 있으면, 이전 루트는 `+`의 왼쪽이 되고, 다음 항은 `+`의 오른쪽이 되며, `+`가 새로운 루트가 된다. 뒤에 이어서 나오는 모든 `+`에 대해 반복한다.

## 효율 계산해보기

### 데이터 하나는 메모리를 얼마나 사용할까?

숫자 또는 기호를 저장할 공간과 왼쪽 및 오른쪽 정보를 저장할 공간이 필요하다.

### 데이터를 반복하는 데는 메모리가 얼마나 사용될까?

수식을 깊이 탐색하거나 계산할 때, 컴퓨터는 현재 위치를 추적하기 위해 임시 메모리를 사용한다. 이 임시 메모리의 사용량은 루트에서부터의 거리에 비례해서 커진다.

### 데이터 하나를 추가하는 속도는 얼마나 빠를까?

새로운 데이터를 설정하는 데는 상수 시간이 든다. 새로운 데이터를 기존 데이터의 왼쪽 또는 오른쪽에 연결하거나, 기존 구조의 루트를 새로운 데이터의 왼쪽이나 오른쪽 자리에 연결하는 데에도 상수 시간이 든다.

### 데이터에 반복하는 속도는 얼마나 빠를까?

구조에 저장된 데이터의 개수에 비례한다.

## 용어 정리

### 노드 (Node)

데이터와 관련 노드들에 대한 정보를 포장해놓은 것.

### 트리 (Tree)

노드가 자식을 가질 수 있는 계층 구조.

### 이진 트리 (Binary Tree)

모든 노드가 최대 두 개의 자식을 가지며, 왼쪽과 오른쪽으로 구분되는 계층 구조.

### 수식 트리 (Expression Tree)

수식을 표현하는 트리. 이 장의 예제에서 연산자 노드는 두 개의 피연산자 자식을 가지며, 숫자 노드는 단말 노드가 된다.

### 루트 (Root)

트리가 시작되는 노드 (일반적으로 수식에서 가장 마지막에 계산되는 연산을 의미).

### 부모 (Parent)

계층 구조에서 다른 노드 바로 위에 있는 노드.

### 자식 (Child)

부모 노드 바로 아래에 있는 노드.

### 형제 (Sibling)

같은 부모를 가진 다른 노드.

### 조상 (Ancestor)

루트로부터 주어진 노드로 내려가는 경로에서 그 노드보다 앞에 있는 노드. 위쪽 링크를 저장하지 않아도 조상 관계는 존재한다.

### 자손 (Descendant)

주어진 노드에서 하나 이상의 자식 링크를 따라 내려가면 발견되는 노드.

### 단말 (Leaf)

자식이 없는 노드.

### 서브트리 (Subtree)

하나의 노드와 그 노드의 모든 자손들로 구성된 트리 (부분 수식).

### 재귀 (Recursion)

함수가 동일한 문제의 더 작은 부분에 대해 자기 자신을 호출하는 기법.

### 종료 조건 (Base Case)

추가적인 재귀 호출 없이 함수를 반환하는 조건. 수식 계산은 숫자 노드에서 멈춘다.

## 규칙

### 이 자료구조의 규칙은 무엇일까?

- 트리의 루트는 하나다.
- 두 부모 노드가 자식 노드를 공유할 수 없고, 동일한 노드를 왼쪽 자식과 오른쪽 자식으로 동시에 사용할 수 없다.
- 자식 링크를 따라 계속 내려갔을 때 다시 원래 위치로 돌아오는 루프가 만들어져서는 안 된다.

### 규칙이 깨지면 어떻게 될까?

- 루트 규칙이 깨질 경우: 한 루트에서 시작된 반복 작업이 다른 루트에 도달할 수 없다.
- 단일 부모 규칙이 깨질 경우: 반복 작업을 할 때 노드를 중복해서 방문하게 된다.
- 비순환 규칙이 깨질 경우: 반복 작업이 무한 루프에 빠진다.

### 규칙을 어떻게 지킬까?

새로운 부모는 기존 서브트리와 새로 생성된 노드들을 결합하여, 순환이나 공유되는 자식이 없는 트리를 보존한다. 프로그래머는 반드시 초기화된 노드와 사용 중인 `nodes` 배열의 유효한 인덱스를 사용해야 한다.

## 코딩 계획

모든 노드는 `nodes` 배열에 저장되고 이 배열에 대한 정수 인덱스로 나타낸다. `nodes[root]`는 현재 서브트리의 루트에 있는 노드이다. `-1`은 자식이 없음을 의미하며, `0`은 처음 노드를 가리키는 유효한 인덱스다.

### 노드 설계하기

- `2`, `+`, `*`와 같은 `data`라는 이름의 문자 하나를 저장한다.
- 두 개의 인덱스를 저장한다. 하나는 `left` 자식을 위한 것이고, 다른 하나는 `right` 자식을 위한 것이다.

### 노드 할당 및 초기화하기

- `size` 변수에 기록된 다음 빈 배열 위치를 사용한다.
- 데이터를 저장하고 왼쪽과 오른쪽 인덱스를 모두 `-1`로 설정한다.
- `size`를 증가시키고, 방금 할당된 위치를 새 노드의 인덱스로 반환한다.

### 자식 추가하기

- 인덱스가 `-1`인 비어 있는 자식 위치를 선택한다.
- 부모의 `left`나 `right` 멤버에 자식의 인덱스를 저장한다.

### 수식 문자열에서 항 만들기

전역 변수 `pos`는 `eq` 문자열에서 아직 읽지 않은 다음 문자의 위치를 나타낸다. 문자를 소비한다는 것은 문자를 읽고 `pos`를 증가시키는 것을 의미한다.

1. 숫자 하나를 소비하여 노드를 할당하고, 그 인덱스를 현재 루트로 만든다.
2. 다음 문자가 `*`인 동안, 이를 소비하고 연산자 노드를 할당한다.
3. 그 다음 숫자를 소비하고 노드를 할당한다.
4. 연산자의 왼쪽에 이전 루트를 연결하고, 오른쪽에 새로운 숫자를 연결한다.
5. 연산자를 현재 루트로 만들고 2단계부터 반복한다.
6. 다음 문자가 `*`가 아니면, 해당 문자는 읽지 않은 상태로 남겨두고 루트를 반환한다.

### 수식 문자열에서 항들의 합 만들기

유효한 입력의 경우, 마지막으로 남는 읽지 않은 문자는 `\0`(널 문자)이다.

1. 완전한 항을 하나 만들고 그 인덱스를 현재 루트로 만든다.
2. 다음 문자가 `+`인 동안, 이를 소비하고 연산자 노드를 할당한다.
3. 다음 완전한 항을 만든다.
4. 연산자의 왼쪽에 이전 루트를 연결하고, 오른쪽에 새로운 항을 연결한다.
5. 연산자를 현재 루트로 만들고 2단계부터 반복한다.
6. 다음 문자가 `+`가 아니면 루트를 반환한다.

### 수식 트리 계산하기

1. 숫자 노드에서는 문자에서 `'0'`을 빼서 정수로 변환한 뒤 그 값을 반환한다(종료 조건).
2. 연산자 노드에서는 먼저 왼쪽 자식을 계산하고 그다음 오른쪽 자식을 계산하여 각각의 지역 변수 값으로 저장한다.
3. 그 값들을 현재 연산자로 계산하고, 계산된 결과를 반환한다.

## 새로운 C 문법 설명

### `struct` 태그 정의하기

사용자 정의 데이터 타입은 `struct` 키워드와 태그를 사용하여 정의할 수 있으며, 구조체의 멤버들은 뒤따르는 중괄호 `{}` 안에 선언된다. 예를 들어, `struct TreeNode { char data; int left; int right; };`와 같이 작성한다.

### `struct` 태그 사용하기

태그는 컴파일러에게 참조하려는 사용자 정의 데이터 타입이 무엇인지 알려주는 역할을 한다. 노드 변수를 선언할 때 타입을 `struct TreeNode`라고 작성한다.

### `.` (멤버 접근하기)

`nodes[root].data`는 `root` 인덱스에 위치한 노드의 `data` 멤버에 접근한다. 대괄호(`[]`)는 배열의 요소를 선택하고, 마침표(`.`)는 해당 요소의 멤버 중 하나를 선택하는 역할을 한다.

### 재귀 함수

재귀 함수는 동일한 문제의 더 작은 부분에 대해 자기 자신을 호출한다. 재귀 함수에는 재귀 종료 조건이 필요하다. 재귀 종료 조건이 없으면 호출이 무한히 계속될 수 있다. 수식 계산기는 숫자 노드를 재귀 종료 조건으로 사용한다.

## C 코드

### 노드 설계하기

동일한 구조체를 사용하여 숫자 노드나 두 개의 자식을 가진 연산자 노드를 모두 표현한다.

```c
struct TreeNode {
        char data; /* 숫자 문자, '+', 또는 '*' */
        int left;  /* nodes 배열 내 왼쪽 자식의 인덱스. 없으면 -1 */
        int right; /* nodes 배열 내 오른쪽 자식의 인덱스. 없으면 -1 */
};
```

### 노드 할당하기

`size`는 사용된 노드의 개수를 세는 동시에 다음 빈 위치를 가리킨다. 배열이 함수 외부에 선언되었으므로, 함수가 반환된 후에도 노드들은 계속 유지된다.

```c
/* 한 번에 하나의 수식만 처리한다. 노드들은 프로그램 전체 실행 시간 동안 유지된다. */
struct TreeNode nodes[20];
int size = 0;

int new_node(char data)
{
        nodes[size].data = data;
        /* 새로 할당된 노드는 아직 자식이 없다. */
        nodes[size].left = nodes[size].right = -1;
        return size++; /* size를 증가시킨다. 반환되는 값은 증가하기 전의 원래 인덱스이다. */
}
```

### 항 만들기

`term()` 함수는 하나의 숫자 뒤에 0개 이상의 `*`-숫자 쌍이 이어지는 구조를 만든다. `eq[pos++]`에서 `pos`의 이전 값으로 문자를 선택한 후 `pos`가 증가한다. 루프 조건에서 `eq[pos]`를 확인할 때는 문자를 읽어 비교하지만 `pos`를 증가시키지 않으므로, 그 문자를 소비하지 않는다.

```c
char eq[20] = "1+2*3"; /* 공백 없음; 문자열은 '\0'으로 끝난다. */
int pos = 0;          /* 아직 읽지 않은 다음 문자의 인덱스 */

int term(void)
{
        /* 첫 번째 숫자를 노드가 하나인 서브트리로 삼아 시작한다. */
        int root = new_node(eq[pos++]);
        while (eq[pos] == '*') {
                int op = new_node(eq[pos++]);  /* '*' 소비 */
                int num = new_node(eq[pos++]); /* 다음 숫자 소비 */
                /* 지금까지 만든 항을 다음 숫자와 그룹화한다. */
                nodes[op].left = root;
                nodes[op].right = num;
                root = op; /* 이제 새로운 연산자가 이 서브트리의 루트가 된다. */
        }
        /* 호출자를 위해 '+'나 '\0'은 읽지 않은 상태로 남겨둔다. */
        return root;
}
```

### 항들의 합 만들기

`terms()` 함수는 `+`의 각 피연산자에 대해 `term()`을 호출한다. 두 함수는 `pos` 변수를 공유하므로, 각각의 호출은 이전 호출이 멈춘 위치에서부터 이어진다.

```c
int terms(void)
{
        int root = term();
        while (eq[pos] == '+') {
                int op = new_node(eq[pos++]); /* '+' 소비 */
                /* 모든 곱셈을 포함하여 다음 항을 완성한다. */
                int next_term = term();
                nodes[op].left = root;
                nodes[op].right = next_term;
                root = op; /* 새로운 '+'가 두 서브트리를 연결한다. */
        }
        return root; /* 전체 수식의 루트 인덱스 */
}
```

### 연산자보다 자식 먼저 계산하기

`node`는 인덱스인 반면, 반환 값은 서브트리의 계산 결과이다. C 언어에서 숫자 문자의 코드는 연속적이기 때문에, `'0'`을 빼면 `'3'`과 같이 저장된 숫자 문자가 정수 `3`으로 변환된다. 이 수식 계산기는 유효한 입력으로 완성된 트리를 가정하며, 잘못된 형태의 트리를 따로 검증하지는 않는다.

```c
int eval_tree(int node)
{
        /* 종료 조건: 숫자 노드는 자신의 숫자 값을 정답으로 제공한다. */
        if (nodes[node].data >= '0' && nodes[node].data <= '9') {
                return nodes[node].data - '0';
        }

        /* 유효한 트리는 숫자와 지원되는 두 개의 연산자만을 포함한다. */
        if (nodes[node].data != '+' && nodes[node].data != '*') return -1;

        /* 각각의 호출은 자신만의 결과를 유지하며, 왼쪽 호출이 먼저 끝난다. */
        int left = eval_tree(nodes[node].left);
        int right = eval_tree(nodes[node].right);

        /* 저장된 연산자를 변경하지 않고 반환된 값들을 연산한다. */
        if (nodes[node].data == '+') return left + right;
        if (nodes[node].data == '*') return left * right;

        return -1;
}
```

### 예제 실행하기

`main` 함수는 프로그램을 시작하고, 트리를 한 번 만든 다음, 수식 계산기가 반환한 결과를 출력한다.

```c
#include <stdio.h> /* printf 선언 포함 */

int main(void)
{
        int root = terms();           /* 트리를 만들고 그 루트 인덱스를 보관한다. */
        int answer = eval_tree(root); /* 해당 인덱스부터 트리를 계산한다. */
        printf("%s = %d\n", eq, answer);
        return 0;
}
```

출력 결과는 `1+2*3 = 7`이다. `printf`에서 `%s`는 수식 문자열을 출력하고, `%d`는 정수 형태의 정답을 출력하며, `\n`은 줄을 바꾼다. 루트는 `'+'`를 저장하고, 루트의 오른쪽 자식은 `'*'`를 저장하며, 이 `'*'`의 자식들은 각각 `'2'`와 `'3'`을 저장한다.

## C 코드 전체 설명 (Full C Code Explanation)

이 절은 C를 한 번도 읽어 본 적이 없는 사람을 위한 설명이다. 변수, 문자, 배열, 구조체, 함수, 반복, 재귀를 모두 처음부터 설명한다. 앞의 본문과 코드를 바꾸지 않고, 그 코드가 무슨 뜻인지 여기에서 천천히 풀어 읽는다.

문법을 읽는 일과 실행을 따라가는 일은 서로 다르다. `nodes[op].left = root;`의 기호를 이해한 다음에는, 실제로 `op`와 `root`에 어떤 정수가 들어 있는지 확인해야 한다. 이 절에서는 두 가지를 함께 연습한다.

### 1. 코드를 읽는 순서와 예제의 출발점

**프로그램**은 컴퓨터가 수행할 작업을 적은 것이다. **C**는 그 작업을 표현하는 프로그래밍 언어이고, **문법**은 어떤 단어와 기호를 어떤 모양으로 써야 하는지를 정한 규칙이다. 코드를 파일에 적는 것과 그 프로그램을 실행하는 것은 별개의 단계이다.

앞의 여섯 코드 조각은 하나의 프로그램을 나누어 보여 준다.

1. 노드 하나에 어떤 정보를 저장할지 정한다.
2. 노드들을 저장할 배열과 새 노드를 준비하는 함수를 만든다.
3. 수식 문자열을 준비하고 곱셈으로 연결된 항을 만드는 함수를 만든다.
4. 항들을 덧셈으로 연결하는 함수를 만든다.
5. 만들어진 트리를 계산하는 함수를 만든다.
6. `main`에서 트리를 만들고 계산 결과를 출력한다.

**함수**는 이름을 붙여 놓은 작업 묶음이다. 함수를 정의했다고 그 안의 작업이 즉시 실행되는 것은 아니다. 다른 곳에서 그 함수를 **호출**해야 안으로 들어가 실행한다.

이 예제에서 실행의 출발점은 `main`이다. `main`은 `terms`를 호출하고, `terms`는 필요할 때 `term`과 `new_node`를 호출한다. 트리가 만들어지면 `main`이 `eval_tree`를 호출한다. 따라서 파일을 위에서 아래로 읽는 순서와 함수가 실제로 실행되는 순서는 다르다.

```text
프로그램 시작
  → main
      → terms: 트리를 만든다.
      → eval_tree: 트리의 계산 결과를 구한다.
      → printf: 화면에 결과를 쓴다.
  → 프로그램 종료
```

이 상자의 화살표와 한국어는 실행 순서를 설명하는 그림이다. C 소스 파일에 그대로 입력하는 코드가 아니다. 실제 실행 가능한 전체 C 프로그램은 13번에서 제공한다.

#### 먼저 고정할 입력 조건

이번 예제의 입력은 다음 문자열이다.

```c
"1+2*3"
```

여기에는 `'1'`, `'+'`, `'2'`, `'*'`, `'3'`라는 다섯 문자가 들어 있다. 우리가 만들 프로그램은 이 문자를 읽어 수식 트리로 저장하고, 그 트리를 계산하여 정수 `7`을 구한다. 입력은 소스 코드 안에 미리 적혀 있으며, 이 프로그램은 실행 중에 키보드로 수식을 입력받지 않는다.

이 프로그램이 처리한다고 가정하는 수식에는 다음 조건이 있다.

- 비어 있지 않고, 숫자 한 개로 시작한다.
- 숫자는 `'0'`부터 `'9'`까지의 **한 자리** 숫자 문자이다.
- 숫자 뒤에는 수식의 끝이 오거나, `'+'` 또는 `'*'` 다음에 숫자 하나가 온다.
- 공백, 괄호, 음수 표시, 소수점, 그 밖의 연산자는 없다.
- 수식에 들어 있는 문자는 최대 19개이다. 문자열의 끝 표시를 저장할 한 칸도 필요하다.
- 모든 중간 계산 결과와 최종 결과가 `int`로 표현할 수 있는 범위 안에 있다.

`"7"`, `"2*3*4"`, `"1+2+3"`은 이 조건에 맞는다. `"12+3"`, `"1 + 2"`, `"1+"`, `"(1+2)*3"`은 맞지 않는다. 이 코드는 잘못된 입력을 찾아서 고치는 프로그램이 아니며, 위 조건을 만족하는 입력을 설명하기 위한 예제이다.

#### 화면에 보이는 글자를 구분하기

코드 상자 앞뒤의 백틱 세 개와 첫 줄의 `c`는 교재에서 코드를 표시하기 위한 것이다. C 파일에는 상자 안의 코드만 옮긴다.

`int`, `char`, `struct`, `while`, `if`, `return`, `void`는 C가 뜻을 정해 놓은 **키워드**이다. `nodes`, `size`, `new_node` 같은 이름은 작성자가 정했다. 이름은 대소문자를 구분하므로 `size`와 `Size`는 서로 다르다.

공백과 들여쓰기는 사람이 코드의 구조를 읽는 데 도움을 준다. 실제 작업의 묶음은 중괄호 `{`와 `}`로 정한다. 줄바꿈 자체가 모든 문장을 끝내는 것은 아니므로, 세미콜론 `;`도 함께 읽는다.

```c
/* 새로 할당된 노드는 아직 자식이 없다. */
```

`/*`는 **주석**의 시작이고 `*/`는 끝이다. 사이의 한국어는 사람을 위한 설명이며, 실행되는 명령이 아니다. 주석 안의 `*`를 곱셈 기호로 읽지 않는다.

### 2. 변수, 자료형, 이름, 선언과 값의 변화

**변수**는 이름을 통해 값을 저장하고 다시 읽을 수 있게 하는 것이다. `size`에 사용 중인 노드 수를 저장하면, 나중에 그 이름으로 현재 개수를 읽거나 바꿀 수 있다.

```c
int size = 0;
```

| 부분 | 의미 |
| --- | --- |
| `int` | 정수를 다루는 자료형을 사용한다. |
| `size` | 이 변수에 붙인 이름이다. |
| `=` | 선언하면서 첫 값을 지정한다. |
| `0` | 처음 저장할 정수 값이다. |
| `;` | 이 선언을 끝낸다. |

**자료형**은 저장하는 값의 종류와 가능한 연산을 정한다. `int`는 `0`, `1`, `20`, `-1` 같은 정수를 표현한다. 정수를 무한히 크게 저장할 수 있는 것은 아니다. 저장 범위와 메모리 크기는 C 실행 환경에 따라 달라지며, 모든 환경에서 반드시 4바이트라고 생각하면 안 된다.

`char`도 정수형의 한 종류이며, 이 코드에서는 문자 하나의 코드를 저장하는 데 사용한다. **문자 코드**는 문자를 컴퓨터 안에서 나타내는 정수 값이다. 화면에 보이는 글자 `'3'`와 수학 계산에 쓰는 정수 `3`은 여기에서 구분해야 한다.

```c
char data = '+';
```

이 줄은 `data`라는 변수를 만들고 문자 `'+'`를 저장한다. 덧셈을 실행하는 줄이 아니다. 작은따옴표가 붙어 있으면 그 안의 글자 자체를 나타낸다.

**선언**은 어떤 이름을 어떤 자료형으로 사용할지 알리는 것이다. 선언하면서 첫 값을 주는 것을 **초기화**라고 한다. 이미 있는 저장 공간에 값을 넣는 것은 **대입**이라고 한다.

```c
int root = 0;
root = 1;
```

첫 줄은 `root`라는 정수 변수를 선언하고 `0`으로 초기화한다. 둘째 줄은 같은 변수의 값을 `1`로 바꾼다. 둘째 줄에는 새로운 변수를 만드는 `int`가 없다.

`root = op;`는 오른쪽 `op`에 현재 들어 있는 값을 읽어 왼쪽 `root`에 복사한다. 그 이후 `op`를 바꾼다고 `root`도 자동으로 함께 바뀌지는 않는다. 대입은 두 이름을 영원히 묶는 작업이 아니다.

이름 자체에는 자동으로 수행되는 기능이 없다. `size`라고 썼다고 C가 노드 수를 알아서 세지 않으며, `root`라고 썼다고 자동으로 트리의 시작점이 되는 것도 아니다. 우리가 정한 규칙에 따라 값을 저장하고 사용해야 한다.

| 이름 | 저장하는 값의 역할 |
| --- | --- |
| `nodes` | 모든 노드를 저장하는 배열의 이름 |
| `size` | 사용 중인 노드 수이자 다음에 사용할 배열 위치 |
| `eq` | 입력 수식의 문자들을 저장하는 배열의 이름 |
| `pos` | 수식에서 아직 소비하지 않은 다음 문자의 위치 |
| `root` | 현재 만들고 있는 트리나 서브트리의 시작 노드 인덱스 |
| `op` | 새로 만든 연산자 노드의 인덱스 |
| `num` | 새로 만든 숫자 노드의 인덱스 |
| `next_term` | 다음 항의 루트 인덱스 |
| `node` | 이번 계산 호출이 처리할 노드의 인덱스 |
| `left`, `right` | `eval_tree` 안에서는 자식들을 계산한 정수 결과 |
| `answer` | 전체 수식의 계산 결과 |

밑줄 `_`은 이름 안에 쓸 수 있는 글자이다. `new_node`와 `next_term`은 각각 하나의 이름이다. 밑줄이 별도의 연산을 수행하지는 않는다.

#### 전역 변수와 지역 변수

함수 바깥에서 선언한 `nodes`, `size`, `eq`, `pos`는 이 예제의 **전역 변수**이다. 이 파일에서 선언 뒤에 나오는 함수들은 이 이름들을 통해 같은 저장 공간을 사용한다.

함수 안에서 선언한 `root`, `op`, `num`, `next_term`, `answer` 등은 **지역 변수**이다. 이름을 사용할 수 있는 범위를 **스코프**라고 한다. 보통 블록 안에서 선언한 지역 변수 이름은 그 선언 뒤부터 해당 블록의 닫는 `}`까지 사용할 수 있다.

`term`의 `root`, `terms`의 `root`, `main`의 `root`는 철자가 같아도 서로 다른 변수이다. 각 함수는 자신의 `root` 값을 가진다. 한 함수가 다른 함수를 호출한다고 해서 두 지역 변수가 같은 저장 공간이 되는 것은 아니다.

함수의 입력을 받는 `data`나 `node`도 해당 함수 호출에서 사용하는 지역적인 이름이다. 재귀 호출처럼 같은 함수가 다시 호출되면, 각 호출은 자신의 입력 값과 지역 변수를 가진다.

이 예제에서 함수 안에 선언만 하고 첫 값을 정하지 않은 정수 변수를 읽어서는 안 된다. 지역 변수가 모두 자동으로 `0`이 되는 것은 아니다. 실제 코드의 지역 변수들은 첫 값을 지정한 뒤 사용한다.

### 3. 괄호, 구두점, 연산자와 조건을 읽는 법

**식**은 값을 나타내거나 계산하는 코드이다. `0`, `size`, `eq[pos]`, `left + right`, `size++`는 모두 식이다. **문장**은 프로그램에서 수행할 작업을 구성하는 단위이다. `root = op;`는 식 뒤에 세미콜론을 붙여 만든 문장이다.

같은 모양의 기호라도 어느 위치에 쓰였는지에 따라 뜻이 달라질 수 있다. 다음 표는 앞의 코드에 등장하는 기호를 모은 것이다.

| 기호 | 이 장에서의 역할 | 예 |
| --- | --- | --- |
| `=` | 초기값 지정 또는 대입 | `int pos = 0;`, `root = op;` |
| `==` | 두 값이 같은지 비교 | `eq[pos] == '*'` |
| `!=` | 두 값이 다른지 비교 | `nodes[node].data != '+'` |
| `>=` | 왼쪽 값이 오른쪽 값 이상인지 비교 | `nodes[node].data >= '0'` |
| `<=` | 왼쪽 값이 오른쪽 값 이하인지 비교 | `nodes[node].data <= '9'` |
| `&&` | 양쪽 조건이 모두 참인지 확인 | `조건1 && 조건2` |
| `+` | 두 정수를 더함 | `left + right` |
| `-` | 두 정수의 차를 구함 | `nodes[node].data - '0'` |
| `-` | 한 값 앞에서 음수를 만듦 | `-1` |
| `*` | 작은따옴표 바깥에서는 두 정수를 곱함 | `left * right` |
| `++` | 변수 값을 1 증가시킴 | `size++`, `pos++` |
| `[]` | 배열 선언에서는 칸 수, 배열 사용에서는 인덱스 | `nodes[20]`, `nodes[op]` |
| `.` | 구조체에서 멤버 하나를 선택 | `nodes[op].left` |
| `()` | 함수의 입력 목록, 함수 호출, 조건의 경계 | `term(void)`, `term()`, `if (...)` |
| `{}` | 구조체 멤버 목록 또는 실행할 코드의 블록 | `struct TreeNode { ... };` |
| `;` | 선언이나 문장을 끝냄 | `return root;` |
| `,` | 이 코드에서는 함수에 주는 값들을 구분 | `printf("%s = %d\n", eq, answer)` |
| `' '` | 작은따옴표 사이의 문자 한 개를 나타냄 | `'+'`, `'0'` |
| `" "` | 큰따옴표 사이의 문자열을 나타냄 | `"1+2*3"` |
| `/* */` | 주석을 감쌈 | `/* '+' 소비 */` |

표의 `조건1`, `조건2`, `...`는 설명용 표현이며 원래 프로그램의 이름이나 코드가 아니다. 실제 코드를 읽을 때는 생략한 부분에 어떤 식이나 문장이 들어 있는지 확인한다.

`==`, `!=`, `>=`, `<=`, `&&`, `++`는 각각 두 글자로 된 하나의 연산자이다. 가운데를 띄워 `= =`처럼 쓰지 않는다. 반면 `root = op`에서 대입 기호 양옆의 공백은 읽기 쉽게 넣은 것이다.

`int root = 0;`의 `=`와 `if (root == 0)`의 `==`는 다르다. 첫 코드는 값을 정하고, 두 번째 식은 현재 값이 같은지 물어본다. 비교를 대입으로 바꾸면 프로그램의 의미가 달라진다.

#### 참과 거짓

**조건**은 어떤 작업을 할지 결정하기 위해 검사하는 식이다. C의 비교 연산자는 조건이 성립하면 정수 `1`, 성립하지 않으면 정수 `0`을 만든다. 조건으로 일반 정수 값을 사용할 때는 `0`을 거짓, `0`이 아닌 값을 참으로 취급한다.

```c
nodes[node].data >= '0' && nodes[node].data <= '9'
```

이 식은 현재 문자가 `'0'` 이상이면서 `'9'` 이하인지 검사한다. 비교 연산들이 먼저 각각의 조건을 만들고, `&&`가 두 조건을 연결한다. 다음처럼 묶어 읽을 수 있다.

```c
(nodes[node].data >= '0') && (nodes[node].data <= '9')
```

`&&`는 왼쪽 조건부터 검사한다. 왼쪽이 거짓이면 오른쪽은 검사하지 않고 전체 결과를 거짓으로 정한다. 왼쪽이 참일 때만 오른쪽을 검사한다. 이를 **단락 평가**라고 한다.

`nodes[node].data != '+' && nodes[node].data != '*'`에는 두 번의 비교가 있다. 현재 문자가 `'+'`가 아니고 `'*'`도 아닌지를 확인하려는 것이다. `'+'`일 때는 첫 비교가 거짓이므로 두 번째 비교는 필요 없다.

#### 괄호와 세미콜론의 짝

`if`는 조건이 참일 때 작업하고, `while`은 조건이 참인 동안 작업을 반복한다. 둘 다 조건을 `(`와 `)`로 감싼다. 작업 여러 개를 함께 묶을 때는 `{`와 `}`를 사용한다.

블록 안에 다른 블록을 넣을 수 있다. 닫는 `}`는 아직 닫히지 않은 가장 가까운 여는 `{`와 짝을 이룬다. 들여쓰기를 보면 짝을 찾기 쉽지만, 실행을 결정하는 것은 실제 괄호이다.

`while (eq[pos] == '*') {`에서 `)` 뒤에 세미콜론이 없는 것을 보자. 그 자리에 `;`를 넣으면 반복할 본문이 빈 문장이 되어 뜻이 달라진다. 줄이 끝났다고 아무 곳에나 세미콜론을 붙이지 않는다.

구조체 정의의 끝에는 `};`를 쓴다. 구조체를 정의하는 선언을 끝내기 때문이다. 함수 본문의 마지막 `}` 뒤에는 이 코드에서 세미콜론을 붙이지 않는다. `return root;`처럼 함수 내부의 문장은 세미콜론으로 끝난다.

### 4. `struct TreeNode`의 모든 부분

트리의 **노드**는 데이터 하나와 자식에 대한 정보를 함께 담는 단위이다. 서로 관련된 여러 값을 한 단위로 묶는 C의 기능이 **구조체**, 즉 `struct`이다.

```c
struct TreeNode {
        char data; /* 숫자 문자, '+', 또는 '*' */
        int left;  /* nodes 배열 내 왼쪽 자식의 인덱스. 없으면 -1 */
        int right; /* nodes 배열 내 오른쪽 자식의 인덱스. 없으면 -1 */
};
```

| 부분 | 의미 |
| --- | --- |
| `struct` | 구조체 자료형을 정의한다는 키워드이다. |
| `TreeNode` | 이 구조체 종류에 붙인 태그 이름이다. 작성자가 정했다. |
| `{` | 이 구조체에 들어갈 멤버들의 목록을 시작한다. |
| `char data;` | `data`라는 이름의 문자 저장 멤버를 선언한다. |
| `int left;` | `left`라는 이름의 정수 저장 멤버를 선언한다. |
| `int right;` | `right`라는 이름의 정수 저장 멤버를 선언한다. |
| `}` | 멤버 목록을 끝낸다. |
| `;` | 구조체 정의 선언을 끝낸다. |

구조체 안의 이름 붙은 저장 항목을 **멤버**라고 한다. 모든 `struct TreeNode` 값에는 `data`, `left`, `right`라는 세 멤버가 있다.

이 정의는 노드가 어떤 모양인지를 정한다. 이 줄만으로 `'1'` 노드나 `'+'` 노드가 실제 배열에 생성되는 것은 아니다. 뒤에서 `struct TreeNode nodes[20];`로 저장 공간을 준비한다.

이 코드에는 별도의 자료형 별칭을 만드는 선언이 없다. 따라서 이 구조체의 자료형을 사용할 때는 `TreeNode`만 쓰지 않고 **`struct TreeNode`**라고 쓴다.

`data`는 노드에 저장한 문자이다. `left`와 `right`는 자식 노드가 있는 배열 위치이다. 자식의 숫자 값을 직접 저장하는 것이 아니다.

| 저장 예 | 의미 |
| --- | --- |
| `data`에 `'+'` | 이 노드는 덧셈을 나타낸다. |
| `left`에 `0` | 왼쪽 자식은 `nodes[0]`에 있다. |
| `right`에 `3` | 오른쪽 자식은 `nodes[3]`에 있다. |

위 노드의 오른쪽 자식 인덱스가 `3`이라고 해서 오른쪽 계산 결과가 `3`이라는 뜻은 아니다. 실제 예제에서 `nodes[3]`에는 `'*'`가 저장되고, 그 서브트리의 계산 결과는 `6`이다.

숫자 노드도 같은 구조체를 사용한다. 예를 들어 문자 `'2'`를 저장한 숫자 노드는 `data`가 `'2'`, `left`가 `-1`, `right`가 `-1`이다. `-1`은 이 프로그램에서 자식이 없다고 정한 표시이다.

#### 배열에서 노드를 고르고, 노드에서 멤버를 고르기

```c
nodes[op].left = root;
```

다음과 같이 순서대로 뜻을 읽는다.

1. `op`에 들어 있는 정수를 읽는다.
2. `nodes[op]`로 그 인덱스의 노드 한 개를 고른다.
3. `.left`로 그 노드 안의 왼쪽 자식 멤버를 고른다.
4. 오른쪽 `root`에 들어 있는 정수를 그 멤버에 저장한다.

`op`가 `3`, `root`가 `2`이면 `nodes[3].left`에 정수 `2`가 저장된다. 노드 `2` 전체를 복사하거나 배열에서 이동시키지 않는다. 노드 `3`에서 노드 `2`로 찾아갈 수 있는 인덱스 하나를 기록하는 것이다.

`nodes[3].left`의 `left`는 구조체 멤버 이름이다. 뒤의 `eval_tree`에서 나오는 `int left = ...;`의 `left`는 함수 안의 별도 정수 변수 이름이다. 철자가 같아도 문맥과 저장 공간이 다르다.

### 5. `nodes[20]`, `size`, 전역 저장 공간과 `-1`

```c
struct TreeNode nodes[20];
int size = 0;
```

첫 줄의 `struct TreeNode`는 배열 한 칸에 저장할 자료형이다. `nodes`는 배열 이름이며, 선언에서의 `[20]`은 그런 칸을 20개 준비한다는 뜻이다. `;`는 선언을 끝낸다.

**배열**은 같은 종류의 값을 여러 칸에 저장하고, 번호로 각 칸을 선택하는 것이다. 이 번호를 **인덱스**라고 한다. C 배열은 첫 칸의 번호가 `0`이므로, 이 배열의 인덱스는 `0`부터 `19`까지이다.

| 구분 | 이 예제의 의미 |
| --- | --- |
| 배열의 전체 칸 수 | 항상 20칸이다. |
| `size` | 그중 노드로 사용하도록 준비한 칸 수이다. |
| 사용 중인 노드 | `size`가 5라면 인덱스 `0`부터 `4`까지이다. |
| 다음에 사용할 칸 | `size`가 5라면 `nodes[5]`이다. |

`size`를 `5`로 바꾸어도 배열 자체가 5칸으로 줄어들지는 않는다. `size`는 우리가 별도로 관리하는 개수이다. 또한 `size`가 `20`이라면 다음 빈칸은 더 이상 없으며, `nodes[20]`에 접근하면 배열 범위를 벗어난다.

이 선언들은 함수 바깥에 있다. 이 저장 공간은 프로그램이 실행되는 동안 유지된다. `new_node`가 끝나거나 `term`이 반환되어도 배열에 저장한 노드들은 사라지지 않는다.

전역 `nodes`는 명시적으로 초기값을 적지 않았으므로, 프로그램 시작 때 각 멤버가 0으로 초기화된다. `data`의 0은 널 문자 값이고, `left`와 `right`의 0은 정수 0이다. 그러나 이것을 “모든 노드의 자식이 없다”라는 뜻으로 읽으면 안 된다.

**`0`은 첫 번째 노드를 가리키는 유효한 인덱스이다.** 이 프로그램에서 자식이 없다는 표시는 `-1`이다. 그래서 `new_node`는 새로 사용할 노드의 자식 멤버를 반드시 둘 다 `-1`로 설정한다.

```text
인덱스 0: 첫 번째 노드가 저장될 수 있는 실제 위치
인덱스 1: 두 번째 노드가 저장될 수 있는 실제 위치
표시 -1: 이 멤버에는 자식이 연결되지 않았음
```

`nodes[-1]`이라는 칸이 존재하는 것은 아니다. `-1`은 자식이 없는 상태를 기록하기 위한 약속일 뿐, 배열을 읽을 때 쓸 인덱스가 아니다. 배열 범위 안에 있는 번호라도 아직 `new_node`로 준비하지 않은 칸을 유효한 트리 노드로 사용하면 안 된다.

또한 `new_node`라는 함수 이름 때문에 실행 중에 배열 자체를 계속 늘린다고 생각하지 말자. 저장 공간 20칸은 이미 준비되어 있다. 이 함수는 그중 다음 칸을 초기화하고 사용 중인 칸으로 취급한다.

### 6. 함수의 입력과 반환, `new_node` 한 줄씩 읽기

**함수 정의**는 이름과 입력 형식, 반환 형식, 실행할 본문을 적는 것이다. **함수 호출**은 그 이름 뒤에 소괄호를 써서 실제로 실행을 요청하는 것이다.

```c
int new_node(char data)
{
        nodes[size].data = data;
        nodes[size].left = nodes[size].right = -1;
        return size++;
}
```

| 부분 | 의미 |
| --- | --- |
| 첫 번째 `int` | 호출이 끝나면 정수 값 하나를 돌려준다. |
| `new_node` | 함수 이름이다. |
| `(` | 입력을 받을 매개변수 목록을 시작한다. |
| `char data` | 전달받은 문자 값을 지역 이름 `data`로 사용한다. |
| `)` | 매개변수 목록을 끝낸다. |
| `{`와 `}` | 함수가 호출되었을 때 실행할 본문의 경계이다. |

정의에 적은 입력 이름 `data`를 **매개변수**라고 한다. 호출할 때 실제로 주는 값이나 식을 **인자**라고 한다.

```c
int index = new_node('2');
```

이 예시에서 `'2'`는 인자이고, `new_node`가 실행되는 동안 매개변수 `data`에는 그 문자 값이 들어 있다. `new_node`가 정수 인덱스를 반환하면, 호출한 곳의 `index`가 그 값을 첫 값으로 받는다. `index`는 이 설명에서 추가한 이름이며 원래 프로그램에 필요한 새 전역 변수가 아니다.

#### `nodes[size].data = data;`

왼쪽의 `nodes[size].data`는 배열의 다음 빈칸에 있는 `data` 멤버이다. 오른쪽의 `data`는 이번 함수 호출이 전달받은 문자 값이다. 같은 이름이 보이지만, 하나는 멤버이고 다른 하나는 매개변수이다.

`size`가 `2`이고 전달받은 문자가 `'2'`라면, 이 문장은 `nodes[2].data`에 `'2'`를 저장한다. 아직 `size`를 증가시키지는 않았으므로 다음 문장에서도 같은 인덱스 `2`를 사용한다.

#### `nodes[size].left = nodes[size].right = -1;`

`=`가 두 개라고 해서 같은지 비교하는 `==`가 되는 것은 아니다. 이 줄은 **연결된 대입**이다. C의 대입 묶음 규칙에 따라 다음처럼 읽는다.

```c
nodes[size].left = (nodes[size].right = -1);
```

안쪽의 `nodes[size].right = -1`은 오른쪽 자식 멤버에 `-1`을 대입하며, 그 대입식의 값도 `-1`이다. 바깥 대입은 그 값을 왼쪽 자식 멤버에 사용한다. 이 문장이 끝나면 두 멤버가 모두 `-1`이다.

이 코드에서 필요한 최종 저장 결과는 다음처럼 두 줄로 풀어 써도 같다.

```c
nodes[size].right = -1;
nodes[size].left = -1;
```

두 줄은 뜻을 풀어 보여 주기 위한 설명이다. 원래 함수에는 앞의 연결된 대입 한 줄만 있다. 새 노드가 숫자인지 연산자인지와 관계없이 처음에는 자식이 없는 상태로 준비한다.

#### `return size++;`

`return`은 현재 함수 호출을 끝내고 호출한 곳에 값을 돌려주는 키워드이다. 뒤의 `size++`는 값의 사용과 증가를 함께 표현한다.

`++`를 변수 이름 **뒤에** 붙인 것을 **후위 증가**라고 한다. `size++`라는 식의 값은 증가하기 전의 값이고, `size`에 저장된 값은 1 증가한다. 함수가 반환을 마쳤을 때 증가는 이미 반영되어 있다.

| 호출 시작 때 `size` | 준비한 노드 | 반환하는 값 | 호출이 끝난 뒤 `size` |
| --- | --- | --- | --- |
| 0 | `nodes[0]` | 0 | 1 |
| 1 | `nodes[1]` | 1 | 2 |
| 2 | `nodes[2]` | 2 | 3 |

첫 호출에서 `1`을 반환하는 것이 아니다. 방금 준비한 칸이 `nodes[0]`이므로 그 인덱스 `0`을 반환한다. 다음 호출이 다른 칸을 쓰도록 개수만 `1`로 늘어난다.

이 함수에 한해서 다음처럼 풀어 읽으면 같은 핵심 동작을 이해할 수 있다.

```c
int allocated_index = size;
size = size + 1;
return allocated_index;
```

`allocated_index`는 설명을 위해 붙인 지역 변수 이름이다. 원래 코드의 `return size++;`를 이해하기 위한 예시이므로 원래 줄 뒤에 덧붙이는 코드가 아니다.

`return`이 반환하는 것은 정수 하나이다. `new_node`는 문자 `'2'`의 수학적 값 `2`를 반환하려는 함수가 아니다. 새 노드가 배열의 어디에 있는지를 돌려준다. 문자 `'7'`로 첫 노드를 만들어도 반환하는 인덱스는 `0`이다.

### 7. 문자열 `eq`, 문자와 정수, `pos++`로 소비하기

```c
char eq[20] = "1+2*3";
int pos = 0;
```

첫 줄은 문자 값을 20칸에 저장할 배열 `eq`를 선언한다. 큰따옴표로 감싼 `"1+2*3"`는 **문자열 리터럴**이다. 문자열은 문자들이 순서대로 이어진 것이다.

C의 문자열 끝에는 **널 문자** `\0`이 필요하다. 코드에서 문자 하나로 적을 때는 `'\0'`이라고 쓴다. 역슬래시와 `0`이 두 글자로 보이지만, 이 표기는 값이 0인 문자 한 개를 나타낸다.

문자열 리터럴로 이 배열을 초기화하면, 수식의 다섯 문자 다음에 끝 표시가 저장된다. 나머지 칸도 0으로 초기화된다.

| 배열 인덱스 | 0 | 1 | 2 | 3 | 4 | 5 | 6부터 19까지 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 저장된 문자 | `'1'` | `'+'` | `'2'` | `'*'` | `'3'` | `'\0'` | 모두 `'\0'` |
| 수식에 포함되는가? | 포함 | 포함 | 포함 | 포함 | 포함 | 끝 표시 | 수식 뒤의 남은 공간 |

인덱스 `5`(여섯 번째 칸)의 널 문자가 문자열을 끝낸다. 그 뒤에 있는 칸들을 수식 문자로 처리하지 않는다. `eq[20]`이라는 선언은 20자리 숫자 하나를 저장한다는 뜻이 아니다.

다음 네 가지를 구분하자.

| 표현 | 뜻 |
| --- | --- |
| `3` | 계산에 쓸 정수 3이다. |
| `'3'` | 글자 3을 나타내는 문자 상수이다. C에서 이런 문자 상수의 자료형은 `int`이다. |
| `"3"` | 문자 `'3'`와 끝 표시 `'\0'`으로 이루어진 문자열이다. |
| `'\0'` | 값이 0인 널 문자이다. 숫자 글자 `'0'`과 다르다. |

`'0'`은 문자 0의 코드 값이며 정수 `0`과 같다고 생각하면 안 된다. C는 `'0'`, `'1'`, …, `'9'`의 코드가 순서대로 연속한다는 것을 보장한다. 따라서 `'3' - '0'`은 정수 `3`이 된다. 특정 문자 코드표의 숫자를 외울 필요는 없다.

#### `pos`는 읽을 위치를 기억한다

`int pos = 0;`은 수식의 첫 번째 칸부터 읽겠다는 뜻이다. `pos`는 전역 변수이므로 `term`과 `terms`가 같은 값을 사용한다.

- `eq[pos]`는 현재 위치의 문자 값을 읽는다. 이 식만으로 `pos`는 바뀌지 않는다.
- `pos++`는 현재 위치 값을 식의 값으로 사용하면서 `pos`를 1 증가시킨다.
- `eq[pos++]`는 증가하기 전의 위치로 문자를 고르고, 다음에 읽을 위치를 1 증가시킨다.

이 교재에서 문자를 **소비한다**는 말은 문자를 읽는 것에 더해, 읽을 위치 `pos`를 다음 칸으로 진행시킨다는 뜻이다. 문자를 배열에서 지우는 것은 아니다.

```c
int root = new_node(eq[pos++]);
```

`pos`가 `0`, `size`가 `0`일 때 이 선언을 읽어 보자.

1. `pos++`가 제공하는 인덱스는 이전 값 `0`이다.
2. 따라서 인자로 전달할 문자 값은 `eq[0]`, 즉 `'1'`이다.
3. `pos`는 `1`로 증가한다. 이 증가는 `new_node`의 본문이 시작되기 전에 완료된다.
4. `new_node`는 전달받은 `'1'`을 `nodes[0]`에 저장하고 인덱스 `0`을 반환한다.
5. 지역 정수 변수 `root`가 반환 값 `0`으로 초기화된다. `size`는 `1`이다.

이 설명은 `eq[pos++]`가 오래된 위치를 인덱스로 쓴다는 점을 보여 준다. 문자 읽기와 `pos` 증가의 세부 실행 시점을 임의로 다른 복잡한 식에 일반화할 필요는 없다.

이 호출의 효과는 다음처럼 풀어 써서 이해할 수도 있다.

```c
char current = eq[pos];
pos = pos + 1;
int root = new_node(current);
```

여기서 `current`는 설명을 위해 추가한 지역 이름이다. 두 가지 형태를 동시에 실행하면 같은 동작을 두 번 수행하므로, 원래 코드에 이 세 줄을 더하는 것이 아니다.

반면 `while (eq[pos] == '*')`에는 `pos++`가 없다. 다음 문자가 곱셈 기호인지 확인만 한다. 조건이 거짓이면 그 문자는 다음 함수가 처리할 수 있도록 같은 위치에 남아 있다.

### 8. `term(void)`의 모든 줄과 곱셈 반복

**항**은 이 예제에서 숫자 하나 또는 여러 숫자가 곱셈으로 연결된 부분이다. `"1+2*3"`에는 `"1"`과 `"2*3"`이라는 두 항이 있다. `term`은 현재 `pos`에서 시작하는 항 하나의 트리를 만든다.

```c
int term(void)
{
        int root = new_node(eq[pos++]);
        while (eq[pos] == '*') {
                int op = new_node(eq[pos++]);
                int num = new_node(eq[pos++]);
                nodes[op].left = root;
                nodes[op].right = num;
                root = op;
        }
        return root;
}
```

`int term(void)`에서 첫 `int`는 정수를 반환한다는 뜻이다. `term`은 함수 이름이며, 매개변수 목록의 `void`는 전달받는 인자가 없음을 뜻한다. 함수 호출은 `term()`이라고 쓴다. 정수 0을 인자로 준다는 뜻이 아니다.

전달받는 인자가 없어도 할 일에 필요한 값이 없다는 뜻은 아니다. 이 함수는 전역 `eq`, `pos`, `nodes`, `size`를 사용한다. 그리고 항의 계산 결과가 아니라 **항의 루트 인덱스**를 반환한다.

#### 첫 숫자로 시작하기

```c
int root = new_node(eq[pos++]);
```

현재 문자는 유효한 입력 조건에 의해 숫자라고 가정한다. 그 문자를 소비하고 노드 하나를 준비한다. 반환받은 인덱스를 지역 변수 `root`에 저장한다. 숫자 하나만 있는 트리도 트리이며, 그 숫자 노드가 루트이다.

이 줄에는 숫자인지 확인하는 `if`가 없다. 입력이 숫자로 시작한다고 가정한 코드이기 때문이다.

#### `while`의 검사, 본문, 다시 검사

```c
while (eq[pos] == '*') {
```

`while`은 “이 조건이 참인 동안 본문을 반복하라”라는 키워드이다. `eq[pos]`에 있는 문자와 문자 `'*'`가 같은지 `==`로 비교한다. 작은따옴표 속의 `*`는 곱셈 기호라는 문자이며, 이 조건 자체가 정수 곱셈을 하지는 않는다.

실행 순서는 다음과 같다.

1. 조건을 검사한다.
2. 거짓이면 반복문의 닫는 `}` 다음으로 이동한다.
3. 참이면 중괄호 안의 문장들을 위에서 아래로 실행한다.
4. 본문의 끝에 도달하면 조건으로 돌아가 다시 검사한다.

처음부터 조건이 거짓이면 본문은 한 번도 실행하지 않는다. `"1+2*3"`에서 첫 번째 `term()`은 `'1'`을 소비한 뒤 `'+'`를 보므로, 바로 `return root;`로 간다.

#### 반복문 안의 다섯 문장

```c
int op = new_node(eq[pos++]);
```

조건이 참이므로 현재 문자는 `'*'`이다. 이를 소비하고 연산자 노드를 만든 뒤 인덱스를 지역 변수 `op`에 저장한다. 새 연산자 노드의 자식은 아직 둘 다 `-1`이다.

```c
int num = new_node(eq[pos++]);
```

그다음 문자를 소비해 숫자 노드를 만든다. 유효한 수식에서는 `'*'` 뒤에 숫자 하나가 있다. 새 숫자 노드의 인덱스를 지역 변수 `num`에 저장한다.

```c
nodes[op].left = root;
```

새 곱셈 노드의 왼쪽 자식 인덱스에 지금까지 만들었던 항의 `root` 값을 저장한다. 기존 항의 노드들은 배열의 원래 칸에 그대로 있다.

```c
nodes[op].right = num;
```

같은 곱셈 노드의 오른쪽 자식 인덱스에 방금 만든 숫자 노드 인덱스를 저장한다.

```c
root = op;
```

현재 항의 루트를 새 곱셈 노드로 바꾼다. 이 시점에는 이전 루트가 이미 새 노드의 `left`에 저장되어 있으므로 기존 항을 잃지 않는다. 별도의 `old_root` 변수가 없어도, 대입 전의 `root`가 이전 루트 역할을 한 것이다.

반복 한 번이 끝나면 다시 현재 `eq[pos]`를 검사한다. `'*'`가 더 있으면 지금까지 만든 **전체 항**이 다음 곱셈 노드의 왼쪽 자식이 된다.

| 본문의 동작 | 보존하거나 새로 만드는 것 |
| --- | --- |
| 연산자 노드 만들기 | 새로운 부모 노드 인덱스 `op` |
| 숫자 노드 만들기 | 새로운 오른쪽 자식 인덱스 `num` |
| 왼쪽 연결 | 이전 `root`가 가리키는 전체 서브트리 |
| 오른쪽 연결 | 새 숫자 노드 |
| `root = op` | 두 자식을 포함한 더 큰 항의 시작점 |

`op`와 `num`은 반복문 본문 블록 안의 지역 변수이다. 각 반복에서 새로 값을 받고, 그 블록 밖에서는 이름을 사용할 수 없다. 반면 `root`는 함수 본문에서 선언했으므로 반복문 뒤의 `return root;`에서도 사용할 수 있다.

#### 왜 왼쪽부터 묶이는가?

`"2*3*4"`에서는 먼저 `2*3` 트리를 만든다. 다음 `*4`를 읽으면 새로운 `'*'`가 그 전체 트리를 왼쪽에, `'4'`를 오른쪽에 둔다. 따라서 구조가 `(2*3)*4`가 된다. 이것을 **왼쪽 결합**이라고 한다.

`return root;`는 완성한 항의 루트 인덱스를 돌려준다. 다음 문자가 `'+'` 또는 `'\0'`이면 `while`의 비교만 했을 뿐 소비하지 않았으므로, `pos`는 그 문자의 위치를 그대로 가리킨다.

### 9. `terms(void)`의 모든 줄과 연산자 우선순위

`terms`는 하나 이상의 항을 덧셈으로 연결한다. 함수 이름의 마지막 `s`는 작성자가 붙인 이름의 일부이다. C가 복수형 단어를 자동으로 해석하는 것은 아니다.

```c
int terms(void)
{
        int root = term();
        while (eq[pos] == '+') {
                int op = new_node(eq[pos++]);
                int next_term = term();
                nodes[op].left = root;
                nodes[op].right = next_term;
                root = op;
        }
        return root;
}
```

`int terms(void)`는 인자 없이 호출하며 정수 하나를 반환하는 함수 정의이다. 반환하는 정수는 전체 수식의 루트 인덱스이다.

```c
int root = term();
```

먼저 `term()`을 실행해 항 하나를 완성한다. 호출이 끝날 때까지 `terms`는 이 줄에서 기다린다. 반환된 항의 루트 인덱스로 `terms` 자신의 지역 변수 `root`를 초기화한다.

`term`의 `root`를 직접 사용하는 것이 아니라, 함수가 **반환한 정수 값**을 새로운 지역 변수에 저장하는 것이다. 두 함수가 사용하는 전역 `pos`는 하나이므로, 호출이 끝나면 `pos`는 그 항 뒤의 문자 위치에 있다.

```c
while (eq[pos] == '+') {
```

아직 소비하지 않은 문자가 `'+'`인지 검사한다. 참이면 덧셈으로 연결할 항이 더 있다고 보고 본문을 실행한다. 거짓이면 반복을 끝내고 현재 루트를 반환한다.

```c
int op = new_node(eq[pos++]);
```

현재의 `'+'`를 소비하고 덧셈 노드를 만든다. 인덱스를 `op`에 저장한다. 이 시점에는 다음 항을 아직 만들지 않았으므로, 새 덧셈 노드의 자식들은 아직 `-1`이다.

```c
int next_term = term();
```

현재 `pos`에서 다음 항을 **끝까지** 만든다. 이 `term()` 호출은 숫자 하나만 처리하고 무조건 끝나지 않는다. 뒤에 `'*'`가 있으면 곱셈 부분을 계속 처리한 뒤, 그 항 전체의 루트 인덱스를 반환한다.

```c
nodes[op].left = root;
nodes[op].right = next_term;
root = op;
```

첫 줄은 지금까지 만든 수식을 새 덧셈의 왼쪽 자식으로 연결한다. 둘째 줄은 방금 완성한 항을 오른쪽 자식으로 연결한다. 셋째 줄은 새 덧셈 노드를 현재 수식의 루트로 삼는다.

본문이 끝나면 `while`이 다음 문자를 다시 검사한다. `'+'`가 더 있으면 같은 과정을 반복한다. 마지막 `return root;`는 지금까지 연결한 전체 수식의 루트를 돌려준다.

#### 두 함수가 함께 만드는 우선순위

`"1+2*3"`을 처리할 때 `terms`의 흐름은 다음과 같다.

| 실행 지점 | `pos`의 변화 | 얻은 부분 |
| --- | --- | --- |
| 첫 번째 `term()` | 0에서 1로 | 숫자 `'1'` 노드 |
| `'+'` 소비 | 1에서 2로 | 덧셈 노드 |
| 두 번째 `term()` | 2에서 5로 | `'2'`, `'*'`, `'3'`을 모두 포함한 곱셈 트리 |
| 덧셈의 자식 연결 | 5 그대로 | 왼쪽은 `1`, 오른쪽은 `2*3`인 전체 트리 |

곱셈이 먼저 계산되는 구조는 `term`이 곱셈 부분을 묶어 완성한 뒤 그 루트를 `terms`에 돌려주기 때문에 만들어진다. C가 `eq` 안의 문자열을 저절로 수식으로 실행하는 것이 아니다. 문자열 안에는 문자들만 있고, 우리 함수들이 그 문자들을 읽어 연결 관계를 만든다.

`terms`가 `"1+2+3"`을 처리할 때도 이전 루트를 새 `'+'`의 왼쪽에 연결하므로 `(1+2)+3` 구조가 된다. 두 함수 모두 기존 서브트리를 연결한 다음에 `root`를 바꾼다는 순서가 중요하다.

### 10. `1+2*3` 트리를 만드는 전체 실행 기록

이제 프로그램을 새로 시작한 상태에서 하나도 건너뛰지 않고 추적해 보자. 처음에는 `size = 0`, `pos = 0`이며, 입력 문자열은 `"1+2*3"`이다.

`main`이 `terms()`를 호출하면, `terms`의 첫 문장은 `term()`을 호출한다. 아래 표에서 각 `root`가 어느 함수의 지역 변수인지 구별해서 읽는다.

| 순서 | 실행한 작업 | 작업 뒤 `pos` | 작업 뒤 `size` | 반환 값 또는 지역 변수 |
| --- | --- | --- | --- | --- |
| 1 | 첫 `term`이 `'1'`을 소비하고 노드를 만든다. | 1 | 1 | `term`의 `root = 0` |
| 2 | `eq[1]`의 `'+'`가 `'*'`인지 검사한다. 거짓이다. | 1 | 1 | 첫 `term`이 `0` 반환 |
| 3 | `terms`가 반환 값을 받는다. | 1 | 1 | `terms`의 `root = 0` |
| 4 | `eq[1]`이 `'+'`인지 검사한다. 참이다. | 1 | 1 | 덧셈 반복문 진입 |
| 5 | `'+'`를 소비하고 노드를 만든다. | 2 | 2 | `terms`의 `op = 1` |
| 6 | 두 번째 `term`이 `'2'`를 소비하고 노드를 만든다. | 3 | 3 | `term`의 `root = 2` |
| 7 | `eq[3]`의 `'*'`가 `'*'`인지 검사한다. 참이다. | 3 | 3 | 곱셈 반복문 진입 |
| 8 | `'*'`를 소비하고 노드를 만든다. | 4 | 4 | `term`의 `op = 3` |
| 9 | `'3'`을 소비하고 노드를 만든다. | 5 | 5 | `term`의 `num = 4` |
| 10 | `nodes[3].left = 2;`에 해당하는 대입을 한다. | 5 | 5 | 곱셈의 왼쪽 연결 |
| 11 | `nodes[3].right = 4;`에 해당하는 대입을 한다. | 5 | 5 | 곱셈의 오른쪽 연결 |
| 12 | `term`이 `root = op;`를 실행한다. | 5 | 5 | `term`의 `root = 3` |
| 13 | `eq[5]`의 `'\0'`가 `'*'`인지 검사한다. 거짓이다. | 5 | 5 | 두 번째 `term`이 `3` 반환 |
| 14 | `terms`가 반환 값을 받는다. | 5 | 5 | `next_term = 3` |
| 15 | `nodes[1].left = 0;`에 해당하는 대입을 한다. | 5 | 5 | 덧셈의 왼쪽 연결 |
| 16 | `nodes[1].right = 3;`에 해당하는 대입을 한다. | 5 | 5 | 덧셈의 오른쪽 연결 |
| 17 | `terms`가 `root = op;`를 실행한다. | 5 | 5 | `terms`의 `root = 1` |
| 18 | `eq[5]`의 `'\0'`가 `'+'`인지 검사한다. 거짓이다. | 5 | 5 | `terms`가 `1` 반환 |
| 19 | `main`이 반환 값을 받는다. | 5 | 5 | `main`의 `root = 1` |

표의 `nodes[3].left = 2;` 같은 표기는 실행 시 변수 값을 넣어 보여 준 것이다. 원래 프로그램에서는 `nodes[op].left = root;`라는 일반적인 문장을 실행한다.

#### 노드가 생성되는 정확한 순서

`new_node`는 다음 빈칸을 차례대로 사용한다. 따라서 이 입력의 저장 순서는 다음과 같이 고정된다.

| 생성 순서 | 반환한 인덱스 | 저장한 `data` |
| --- | --- | --- |
| 첫 번째 | 0 | `'1'` |
| 두 번째 | 1 | `'+'` |
| 세 번째 | 2 | `'2'` |
| 네 번째 | 3 | `'*'` |
| 다섯 번째 | 4 | `'3'` |

`'+'` 노드는 `'2'`, `'*'`, `'3'` 노드보다 먼저 만들어진다. 하지만 덧셈의 자식 연결은 오른쪽 항의 생성이 끝난 다음에 이루어진다. **노드의 저장 순서와 트리 안에서의 높이는 서로 다른 정보이다.**

#### 완성한 노드 표

| 인덱스 | `data` | `left` | `right` | 의미 |
| --- | --- | --- | --- | --- |
| 0 | `'1'` | -1 | -1 | 숫자 1을 나타내는 단말 |
| 1 | `'+'` | 0 | 3 | 전체 수식의 루트 |
| 2 | `'2'` | -1 | -1 | 숫자 2를 나타내는 단말 |
| 3 | `'*'` | 2 | 4 | 오른쪽 항의 루트 |
| 4 | `'3'` | -1 | -1 | 숫자 3을 나타내는 단말 |

```text
                 인덱스 1: '+'
                 /           \
        인덱스 0: '1'      인덱스 3: '*'
                           /           \
                  인덱스 2: '2'      인덱스 4: '3'
```

연결은 `1 → 0`, `1 → 3`, `3 → 2`, `3 → 4`이다. 그림의 선은 자식 멤버에 저장한 정수 인덱스를 읽어서 해석한 관계이다. 배열 칸을 실제로 그림처럼 옮겨 놓은 것은 아니다.

이때 `root = 1`, `size = 5`, `pos = 5`이다. 세 값이 우연히 모두 같아야 한다는 규칙은 없다. `root`는 시작 노드의 위치, `size`는 준비한 노드 수, `pos`는 다음 문자 위치라는 서로 다른 역할이다.

널 문자는 조건에서 확인했지만 소비하지 않았다. 그래서 `pos`가 `6`이 되지 않는다. 수식의 다섯 문자에 대해서만 노드를 만들었으므로, 널 문자를 저장한 여섯 번째 노드도 없다.

### 11. `eval_tree`의 모든 줄과 재귀의 종료 조건

트리를 만들었으므로 이제 그 구조를 따라 계산한다. **재귀**는 함수가 문제의 더 작은 부분을 처리하기 위해 자기 자신을 다시 호출하는 것이다. 여기서는 자식 서브트리의 계산을 같은 `eval_tree` 함수에 요청한다. 앞의 `term`과 `terms`는 `while` 반복으로 트리를 만들며 자기 자신을 호출하지 않는다. 트리를 만드는 단계와 재귀로 계산하는 단계를 구분하자.

```c
int eval_tree(int node)
{
        if (nodes[node].data >= '0' && nodes[node].data <= '9') {
                return nodes[node].data - '0';
        }

        if (nodes[node].data != '+' && nodes[node].data != '*') return -1;

        int left = eval_tree(nodes[node].left);
        int right = eval_tree(nodes[node].right);

        if (nodes[node].data == '+') return left + right;
        if (nodes[node].data == '*') return left * right;

        return -1;
}
```

`int eval_tree(int node)`에는 `int`가 두 번 나온다. 첫 번째는 반환하는 값이 정수임을, 두 번째는 입력 `node`가 정수임을 뜻한다. 입력 정수는 노드 **인덱스**이며, 반환 정수는 해당 서브트리의 **계산 결과**이다.

`eval_tree(1)`을 호출하면 매개변수 `node`에 `1`이 들어간다. 따라서 함수 안의 `nodes[node]`는 이번 호출에서 `nodes[1]`을 뜻한다. 매개변수 이름을 `node`라고 썼지만 구조체 전체를 전달받은 것은 아니다.

#### 숫자 범위를 확인하고 정수로 바꾸기

```c
if (nodes[node].data >= '0' && nodes[node].data <= '9') {
        return nodes[node].data - '0';
}
```

`if`는 소괄호 안의 조건이 참일 때만 뒤의 문장이나 블록을 실행한다. 이 조건은 현재 노드의 `data`가 숫자 문자 범위 안에 있는지 확인한다.

현재 문자가 `'3'`이면 `'0'` 이상이며 `'9'` 이하이므로 조건이 참이다. 이어서 `'3' - '0'`을 계산하여 정수 `3`을 반환한다. 숫자 문자 코드가 연속하므로 가능한 변환이다.

`return`을 실행하면 **이번 함수 호출**은 즉시 끝난다. 아래의 연산자 검사나 자식 호출까지 계속 내려가지 않는다. 숫자 노드는 자식 멤버가 `-1`이어도 `eval_tree(-1)`을 호출하지 않는다.

더 이상 자신을 호출하지 않고 값을 돌려주는 경우를 **종료 조건**이라고 한다. 이 함수의 정상적인 종료 조건은 숫자 노드이다. 자식이 없다는 `-1`에 도달해서 멈추는 방식이 아니다.

#### 지원하지 않는 문자를 걸러 내는 한 줄

```c
if (nodes[node].data != '+' && nodes[node].data != '*') return -1;
```

숫자 처리에서 반환하지 않았다면 여기로 온다. 현재 문자가 `'+'`도 아니고 `'*'`도 아니면 `-1`을 반환한다. `!=`는 서로 다르다는 비교이고, `&&`는 두 비교가 모두 참이어야 함을 뜻한다.

여기에는 중괄호가 없다. C는 조건에 따라 실행할 문장이 하나뿐이면 다음처럼 한 문장을 바로 쓸 수 있다.

```c
if (nodes[node].data != '+' && nodes[node].data != '*') {
        return -1;
}
```

이 블록 형태는 위 한 줄과 같은 조건부 반환을 표현한다. 원래 줄 뒤에 새로 추가해서 두 번 검사하라는 뜻이 아니다.

중괄호가 없는 `if`는 바로 다음 **한 문장**만 조건에 포함한다. 들여쓰기나 줄바꿈을 더 한다고 뒤의 여러 문장이 자동으로 같은 조건에 묶이지는 않는다.

이 검사는 입력 문자열이나 트리의 모든 오류를 검증하지 않는다. 이미 첫 조건에서 `nodes[node]`를 읽었으므로, `node` 자체가 유효하지 않다면 이 검사로 보호할 수 없다. 연산자에 유효한 두 자식이 있는지도 검사하지 않는다.

#### 자식들을 계산하는 두 문장

```c
int left = eval_tree(nodes[node].left);
int right = eval_tree(nodes[node].right);
```

첫 줄은 현재 노드의 왼쪽 자식 인덱스를 읽고, 그 인덱스로 `eval_tree`를 호출한다. 그 호출이 끝나서 반환한 정수 결과를 현재 호출의 지역 변수 `left`에 저장한다.

둘째 줄은 오른쪽 자식에 대해 같은 일을 하며 결과를 `right`에 저장한다. 두 호출이 서로 다른 문장에 있으므로 **왼쪽 호출이 끝난 뒤 오른쪽 호출을 시작한다.**

예를 들어 현재 `node`가 `3`이면 첫 줄은 자식 인덱스 `2`로 `eval_tree(2)`를 호출한다. 그 결과 정수 `2`가 `left`에 들어간다. 둘째 줄은 자식 인덱스 `4`로 `eval_tree(4)`를 호출하고, 결과 정수 `3`을 `right`에 넣는다.

여기서 지역 변수 `right`의 값은 `3`이고, 구조체 멤버 `nodes[3].right`의 값은 `4`이다. 전자는 계산 결과, 후자는 자식의 위치이므로 서로 다른 값이 정상이다.

#### 연산자에 맞는 정수 연산을 수행하기

```c
if (nodes[node].data == '+') return left + right;
if (nodes[node].data == '*') return left * right;
```

첫 줄은 저장된 문자가 `'+'`인지 비교한다. 맞으면 이미 구한 두 정수를 더한 결과를 반환한다. 작은따옴표가 없는 `left + right`의 `+`가 실제 정수 덧셈을 수행한다.

두 번째 줄은 저장된 문자가 `'*'`인지 비교한다. 맞으면 `left * right`로 두 정수를 곱한 결과를 반환한다. 조건 안의 `'*'`는 문자이고, 반환식의 `*`는 곱셈 연산자이다.

첫 줄에서 `return`했다면 둘째 줄은 실행하지 않는다. `if`가 두 개라고 해서 덧셈과 곱셈을 모두 수행하는 것이 아니다.

```c
return -1;
```

마지막 줄은 앞에서 반환하지 않은 경우에 정수 `-1`을 반환하도록 적은 것이다. 입력과 트리의 가정이 맞고 저장 데이터가 바뀌지 않는 이 예제에서는, 지원되는 연산자는 위의 두 반환 중 하나로 이미 끝난다.

이 `-1`은 오류를 나타내려는 반환 값이다. 자식 멤버에서의 `-1`은 자식 없음, 여기서의 `-1`은 계산 결과 대신 반환한 표시이므로 역할이 다르다. 또 부모 호출은 자식의 오류 반환을 별도로 검사하지 않으므로, 이 코드 전체를 완전한 오류 처리기로 생각하면 안 된다.

### 12. 재귀 계산을 끝까지 따라가기

완성한 트리의 루트 인덱스는 `1`이다. `main`은 다음 선언을 실행한다.

```c
int answer = eval_tree(root);
```

여기서 `root`의 값은 `1`이므로 `eval_tree(1)`을 호출한다. 호출이 끝나서 계산 결과를 돌려줄 때까지 `answer`의 초기화는 기다린다.

#### 호출마다 다른 지역 변수

함수가 다른 함수를 호출하면, 컴퓨터는 호출한 함수가 나중에 어디서 계속해야 하는지와 그 함수의 지역 값들을 유지한다. 이러한 호출별 작업 상태를 **호출 프레임**이라고 부르기도 한다.

`eval_tree(1)`이 `eval_tree(3)`을 호출할 때, 앞 호출의 `node = 1`이 뒤 호출의 `node = 3`으로 바뀌는 것이 아니다. 두 호출은 자신의 `node`를 가진다. 뒤 호출이 끝나면 앞 호출은 보관한 상태로 작업을 이어간다.

숫자 노드 호출은 첫 `return`에서 끝나므로 아래의 지역 변수 `left`, `right` 선언까지 도달하지 않는다. 연산자 노드 호출은 자식 결과를 받을 자신의 `left`, `right`를 사용한다.

#### 왼쪽부터 계산하는 실제 흐름

```text
1. eval_tree(1): '+'이므로 자식 결과가 필요하다.
   2. eval_tree(0): '1'이므로 정수 1을 반환한다.
   3. eval_tree(1)의 left에 1을 저장한다.
   4. eval_tree(3): '*'이므로 자식 결과가 필요하다.
      5. eval_tree(2): '2'이므로 정수 2를 반환한다.
      6. eval_tree(3)의 left에 2를 저장한다.
      7. eval_tree(4): '3'이므로 정수 3을 반환한다.
      8. eval_tree(3)의 right에 3을 저장한다.
      9. eval_tree(3)은 2 * 3의 결과 6을 반환한다.
  10. eval_tree(1)의 right에 6을 저장한다.
  11. eval_tree(1)은 1 + 6의 결과 7을 반환한다.
12. main의 answer에 7을 저장한다.
```

표로는 다음처럼 볼 수 있다. 숫자 노드의 빈 결과 칸은 값이 0이라는 뜻이 아니라, 자식 계산을 하지 않았다는 뜻이다.

| 이번 호출 | 저장 문자 | 왼쪽 자식 인덱스 | 지역 `left`의 결과 | 오른쪽 자식 인덱스 | 지역 `right`의 결과 | 반환 결과 |
| --- | --- | --- | --- | --- | --- | --- |
| `eval_tree(0)` | `'1'` | -1 | 계산하지 않음 | -1 | 계산하지 않음 | 1 |
| `eval_tree(2)` | `'2'` | -1 | 계산하지 않음 | -1 | 계산하지 않음 | 2 |
| `eval_tree(4)` | `'3'` | -1 | 계산하지 않음 | -1 | 계산하지 않음 | 3 |
| `eval_tree(3)` | `'*'` | 2 | 2 | 4 | 3 | 6 |
| `eval_tree(1)` | `'+'` | 0 | 1 | 3 | 6 | 7 |

실제 방문 시작 순서는 `1 → 0 → 3 → 2 → 4`이다. 완료하여 결과를 돌려주는 순서는 `0 → 2 → 4 → 3 → 1`이다. 부모는 자식 결과가 필요하므로 먼저 시작해도 나중에 반환할 수 있다.

`eval_tree`에는 `nodes[node].data = ...;`라는 대입이 없다. 계산이 끝난 뒤에도 `nodes[1].data`는 `'+'`, `nodes[3].data`는 `'*'`이다. 문자 `'*'`를 숫자 `6`으로 덮어쓰지 않는다. `6`은 함수의 반환 값과 부모 호출의 지역 변수에 담긴다.

`size`와 `pos`도 계산 중에는 바꾸지 않는다. 트리를 만든 뒤의 `size = 5`, `pos = 5`가 그대로 유지된다. `eq`에 저장된 수식 문자열도 그대로이다.

| 함수 | 입력 또는 사용하는 정보 | 반환하는 정수의 의미 |
| --- | --- | --- |
| `new_node` | 저장할 문자 | 새 노드의 배열 인덱스 |
| `term` | 현재 `eq`, `pos` | 항의 루트 인덱스 |
| `terms` | 현재 `eq`, `pos` | 전체 수식의 루트 인덱스 |
| `eval_tree` | 노드 인덱스 | 그 서브트리의 계산 결과 |

반환 자료형이 모두 `int`라고 해서 같은 종류의 정보를 뜻하지 않는다. 특히 `terms()`가 반환한 `1`은 정답 1이 아니라 루트 위치 1이고, `eval_tree(1)`이 반환한 `7`이 수식의 정답이다.

### 13. 전체 실행 프로그램과 출력 문법

아래 코드는 앞의 여섯 코드 조각을 하나로 모은 것이다. 출력 함수의 선언을 읽어 오도록 `#include <stdio.h>`를 맨 앞에 놓았다. 새 C 파일 하나에 이 상자 안의 코드만 복사하여 실행할 수 있다.

```c
#include <stdio.h> /* printf 선언 포함 */

struct TreeNode {
        char data; /* 숫자 문자, '+', 또는 '*' */
        int left;  /* nodes 배열 내 왼쪽 자식의 인덱스. 없으면 -1 */
        int right; /* nodes 배열 내 오른쪽 자식의 인덱스. 없으면 -1 */
};

/* 한 번에 하나의 수식만 처리한다. 노드들은 프로그램 전체 실행 시간 동안 유지된다. */
struct TreeNode nodes[20];
int size = 0;

int new_node(char data)
{
        nodes[size].data = data;
        /* 새로 할당된 노드는 아직 자식이 없다. */
        nodes[size].left = nodes[size].right = -1;
        return size++; /* size를 증가시킨다. 반환되는 값은 증가하기 전의 원래 인덱스이다. */
}

char eq[20] = "1+2*3"; /* 공백 없음; 문자열은 '\0'으로 끝난다. */
int pos = 0;          /* 아직 읽지 않은 다음 문자의 인덱스 */

int term(void)
{
        /* 첫 번째 숫자를 노드가 하나인 서브트리로 삼아 시작한다. */
        int root = new_node(eq[pos++]);
        while (eq[pos] == '*') {
                int op = new_node(eq[pos++]);  /* '*' 소비 */
                int num = new_node(eq[pos++]); /* 다음 숫자 소비 */
                /* 지금까지 만든 항을 다음 숫자와 그룹화한다. */
                nodes[op].left = root;
                nodes[op].right = num;
                root = op; /* 이제 새로운 연산자가 이 서브트리의 루트가 된다. */
        }
        /* 호출자를 위해 '+'나 '\0'은 읽지 않은 상태로 남겨둔다. */
        return root;
}

int terms(void)
{
        int root = term();
        while (eq[pos] == '+') {
                int op = new_node(eq[pos++]); /* '+' 소비 */
                /* 모든 곱셈을 포함하여 다음 항을 완성한다. */
                int next_term = term();
                nodes[op].left = root;
                nodes[op].right = next_term;
                root = op; /* 새로운 '+'가 두 서브트리를 연결한다. */
        }
        return root; /* 전체 수식의 루트 인덱스 */
}

int eval_tree(int node)
{
        /* 종료 조건: 숫자 노드는 자신의 숫자 값을 정답으로 제공한다. */
        if (nodes[node].data >= '0' && nodes[node].data <= '9') {
                return nodes[node].data - '0';
        }

        /* 유효한 트리는 숫자와 지원되는 두 개의 연산자만을 포함한다. */
        if (nodes[node].data != '+' && nodes[node].data != '*') return -1;

        /* 각각의 호출은 자신만의 결과를 유지하며, 왼쪽 호출이 먼저 끝난다. */
        int left = eval_tree(nodes[node].left);
        int right = eval_tree(nodes[node].right);

        /* 저장된 연산자를 변경하지 않고 반환된 값들을 연산한다. */
        if (nodes[node].data == '+') return left + right;
        if (nodes[node].data == '*') return left * right;

        return -1;
}

int main(void)
{
        int root = terms();           /* 트리를 만들고 그 루트 인덱스를 보관한다. */
        int answer = eval_tree(root); /* 해당 인덱스부터 트리를 계산한다. */
        printf("%s = %d\n", eq, answer);
        return 0;
}
```

#### `#include <stdio.h>`

`#`로 시작하는 이 줄은 일반적인 실행 문장과 다르게, 컴파일 준비 과정에서 처리하는 **전처리 지시문**이다. `include`는 지정한 헤더의 내용을 사용하도록 지시한다.

**헤더**는 다른 코드가 제공하는 함수 등의 선언을 알려 주는 파일이다. `<stdio.h>`는 표준 입력과 출력에 관련된 헤더를 지정한다. 이 예제에서는 `printf`를 올바르게 호출하는 데 필요한 선언을 얻는다.

`<`와 `>`는 이 위치에서 헤더 이름을 감싸는 기호이다. 수의 크기를 비교하는 식이 아니다. `stdio.h`의 `.h`는 헤더 이름의 일부이며, `nodes[0].data`의 마침표처럼 구조체 멤버를 선택하지 않는다.

이 줄 끝에는 세미콜론을 붙이지 않는다. 또한 헤더를 포함한다고 화면에 무엇인가 자동으로 출력되는 것은 아니다. 실제 출력은 `main` 안의 `printf` 호출이 실행될 때 일어난다.

#### `int main(void)`와 시작점

`main`은 이 실행 예제에서 프로그램이 시작하는 함수 이름이다. `int`는 정수를 반환한다는 뜻이며, `(void)`는 이 형태의 함수가 인자를 받지 않는다는 뜻이다. 중괄호 안이 실행할 본문이다.

```c
int root = terms();
```

`terms()`를 호출하여 트리 전체를 만든다. 반환된 정수 인덱스 `1`로 `main`의 지역 변수 `root`를 초기화한다. 단순히 함수 이름을 저장하는 코드가 아니다. 소괄호가 있으므로 함수를 실행한다.

```c
int answer = eval_tree(root);
```

현재 `root`의 값 `1`을 인자로 주어 계산 함수를 호출한다. 반환된 계산 결과 `7`을 `answer`의 첫 값으로 저장한다.

#### `printf`의 각 부분

```c
printf("%s = %d\n", eq, answer);
```

`printf`는 정해진 형식에 따라 글자와 값을 출력하는 표준 라이브러리 함수이다. **라이브러리**는 여러 프로그램이 사용할 수 있도록 준비된 코드 모음이다. 이 함수는 우리가 이 파일에서 본문을 직접 작성하지 않고 제공되는 기능을 사용한다.

| 부분 | 의미 |
| --- | --- |
| `printf` | 호출할 출력 함수의 이름이다. |
| `(` | 함수에 전달할 인자 목록을 시작한다. |
| `"%s = %d\n"` | 출력 모양을 정한 첫 번째 인자, 형식 문자열이다. |
| 첫 번째 `,` | 첫 인자와 둘째 인자를 구분한다. |
| `eq` | `%s` 자리에 출력할 수식 문자열이다. |
| 두 번째 `,` | 둘째 인자와 셋째 인자를 구분한다. |
| `answer` | `%d` 자리에 출력할 정수 값이다. |
| `)` | 인자 목록을 끝낸다. |
| `;` | 함수 호출 문장을 끝낸다. |

**형식 문자열**은 그대로 출력할 문자와, 다른 인자의 값을 넣을 자리를 함께 지정한다. 여기에는 다음 내용이 순서대로 들어 있다.

1. `%s`: 뒤에서 전달한 문자열 `eq`를 출력한다. 처음 문자부터 널 문자 직전까지 출력하며 널 문자 자체는 보이지 않는다.
2. 공백 하나, `=`, 공백 하나: 문자열에 적힌 모양대로 출력한다. 여기의 `=`는 대입 연산자가 아니라 출력할 글자이다.
3. `%d`: 다음 인자 `answer`를 십진수 정수로 출력한다. 지금은 `7`이 출력된다.
4. `\n`: 줄바꿈 문자이다. 결과 뒤에서 다음 줄로 이동한다.

`%s`와 `%d`는 이 문자열 안에서 `printf`가 해석하는 표시이다. 이 코드에서 `%`가 나머지 계산을 수행하는 것은 아니다. 또한 형식 문자열을 감싼 큰따옴표는 실제 출력되지 않는다.

`\n`은 역슬래시와 `n`을 각각 출력하라는 뜻이 아니다. C 문자열에서 특별한 문자 하나를 나타내는 **이스케이프 시퀀스**이다. `'\0'`과 `\n`은 둘 다 역슬래시로 시작하지만, 앞의 것은 문자열 끝에 쓰는 값 0의 문자이고 뒤의 것은 출력 줄을 바꾸는 문자이다.

`printf`도 반환 값이 있지만 이 예제는 그 값을 변수에 저장하지 않고 출력 효과만 사용한다. 프로그램의 정답을 반환하는 일은 앞의 `eval_tree`가 수행했다.

#### `return 0;`의 의미

`main`의 `return 0;`은 프로그램을 정상적으로 마쳤다고 실행 환경에 알리는 정수 값을 돌려준다. 화면에 정수 `0`을 출력하는 문장이 아니다. 수식의 정답 `7`을 `0`으로 바꾸는 것도 아니다.

숫자 `0`은 문맥에 따라 역할이 다르다. `root = 0`이라면 첫 노드의 인덱스이고, 조건의 값 `0`은 거짓이며, `main`의 반환 값 `0`은 정상 종료를 나타낸다. 값의 모양만 보지 말고 어느 곳에 사용되는지 확인한다.

프로그램의 출력은 다음 한 줄이다.

```text
1+2*3 = 7
```

마지막 `7` 뒤에는 줄바꿈 한 개가 있다. 출력에 문자열의 큰따옴표나 널 문자가 보이지 않는 것이 정상이다. 노드 표나 중간 호출 기록은 이 프로그램이 추가로 출력하지 않는다.

#### 터미널에서 직접 실행해 보기

**소스 파일**은 C 코드를 글자로 저장한 파일이다. 위 전체 프로그램을 `chapter2_full.c`라는 파일에 저장한다. 아래 명령은 C 컴파일러를 `cc`라는 이름으로 사용할 수 있는 터미널 환경에서의 예이다.

**컴파일러**는 C 소스 코드를 실행 가능한 프로그램으로 바꾸는 도구이다. **터미널**은 명령을 글자로 입력하여 도구나 프로그램을 실행하는 창이다. 파일이 있는 폴더에서 다음 두 명령을 한 줄씩 실행한다.

```sh
cc -std=c11 -Wall -Wextra -Wpedantic chapter2_full.c -o chapter2_full
./chapter2_full
```

| 부분 | 의미 |
| --- | --- |
| `cc` | 설치된 C 컴파일러를 실행하는 명령 이름이다. |
| `-std=c11` | C11 문법 기준으로 컴파일하도록 지정한다. 이 기준은 코드의 중간 지역 변수 선언도 허용한다. |
| `-Wall` | 일반적으로 유용한 경고들을 켠다. 이름과 달리 가능한 모든 경고를 뜻하지는 않는다. |
| `-Wextra` | 추가 경고들을 켠다. |
| `-Wpedantic` | 선택한 C 표준에서 벗어나는 부분 등에 대한 경고를 요청한다. |
| `chapter2_full.c` | 읽을 C 소스 파일 이름이다. |
| `-o chapter2_full` | 만들어질 실행 파일의 이름을 `chapter2_full`로 지정한다. |
| `./chapter2_full` | 현재 폴더에 생성된 실행 파일을 실행한다. `./`는 현재 폴더를 나타낸다. |

명령의 `-`로 시작하는 부분들은 컴파일러의 **옵션**이다. C 프로그램 내부의 뺄셈식이 아니다. 명령의 공백은 명령 이름과 각 인자를 구분한다.

터미널 명령도 상자의 백틱이나 `sh` 표시 없이 입력한다. 터미널이 앞에 보여 주는 프롬프트가 있더라도 그 기호까지 복사할 필요는 없다. 컴파일 오류가 있다면 먼저 고친 뒤 실행한다. 경고가 없다는 사실만으로 모든 입력에 안전한 프로그램이 되었다는 뜻은 아니다.

### 14. 이 예제의 경계와 다른 입력을 읽는 법

이 프로그램은 정해진 형태의 올바른 수식 하나를 처리하는 예제이다. 설명을 이해하려면 실제로 검사하는 것과 입력에 대해 가정한 것을 구별해야 한다.

#### 20칸 배열과 최대 19문자

수식의 모든 숫자 문자와 연산자 문자는 각각 노드 하나를 만든다. 길이가 `n`인 유효한 수식은 노드 `n`개를 사용한다. `eq[20]`에는 수식 문자뿐 아니라 마지막 널 문자도 저장해야 하므로 수식 자체는 최대 19문자이다.

숫자 한 개로 시작하고 그 뒤에 연산자와 숫자가 두 문자씩 붙으므로, 가능한 수식 길이는 `1`, `3`, `5`, …, `19`와 같이 홀수이다. 다만 길이가 홀수라는 사실만으로 올바른 수식이 되는 것은 아니다. `"1++"`도 길이 3이지만 조건에 맞지 않는다.

최대 길이 19의 유효한 수식은 `nodes[0]`부터 `nodes[18]`까지 19칸을 사용한다. `nodes`에는 20칸이 있지만, 입력 문자열의 끝 표시 때문에 이 예제의 최대 수식 길이는 19이다.

`new_node` 내부에는 공간이 남았는지 검사하는 조건이 없다. 다른 코드가 너무 많이 호출하거나 입력 가정을 깨면 배열 범위를 벗어날 수 있다. C가 배열의 범위 오류를 자동으로 안전하게 막아 주는 것도 아니다.

#### 올바르지 않은 문자열이나 트리

`"12+3"`에서 `term`은 첫 문자 `'1'`을 읽고, 다음 문자 `'2'`가 `'*'`가 아니므로 멈춘다. `terms`도 `'2'`가 `'+'`가 아니므로 멈춘다. 전체 문자열이 올바르게 처리되었다고 확인하는 검사가 없으므로, 이 예제로 여러 자리 숫자를 계산할 수 없다.

`"1 +2"`에서도 공백을 건너뛰는 코드가 없으므로 진행이 멈춘다. `"1+"`처럼 숫자가 빠진 입력은 이 코드의 가정 밖이다. 널 문자를 숫자처럼 소비한 뒤 계속 읽는 등 잘못된 처리가 이어질 수 있다. 이런 입력을 넣어도 언제나 `-1`로 안전하게 끝난다고 기대하면 안 된다.

`eval_tree`는 유효한 노드 인덱스, 올바른 숫자 또는 지원하는 연산자, 연산자의 두 자식이 모두 있는 트리를 가정한다. 자식 링크가 자기 자신으로 돌아오는 순환, 유효하지 않은 인덱스, 공유된 자식 등을 검증하지 않는다.

숫자 노드에서 먼저 반환하기 때문에 정상적인 트리에서는 자식 없음 표시 `-1`을 따라가지 않는다. 연산자 노드의 자식이 `-1`이라면 그 가정이 깨진 것이다. `eval_tree(-1)`을 호출해서 종료 조건으로 삼으면 안 된다.

지원되지 않는 문자일 때의 `return -1`도 완전한 오류 처리가 아니다. 예를 들어 자식 호출이 `-1`을 반환하더라도 부모는 이를 오류로 따로 확인하지 않고 덧셈이나 곱셈에 사용할 수 있다.

또한 중간 계산이 `int`의 표현 범위를 벗어나는 경우를 검사하지 않는다. 큰 결과가 나오는 입력까지 처리하려면 입력과 계산의 범위를 확인하는 별도의 설계가 필요하다. 여기서는 모든 결과가 범위 안에 있다고 가정한다.

#### 한 번 더 만들 때는 상태가 남아 있다

현재 프로그램은 `terms()`를 한 번만 호출한다. 첫 실행 뒤에는 `size = 5`, `pos = 5`가 남아 있다. 아무 준비 없이 다시 호출하면 처음부터 같은 수식을 읽는 것이 아니다.

새 수식을 처음부터 만들려면 올바르게 끝 표시가 있는 새 입력을 준비하고, 만들기 전에 `pos = 0;`과 `size = 0;`으로 이번 수식의 읽기 위치와 사용 개수를 다시 정해야 한다. 두 변수는 역할이 다르므로 둘 다 고려해야 한다.

이렇게 다시 시작하면 새 노드들이 배열의 앞부분을 덮어쓴다. 이전 수식의 루트 인덱스를 보관했다고 이전 트리가 그대로 유지되는 것은 아니다. 동시에 여러 수식의 트리를 보관하는 기능은 이 프로그램에 없다.

#### 다른 유효한 입력을 새 실행에서 추적하기

다음 표의 각 행은 `size = 0`, `pos = 0`인 **별도의 새 실행**을 뜻한다. 앞 행의 상태에서 다음 행으로 이어서 실행하는 것이 아니다.

| 입력 문자열 | 생성 인덱스와 문자 | 최종 루트 | 최종 `size` | 최종 `pos` | 계산 결과 |
| --- | --- | --- | --- | --- | --- |
| `"7"` | `0:'7'` | 0 | 1 | 1 | 7 |
| `"2*3*4"` | `0:'2', 1:'*', 2:'3', 3:'*', 4:'4'` | 3 | 5 | 5 | 24 |
| `"1+2+3"` | `0:'1', 1:'+', 2:'2', 3:'+', 4:'3'` | 3 | 5 | 5 | 6 |

`"7"`에서는 숫자 노드 하나가 곧 루트이다. 곱셈 반복과 덧셈 반복은 둘 다 한 번도 실행되지 않는다. 루트가 인덱스 `0`인 정상적인 경우이다.

`"2*3*4"`에서는 인덱스 `1`의 `'*'`가 자식 `0`과 `2`를 가진다. 인덱스 `3`의 새 `'*'`는 그 이전 루트 `1`과 새 숫자 `4`를 자식으로 가진다. 따라서 `(2*3)*4`를 계산한다.

`"1+2+3"`에서도 인덱스 `1`의 첫 `'+'`가 자식 `0`과 `2`를 가진다. 인덱스 `3`의 두 번째 `'+'`는 자식 `1`과 `4`를 가진다. 따라서 `(1+2)+3` 구조이다.

### 15. 직접 예측하는 문제와 해설

먼저 종이나 빈 표에 예상 값을 적은 뒤 해설과 비교하자. 정수 하나가 노드의 위치인지, 문자 코드인지, 계산 결과인지도 함께 설명해 보자.

#### 문제

1. `int size = 0;`의 다섯 부분 `int`, `size`, `=`, `0`, `;`는 각각 무엇을 뜻하는가?
2. 새 프로그램에서 `new_node('7')`을 한 번 호출하면 반환 값과 호출 뒤 `size`는 각각 무엇인가? `nodes[0]`의 세 멤버는 무엇인가?
3. `size`가 `4`일 때 `return size++;`를 실행하면 어떤 값을 반환하며, `size`에는 무엇이 남는가?
4. `eq`가 `"1+2*3"`, `pos`가 `2`일 때 `new_node(eq[pos++])`에 전달되는 문자는 무엇인가? 함수 본문이 시작될 때 `pos`는 얼마인가?
5. 같은 문자열에서 `pos`가 `1`일 때 `eq[pos] == '*'`의 결과는 무엇인가? 비교 뒤 `pos`는 바뀌는가?
6. `'0'`, `0`, `'\0'`, `"0"`은 각각 무엇인가? `'8' - '0'`은 어떤 정수를 만드는가?
7. `nodes[1].right = 3;`은 노드에 숫자 값 `3`을 저장하는 것인가, 어느 자식이 있는지 기록하는 것인가?
8. `"1+2*3"`에서 첫 번째 `term()`은 어떤 인덱스를 반환하고, 두 번째 `term()`은 어떤 인덱스를 반환하는가?
9. 전체 트리를 만든 직후 `main`의 `root`, `size`, `pos`를 적어 보자. 마지막 널 문자의 노드도 만들어지는가?
10. `"1+2*3"`에서 `eval_tree(3)`이 계산할 때 구조체 멤버 `nodes[3].right`와 지역 변수 `right`에는 각각 무엇이 들어 있는가?
11. 숫자 노드의 자식은 `-1`인데, 정상적인 계산은 왜 `eval_tree(-1)`을 호출하지 않는가?
12. `eval_tree(1)`이 `eval_tree(3)`을 호출하면 앞 호출의 매개변수 `node`도 `3`으로 바뀌는가? 두 호출의 지역 `left` 값은 같은가?
13. 전체 계산이 끝나면 `nodes[1].data`와 `nodes[3].data`에 각각 무엇이 남아 있는가? 화면에는 무엇이 출력되는가?
14. `if (nodes[node].data == '+') return left + right;`에는 왜 중괄호가 없어도 되는가? 이 `if`의 조건에 포함되는 문장은 몇 개인가?
15. 새 실행의 입력이 `"2*3*4"`라면 최종 루트는 어느 인덱스인가? 그 루트의 왼쪽과 오른쪽 자식 인덱스는 무엇인가?
16. `eq[20]`인데 최대 수식 길이가 20이 아니라 19인 이유는 무엇인가? 길이 19인 유효한 수식은 노드를 몇 개 사용하는가?
17. `main`의 `return 0;`은 정답이 0이라는 뜻인가? 정답을 실제로 화면에 출력하는 문장은 어느 것인가?
18. 첫 트리를 만든 뒤 상태를 바꾸지 않고 `terms()`를 다시 호출하면 같은 트리를 처음부터 다시 만드는가?

#### 해설

1. `int`는 정수 자료형, `size`는 작성자가 붙인 변수 이름, `=`는 선언에서 첫 값 지정, `0`은 그 첫 정수 값, `;`는 선언의 끝이다. 이 이름으로 노드 수를 관리하는 것은 프로그램에서 정한 역할이다.

2. 인덱스 `0`을 반환하고 `size`는 `1`이 된다. `nodes[0].data`는 `'7'`, `left`와 `right`는 모두 `-1`이다. 반환 값이 숫자 글자 7의 계산 값 `7`이 아니라 첫 노드의 위치 `0`이라는 점을 확인한다.

3. 이전 값 `4`를 반환하고 `size`는 `5`가 된다. 후위 증가식의 값과 증가 뒤 변수의 값을 나누어 읽어야 한다.

4. 이전 위치 `2`의 문자 `'2'`를 전달한다. `pos`의 증가는 호출되는 함수 본문이 시작되기 전에 완료되므로 그때는 `3`이다. 문자열에서 문자가 삭제되는 것은 아니다.

5. `eq[1]`은 `'+'`이므로 비교는 거짓, 정수 값으로는 `0`이다. 이 식에는 `pos++`가 없으므로 `pos`는 계속 `1`이다.

6. `'0'`은 숫자 글자의 문자 코드, `0`은 정수 0, `'\0'`은 값 0의 널 문자, `"0"`은 문자 `'0'`과 끝 표시로 이루어진 문자열이다. C의 숫자 문자 코드가 연속하므로 `'8' - '0'`은 정수 `8`이다.

7. 노드 `1`의 오른쪽 자식이 `nodes[3]`에 있음을 기록한다. 멤버 자체에 저장되는 값은 정수 `3`이지만, 그 역할은 계산 결과가 아니라 자식 인덱스이다. 이 예제에서 그 자식의 문자는 `'*'`이고 계산 결과는 `6`이다.

8. 첫 `term()`은 숫자 `'1'` 노드의 인덱스 `0`을 반환한다. 두 번째는 `2*3` 전체의 루트인 `'*'` 노드 인덱스 `3`을 반환한다. 두 호출이 반환하는 것은 서로 다른 항의 시작점이다.

9. `root = 1`, `size = 5`, `pos = 5`이다. 널 문자는 반복 조건에서 확인만 하므로 노드로 만들지 않는다.

10. 구조체 멤버 `nodes[3].right`는 오른쪽 자식의 인덱스 `4`이다. `eval_tree(4)`가 문자 `'3'`을 정수로 변환해 반환하므로 지역 변수 `right`는 `3`이다.

11. 숫자 문자를 확인한 첫 `if`에서 숫자 값을 `return`하고 그 호출을 끝내기 때문이다. 자식에 대한 두 재귀 호출까지 내려가지 않는다. `-1`이라는 인덱스에 접근해서 종료하는 방식이 아니다.

12. 앞 호출의 `node`는 계속 `1`이고 뒤 호출의 `node`는 별도로 `3`이다. 앞 호출의 `left`는 왼쪽 숫자의 결과 `1`을 보관하고, 뒤 호출의 `left`는 곱셈의 왼쪽 숫자 결과 `2`를 보관한다.

13. 저장된 문자는 각각 `'+'`와 `'*'`로 유지된다. 화면에는 `1+2*3 = 7`과 줄바꿈 한 개가 출력된다. 계산 결과는 반환 값과 지역 변수에 담기며 저장 문자를 덮어쓰지 않는다.

14. 조건부로 실행할 문장이 `return left + right;` 하나이므로 중괄호를 생략할 수 있다. 그다음 문장까지 같은 조건에 포함되는 것은 아니다.

15. 최종 루트는 인덱스 `3`의 두 번째 `'*'`이다. 왼쪽 자식은 이전 곱셈 트리의 루트 `1`, 오른쪽 자식은 문자 `'4'` 노드의 인덱스 `4`이다. 계산 결과는 `24`이다.

16. 수식 문자 뒤에 널 문자 한 개를 저장할 공간이 필요하기 때문이다. 길이 19인 유효한 수식은 숫자와 연산자 각각에 노드 하나씩, 총 19개를 사용한다.

17. `return 0;`은 프로그램의 정상 종료를 나타낸다. 정답을 출력하는 것은 `printf("%s = %d\n", eq, answer);`이며, 정답 값 자체는 `eval_tree`가 계산하여 `answer`에 반환한 것이다.

18. 아니다. `pos`는 이미 문자열 끝의 위치에 있고 `size`는 사용한 노드 수를 유지한다. 새 수식을 다시 만들려면 올바른 입력을 준비하고 읽기 위치와 사용 개수를 초기 상태로 되돌리는 처리가 필요하다. 배열을 재사용하면 이전 트리가 보존되는 것도 아니다.
