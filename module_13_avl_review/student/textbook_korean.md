## Thinking Logically

### 데이터를 바꾸지 않고 한 값을 어떻게 찾을까?

다음 순서로 값이 들어왔다. 17이 있는 첫 위치를 찾으려 한다. 같은 값이 두 번 있으므로 위치도 구분해야 한다.

```text
인덱스:  0   1   2  3   4   5
값:     31  23  17  8  17  42
```

앞에서부터 한 칸씩 읽고 처음 일치할 때 멈춘다. 1장에서 사용한 선형 탐색이다. 31, 23, 17을 비교하면 인덱스 2를 반환한다. 99를 찾으면 여섯 값을 모두 확인한 뒤 `-1`을 반환한다. 탐색은 입력 순서를 바꾸지 않는다. 빈 입력도 어떤 칸도 읽지 않고 `-1`을 반환한다.

### 한 번 비교해서 여러 위치를 제외하려면 무엇이 필요할까?

원래 배열에서 23을 보아도 17이 어느 쪽에 있는지 결정할 수 없다. 값의 순서에 규칙이 없기 때문이다. 왼쪽에서 오른쪽으로 값이 작아지지 않는다면 17보다 작은 값과 그 앞의 값은 모두 제외할 수 있다. 가운데 값을 비교해서 후보 구간을 줄이는 방법을 이진 탐색이라고 한다.

같은 여섯 값을 다음처럼 정리한다. 이웃한 두 값이 같아도 된다. 이 순서를 비감소 순서라고 한다.

```text
인덱스:  0   1   2   3   4   5
값:      8  17  17  23  31  42
```

후보를 `[lo, hi)`로 둔다. `lo`는 포함하고 `hi`는 포함하지 않는 반열린 구간이다. `lo` 앞의 값은 모두 찾는 값보다 작다. `hi`부터 뒤의 값은 모두 찾는 값 이상이다. 처음에는 `lo=0`, `hi=6`이므로 제외한 위치가 없다.

첫 17을 찾을 때 가운데 값과 비교한다. 같더라도 바로 반환하지 않고 왼쪽을 계속 확인한다. 더 이른 17이 있을 수 있기 때문이다.

| 비교 전 `lo`, `hi` | `mid` | 값 | 변경 |
| --- | ---: | ---: | --- |
| 0, 6 | 3 | 23 | `hi=3` |
| 0, 3 | 1 | 17 | `hi=1` |
| 0, 1 | 0 | 8 | `lo=1` |

`lo==hi==1`이면 인덱스 1이 존재하고 그 값이 17인지 확인한다. 1을 반환한다. 이 위치는 정렬한 배열의 위치다. 원래 배열의 첫 일치 위치는 2였다. 정렬하면 위치가 바뀐다. 배열 위치는 기록을 영구히 식별하는 이름이 아니다. 99를 찾을 때는 경계가 6에서 만나므로 `sorted[6]`을 읽지 않고 `-1`을 반환한다.

함수는 이미 정렬된 입력을 요구한다. 정렬 여부를 검사하거나 스스로 정렬하지 않는다. 가운데 위치는 `lo + (hi-lo)/2`로 계산한다. 두 큰 경계를 먼저 더하지 않기 위해서다. 현재 실습은 최대 64개 값으로 범위를 제한한다.

### 이미 정리한 앞부분을 어떻게 늘릴까?

이진 탐색을 하려면 먼저 값을 정리해야 한다. 기존 값을 보관하지 않고 새 값을 덮어쓰면 데이터를 잃는다. 앞부분을 정렬된 상태로 유지하면서 다음 값을 끼워 넣는다. 다음 값을 따로 보관하고 그보다 큰 앞의 값을 한 칸씩 오른쪽으로 옮긴 뒤 빈자리에 보관한 값을 쓴다. 삽입 정렬이다.

| 보관한 다음 값 | 삽입 후 배열 | 이번 오른쪽 이동 수 |
| ---: | --- | ---: |
| 23 | 23, 31, 17, 8, 17, 42 | 1 |
| 17 | 17, 23, 31, 8, 17, 42 | 2 |
| 8 | 8, 17, 23, 31, 17, 42 | 3 |
| 17 | 8, 17, 17, 23, 31, 42 | 2 |
| 42 | 8, 17, 17, 23, 31, 42 | 0 |

종이에서는 원래 인덱스 2의 17에 A, 인덱스 4의 17에 B를 붙일 수 있다. 반복문은 보관한 값보다 엄격히 큰 값만 이동한다. 따라서 17A가 17B보다 앞에 남는다. 같은 키를 가진 기록의 원래 상대 순서를 보존하는 성질을 안정성이라고 한다. 정수 출력만 보면 두 17의 정체가 드러나지 않는다. 결과에 같은 정수가 두 개 보인다고 안정성이 증명되지는 않는다.

### 긴 앞부분을 계속 옮기는 일을 어떻게 줄일까?

다음 값이 매번 앞쪽에 들어가면 삽입 정렬은 앞의 값을 여러 번 이동한다. 입력을 두 작은 구간으로 나누고 각각 정렬한 뒤 두 정렬 결과를 합칠 수 있다. 병합 정렬이다. 값이 없거나 하나인 구간은 이미 순서 조건을 만족한다.

같은 여섯 기록을 `[31,23,17A]`와 `[8,17B,42]`로 나눈다. 각각 재귀적으로 정렬하면 `[17A,23,31]`과 `[8,17B,42]`다. 두 구간의 아직 쓰지 않은 첫 값을 비교한다. 오른쪽의 8을 먼저 복사한다. 다음 두 값이 모두 17이면 왼쪽의 17A를 먼저 복사한다. 계속하면 `[8,17A,17B,23,31,42]`를 얻는다.

합친 값은 별도의 임시 배열에 쓴 뒤 해당 구간으로 복사해 돌려놓는다. 이 작업 공간이 스크래치 버퍼다. 모든 재귀 호출에서 같은 버퍼를 재사용한다. 호출자는 값 배열과 겹치지 않는 쓰기 가능한 정수 `n`칸을 제공한다. `malloc`이나 `free`는 호출하지 않는다. 작은 구간의 안정성과 같을 때 왼쪽을 먼저 선택하는 규칙이 함께 같은 기록의 순서를 지킨다.

### 앞에서 배운 구조 중 무엇을 고를까?

정렬 배열에서 빠르게 찾으려면 준비 작업이 필요하다. 짧은 배열을 한 번만 찾을 때는 정렬보다 한 번의 순차 확인이 적은 일을 할 수 있다. 바뀌지 않는 같은 자료를 여러 번 찾으면 준비 작업을 공유할 수 있다. 자료가 바뀌면 순서를 유지하거나 다시 정렬하는 일도 고려한다.

찾을 대상, 변경 빈도, 필요한 순서, 사용할 저장 공간을 먼저 적는다. 그다음 방법을 고른다.

| 요청 | 후보 | 확인할 이유 |
| --- | --- | --- |
| 짧은 정렬 전 자료에서 한 번 찾기 | 선형 탐색 | 정렬이나 별도 인덱스 준비가 없다 |
| 바뀌지 않는 정렬 자료에서 여러 번 찾기 | 이진 탐색 | 가운데 배열 위치에 직접 접근한다 |
| 이미 아는 선행 노드 뒤에서 삽입·삭제 | 연결 노드 | 값을 밀지 않고 지역 연결을 바꾼다 |
| 적절히 분산된 키로 정확히 일치하는 항목 찾기 | 해시 버킷 | 선택한 연결만 확인하되 충돌과 용량을 고려한다 |
| 갱신하면서 키 순서 유지하기 | AVL 트리 | 균형으로 탐색·갱신 경로를 짧게 유지한다 |
| 대기 항목의 최솟값을 계속 선택하기 | 최소 힙 | 루트는 최솟값을 알려 주지만 임의 키를 바로 찾지는 못한다 |
| 그래프 대기 작업을 도착 순서나 비용 순서로 처리하기 | BFS 큐 또는 Dijkstra 힙 | 그래프에서 묻는 문제에 맞는 선택 규칙을 쓴다 |

연결 리스트의 값을 정렬해도 배열의 이진 탐색 비용을 그대로 얻지는 못한다. 가운데로 이동하려면 연결을 따라가는 일이 필요하다. 힙도 정렬 배열이 아니다. 모든 작은 값이 모든 큰 값의 왼쪽에 놓이지 않는다. 관계를 따라 처리하는 순회와 정확한 키를 찾는 탐색은 다른 요청이다.

14장에서는 그래프 간선을 가중치가 작은 순서로 확인한다. 이 장은 그 준비 비용과 같은 가중치의 순서를 정하는 이유를 설명한다. 14장의 간선 정렬 코드는 계속 제공한다. 간선을 연결할지 결정하는 새 규칙은 14장에서 배운다.

## Calculating Efficiency

### 여섯 값에서는 실제로 몇 번 일할까?

원래 배열에서 17을 찾는 선형 탐색은 세 값을 비교한다. 정렬 뒤의 이진 탐색 표는 구간 결정 세 번과 마지막 일치 검사 한 번을 한다. 이 작은 사례에서는 세 번 비교하는 선형 탐색보다 적지 않다. 원래 배열에서 없는 값을 찾으면 여섯 값을 모두 비교한다. 준비 작업과 질의 작업을 나누어 센다.

삽입 정렬은 공통 입력에서 오른쪽 이동을 여덟 번 한다. 다섯 단계에서 보관한 키를 마지막 빈자리에 쓰는 일도 한다. 실제로 도달한 실패 비교도 포함하면 값 비교는 열 번이다. 위치의 범위 검사는 따로 센다. 이미 정렬된 입력에는 이동이 없다. 반대 순서는 `1+2+...+(n-1)`번 이동할 수 있으므로 최악의 일은 `O(n^2)`로 커진다. 최선은 `O(n)`이고 추가 지역 저장 공간은 `O(1)`이다.

### 반씩 줄이면 증가 양상이 왜 바뀔까?

이진 탐색은 한 번 결정할 때 후보 위치를 대략 절반 이하로 줄인다. 반복해서 반으로 나누는 결정 수는 `O(log(n+1))`이다. 마지막 범위·일치 검사는 고정된 일이다. 경계 인덱스 몇 개만 저장하므로 추가 공간은 `O(1)`이다. 선형 탐색은 `n`칸을 모두 확인할 수 있으므로 일은 `O(n)`, 추가 공간은 `O(1)`이다.

병합 정렬은 값이 하나 이하일 때까지 구간을 나눈다. 병합의 한 층 전체에서 `n`에 비례하는 값을 복사한다. 나누는 층수는 로그로 증가한다. `n>=2`에서 정렬 작업은 `O(n log n)`이다. 재사용 버퍼는 정수 `n`칸, 활성 재귀 호출은 `O(log n)`개이므로 추가 공간은 `O(n)`이다. 빈 입력과 한 값 입력은 고정된 일만 하고 원소를 읽거나 버퍼에 쓰지 않는다.

### 준비와 갱신 비용을 함께 보면 선택이 어떻게 달라질까?

바뀌지 않는 자료를 `q`번 찾으면 선형 탐색은 `O(q*n)`의 일을 할 수 있다. 한 번 병합 정렬한 뒤 이진 탐색하면 `n>=2`에서 `O(n log n + q log(n+1))`이다. 실제 상수, 일찍 찾는 경우, 갱신 작업도 판단에 필요하다. 배열 삽입은 `O(n)`개의 값을 밀 수 있다. 정렬이 언제나 이득이라고 말하지 않는다.

균형을 유지한 AVL 트리의 일반화한 탐색·갱신은 `O(log(n+1))`이다. 버킷 `b`개인 해시 테이블은 적절한 분산 아래 예상 연결 탐색이 `O(1+n/b)`, 최악은 `O(n)`이다. 최소 힙의 최솟값 확인은 `O(1)`, 삭제는 `O(log n)`이고 임의 키 탐색은 `O(n)`일 수 있다. 이는 일반화한 작업 비교다. 앞 장의 고정 용량 실습에는 각각의 용량과 입력 조건이 남는다.

## Coding Plan

앞에서 추적한 동작 순서로 구현을 읽는다. 함수는 완성된 상태로 제공하므로 수업에서는 예측, 검사, 방법 선택에 집중한다.

1. 0번부터 확인해 첫 일치 위치를 반환한다. 없으면 `-1`을 반환한다.
2. 안전한 가운데 계산으로 `[lo,hi)`를 좁힌다. 같을 때 왼쪽을 남긴다. 닫힌 경계가 실제 위치인지 확인한 뒤 읽는다.
3. 삽입 키를 보관하고 엄격히 큰 값만 이동한 뒤 빈자리를 채운다.
4. 반열린 구간을 재귀적으로 나눈다. 겹치지 않는 버퍼로 병합하고 같으면 왼쪽을 먼저 고른다. 결과를 원래 구간으로 복사한다.
5. 정렬 전 탐색에 쓸 원본과 두 정렬에 쓸 독립 복사본을 보관한다.
6. 중복의 첫 위치, 실패, 빈 입력과 한 값, 부호 있는 극값, 경계, 반복 호출을 확인한다. 독립 기준 결과와 정렬을 비교하고 같은 키의 표식 추적도 남긴다.

## C Code

다음은 현재 `lab.c` 전체다. 모든 공개 함수는 `0<=n<=SEARCH_SORT_CAPACITY`인 64개 이하의 입력을 요구한다. `n>0`이면 정수 `n`개에 접근할 수 있어야 한다. 탐색은 입력을 바꾸지 않는다. `binary_search_first`는 비감소 입력을 요구한다. 정렬은 처음 `n`개의 값만 바꾼다. `merge_sort`는 값 배열과 겹치지 않는 쓰기 가능한 정수 `n`칸의 별도 버퍼를 요구한다. 함수는 이 조건을 가정하며 잘못된 입력의 상태 코드를 반환하지 않는다. `n==0`이면 배열 위치를 읽거나 쓰지 않으므로 널 포인터도 전달할 수 있다.

```c
#ifndef MODULE_13_SEARCH_SORT_LAB_C
#define MODULE_13_SEARCH_SORT_LAB_C

#define SEARCH_SORT_CAPACITY 64

int linear_search(const int values[], int n, int key) {
    for (int i = 0; i < n; ++i) {
        if (values[i] == key) return i;
    }
    return -1;
}

int binary_search_first(const int sorted[], int n, int key) {
    int lo = 0;
    int hi = n;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (sorted[mid] < key) lo = mid + 1;
        else hi = mid;
    }
    if (lo < n && sorted[lo] == key) return lo;
    return -1;
}

void insertion_sort(int values[], int n) {
    for (int i = 1; i < n; ++i) {
        int key = values[i];
        int pos = i;
        while (pos > 0 && values[pos - 1] > key) {
            values[pos] = values[pos - 1];
            --pos;
        }
        values[pos] = key;
    }
}

static void merge_range(int values[], int scratch[], int lo, int hi) {
    if (hi - lo <= 1) return;
    int mid = lo + (hi - lo) / 2;
    merge_range(values, scratch, lo, mid);
    merge_range(values, scratch, mid, hi);
    int left = lo;
    int right = mid;
    int out = lo;
    while (left < mid && right < hi) {
        if (values[left] <= values[right]) scratch[out++] = values[left++];
        else scratch[out++] = values[right++];
    }
    while (left < mid) scratch[out++] = values[left++];
    while (right < hi) scratch[out++] = values[right++];
    for (int i = lo; i < hi; ++i) values[i] = scratch[i];
}

void merge_sort(int values[], int scratch[], int n) {
    merge_range(values, scratch, 0, n);
}

#endif
```

다음 완전한 호출자는 같은 여섯 값을 쓴다. `lab.c`를 포함하므로 이 드라이버만 컴파일한다.

```c
#include <assert.h>
#include <stdio.h>
#include "lab.c"

int main(void) {
    int values[] = {31, 23, 17, 8, 17, 42};
    int insertion[] = {31, 23, 17, 8, 17, 42};
    int scratch[6];
    assert(linear_search(values, 6, 17) == 2);
    printf("Original first index of 17: %d\n", linear_search(values, 6, 17));
    insertion_sort(insertion, 6);
    merge_sort(values, scratch, 6);
    const int expected[] = {8, 17, 17, 23, 31, 42};
    printf("Sorted:");
    for (int i = 0; i < 6; ++i) {
        assert(values[i] == expected[i] && insertion[i] == expected[i]);
        printf(" %d", values[i]);
    }
    printf("\nSorted first index of 17: %d\n", binary_search_first(values, 6, 17));
    assert(binary_search_first(values, 6, 17) == 1);
    assert(binary_search_first(values, 6, 99) == -1);
    puts("PASS: canonical searches and both sorts");
    return 0;
}
```
