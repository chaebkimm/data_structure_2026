# 13장. 왼쪽으로 기우는 레드-블랙 트리

## 논리적으로 생각해 보기

### 검색 방법을 유지하면서 경로를 줄일 수 있을까?

빈 이진 검색 트리에 10, 20, 30, 40, 50, 60, 70을 차례로 넣자. 10 다음부터는 새 키가 매번 오른쪽 자식이 된다. 70을 찾으려면 노드 일곱 개를 방문한다. 각 노드에 키 하나를 저장하고, 작은 값은 왼쪽에서 큰 값은 오른쪽에서 찾는 규칙을 그대로 써 보자. 삽입을 마칠 때 트리의 모양을 어떻게 바꾸면 좋을까?

### 빨간 왼쪽 링크는 2–3–4 트리에서 무엇을 나타낼까?

10과 20을 한 묶음에 담아 보자. 20의 왼쪽 자식으로 10을 두고 둘 사이의 링크를 빨갛게 표시한다. 빨간 링크로 연결된 두 키를 묶어 읽으면 `[10 | 20]`이다. 검은 링크를 지나면 다른 묶음으로 이동한다. 이진 트리에서 10을 찾을 때는 여전히 20을 먼저 방문하고 왼쪽의 10으로 내려간다.

10, 20, 30을 차례로 넣으면서 세 장면을 보자. R과 B는 해당 키로 들어오는 링크의 색이다. root는 B로 표시한다.

```text
10을 넣은 뒤           20을 넣고 회전한 뒤       30을 붙이고 색을 뒤집기 직전

      10B                    20B                       20B
                            /                         /   \
                          10R                       10R   30R

     [10]                [10 | 20]               [10 | 20 | 30]
     2-노드                 3-노드                    4-노드
```

**2–3–4 트리**에서 노드 이름의 숫자는 내부 노드의 자식 구간 수다. 키가 하나면 구간이 둘, 키가 둘이면 구간이 셋, 키가 셋이면 구간이 넷이다. `[10 | 20 | 30]`의 자식 구간은 10 미만, 10과 20 사이, 20과 30 사이, 30 초과다. 잎에서는 이 자리가 비어 있다.

2–3–4 트리는 4-노드를 그대로 둘 수 있다. 이 장의 코드는 삽입 후 아래에서 위로 돌아오면서 두 자식 링크가 모두 빨간 노드를 만나면 곧바로 나눈다. 색을 뒤집고 root를 검게 바꾸면 `[20]` 아래에 `[10]`과 `[30]`이 각각 자식으로 놓인다. 따라서 삽입이 끝난 이진 트리를 묶어 읽으면 2-노드와 3-노드만 남는다.

이 장에서 이진 표현과 이 삽입 규칙을 함께 쓰는 트리가 **왼쪽으로 기우는 레드-블랙 트리(left-leaning red–black tree, LLRB)**다. 삽입을 마치면 root는 검은색이고 빨간 링크는 모두 왼쪽을 향한다. 한 경로에서 빨간 링크가 두 번 연속 나오지 않는다. root에서 자식이 없는 자리까지 어느 경로를 따라가도 검은 노드의 수는 같다. 이 장에서는 이 수를 **검은 높이(black height)**라고 한다. 검은 root는 세고, 자식이 없는 자리는 0개로 센다. 링크 색을 검사할 때 빈 링크는 검은색으로 취급한다.

### 두 번째 키가 오른쪽에 들어가면 어떻게 할까?

10 다음에 20을 넣자. 새 자식은 빨간 링크로 붙인다. 이때 경로의 검은 노드 수는 늘지 않는다. 새 링크가 오른쪽을 향하므로 20을 올리고 10을 그 왼쪽에 둔다. 20은 원래 root의 색을 이어받는다. 이 동작이 **왼쪽 회전(left rotation)**이다. 키 순서는 그대로다. 회전 뒤의 빨간 왼쪽 링크가 3-노드 `[10 | 20]`을 나타낸다.

```text
회전 전                  10에서 왼쪽 회전한 뒤

   10B                          20B
      \                        /
      20R                    10R
```

20에서 빈 오른쪽 자식까지 가는 경로에는 검은 키가 하나 있다. 왼쪽의 10을 거쳐 빈 자식까지 가는 경로에서도 검은 키는 하나다. 두 경로의 길이는 달라도 검은 노드의 수는 같다.

### 왼쪽에 키가 두 번 연속 들어가면 어떻게 할까?

빈 트리에 30, 20, 10을 넣자. 20까지 넣으면 빨간 링크 하나가 왼쪽을 향한다. 10을 넣는 순간 빨간 링크 두 개가 연속으로 나타난다. **오른쪽 회전(right rotation)**으로 20을 올린다. 20은 30의 색을 이어받고, 30은 20의 빨간 오른쪽 자식이 된다. 이제 20의 두 자식이 모두 빨갛다. **색 뒤집기(color flip)**로 두 자식을 검게 바꾸고 20을 빨갛게 바꾼다. 삽입의 마지막에는 root를 검게 바꾼다.

```text
10을 붙인 직후            30에서 오른쪽 회전       20에서 색을 뒤집고 root를 검게

       30B                      20B                         20B
       /                       /   \                       /   \
     20R                     10R   30R                   10B   30B
     /
   10R
```

가운데 그림의 빨간 링크 두 개를 묶어 읽으면 4-노드 `[10 | 20 | 30]`이다. 색을 뒤집으면 양 끝의 키가 각각 별도의 묶음이 된다. 가운데 키로 들어오는 링크가 빨갛게 바뀌므로 부모가 있으면 가운데 키는 부모의 묶음에 속하게 된다. 여기서는 20이 root이므로 마지막에 20을 검게 바꾸면 검은 층이 하나 생긴다. 색을 뒤집는 동안 자식 인덱스는 그대로다.

### 회전할 때 두 키 사이의 부분 트리는 어디로 갈까?

다시 작은 순서로 넣어 보자. 40까지 넣으면 root는 20B, 그 오른쪽 자식은 40B, 40의 왼쪽 자식은 30R이다. 50을 40의 오른쪽에 붙인다. 40에서 색을 뒤집은 뒤 20에서 왼쪽으로 회전한다. 회전하는 동안 30을 따라가 보자.

```text
40에서 색을 뒤집은 뒤           20에서 왼쪽 회전한 뒤

       20B                             40B
      /   \                          /    \
    10B   40R                      20R    50B
          / \                     /   \
        30B 50B                 10B   30B
```

30은 40의 왼쪽 자식이었다. 20 < 30 < 40이므로 회전 뒤에는 20의 오른쪽 자식이 된다. 30을 찾으면 40, 20, 30을 방문한다. 35를 찾아도 같은 노드를 거친 뒤 30의 오른쪽 빈 링크에서 끝난다.

### 색 변화는 어디까지 이어질까?

60을 넣으면 50에서 오른쪽으로 빨간 링크가 생긴다. 50에서 왼쪽으로 회전하면 60의 왼쪽 자식이 50R이 된다. 70을 넣으면 60의 두 자식이 모두 빨갛다. 60에서 색을 뒤집는다. 부모인 40의 왼쪽 자식 20은 이미 빨갛다. 이제 40에서도 색을 뒤집고 root를 검게 바꾼다. 키 일곱 개가 모두 검게 된다. 이번 삽입으로 검은 높이는 2에서 3이 된다. 가장 긴 이진 경로의 간선 수는 여전히 2다.

## 효율 계산해 보기

### 검색 경로가 짧게 유지되는 이유는 무엇일까?

완성된 트리에서 70을 찾으면 40, 60, 70을 방문한다. 같은 입력으로 만든 보통 이진 검색 트리에서는 일곱 노드를 방문했다. 두 검색 모두 키 비교와 자식 링크만 사용한다.

삽입이 끝난 그림에서 빨간 링크로 연결된 키를 묶자. 한 묶음에는 키가 하나 또는 둘이다. 내부에 있는 묶음에는 자식 묶음이 적어도 둘이다. 검은 층이 b개이면 키가 적어도 2^b − 1개 필요하다. 키가 n개일 때 b는 최대 log₂(n + 1)이다. 한 경로에서 한 묶음을 통과할 때 이진 노드를 최대 두 개 방문하므로 전체 방문 수는 최대 2b다. 삽입도 한 경로를 따라가고 각 호출에서 돌아올 때 일정한 횟수의 검사와 복구만 한다. 검색과 삽입의 최악 시간은 O(log(n + 1))이다. 재귀 삽입에 쓰이는 호출 스택 공간은 O(log(n + 1))이다.

## 용어 정리

| 용어 | 뜻 |
|---|---|
| 빨간 링크 | 부모의 키와 자식의 키가 같은 2–3–4 노드에 속한다는 표시 |
| 검은 높이 | 이 장에서 root부터 빈 자식까지 한 경로에 있는 검은 키의 수 |
| 왼쪽 회전 | 오른쪽 자식을 올리고 그 자식의 왼쪽 부분 트리를 기존 root의 오른쪽에 연결하는 동작 |
| 오른쪽 회전 | 왼쪽 자식을 올리고 그 자식의 오른쪽 부분 트리를 기존 root의 왼쪽에 연결하는 동작 |
| 색 뒤집기 | 삽입 중 두 빨간 자식을 검게, 검은 부모를 빨갛게 바꾸는 동작 |

## 코딩 계획

1. 이진 검색 트리의 키 비교 규칙으로 내려간다. 링크가 빈 자리에 빨간 노드를 붙인다.
2. 자식 호출에서 돌아올 때 오른쪽 링크만 빨갛다면 왼쪽으로 회전한다.
3. 회전 결과에서 왼쪽 링크와 그다음 왼쪽 링크가 모두 빨갛다면 오른쪽으로 회전한다.
4. 그 결과에서 두 자식의 링크가 모두 빨갛다면 색을 뒤집는다. 현재 부분 트리의 root를 반환한다. 마지막에 반환된 root를 저장하고 검게 바꾼다.

## C 코드

[노드 구조체](../code/llrb.h)의 `left`와 `right`는 자식 인덱스다. 빈 자식은 `NO_NODE`로 표시한다. 자식의 `red` 필드가 부모에서 들어오는 링크의 색을 저장한다. [insert_at 함수](../code/llrb.c)의 첫 번째 복구 조건을 보자.

```c
if (is_red(tree, node->right) && !is_red(tree, node->left)) {
    id = rotate_left(tree, id);
    node = &tree->nodes[id];
}
```

회전이 반환한 인덱스는 부분 트리의 새 root다. 50을 넣을 때 이 값을 저장해야 40이 있던 자리를 새 root로 삼을 수 있다. 이어지는 두 조건은 갱신된 노드에서 순서대로 각각 검사한다. 오른쪽 회전 직후에도 색 뒤집기가 필요할 수 있다.

예제는 서로 다른 정수 키를 최대 64개 저장한다. 중복 키를 넣거나 트리가 가득 찬 경우에는 집합을 그대로 두고 `false`를 반환한다. [실습](lab.md)에서 두 입력 순서의 링크, 색, 검색 경로를 확인한다.
