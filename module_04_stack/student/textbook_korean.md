# 제4장. 마지막에 추가한 값부터 삭제하기

남아 있는 데이터 중 가장 나중에 추가한 데이터만 확인하거나 삭제하도록 저장한다. 그 규칙으로 수식의 연산을 언제 수행할지 정한다.

## 논리적으로 생각해 보기

### 왜 특별한 순서가 필요할까?

접시 세 개를 쌓아 보자. 맨 위의 접시를 꺼내려면 가장 나중에 놓은 접시부터 꺼낸다. 먼저 놓은 접시들은 제자리에 남는다. 리스트에 접시의 이름을 저장할 수는 있다. 하지만 아무 위치에서나 삭제하도록 허용하면 이 규칙을 나타내지 못한다.

한쪽 끝에서만 데이터를 추가하고 확인하고 삭제해야 한다. 남아 있는 데이터 중 나중에 추가한 것을 먼저 삭제하는 규칙을 후입선출(LIFO)이라고 한다. 이 규칙을 따르는 자료 구조가 스택(stack)이다. 접근할 수 있는 끝이 마지막 데이터 위치인 `top`이다. 데이터를 넣는 연산은 추가(push), 마지막 데이터를 읽는 연산은 확인(peek), 마지막 데이터를 꺼내는 연산은 삭제(pop)다.

### 배열로 이 순서를 어떻게 유지할까?

리스트의 데이터를 배열의 연속된 칸에 저장하는 방법을 이미 배웠다. 스택의 데이터도 인덱스 0부터 같은 방식으로 저장한다. 마지막으로 사용 중인 칸의 인덱스를 `top`에 기록한다.

빈 스택에는 사용 중인 마지막 칸이 없으므로 `top`을 -1로 시작한다. `'A'`, `'B'`, `'C'`를 추가하면 인덱스 0, 1, 2에 각각 저장된다. 마지막 인덱스는 2다. 데이터 개수는 `top + 1`이므로 3이다. 인덱스와 개수는 다르다.

### 데이터를 어떻게 추가하고 확인하고 삭제할까?

추가할 때는 `top`을 먼저 늘리고 새 인덱스에 값을 쓴다. 가장 나중에 추가한 데이터를 확인할 때는 `stack[top]`을 읽는다. 삭제할 때는 현재 칸을 읽은 뒤 `top`을 줄인다. 앞선 칸들은 이동하지 않는다.

| 동작 | 사용 중인 데이터, 아래부터 위로 | `top` | 데이터 개수 | 반환값 |
|---|---|---:|---:|---|
| 시작 | 없음 | -1 | 0 | — |
| `push('A')` | A | 0 | 1 | — |
| `push('B')` | A, B | 1 | 2 | — |
| `push('C')` | A, B, C | 2 | 3 | — |
| `peek()` | A, B, C | 2 | 3 | `'C'` |
| `pop()` | A, B | 1 | 2 | `'C'` |

`'C'`를 삭제해도 이전 칸의 내용은 지우지 않는다. 사용 중인 배열 구간이 이제 인덱스 1에서 끝난다. 나중의 추가가 인덱스 2를 덮어쓸 수 있다.

### 경계에서는 어떤 일이 생길까?

배열 칸 열 개에는 데이터 열 개를 저장할 수 있다. `top == 9`이면 `top + 1 == capacity`이므로 가득 찬 상태다. `top == -1`이면 빈 상태다.

가득 찬 스택에 추가하는 것이 오버플로(overflow)다. 빈 스택에서 확인하거나 삭제하는 것이 언더플로(underflow)다. 실습의 `is_full`과 `is_empty`는 그 상태를 알려 준다. 하지만 추가, 확인, 삭제 함수가 이 검사를 자동으로 호출하지는 않는다. 가득 찬 상태에서 추가하면 인덱스 10에 쓰려고 한다. 빈 상태에서 확인하거나 삭제하면 인덱스 -1을 읽으려고 한다. 두 위치 모두 배열 밖이다. 정해진 실패 결과나 이전 상태의 보존을 보장하지 않는다.

유지할 규칙은 `-1 <= top < capacity`이며 사용 중인 데이터는 인덱스 0부터 `top`까지다. 이것이 스택의 불변식(invariant)이다. 스택 연산으로는 사용 중인 마지막 데이터에만 접근한다.

### 함수 호출과는 어떤 관계가 있을까?

함수가 다른 함수를 호출하면 새 호출이 끝난 뒤 이전 호출을 이어 가야 한다. 중첩된 함수 호출도 나중에 시작한 호출부터 끝나는 순서를 따른다. 한 호출을 이어 가는 데 필요한 정보를 호출 프레임(call frame)이라고 한다. 이 비교는 순서를 설명한다. 실습의 정수 배열 자체가 프로그램 실행에 쓰이는 호출 스택은 아니다.

### 수식의 연산자는 언제 계산해야 할까?

`1-2*3+4`를 보자. 연산자가 나타나자마자 계산하면 곱셈을 준비하기 전에 뺄셈을 하게 된다. 곱셈의 우선순위(precedence)가 더 높으므로 `2*3`을 먼저 계산해야 한다. 뺄셈과 덧셈은 우선순위가 같으므로 왼쪽부터 처리한다. 이 규칙이 좌측결합(left associativity)이다.

묶이는 순서를 괄호로 표시하면 `((1-(2*3))+4)`다. 닫는 괄호는 아직 끝나지 않은 묶음 중 가장 최근에 연 묶음을 끝낸다. 이 순서에도 스택을 사용할 수 있다.

### 스택 두 개로 수식을 어떻게 직접 계산할까?

기다리는 연산자와 숫자를 나누어 저장한다. 입력은 왼쪽부터 읽는다. 숫자가 나오면 저장한다. 새 연산자를 저장하기 전에 우선순위가 새 연산자 이상인 대기 연산자를 처리한다. 연산 하나를 처리할 때는 연산자를 삭제한다. 오른쪽 숫자와 왼쪽 숫자를 차례로 삭제한다. 계산한 결과를 저장한다.

`1-2*3+4`에서 `*`가 나오면 `-`는 기다린다. `+`가 나오면 `2*3`을 계산해 6을 얻고, `1-6`을 계산해 -5를 얻는다. `+`를 저장하고 4를 읽은 뒤 `-5+4`를 계산해 -1을 얻는다. 직접 계산하는 방법에서 다음에 사용할 순서가 나온다. 실습은 변환과 계산을 두 단계로 나누고 전역 스택 하나를 다시 사용한다.

### 연산자를 필요한 값 뒤에 쓰면 어떨까?

연산자는 보통 연산에 쓰이는 값인 피연산자(operand) 사이에 놓인다. 이 순서가 중위 표기(infix notation)다. 연산자를 두 피연산자 뒤에 쓸 수도 있다. 이 순서는 후위 표기(postfix notation)다.

숫자는 읽을 때 쓴다. 기다리는 연산자는 두 스택으로 직접 계산할 때 계산을 수행했을 위치에 쓴다. 그러면 `1-2*3+4`가 `123*-4+`로 바뀐다. `*`는 2와 3 뒤에 놓인다. `-`는 1과 곱셈 결과 뒤에 놓인다. 마지막 `+`는 뺄셈 결과와 4 뒤에 놓인다.

### 계산하지 않고 그 순서를 어떻게 만들까?

스택에는 기다리는 연산자만 저장한다. 숫자는 출력에 바로 복사한다. 새 연산자를 추가하기 전에 스택이 비어 있지 않은 동안 대기 연산자를 확인한다. 마지막 연산자의 우선순위가 더 낮으면 멈춘다. 그렇지 않으면 삭제하고 출력에 복사한다. 우선순위가 같을 때도 이전 연산자를 먼저 삭제하므로 좌측결합이 유지된다.

코드는 마지막 데이터를 읽기 전에 스택이 비었는지 검사한다. 입력을 모두 읽으면 남은 연산자를 삭제해 출력에 쓴다. 그 뒤 널 문자 `'\0'`을 출력 문자 바로 다음에 직접 써서 문자열을 끝낸다.

표에는 지금까지 쓴 문자만 표시한다. 중간 출력은 널 종료 문자열이라는 보장이 없다. 출력 버퍼를 다시 사용할 때도 마찬가지다.

| 입력 또는 동작 | 지금까지 출력한 문자 | 연산자 스택, 아래부터 위로 | `top` |
|---|---|---|---:|
| 시작 | 없음 | 없음 | -1 |
| `1` | `1` | 없음 | -1 |
| `-` | `1` | `-` | 0 |
| `2` | `12` | `-` | 0 |
| `*` | `12` | `-`, `*` | 1 |
| `3` | `123` | `-`, `*` | 1 |
| `+`: `*` 삭제, `-` 삭제, `+` 추가 | `123*-` | `+` | 0 |
| `4` | `123*-4` | `+` | 0 |
| `+`를 삭제해 출력 | `123*-4+` | 없음 | -1 |
| `'\0'` 쓰기 | `123*-4+` 뒤에 `'\0'` | 없음 | -1 |

괄호가 없을 때는 대기 연산자들이 아래에서 위로 갈수록 반드시 높은 우선순위를 갖는다. 새 연산자를 추가하기 전에 우선순위가 같거나 더 높은 이전 연산자를 삭제하기 때문이다.

### 바뀐 수식은 어떻게 계산할까?

출력을 왼쪽부터 읽는다. 숫자 문자를 정수로 바꾸어 추가한다. 연산자가 나오면 오른쪽 피연산자를 먼저 삭제하고 왼쪽 피연산자를 삭제한다. 두 값으로 계산한 결과를 추가한다.

| 입력 | 동작 | 사용 중인 정수 값, 아래부터 위로 | `top` |
|---|---|---|---:|
| 시작 | 스택 초기화 | 없음 | -1 |
| `1` | 1 추가 | 1 | 0 |
| `2` | 2 추가 | 1, 2 | 1 |
| `3` | 3 추가 | 1, 2, 3 | 2 |
| `*` | `2 * 3 = 6` | 1, 6 | 1 |
| `-` | `1 - 6 = -5` | -5 | 0 |
| `4` | 4 추가 | -5, 4 | 1 |
| `+` | `-5 + 4 = -1` | -1 | 0 |
| 마지막 값을 삭제해 반환 | -1 반환 | 없음 | -1 |

저장된 각 값은 나중의 연산이 사용할 수 있는 완성된 부분 수식의 결과다. 올바른 후위 표기에서 연산자를 읽는 시점에는 마지막 두 값이 그 연산자의 피연산자다. 입력의 모든 앞선 시점에 성립하는 규칙은 아니다. 아직 읽지 않은 피연산자가 있을 수 있다.

### 괄호가 있으면 변환이 어떻게 달라질까?

묶음 안의 계산은 바깥 연산보다 먼저 끝나야 한다. 두 번째 변환 함수는 이 경계를 직접 처리한다. `eq_paren`에서 `1+(2+3)`을 읽는다.

`(`가 나오면 추가한다. 우선순위가 0이므로 일반 산술 연산자의 비교는 그 경계에서 멈춘다. `)`가 나오면 스택이 비어 있지 않은 동안 데이터를 하나씩 삭제한다. 삭제한 데이터가 `(`이면 출력에 복사하지 않고 멈춘다. 그렇지 않으면 삭제한 연산자를 출력에 복사한다. 올바른 후위 표기 결과에는 두 괄호 모두 나타나지 않는다. 변환은 연산자를 쓰는 단계이며 계산하는 단계가 아니다.

| 입력 또는 동작 | 지금까지 출력한 문자 | 연산자 스택, 아래부터 위로 | `top` |
|---|---|---|---:|
| 시작 | 없음 | 없음 | -1 |
| `1` | `1` | 없음 | -1 |
| `+` | `1` | `+` | 0 |
| `(` | `1` | `+`, `(` | 1 |
| `2` | `12` | `+`, `(` | 1 |
| `+` | `12` | `+`, `(`, `+` | 2 |
| `3` | `123` | `+`, `(`, `+` | 2 |
| `)`: `+` 삭제 후 출력, `(` 삭제 후 버리기 | `123+` | `+` | 0 |
| `+`를 삭제해 출력 | `123++` | 없음 | -1 |
| `'\0'` 쓰기 | `123++` 뒤에 `'\0'` | 없음 | -1 |

출력은 `123++`다. 같은 계산 함수가 `2+3`을 먼저 계산하고 `1+5`를 계산해 6을 반환한다. 대기 중인 산술 연산자의 우선순위는 `(`로 나뉜 각 구간 안에서만 증가한다. 괄호 경계를 넘어서는 증가 순서를 보장하지 않는다.

### 제공된 코드에는 어떤 입력을 사용할까?

각 버퍼는 문자 여덟 개를 저장한다. 입력 또는 출력 문자 최대 일곱 개와 `'\0'` 하나를 넣을 수 있다. 반복문은 널 문자에서 멈추므로 더 짧은 올바른 수식도 사용할 수 있다. 예를 들어 `2+3`은 `23+`로 바뀌고 계산 결과는 5다. 한 자리 숫자 하나도 올바른 수식이다. 빈 수식은 계산에 사용할 수 없다.

한 자리 숫자와 두 피연산자를 쓰는 연산자 `+`, `-`, `*`, `/`, `%`를 사용한다. 공백, 여러 자리 피연산자, 단항 부호는 넣지 않는다. 계산 중에 얻는 음수 정수 결과는 사용할 수 있다. `convert_to_postfix`는 괄호 없는 수식을 받는다. 짝이 맞는 괄호는 `infix_to_postfix_parentheses`만 처리한다. 이 함수의 입력 길이 제한인 일곱 문자에는 괄호도 포함된다. 출력에서는 괄호가 빠진다.

코드는 올바른 문법, 충분한 스택과 출력 공간, 널 종료 입력을 가정한다. 각 연산자에는 피연산자가 두 개 있어야 한다. 계산을 마치면 결과가 정확히 하나 남아야 한다. 나눗셈과 나머지 연산의 오른쪽 피연산자는 0이 아니어야 한다. 나눗셈과 나머지 연산에 필요한 몫을 포함해 모든 정수 연산은 자료형으로 표현 가능해야 한다. 코드는 이 조건을 검사하지 않는다. 괄호 변환 함수는 삭제할 때마다 빈 스택인지 검사한다. 하지만 짝이 없는 닫는 괄호를 보고하지는 않는다. 짝을 찾지 못한 채 연산자를 비우고 닫는 괄호를 버릴 수 있다. 짝이 없는 여는 괄호는 출력에 복사될 수 있다. 이런 동작은 수식의 유효성을 검증한 것이 아니다.

## 효율 계산해보기

### 스택 연산 한 번에는 얼마나 많은 작업이 필요할까?

추가는 인덱스 하나를 늘리고 칸 하나에 쓴다. 확인은 칸 하나를 읽는다. 삭제는 칸 하나를 읽고 인덱스 하나를 줄인다. 각 경계 검사도 정해진 횟수의 산술 연산과 비교를 수행한다. 기존 데이터는 이동하지 않는다. 따라서 각 연산은 상수 시간인 `O(1)`이 걸린다.

### 반복문 안의 반복문은 모든 일을 되풀이할까?

`1-2*3+4`를 변환할 때는 문자 일곱 개를 읽는다. 연산자 세 개는 각각 한 번 추가하고 한 번 삭제한다. 따라서 추가 세 번과 삭제 세 번을 수행한다. 마지막 널 문자는 출력에 한 번 쓰며 스택 연산은 사용하지 않는다. 새 연산자 하나가 이전 연산자 여러 개를 삭제하게 만들 수 있다. 하지만 이미 삭제한 연산자를 다시 삭제하지는 않는다.

입력이 `n`개 문자이면 읽기, 추가, 삭제의 전체 횟수는 `n`에 비례해 늘어난다. 변환 시간은 `O(n)`이다. 괄호를 처리하는 함수에서도 각 `(`를 한 번 추가하고 한 번 삭제한다. `1+(2+3)`에서는 연산자 두 개와 여는 괄호 하나에 추가 세 번과 삭제 세 번을 사용한다. 같은 시간 한계가 적용된다.

`123*-4+`를 계산할 때는 원래 숫자 네 개를 추가하고 연산 세 개를 계산한 뒤 결과 하나를 반환한다. 각 계산은 삭제 두 번과 추가 한 번을 사용한다. 마지막 답의 삭제까지 포함하면 이 예제는 추가 일곱 번과 삭제 일곱 번을 수행한다. 후위 표기 문자가 `m`개이면 계산 시간은 `O(m)`이다. `1+(2+3)`에서는 괄호가 사라지므로 입력 문자 일곱 개가 후위 표기 문자 다섯 개가 된다.

### 공간은 얼마나 확보하고 사용할까?

실습은 `stack`에 정수 열 개의 공간을 확보한다. `eq`, `postfix`, `eq_paren`에는 각각 문자 여덟 개의 공간을 확보한다. 수식이 짧아도 확보한 공간은 그대로다. 현재 스택 데이터는 길이가 `top + 1`인 사용 중인 앞쪽 구간에만 있다. `top`을 초기화해도 칸의 내용은 지우지 않는다.

첫 번째 수식의 변환은 최대 두 칸을 사용하며 `top`의 최댓값은 1이다. 계산은 최대 세 칸을 사용한다. 괄호 예제는 변환 중 최대 세 칸을 사용하며 `top`의 최댓값은 2다. 계산 중에도 최대 세 칸을 사용한다. 변환과 계산은 같은 정수 배열을 차례로 다시 사용한다.

입력에 맞춰 버퍼를 늘리는 버전이라면 연산자나 피연산자 스택과 출력에 각각 최악의 경우 `O(n)` 공간이 필요하다. 제공된 고정 배열은 상수 공간을 확보하고 용량을 제한한다. 임의 길이의 입력을 처리할 수는 없다.

## 코딩 계획

스택 보조 함수를 먼저 만든다. 수식을 변환한 뒤 출력을 계산한다. 마지막으로 괄호를 구별하는 변환 함수를 추가한다. 두 변환 함수는 같은 출력 버퍼에 쓴다. 계산과 같은 정수 스택을 다시 사용한다.

1. **스택 데이터를 저장하고 접근한다.** `stack[10]`, `capacity = 10`, `top = -1`을 선언한다. 추가는 `stack[++top]`, 확인은 `stack[top]`, 삭제는 `stack[top--]`로 구현한다. `top + 1 == capacity`로 가득 찬 상태를, `top == -1`로 빈 상태를 알린다.
2. **우선순위와 수식 저장 공간을 준비한다.** `+`, `-`에는 1을, `*`, `/`, `%`에는 2를, 나머지에는 0을 반환한다. 첫 입력은 `eq`에 저장하고 출력에는 `postfix`를 확보한다.
3. **첫 수식을 변환한다.** `top`을 -1로 초기화하고 종료 문자까지 `eq`를 읽는다. 숫자는 바로 복사한다. 스택이 비어 있지 않은 동안 마지막 연산자의 우선순위가 더 낮으면 멈춘다. 그렇지 않으면 삭제해 출력한다. 새 연산자를 추가한다. 남은 연산자를 비우고 `'\0'`을 직접 써서 출력을 끝낸다.
4. **연산 하나를 계산한다.** `calc`가 왼쪽과 오른쪽 정수 인수에 적용할 산술 연산을 선택하게 한다.
5. **후위 표기 출력을 계산한다.** `top`을 초기화하고 종료 문자까지 `postfix`를 읽는다. 숫자는 정수 값으로 추가한다. 연산자이면 `num2`, `num1` 순서로 삭제하고 `calc(num1, num2, c)`의 결과를 추가한다. 마지막 답을 삭제해 반환한다.
6. **괄호 있는 수식을 변환한다.** `eq_paren`을 읽는다. 숫자와 산술 연산자는 같은 방식으로 처리한다. `(`는 바로 추가한다. `)`가 나오면 스택이 비어 있지 않은 동안 데이터를 삭제한다. 삭제한 값이 `(`이면 멈추고, 그렇지 않으면 출력에 쓴다. 남은 연산자를 `postfix`에 쓰며 비운 뒤 `'\0'`을 직접 쓴다.

## C 코드

다음 여섯 블록은 `lab.c`를 소스 순서대로 옮긴 것이다. 실습 파일은 보조 함수와 전역 저장 공간을 정의한다. 별도의 실행 파일이 `main`을 제공한다.

### 1. 가장 나중에 추가한 데이터 저장과 접근

배열은 정수 칸 열 개를 확보한다. `capacity`는 그 한계를 기록한다. 값을 바꾸어도 배열 크기는 바뀌지 않는다. `top`은 칸의 내용과 별개로 사용 중인 칸을 정한다. 전역 배열의 칸들은 처음에 0을 담지만 `top == -1`이므로 스택은 비어 있다.

```c
int stack[10];
int capacity = 10;
int top = -1;

void push(int data) {stack[++top] = data;}

int peek() {return stack[top];}
int pop() {return stack[top--];}

int is_full() {return top + 1 == capacity;}
int is_empty() {return top == -1;}
```

`++top`은 값을 늘린 뒤 인덱스로 제공한다. -1에서 시작하면 첫 추가는 인덱스 0에 쓴다. `top--`은 이전 인덱스를 제공한 뒤 값을 줄인다. 2에서 시작하면 삭제는 인덱스 2를 읽고 `top == 1`을 남긴다. 이 식은 새 인덱스가 아니라 저장된 정수를 반환한다.

`is_full`과 `is_empty`는 비교가 참이면 1, 거짓이면 0을 반환한다. 상태는 바꾸지 않는다. 다른 보조 함수에는 검사가 없으므로 필요할 때 호출자가 경계를 검사해야 한다.

### 2. 우선순위를 정하고 문자열 공간 확보하기

변환은 대기 연산자와 새 연산자를 비교해야 한다. 함수는 그 비교에 쓸 작은 정수 값을 제공한다. 여는 괄호에는 0을 반환하므로 묶음 안의 산술 연산자를 처리할 때 경계가 남는다.

```c
int prec(char op) {
    switch (op) {
        case '*': case '/': case '%':
            return 2;
        case '+': case '-':
            return 1;
        default:
            return 0;
    }
}

char eq[8] = "1-2*3+4";
char postfix[8] = "";
```

`switch`는 일치하는 `case` 레이블을 선택한다. 연속된 `*`, `/`, `%` 레이블은 `return 2;`를 함께 사용한다. `+`, `-` 레이블은 `return 1;`을 함께 사용한다. 각 `return`이 함수를 끝내므로 이 분기에는 `break`가 필요하지 않다. `default`는 나머지 모든 문자를 처리해 0을 반환한다.

0을 반환해도 입력을 검증한 것은 아니다. 변환 함수는 지원하지 않는 문자를 저장한 뒤 출력에 복사할 수 있다. `!is_empty()` 검사는 비교 반복문이 빈 스택을 읽는 것을 막는다. 잘못된 수식을 거부하는 검사는 아니다. 아래 숫자 검사에서 `&&`는 양쪽 경계 조건이 모두 참이어야 한다.

문자열 `"1-2*3+4"`에는 보이는 문자 일곱 개와 그 뒤의 `'\0'`이 들어 있다. 작은따옴표는 문자 하나를 나타낸다. 큰따옴표는 문자열을 나타낸다. 널 문자의 값은 0이며 숫자 문자 `'0'`과 다르다. 처음에 비어 있는 출력 배열은 값이 0인 칸 여덟 개를 갖는다.

### 3. 후위 표기 순서로 쓰기

변환은 출력 위치와 사용 중인 스택을 새로 시작한다. 호출자가 미리 스택을 비울 필요는 없다. 출력 버퍼를 미리 지우지는 않는다. 새롭게 종료된 결과를 쓴다.

```c
void convert_to_postfix() {
    int pos = 0;
    top = -1;
    for (int i = 0; eq[i] != '\0'; i++) {
        char c = eq[i];
        if (c >= '0' && c <= '9') {
            postfix[pos++] = c;
        }
        else {
            while (!is_empty()) {
                char op = peek();
                if (prec(op) < prec(c)) {
                    break;
                }
                postfix[pos++] = pop();
            }
            push(c);
        }
    }
    while (!is_empty()) {
        postfix[pos++] = pop();
    }
    postfix[pos++] = '\0';
}
```

`pos`는 다음 출력 인덱스다. `postfix[pos++] = c;`는 이전 위치에 쓴 뒤 값을 늘린다. `top = -1;`은 이전 스택 데이터를 모두 사용 중인 구간에서 제외한다. 첫 연산자를 추가할 때까지 스택은 비어 있다.

`for` 반복문은 `eq[i] != '\0'`을 검사한다. 실제 문자열 길이가 반복 횟수를 정한다. `1-2*3+4`에서는 인덱스 0부터 6까지 읽는다. 연산자가 나오면 `while (!is_empty())`가 대기 데이터가 있을 때만 `peek()`를 허용한다. `prec(op) < prec(c)`이면 `break`가 이 안쪽 `while` 반복문을 끝낸다. 바깥 `for` 반복문을 끝내거나 함수에서 반환하는 것은 아니다. 실행은 `push(c)`로 이어진다.

그렇지 않으면 `postfix[pos++] = pop();`이 대기 연산자를 쓴다. 다음 반복은 빈 상태를 다시 검사한 뒤 `peek()`로 새 `op`를 선언한다. 같은 우선순위는 더 낮다는 조건을 만족하지 않으므로 이전 연산자를 먼저 삭제한다.

| 새 `+`를 읽을 때의 단계 | 지금까지 출력한 문자 | `pos` | `top` |
|---|---|---:|---:|
| 삭제 전 | `123` | 3 | 1 |
| `*` 삭제 | `123*` | 4 | 0 |
| `-` 삭제 | `123*-` | 5 | -1 |
| 빈 스택에서 반복을 마치고 `+` 추가 | `123*-` | 5 | 0 |

4를 읽은 뒤에는 `pos == 6`이다. 마지막 반복문은 `+`를 삭제해 `postfix[6]`에 쓴다. `top == -1`, `pos == 7`이 남는다. 이제 스택이 비었으므로 반복문이 끝난다. 별도의 문장 `postfix[pos++] = '\0';`이 인덱스 7에 종료 문자를 쓰고 `pos`를 8로 늘린다. `top`은 바꾸지 않는다.

더 짧은 입력 `2+3`의 출력은 `23+`다. 종료 문자는 인덱스 3에 있고 마지막 `pos`는 4다. 종료 문자 뒤에 이전 바이트가 남아 있을 수 있다. 계산 함수와 문자열 출력은 새 종료 문자에서 멈추므로 그 바이트를 사용하지 않는다.

### 4. 정수 연산 하나의 결과 반환하기

정수 피연산자 두 개가 준비되면 연산자가 결합 방법을 정한다. `num1`은 왼쪽 피연산자다. `num2`는 오른쪽 피연산자다.

```c
int calc(int num1, int num2, int op) {
    switch (op) {
        case '+': return num1 + num2;
        case '-': return num1 - num2;
        case '*': return num1 * num2;
        case '/': return num1 / num2;
        case '%': return num1 % num2;
    }
    return 0;
}
```

`switch`는 일치하는 `case` 레이블을 선택한다. 각 분기는 바로 반환하므로 `break`가 필요하지 않다. 알 수 없는 연산자에 마지막으로 반환하는 0은 오류 보고가 아니다. 0도 올바른 결과일 수 있다. 함수는 연산자와 산술 연산이 유효하다고 가정한다.

이 장의 예제에서 `calc(2, 3, '*')`는 6을 반환한다. `calc(1, 6, '-')`는 -5를 반환한다. `calc(-5, 4, '+')`는 -1을 반환한다. 정수 나눗셈이므로 `calc(7, 2, '/')`는 3을 반환한다. 대응하는 나머지인 `calc(7, 2, '%')`는 1이다.

### 5. 정수 결과를 위해 스택 다시 사용하기

변환된 문자열이 이미 연산 순서를 정한다. 따라서 계산에는 숫자와 완성된 결과만 필요하다. 첫 숫자를 읽기 전에 같은 스택을 빈 상태로 초기화한다.

```c
int eval_postfix() {
    top = -1;

    for (int i = 0; postfix[i] != '\0'; i++) {
        char c = postfix[i];
        if (c >= '0' && c <= '9') {
            push(c - '0');
        }
        else {
            int num2 = pop();
            int num1 = pop();
            push(calc(num1, num2, c));
        }
    }

    return pop();
}
```

반복문은 `postfix`의 실제 널 종료 문자에서 멈춘다. `c - '0'`이 숫자 문자를 정수로 바꾼다. C는 숫자 문자의 값이 연속됨을 보장한다. 뺄셈은 피연산자 순서를 유지해야 한다. 첫 삭제로 오른쪽 피연산자 6을 얻는다. 두 번째 삭제로 왼쪽 피연산자 1을 얻는다. 따라서 결과는 `1 - 6`이다.

| `123*-4+`의 연산자 | 오른쪽 피연산자 | 왼쪽 피연산자 | `top`: 시작 → 첫 삭제 → 둘째 삭제 → 추가 |
|---|---:|---:|---|
| `*` | 3 | 2 | 2 → 1 → 0 → 1 |
| `-` | 6 | 1 | 1 → 0 → -1 → 0 |
| `+` | 4 | -5 | 1 → 0 → -1 → 0 |

올바른 수식은 `stack[0]`에 결과 하나를 남긴다. 이때 `top == 0`이다. `return pop();`은 그 결과를 반환하고 `top == -1`을 남긴다. 계산은 입력과 출력 문자열을 바꾸지 않는다. 함수는 피연산자가 부족한지 또는 결과가 더 남는지 검사하지 않는다.

### 6. 괄호 안의 연산을 묶음 안에 두기

두 번째 변환 함수는 묶음이 닫히기 전에 바깥 연산이 출력되지 않도록 해야 한다. 여는 괄호를 경계로 저장한다. 닫는 괄호는 산술 연산자와 별도로 처리한다.

```c
char eq_paren[8] = "1+(2+3)";

void infix_to_postfix_parentheses() {
    int pos = 0;
    top = -1;

    for (int i = 0; eq_paren[i] != '\0'; i++) {
        char c = eq_paren[i];

        if (c >= '0' && c <= '9') {
            postfix[pos++] = c;
        }
        else if (c == '(') {
            push(c);
        }
        else if (c == ')') {
            while (!is_empty()) {
                char op = pop();
                if (op == '(') {
                    break;
                }
                postfix[pos++] = op;
            }
        }
        else {
            while (!is_empty()) {
                char op = peek();
                if (prec(op) < prec(c)) {
                    break;
                }
                postfix[pos++] = pop();
            }
            push(c);
        }
    }
    while (!is_empty()) {
        postfix[pos++] = pop();
    }
    postfix[pos++] = '\0';
}
```

`(`에서는 `push(c)`가 경계를 저장한다. `)`에서는 반복문이 먼저 `!is_empty()`를 검사한 뒤 `char op = pop();`으로 데이터를 삭제한다. 그 값이 `(`이면 `break`가 반복문을 끝낸다. 여는 괄호는 이미 삭제했으므로 추가로 삭제하지 않는다. 그 외의 값이면 `postfix[pos++] = op;`가 삭제한 연산자를 출력에 쓴다.

`1+(2+3)`의 닫는 괄호는 안쪽 `+`를 삭제하고 출력 인덱스 3에 쓴다. 이어서 `(`를 삭제하면 바깥 `+`만 남으므로 `top == 0`이다. 마지막으로 비울 때 바깥 `+`를 인덱스 4에 쓰고 `top == -1`, `pos == 5`를 남긴다. 별도의 종료 문자 대입문이 인덱스 5에 `'\0'`을 쓰고 `pos`를 6으로 늘린다. 이어서 `eval_postfix()`를 호출하면 6을 반환하고 다시 `top == -1`을 남긴다.

두 변환 함수는 모두 `postfix`를 덮어쓴다. 두 결과가 모두 필요하면 다음 변환 함수를 호출하기 전에 앞의 결과를 계산하거나 출력한다. 괄호의 짝과 입력이 올바르다는 전제가 필요하다. 짝이 없는 닫는 괄호는 `(`를 찾지 못한 채 반복문을 끝낼 수 있다. 짝이 없는 여는 괄호는 최종 출력에 남을 수 있다. 두 경우 모두 오류를 보고하지 않는다.

### 별도 소스 파일들은 어떻게 함께 동작할까?

함수 밖의 정의는 보조 함수들이 공유하는 저장 공간을 만든다. `pos`, `i`, `c` 같은 지역 변수는 함수 호출 하나에 속한다. 변환 함수들은 `void`를 반환하고 결과를 `postfix`에 남긴다. 계산 함수는 정수를 반환하고 사용 중인 스택을 비운다.

실행 예제는 공유 배열을 `extern`으로 선언한다. 보조 함수도 호출 전에 선언한다. 이 선언들이 별도의 스택이나 출력 배열을 만드는 것은 아니다. 실행 예제와 `lab.c`를 함께 빌드하면 선언과 정의가 연결된다. `module_04_stack/code`에서 `make lab-demo`를 실행해 제공된 보조 함수들을 확인한다.

### 각 상태를 예측할 수 있을까?

1. 세 번 추가한 뒤 `top`은 왜 2이고 개수는 왜 3일까? 첫 데이터가 인덱스 0에 있으므로 개수는 항상 `top + 1`이다.
2. 삭제한 값이 왜 배열에 남아 있어도 될까? `top`을 줄이면 그 칸이 사용 중인 앞쪽 구간에서 제외된다.
3. 새 `+`는 왜 `*`와 `-`를 모두 내보낼까? 우선순위 2와 1은 모두 `prec('+')`보다 낮지 않으므로 `break`를 실행하지 않는다.
4. 변환은 왜 `pos == 8`, `top == -1`로 끝날까? 출력 문자 일곱 개를 쓴 뒤 연산자 스택이 비어 있다. 별도의 쓰기가 `'\0'`을 추가하고 `pos`를 한 번 더 늘린다.
5. `1+(2+3)`은 왜 출력 문자 다섯 개를 만들까? 두 괄호는 경계로 사용한 뒤 버리므로 복사하지 않는다.
6. 짧은 변환 결과는 왜 더 긴 이전 결과를 올바르게 바꿀까? 새 종료 문자를 쓴다. 두 입력 반복문 모두 고정 횟수 대신 종료 문자에 따라 멈춘다.
