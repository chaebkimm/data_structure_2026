# 제4장. 마지막에 넣은 값부터 꺼내기

시작한 순서의 반대로 끝내야 하는 일을 하나의 규칙으로 저장해 보자.

## 논리적으로 생각해 보기

### 왜 꺼내는 순서를 따로 정할까?

`1-2*3+4`에서는 뺄셈과 덧셈보다 곱셈을 먼저 해야 한다. 먼저 나온 연산자가 나중에 나온 연산자의 처리를 기다릴 수 있다. `-`가 기다리는 중에 `*`가 나오면 나중에 나온 `*`부터 처리해야 한다.

### 어떻게 저장할까?

실습에서는 다음 전역 변수로 스택의 상태를 나타낸다.

```c
char stack[10];
int capacity = 10;
int size = 0;
```

배열의 유효한 인덱스는 0부터 9까지다. `size`는 다음 항목을 넣을 위치다. 사용 중인 항목의 수도 나타낸다. 처음 값 `size == 0`은 스택이 비었다는 표시다. `push`는 `stack[size]`에 쓴 뒤 `size`를 늘리므로 첫 항목은 `stack[0]`에 들어간다. 다음 항목들은 인덱스 1, 2 순서로 들어간다. 스택은 인덱스가 큰 쪽으로 자란다.

`size == 3`이면 사용 중인 항목은 인덱스 0부터 2까지에 있다. 맨 위 항목은 `stack[size - 1]`, 즉 `stack[2]`이고 항목 수는 3이다. `size` 이상인 인덱스는 사용하지 않는 구간이다. 가득 찬 상태의 `size == capacity`는 배열 바로 뒤의 경계를 나타낸다. `stack[10]`은 써도 되는 칸이 아니다.

`capacity`는 가득 찬 상태를 검사할 때 사용한다. `stack[10]`이 확보한 칸 수인 10과 같아야 한다. `capacity`만 바꾸어도 배열의 크기는 바뀌지 않는다.

### 넣기, 읽기, 꺼내기는 상태를 어떻게 바꿀까?

저장할 일 세 개에 문자 `'A'`, `'B'`, `'C'`를 붙이자. 아래 목록에서는 맨 오른쪽 항목이 스택의 맨 위다. 들어온 순서와 배열 인덱스가 증가하는 순서가 같다.

| 요청 | 반환값 | 아래에서 위로 나열한 항목 | `size` | 사용 중인 인덱스 |
|---|---|---|---:|---|
| 시작 | — | 비어 있음 | 0 | 없음 |
| `push('A')` | 없음 (`void`) | A | 1 | 0 |
| `push('B')` | 없음 (`void`) | A, B | 2 | 0–1 |
| `push('C')` | 없음 (`void`) | A, B, C | 3 | 0–2 |
| `peek()` | `'C'` | A, B, C | 3 | 0–2 |
| `pop()` | `'C'` | A, B | 2 | 0–1 |
| `pop()` | `'B'` | A | 1 | 0 |
| `pop()` | `'A'` | 비어 있음 | 0 | 없음 |

`pop`은 배열 칸을 지우지 않는다. `size`를 줄이면 이전 맨 위 칸이 사용 구간에서 빠진다. 다음 `push`가 그 칸에 새 값을 덮어쓸 수 있다.

### 가득 차거나 비어 있으면 어떻게 될까?

`size == capacity`이면 스택이 가득 찼다. 이때 `push`는 배열과 `size`를 바꾸지 않고 반환한다. 성공 여부를 나타내는 값도 반환하지 않는다. `size == 0`이면 스택이 비었다. 이때 `peek`와 `pop`은 `'\0'`을 반환하고 `size`를 그대로 둔다. 이처럼 특별한 상태를 나타내려고 사용하는 값을 **센티널(sentinel)**이라고 한다. 별도의 오류 상태를 반환하는 것은 아니다. 호출자가 일부러 `'\0'`을 저장했다면 반환된 문자만으로는 그 항목과 빈 스택을 구분할 수 없다.

이 검사들은 정상적인 가득 찬 상태와 빈 상태에서 배열 접근을 막는다. 수식을 검사하거나, 외부에서 잘못 바꾼 `size`를 복구하지는 않는다.

### 함수 호출과는 어떤 관계가 있을까?

한 함수가 실행을 잠시 멈추고 다른 함수를 호출하면, 실행 환경은 보통 이전 호출을 나중에 이어 가는 데 필요한 정보를 저장한다. 이를 **호출 프레임(call frame)**이라고 한다. 중첩된 호출은 후입선출 순서로 끝난다. 탐구 활동의 숫자 함수 ID와 이 장의 문자 표시는 그 순서를 나타내는 모형이다. 실제 호출 프레임은 아니다. 이 전역 문자 배열도 프로그램 실행 환경의 호출 스택 자체는 아니다.

### 왜 연산자를 피연산자 뒤에 둘까?

`2`처럼 계산에 쓰이는 값을 **피연산자(operand)**라고 한다. `*`처럼 수행할 계산을 나타내는 기호를 **연산자(operator)**라고 한다. `2*3`처럼 연산자를 피연산자 사이에 놓는 방법은 **중위 표기(infix)**다. `23*`처럼 연산자를 뒤에 놓는 방법은 **후위 표기(postfix)**다. 이 실습에서는 숫자 문자 하나가 피연산자 하나다. `23*`는 2와 3을 곱한다는 뜻이지, 수 23을 뜻하지 않는다.

프로그램은 두 단계로 나뉜다. 변환 단계는 전역 문자 스택에 기다리는 연산자를 보관하고 `postfix`에 문자열을 쓴다. 뒤의 계산 단계는 별도의 지역 정수 배열에 계산한 값을 저장한다. 변환 단계에서는 산술 계산을 하지 않는다.

#### 어떤 연산자를 먼저 꺼낼까?

기다리는 연산자와 새 연산자의 처리 순서를 비교하려고 우선순위를 숫자로 나타낸다. `prec`는 다음 값을 반환한다.

| 문자 | 우선순위 |
|---|---:|
| `+`, `-` | 1 |
| `*`, `/`, `%` | 2 |
| `'\0'`을 포함한 나머지 문자 | 0 |

숫자 문자는 후위 표기 출력에 바로 넣는다. 새 연산자를 스택에 넣기 전에는 우선순위가 같거나 더 높은 대기 연산자를 모두 꺼내 출력에 넣는다. 같은 우선순위도 꺼내므로 같은 단계의 연산은 왼쪽부터 처리한다. 이를 **좌결합성(left associativity)**이라고 한다. `8-3-2`는 `(8-3)-2`라는 뜻이다.

빈 스택의 `peek()`는 `'\0'`을 반환하고, 이 문자의 우선순위는 0이다. 지원하는 연산자의 우선순위는 1 또는 2이므로 빈 스택에서는 대기 연산자를 꺼내는 반복이 멈춘다. 실습 코드가 널 센티널을 스택에 미리 넣는 것은 아니다.

#### 예제는 어떻게 변환될까?

`size == 0`인 빈 상태에서 시작하자. 대기 연산자는 스택의 아래에서 위 순서로 나열한다.

| 입력 또는 동작 | 지금까지 쓴 후위 표기 문자 | 대기 연산자 | `size` |
|---|---|---|---:|
| `1` 읽기 | `1` | 비어 있음 | 0 |
| `-` 읽기 | `1` | `-` | 1 |
| `2` 읽기 | `12` | `-` | 1 |
| `*` 읽기 | `12` | `-`, `*` | 2 |
| `3` 읽기 | `123` | `-`, `*` | 2 |
| `+` 읽기: `*` 꺼내기, `-` 꺼내기, `+` 넣기 | `123*-` | `+` | 1 |
| `4` 읽기 | `123*-4` | `+` | 1 |
| 입력 끝: 남은 `+` 꺼내기 | `123*-4+` | 비어 있음 | 0 |

입력과 출력 배열은 각각 여덟 칸이다.

```c
char infix[8] = "1-2*3+4";
char postfix[8] = "";
int postfix_size = 0;
```

`postfix_size`는 후위 표기의 문자 수를 센다. 연산자 스택의 항목 수가 아니다. 변환은 `postfix_size`를 0으로 되돌리고 입력의 `'\0'`을 만날 때까지 읽는다. 마지막에는 `postfix[postfix_size] = '\0'`을 쓴다. 문자열의 끝을 나타내는 `'\0'`을 **널 종료 문자(null terminator)**라고 한다. 예제에서는 `postfix_size == 7`이고 종료 문자는 인덱스 7에 있다. 수식을 구성하는 숫자나 연산자 한 단위를 **토큰(token)**이라고 한다. 종료 문자는 수식 토큰 수에 포함하지 않는다.

`postfix_size`를 초기화해야 두 번째 변환이 이전 결과 뒤에 이어 쓰지 않는다. 종료 문자를 써야 다음 수식이 더 짧아도 남아 있던 문자가 출력되지 않는다. 정상적으로 변환을 마치면 연산자 스택을 모두 비우므로 다음 변환도 빈 상태에서 시작할 수 있다.

### 바뀐 순서로 어떻게 계산할까?

문자로 적힌 수식을 계산하려면 숫자와 중간 결과를 보관해야 한다. `eval_postfix()`는 자기 지역 스택을 둔다.

```c
int values[10];
int value_size = 0;
```

여기서 지역 변수 `value_size`는 사용 중인 정수의 수이면서 다음 항목을 넣을 위치다. 사용 중인 인덱스는 0부터 `value_size - 1`까지이고, 맨 위 값은 `values[value_size - 1]`이다. 두 스택은 모두 인덱스가 큰 쪽으로 자라고 같은 인덱스 규칙을 쓴다. 이 지역 변수는 `eval_postfix()` 안에서 같은 이름의 전역 변수를 가린다. 지역 `value_size`를 바꾸어도 문자 스택의 전역 `value_size`는 바뀌지 않는다.

| 변수 | 뜻 | 항목을 추가하는 방법 |
|---|---|---|
| 전역 `value_size` | 다음 문자를 넣을 위치이자 사용 중인 문자의 수 | `stack[value_size]`에 쓴 뒤 `value_size`를 늘린다. |
| `postfix_size` | `'\0'`을 제외한 후위 표기 문자 수 | `postfix[postfix_size++]`에 추가한다. |
| `eval_postfix()`의 지역 `value_size` | 다음 정수를 넣을 위치이자 사용 중인 정수의 수 | `values[value_size++]`에 쓴다. |

숫자 문자는 `c - '0'`으로 정수 값으로 바꾼다. 연산자가 나오면 정수 두 개를 꺼내 계산한 뒤 결과를 다시 넣는다. 먼저 꺼낸 값은 **오른쪽** 피연산자 `num2`다. 두 번째로 꺼낸 값은 **왼쪽** 피연산자 `num1`이다. 뺄셈, 나눗셈, 나머지 계산에서는 이 순서에 따라 결과가 달라진다.

| 후위 표기 토큰 | 동작 | 아래에서 위로 나열한 값 | `value_size` |
|---|---|---|---:|
| `1` | 1 넣기 | 1 | 1 |
| `2` | 2 넣기 | 1, 2 | 2 |
| `3` | 3 넣기 | 1, 2, 3 | 3 |
| `*` | `2 * 3` | 1, 6 | 2 |
| `-` | `1 - 6` | -5 | 1 |
| `4` | 4 넣기 | -5, 4 | 2 |
| `+` | `-5 + 4` | -1 | 1 |

마지막 `return values[--value_size]`는 `-1`을 반환한다. 중간 결과는 정수이므로 음수이거나 한 자릿수보다 클 수 있다. 이 결과들을 문자 스택에 다시 저장하지 않는다.

`calc`는 `+`, `-`, `*`, `/`, `%`를 구현한다. 나눗셈은 C의 정수 나눗셈이므로 `7/2`의 결과는 3이다. 나머지 연산은 정수 나눗셈 뒤에 남는 값을 구하므로 `7%2`의 결과는 1이다. 이 연산들은 소수 부분을 가진 실수 결과를 만들지 않는다.

### 이 실습에서는 어떤 입력을 사용할까?

제공된 프로그램은 비어 있지 않고 다음 형식에 맞는 입력을 가정한다. 여기서 `digit`은 숫자 문자 하나다. 뒤의 괄호 부분은 연산자와 숫자가 한 쌍이며, 마지막 `*`는 그 쌍이 0번 이상 반복된다는 뜻이다.

```text
digit (('+' | '-' | '*' | '/' | '%') digit)*
```

각 피연산자는 한 자리 숫자다. 전체 수식은 문자 일곱 개와 널 종료 문자 한 개 안에 들어가야 한다. 공백, 괄호, 단항 연산자, 여러 자리 피연산자는 사용하지 않는다. 단항 연산자는 `-3`의 부호처럼 피연산자 하나에 적용하는 연산자다. 나눗셈과 나머지 계산의 오른쪽 피연산자는 0이 아니어야 한다. 산술 결과는 `int`로 표현할 수 있어야 한다. 변환은 빈 연산자 스택에서 시작한다. 이 조건을 만족하는 입력을 정상적으로 변환한 뒤 계산한다.

이 조건들은 호출자가 미리 지켜야 하는 가정이다. 함수 호출 전에 지켜야 하는 조건을 **사전 조건(precondition)**이라고 한다. `lab.c`가 이 조건들을 검사하는 것은 아니다.

- 지원하지 않는 문자의 우선순위는 0이다. 변환 반복문이 빈 스택에서 계속 꺼내기를 하다가 `postfix`의 범위를 벗어나 쓸 수 있다.
- 피연산자가 부족하거나 입력이 비어 있으면 계산 중에 `values[0]`보다 앞쪽을 읽을 수 있다. 피연산자가 너무 많아도 거부하지 않는다. 빈 스택에서 읽거나 꺼내려는 요청을 **언더플로(underflow)**라고 한다.
- 0으로 나누거나 나머지를 구하는지 검사하지 않는다. 정수 자료형이 표현할 수 있는 범위를 벗어나는 **정수 오버플로(integer overflow)**도 검사하지 않는다. 함수들은 오류 상태를 따로 알려 주는 인터페이스가 없다.

`calc`에서 어느 `case`에도 해당하지 않아 0을 반환하더라도 입력을 안전하게 검사한 것으로 해석하면 안 된다. 피연산자를 읽는 동작은 이미 끝났다. 문자와 수식 형식 검사, 피연산자 수 검사, 배열 범위 검사, 산술 오류 보고 기능은 확장 과제다. 이런 확장을 설명했다고 제공된 코드에 이미 구현된 것은 아니다.

### 각 연산은 어떤 규칙을 지켜야 할까?

연산을 정상적으로 마친 전역 문자 스택은 다음 조건을 만족해야 한다. 앞 장에서 배운 불변식을 이 스택에 적용한 것이다. 사용 중인 항목은 배열의 앞쪽에 연속해서 모인다. 이 범위를 **사용 중인 앞쪽 구간(active prefix)**이라고 부르자. `capacity`는 확보한 칸 수인 10이다.

```text
0 <= size <= capacity
사용 중인 인덱스: 0부터 size - 1까지 (size == 0이면 없음)
사용 중인 항목 수: size
size > 0일 때만 stack[size - 1]을 읽는다.
size < capacity일 때만 stack[size]에 새 항목을 쓴다.
```

`push`는 가득 찼는지 검사한 뒤 `stack[size]`에 쓰고 `size`를 늘린다. `pop`은 비었는지 검사하고 `size`를 줄인 뒤 `stack[size]`를 읽는다. `peek`는 `stack[size - 1]`을 읽지만 `size`를 바꾸지 않는다. 어느 연산도 기존 항목을 이동하거나 사용하지 않는 칸을 지우지 않는다.

후위 표기 출력에는 별도 범위 `0 <= postfix_size <= 7`이 있다. `postfix[postfix_size] = '\0'`을 쓸 자리를 남겨야 한다. 올바른 계산에서 지역 `size`는 사용할 수 있는 피연산자와 중간 결과의 수다. 연산자 하나에는 값 두 개가 필요하고, 완성된 수식의 계산이 끝나면 값이 정확히 하나 남는다. 현재 계산 함수는 이 사실들을 검사하지 않고 성립한다고 가정한다.

## 효율 계산해보기

### 스택 연산 한 번에는 얼마나 많은 작업이 필요할까?

`push`는 경계를 한 번 검사하고 한 칸에 쓴 뒤 인덱스를 한 번 바꾼다. `peek`는 경계를 한 번 검사하고 한 칸을 읽는다. `pop`은 경계를 한 번 검사하고 인덱스를 한 번 바꾼 뒤 읽는다. 어느 연산도 기존 원소를 이동하지 않는다. 따라서 각 연산의 시간은 `O(1)`이다.

### 수식의 두 처리 단계는 왜 선형 시간일까?

`1-2*3+4`의 변환은 토큰 일곱 개를 읽고, 연산자 세 개를 넣고, 그 세 개를 꺼낸다. 새 연산자 하나 때문에 여러 번 꺼낼 수는 있다. 하지만 같은 대기 연산자를 두 번 꺼내지는 않는다. 따라서 입력 문자가 `n`개이면 전체 읽기와 스택 작업 시간은 `O(n)`이다.

계산 단계는 후위 표기 토큰 일곱 개를 한 번씩 읽는다. 숫자 문자 하나는 정수 하나를 추가한다. 연산자 세 개는 각각 정수 두 개를 꺼내고 결과 하나를 넣는다. 토큰마다 필요한 작업 수가 일정하므로 계산 시간도 `O(n)`이다.

### 저장 공간은 얼마나 확보할까?

프로그램은 연산자용 문자 열 칸, 중위 표기용 문자 여덟 칸, 후위 표기용 문자 여덟 칸을 선언한다. 계산 중에는 지역 정수 열 칸을 사용한다. 배열 길이가 고정되어 있으므로 입력 길이에 대한 저장 공간은 `O(1)`이다. 현재 입력은 최대 일곱 문자로 제한된다. 입력에 맞추어 배열이 커지도록 일반화하면 후위 표기 출력만으로도 `O(n)` 공간이 필요하다. 지원하는 수식 형식에 따라 스택 공간도 커질 수 있다.

## 용어 정리

아래 용어는 앞의 예제에서 이미 사용한 생각에 이름을 붙인다.
단계 B의 용어 자료는 수업 전체에서 사용하는 더 넓은 범위의 용어를 다룬다.

| 용어 | 이 장에서의 뜻 |
|---|---|
| 스택; 후입선출 (Stack; LIFO) | 남아 있는 항목 중 가장 나중에 넣은 항목을 먼저 꺼내는 접근 규칙 |
| 맨 위 (top) | 항목을 넣고 꺼내는 쪽 끝. 비어 있지 않은 문자 스택에서는 인덱스 `size - 1`이다. |
| 넣기, 읽기, 꺼내기 (push, peek, pop) | 맨 위에 항목을 추가하거나, 맨 위 항목을 읽거나, 읽고 제거하는 동작 |
| 사용 중인 앞쪽 구간 (active prefix) | 문자 배열의 0부터 `size - 1`까지인 인덱스 구간. `size == 0`이면 비어 있다. |
| 언더플로 (underflow) | 스택이 비었는데 항목을 읽거나 꺼내려는 요청 |
| 센티널 (sentinel) | 특별한 뜻을 정한 값. 여기서는 빈 스택의 peek/pop이 반환하는 `'\0'`이다. |
| 불변식 (invariant) | `0 <= size <= capacity`처럼 유효한 연산이 유지하는 규칙 |
| 중위 표기; 후위 표기 (infix; postfix) | 연산자를 피연산자 사이에 쓰는 표기; 연산자를 피연산자 뒤에 쓰는 표기 |
| 피연산자; 연산자 (operand; operator) | 계산할 값; 값에 적용할 연산 |
| 우선순위 (precedence) | 연산자를 먼저 처리할 순서를 정하는 기준 |
| 좌결합성 (left associativity) | 우선순위가 같은 연산자를 왼쪽부터 처리하는 성질 |
| 널 종료 문자 (null terminator) | C 문자열의 끝을 표시하는 `'\0'`. 토큰 수에는 포함하지 않는다. |
| 호출 프레임 (call frame) | 멈춘 함수 호출을 이어서 실행하는 데 필요한 실행 중 정보 |
| 사전 조건 (precondition) | 함수가 실행되기 전에 호출하는 쪽이 만족해야 하는 조건 |
| 정수 오버플로 (integer overflow) | 계산 결과가 `int`로 표현할 수 있는 범위를 벗어나는 경우 |

## 코딩 계획

같은 예제를 두 단계로 구현한다. 연산자를 저장하는 문자 스택과
나중에 계산할 때 사용하는 정수 값을 구분한다.

1. **문자 저장 공간을 준비한다.** 전역 `size`를 0으로 시작한다.
   `size == capacity`이면 가득 찬 상태, `size == 0`이면 빈 상태다.
   넣을 때는 가득 찼는지 검사하고 `stack[size]`에 쓴 뒤 `size`를 늘린다.
   읽거나 꺼낼 때는 빈 상태를 먼저 검사한다. `peek`는 `stack[size - 1]`을 읽는다.
   `pop`은 `size`를 줄인 뒤 `stack[size]`를 읽는다.
2. **우선순위와 문자열을 준비한다.** `+`/`-`의 우선순위는 1,
   `*`/`/`/`%`의 우선순위는 2로 정한다. 각 수식 배열에는 토큰 일곱 개와
   종료 문자 하나를 담을 공간을 확보한다. `postfix_size`는 출력 토큰 수만 센다.
3. **후위 표기로 변환한다.** 연산자 스택이 빈 상태에서 시작한다.
   `postfix_size`를 초기화하고 숫자 문자를 출력에 옮긴다. 기다리는 연산자를 출력할
   시점은 우선순위로 결정한다. 남은 연산자를 모두 꺼낸 뒤 출력의 끝을 표시한다.
4. **정수 계산을 정의한다.** 지원하는 각 연산자에 대해 `num1 op num2`를
   계산한다. 호출하는 쪽이 산술 연산의 사전 조건을 만족해야 한다.
5. **후위 표기를 계산한다.** 지역 정수 배열을 준비하고 `size`를 0으로 시작한다.
   숫자 문자를 정수로 바꾼다. 연산자마다 오른쪽 피연산자를 먼저 꺼내고 왼쪽을
   꺼낸 뒤 계산 결과를 넣는다. 올바른 완성 수식은 결과 하나를 남긴다.
6. **실행하고 근거를 모은다.** 별도의 실행 예제를 사용한다. 후입선출 규칙,
   경계, 우선순위, 피연산자 순서, 반복 변환과 더 짧은 수식의 변환을 검사한다.
   구현되지 않은 검증과 실제로 확인한 지원 동작을 구분해 설명한다.

## 새로운 C 문법 설명

프로그램은 수식의 문자를 저장하고, 배열의 사용 범위 경계를 옮기고,
수행할 산술 연산을 골라야 한다. 아래 문법은 각 동작을 코드에 연결한다.
앞 장에서 배운 문법을 새로운 상황에 적용하는 부분도 있다.

### 문자, 숫자, 끝이 표시된 문자열

수식은 먼저 숫자를 문자로 저장한다. 계산할 때 그 문자를 정수로 바꾼다.
`'3'`은 문자 상수이고, `3`은 정수 값이다. `"3"`은 문자 `'3'` 뒤에
`'\0'`이 붙은 문자열이다. 작은따옴표는 문자 하나를, 큰따옴표는 문자열을
표시한다. 널 문자 `'\0'`의 값은 0이다. 숫자 문자 `'0'`과는 다르다.

`char infix[8] = "1-2*3+4";`는 수식 문자 일곱 개와 종료 문자를 담을
문자 칸 여덟 개를 확보한다. `char postfix[8] = "";`는 여덟 칸을 모두
0으로 초기화한다. `infix[i] != '\0'`은 현재 문자가 아직 종료 문자가 아닌지
검사한다. 변환 후 `postfix[postfix_size] = '\0';`은 마지막 출력 문자 다음에
종료 문자를 쓴다.

숫자임을 확인한 문자는 `c - '0'`으로 정수로 바꾼다. C는 숫자 문자의 값이
연속됨을 보장하므로 `'3' - '0'`은 정수 3이 된다. 비교식의 `'+'`는
작은따옴표로 감싼 연산자 문자다. `num1 + num2`에서 따옴표가 없는 `+`는
덧셈을 수행한다.

### 조건을 묶거나 뒤집기

같은 우선순위에 여러 연산자가 속할 수 있다. `op == '+' || op == '-'`의
`||`는 논리합이다. 두 비교 중 하나 이상이 참이어야 한다.
C는 왼쪽 비교가 거짓일 때만 오른쪽 비교를 검사한다.
앞에서 배운 `c >= '0' && c <= '9'`의 `&&`는 두 비교가 모두 참이어야 한다.
왼쪽 비교가 참일 때만 오른쪽 비교를 검사한다.

마지막에 남은 연산자를 꺼내는 과정은 문자 스택에 항목이 있는 동안 계속해야 한다.
`!is_empty()`는 논리 부정을 사용한다. `!`는 피연산자가 0이면 1을,
그렇지 않으면 0을 만든다. 빈 스택에서 `is_empty()`는 1을 반환하므로
뒤집은 조건은 거짓이 된다. `size == 0` 같은 비교도 참이면 정수 1을,
거짓이면 0을 만든다.

### 인덱스나 개수 바꾸기

넣기와 꺼내기는 경계를 한 칸씩 옮긴다. `size += 1;`은 `size`에 1을 더하고,
`size -= 1;`은 1을 뺀다. 여기서는 각각 `size = size + 1;`과
`size = size - 1;`과 같은 결과를 낸다. 넣기는 쓴 뒤 경계를 늘린다.
꺼내기는 경계를 줄인 뒤 읽는다.

끝에 항목을 추가하려면 증가 전의 빈 위치가 필요하다. `postfix[postfix_size++] = c;`의
후위 증가 연산자는 증가 전 `postfix_size`를 인덱스로 사용한다. 3에서 시작하면
`postfix[3]`에 쓰고 `postfix_size`는 4가 된다. `values[value_size++]`도 정수를 저장할 때
같은 규칙을 사용한다.

정수를 꺼내려면 마지막으로 사용 중인 위치가 필요하다. `values[--value_size]`의
전위 감소 연산자는 `size`를 먼저 줄인 뒤 인덱스로 사용한다. 3에서 시작하면
`values[2]`를 읽고 `size`는 2가 된다. 두 피연산자를 읽는 문장은 따로 있으므로
오른쪽 피연산자를 왼쪽보다 먼저 꺼낸다.

### `switch`와 `case`로 계산 고르기

계산 함수는 연산자 문자에 맞는 계산 하나를 골라야 한다.
`switch (op)`는 `op`의 값을 구한 뒤 일치하는 `case` 레이블에서 실행을 시작한다.
`case '+':`는 콜론으로 끝나는 레이블이며 덧셈을 수행할 분기를 표시한다.
문자 상수는 정수 매개변수 `op`와 비교할 수 있다.

제공된 각 분기는 `return`으로 끝난다. 반환문은 `calc` 호출 전체를 끝내고
계산한 정수를 호출한 곳에 돌려준다. 따라서 여기서는 `break`가 필요 없다.
`return`이나 `break`가 없으면 다음 분기로 실행이 이어질 수 있다.
일치하는 분기가 없으면 switch 뒤의 `return 0;`에 도달한다.
그때 0을 반환한다고 수식을 검증한 것은 아니다.

### 정수 나눗셈과 나머지

값 배열에는 정수를 저장하므로 `/`는 정수 나눗셈을 수행한다.
`7 / 2`의 결과는 3이다. 나눗셈은 소수 부분을 버려 0에 가까운 정수를 만든다.
따라서 `-7 / 2`의 결과는 -3이다. `%`는 나머지를 계산한다.
`7 % 2`의 결과는 1이고, `-7 % 2`의 결과는 -1이다.
여기서 `%`는 산술 연산자다. 출력 형식 문자열 안의 `%d`와 역할이 다르다.

`/`와 `%`의 오른쪽 피연산자는 0이 아니어야 한다.
산술 결과도 `int`로 표현할 수 있어야 한다. 실습 코드는 유효한 산술 연산을
가정한다. 조건을 어겼을 때 이 연산자들이 오류를 나타내는 값을 반환하지는 않는다.

### 다른 소스 파일의 정의 참조하기

실행 예제는 `student/lab.c`에 정의된 배열과 함수를 사용해야 한다.
`extern char infix[8];`는 기존 배열의 이름과 자료형을 선언해 실행 예제가
그 배열을 사용할 수 있게 한다. 두 번째 배열을 새로 만들지는 않는다.
`postfix`와 `postfix_size`도 같은 규칙을 따른다. 두 소스 파일을 모두 컴파일하고
하나의 프로그램으로 연결해야 한다.

`void infix_to_postfix(void);`는 본문을 정의하지 않고 함수를 선언한다.
맨 앞의 `void`는 반환값이 없다는 뜻이고, `(void)`는 매개변수가 없다는 뜻이다.
끝의 세미콜론은 선언을 마친다. 이 형식을 **함수 원형**이라고 한다.
함수 원형은 컴파일러가 호출을 검사할 수 있게 한다.
C11에서 실습 코드처럼 `()`를 사용한 정의는 호출하는 쪽에 같은 수준의
매개변수 검사를 제공하지 않는다.

### 문자열을 출력하고 반환값 버리기

실행 예제는 저장된 문자와 계산한 답을 표시한다.
`#include <stdio.h>`는 `printf`의 선언을 제공한다.
`%s`는 널 종료 문자를 만날 때까지 문자를 출력하고, `%d`는 정수를 출력한다.
`\n`은 출력을 다음 줄로 옮긴다.

`(void)printf("postfix_size: %d\n", postfix_size);`의 `(void)`는 `printf`의 반환값을
명시적으로 버리는 형 변환이다. 호출은 그대로 실행되어 개수를 출력한다.
함수의 매개변수 목록에 쓰인 `(void)`와는 다르다.
마지막 출력 호출의 인수인 `eval_postfix()`는 `%d`로 출력할 정수를 구하도록
실행된다. 이어서 `return 0;`은 `main`을 끝내고 정상 종료를 알린다.

## C 코드

아래 블록은 현재 실습 함수를 소스 순서대로 옮긴 것이다. 읽기 편하도록 하나의 프로그램을 나누었으며, 각각 독립된 프로그램은 아니다. `lab.c`에는 `main`이 없다. 마지막 블록은 별도의 실행 예제다.

읽기 전에 `'3'`(문자), `3`(정수), `"3"`(널 종료 문자가 있는 문자열)을 구분한다. C는 숫자 문자의 값이 연속적임을 보장하므로, 숫자인지 확인한 문자에 `c - '0'`을 적용하면 해당 정수 값을 얻는다. `postfix[postfix_size++] = c`는 증가 전의 개수를 인덱스로 사용한다. `values[--value_size]`는 먼저 감소한 뒤 현재 맨 위를 선택한다.

### 문자 스택 연산

경계 검사는 정상적인 가득 찬 상태나 빈 상태에서 연산할 때 배열 밖을 참조하지 않도록 한다. 전역 변수 `size`를 임의로 바꾼 경우까지 검증하지는 않는다.

```c
char stack[10];
int capacity = 10;
int size = 0;

int is_full() {
    return size == capacity;
}

void push(char data) {
    if (is_full()) {
        return;
    }
    stack[size] = data;
    size += 1;
}

int is_empty() {
    return size == 0;
}

char peek() {
    if (is_empty()) {
        return '\0';
    }
    return stack[size - 1];
}

char pop() {
    if (is_empty()) {
        return '\0';
    }
    char data = stack[size - 1];
    size -= 1;
    return data;
}
```

### 우선순위와 수식 저장 공간

일곱 입력 토큰을 재배열하면 일곱 출력 토큰이 된다. 각 배열의 여덟 번째 칸에는 널 종료 문자를 저장한다.

```c
int prec(char op) {
    if (op == '+' || op == '-') {
        return 1;
    }
    else if (op == '*' || op == '/' || op == '%') {
        return 2;
    }
    return 0;
}

char infix[8] = "1-2*3+4";

char postfix[8] = "";
int postfix_size = 0;
```

### 중위 표기를 후위 표기로 변환하기

변환은 연산자를 계산하지 않고 출력에 기록한다. `>=` 비교는 우선순위가 같은 경우도 포함하여 좌결합성을 유지한다. 지원하는 연산자에 대해서는 빈 스택의 `peek` 반환값이 더 낮은 우선순위를 가지므로 반복이 끝난다.

```c
void infix_to_postfix() {
    postfix_size = 0;
    for (int i = 0; infix[i] != '\0'; i++) {
        char c = infix[i];

        if (c >= '0' && c <= '9') {
            postfix[postfix_size++] = c;
        }
        else {
            char op = peek();
            while (prec(op) >= prec(c)) {
                postfix[postfix_size++] = pop();
                op = peek();
            }
            push(c);
        }
    }
    while (!is_empty()) {
        postfix[postfix_size++] = pop();
    }
    postfix[postfix_size] = '\0';
}
```

### 정수 연산

뺄셈, 나눗셈, 나머지 연산에서는 인수의 순서가 중요하다. 이 소스는 나누는 수가 0이 아니며 계산 결과를 `int`로 표현할 수 있다고 가정한다.

```c
int calc(int num1, int num2, int op) {
    switch (op) {
        case '+': return num1 + num2;
        case '-': return num1 - num2;
        case '*': return num1 * num2;
        case '/': return num1 / num2;
        case '%': return num1 % num2;
    }
    return 0;
}
```

### 후위 표기 계산

숫자와 중간 계산 결과는 정수 배열에 저장한다. 각 연산자는 오른쪽 피연산자를 먼저 꺼낸 뒤 왼쪽 피연산자를 꺼낸다.

```c
int eval_postfix() {
    int values[10];
    int value_size = 0;

    for (int i = 0; i < postfix_size; i++) {
        char c = postfix[i];
        if (c >= '0' && c <= '9') {
            values[value_size++] = c - '0';
        }
        else {
            int num2 = values[--value_size];
            int num1 = values[--value_size];
            values[value_size++] = calc(num1, num2, c);
        }
    }

    return values[--value_size];
}
```

## C 코드 전체 설명 (Full C Code Explanation)

이 참고 설명은 C 코드 절의 여섯 블록을 따른다. 모든 선언과 함수를 설명하고, 각 문장을 예제 수식 `1-2*3+4`와 연결한다. 함수가 무엇을 반환하고 공유 저장 공간에서 무엇을 바꾸는지 각각 추적한다. 반환과 저장 공간의 변경은 서로 다른 결과 전달 방식이다.

### 1. 선언, 함수 호출, 공유 상태 읽기

먼저 호출이 끝난 뒤에도 유지되는 저장 공간을 찾는다. `int size = 0;`과 같은 선언은 변수를 소개하고, 자료형과 처음 값을 정한다. `postfix_size = 0;`과 같은 대입은 기존 변수의 값을 바꾼다. 세미콜론은 이러한 선언과 문장을 끝낸다. 중괄호는 함수, 조건문, 반복문에 속한 문장들을 묶는다.

함수 밖의 정의는 전역 저장 공간을 만든다. `stack`, `capacity`, `size`, `infix`, `postfix`, `postfix_size`는 프로그램이 실행되는 동안 유지된다. 초기화는 이 저장 공간을 준비할 때 이루어지며, 보조 함수를 호출할 때마다 반복되지 않는다. 모든 문자 스택 연산은 같은 `stack`과 전역 `size`를 사용한다.

반환 자료형은 함수가 호출한 곳에 무엇을 전달하는지 알려 준다. `push`와 `infix_to_postfix`의 반환 자료형은 `void`이므로, 작업 결과는 전역 변수의 변경으로 남는다. `peek`와 `pop`은 `char`를 반환한다. 나머지 실습 함수는 `int`를 반환한다. `return;`은 값을 전달하지 않고 `void` 함수를 끝낸다. `return data;`는 함수를 끝내면서 `data`의 값을 전달한다.

매개변수와 일반 지역 변수는 개별 호출에 속한다. `push(char data)`의 `data`는 전달된 문자의 복사본을 받는다. `pop`에서 같은 이름으로 선언한 지역 변수 `data`는 별개의 객체다. 변환 함수의 `i`와 `c`도 계산 함수의 같은 이름 변수와 별개다. 이름을 다시 사용한다고 함수끼리 값이 공유되지는 않는다.

함수를 정의하는 것만으로 본문이 실행되지는 않는다. 실행 예제는 `main`에서 시작하여 변환 함수를 호출하고, 저장된 문자열과 길이를 출력한 뒤 계산 함수를 호출하여 마지막 줄에 출력할 값을 얻는다. 실습 함수 자체는 아무것도 출력하지 않는다.

### 2. 문자 저장 공간: 빈 스택이 0에서 시작하는 이유

처음의 선언들은 저장 공간을 확보하고 어떤 칸을 사용 중인지 나타낸다. `char stack[10];`은 인덱스 0부터 9까지 문자 열 칸을 확보한다. 명시적인 초기값이 없는 전역 배열이므로 처음에는 모든 칸에 값이 0인 문자가 들어 있다. 스택이 비었는지는 칸의 내용이 아니라 `size`로 판단한다.

`int capacity = 10;`은 `is_full`에서 사용하는 용량을 기록한다. 별도의 정수 변수이며, 배열 크기를 바꾸는 명령이 아니다. `stack[10]`이 확보한 칸 수와 같은 값으로 유지한다.

`int size = 0;`은 첫 삽입 위치에서 시작한다. 아직 사용 중인 칸은 없다. 성공하는 첫 `push`는 `stack[0]`에 쓴 뒤 `size`를 1로 바꾼다. 항목이 세 개이면 `size`는 3이고, 사용 중인 칸은 0, 1, 2다. 항목 수는 `size`이고 맨 위 항목의 인덱스는 `size - 1`이다. 가득 차면 `size`는 10이지만 가득 찬 상태 검사로 `stack[10]`에 쓰는 것을 막는다.

### 3. `is_full`과 `push`: 확인하고, 쓰고, 옮기기

문자를 추가하기 전에 빈 칸이 있는지 확인해야 한다. `is_full`은 `size == capacity`의 결과를 반환한다. 동등 비교는 참이면 정수 1, 거짓이면 정수 0을 만든다. 변수를 바꾸거나 배열을 읽지 않고 비교만 한다.

`push(char data)`는 먼저 `is_full`을 호출한다. `if` 조건은 0을 거짓으로, 0이 아닌 값을 참으로 취급한다. 스택이 가득 찼다면 `return;`으로 호출을 즉시 끝낸다. `size`와 배열은 모두 바뀌지 않는다. `push`의 반환 자료형은 `void`이므로 성공 여부를 반환하지 않는다.

그렇지 않으면 `stack[size] = data;`로 다음 빈 칸에 문자를 복사한다. 그 뒤에 `size += 1;`로 삽입 위치를 한 칸 앞으로 옮긴다. 새 칸은 사용 중인 앞쪽 구간에 포함된다. 먼저 쓰면 현재 빈 위치를 사용한다. 그 뒤에 늘리면 해당 위치를 사용 중이라는 사실이 기록된다.

| 호출 | 호출 전 `size` | 기록하는 칸 | 호출 후 `size` |
|---|---:|---|---:|
| `push('A')` | 0 | `stack[0] = 'A'` | 1 |
| `push('B')` | 1 | `stack[1] = 'B'` | 2 |
| `push('C')` | 2 | `stack[2] = 'C'` | 3 |

닫는 중괄호에 도달하면 호출한 곳으로 제어가 돌아간다. 매개변수 `data`는 끝난 호출에 속하지만, 복사된 문자는 전역 배열에 남는다. 기존 문자는 이동하지 않는다.

### 4. `is_empty`, `peek`, `pop`: 마지막으로 사용 중인 칸 찾기

다음 문자를 읽으려면 먼저 빈 상태가 아닌지 확인해야 한다. `is_empty`는 `size == 0`의 결과를 반환한다. `is_full`처럼 저장 공간을 바꾸지 않고 1 또는 0을 반환한다.

`peek`는 배열을 참조하기 전에 `is_empty`를 호출한다. 비어 있으면 즉시 `'\0'`을 반환한다. 그렇지 않으면 `return stack[size - 1];`으로 맨 위 문자를 반환한다. 어느 경로에서도 `size`는 바뀌지 않는다. 앞의 세 번의 `push` 이후 `peek()`는 인덱스 2에서 `'C'`를 읽어 반환하고 `size`는 3으로 유지한다.

`pop`도 같은 빈 상태 검사를 사용하고, 빈 스택에서는 같은 센티널을 반환한다. 비어 있지 않으면 나머지 세 문장이 각각 다음 역할을 한다.

| 문장 | `size == 3`이고 `stack[2] == 'C'`일 때의 효과 |
|---|---|
| `size -= 1;` | `size`를 2로 바꾸어 인덱스 2를 사용 중인 구간에서 제외한다. |
| `char data = stack[size];` | 꺼낸 문자 `'C'`를 지역 변수에 저장한다. |
| `return data;` | 저장해 둔 `'C'`를 반환한다. |

`size`를 줄이기 전에 `stack[size]`를 읽으면 다음 삽입 위치가 선택된다. 먼저 줄여야 이전 맨 위 칸을 읽는다. 그 칸에는 여전히 `'C'`가 남아 있다. 논리적 제거는 저장된 값을 지우지 않고 사용 중인 구간만 바꾼다. 나중의 `push`가 그 칸을 덮어쓸 수 있다.

빈 상태의 `peek`와 `pop`은 배열과 `size`를 모두 그대로 둔다. 센티널 `'\0'`만으로는 빈 상태와 일부러 저장한 널 문자를 구분할 수 없다. 변환 함수는 지원하는 연산자 문자만 저장하므로 실제 항목에는 그 값이 없다. 이러한 검사는 `0 <= size <= capacity`이고 `capacity`가 배열 길이와 같다고 가정한다.

### 5. `prec`: 연산자를 우선순위 값으로 바꾸기

변환 함수는 대기 중인 연산자 중 무엇을 꺼낼지 결정하기 위해 비교할 숫자가 필요하다. `prec(char op)`는 문자 하나를 받아 스택을 바꾸지 않고 그 숫자를 반환한다.

첫 조건 `op == '+' || op == '-'`는 우선순위가 1인 두 연산자 중 하나인지 확인한다. 참이면 `return 1;`로 호출을 즉시 끝낸다. 그렇지 않으면 `else if`가 `'*'`, `'/'`, `'%'` 중 하나인지 확인하고, 일치하면 2를 반환한다. 마지막 `return 0;`은 그 밖의 모든 문자를 처리한다.

예제 수식에서 `prec('-')`는 1이고 `prec('*')`는 2다. 빈 스택에서는 `peek()`가 `'\0'`을 반환하며 `prec('\0')`은 0이다. 따라서 지원하는 모든 입력 연산자의 우선순위는 빈 상태 센티널보다 높다. 이 성질 덕분에 변환 함수의 비교 반복은 스택이 비면 멈춘다.

지원하지 않는 문자에 0을 반환한다고 잘못된 수식을 거부하는 것은 아니다. 그런 문자가 연산자 분기로 들어가면 빈 스택의 `peek` 결과도 `0 >= 0`을 만족할 수 있어, 반복문이 출력 배열 밖까지 계속 쓸 수 있다. 앞에서 제시한 입력 가정을 반드시 지켜야 한다.

### 6. 수식 저장 공간: 문자, 길이, 널 종료 문자

수식을 저장하려면 눈에 보이는 문자와 끝을 표시할 문자를 모두 담을 공간이 필요하다. `char infix[8] = "1-2*3+4";`는 다음 여덟 칸을 만든다.

| 인덱스 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| `infix` | `'1'` | `'-'` | `'2'` | `'*'` | `'3'` | `'+'` | `'4'` | `'\0'` |

`char postfix[8] = "";`는 처음에 빈 문자열을 만든다. 첫 문자는 널 종료 문자다. 나머지 칸도 0으로 시작한다. `int postfix_size = 0;`은 아직 후위 표기 토큰이 없음을 기록한다. 여덟 칸이라는 용량과 토큰 수는 뜻이 다르다.

변환 함수는 숫자 문자를 복사하고 연산자 문자의 순서를 바꾼다. 이 단계에서는 `2 * 3`을 계산하거나 정수 결과를 저장하지 않는다. 변환이 끝나면 후위 표기의 일곱 문자는 `123*-4+`가 된다. 인덱스 7에는 널 종료 문자가 놓인다. `postfix_size`는 널 종료 문자를 제외한 7이다.

### 7. `infix_to_postfix`: 숫자를 읽고 기다리던 연산자 꺼내기

변환 함수는 현재 입력으로 새 출력을 만들어야 한다. 첫 문장인 `postfix_size = 0;`은 출력 개수를 0으로 되돌린다. 출력 배열 전체를 지우거나 `size`를 초기화하지는 않는다. 호출자는 연산자 스택이 빈 상태에서 시작해야 한다. 이전 변환이 정상적으로 끝났다면 연산자 스택은 비어 있다.

`for` 반복문은 지역 변수 `i`를 0에서 시작한다. 매 반복 전에 `infix[i] != '\0'`으로 현재 문자가 아직 수식에 속하는지 확인한다. 본문이 끝나면 `i++`가 다음 문자로 이동한다. 예제에서는 인덱스 0부터 6까지 본문을 실행하고 7에서 멈춘다. `char c = infix[i];`는 현재 문자를 지역 변수에 복사한다.

조건 `c >= '0' && c <= '9'`는 숫자 문자를 판별한다. 참이면 `postfix[postfix_size++] = c;`가 증가하기 전의 출력 개수를 인덱스로 사용해 문자를 저장한다. 문장이 끝나면 `postfix_size`는 1 커진다. 첫 반복에서는 `'1'`이 `postfix[0]`에 들어가고 `postfix_size`는 1이 된다. 숫자 문자를 읽을 때는 연산자를 스택에 넣지 않는다.

숫자가 아니면 `else` 분기는 `c`를 연산자로 취급한다. 입력의 연산자가 지원하는 다섯 종류 중 하나라는 가정에 따른다. `char op = peek();`는 현재 기다리는 연산자나 빈 스택을 나타내는 센티널을 지역 변수에 복사한다. 맨 위를 확인하는 것만으로는 아무것도 제거하지 않는다.

`while` 조건은 `prec(op)`와 `prec(c)`를 비교한다. 기다리는 연산자의 우선순위가 같거나 더 높으면 `postfix[postfix_size++] = pop();`가 연산자를 스택에서 꺼낸다. 반환된 문자는 출력 뒤에 붙는다. 다음 문장인 `op = peek();`는 지역 변수의 복사본을 갱신한다. 따라서 다음 조건은 새로 드러난 맨 위를 검사한다. 전역 스택이 바뀌어도 지역 변수는 저절로 갱신되지 않는다.

조건이 거짓이 되면 `push(c);`가 새로 들어온 연산자를 저장한다. 변환 함수는 다음 입력 문자를 처리하도록 바깥 반복문을 계속한다. `>=`는 우선순위가 같은 경우도 포함한다. 따라서 기다리던 `-`는 새로운 `+`를 저장하기 전에 꺼낸다. 우선순위가 같은 연산자는 왼쪽부터 계산하는 순서가 유지된다.

입력 인덱스 5의 `'+'`가 들어오는 과정을 통해 안쪽 반복문을 자세히 살펴보자. 지금까지 출력한 문자는 `123`이고 `postfix_size`는 3이다. 기다리는 연산자는 인덱스 0의 `'-'`와 인덱스 1의 `'*'`다. `size == 2`다.

| 단계 | 비교 또는 동작 | 지금까지 출력한 문자 | `postfix_size` | 전역 `size` |
|---|---|---|---:|---:|
| 맨 위 읽기 | `op = '*'` | `123` | 3 | 2 |
| 첫 번째 반복 | `2 >= 1`; `'*'`를 꺼낸 뒤 `'-'` 확인 | `123*` | 4 | 1 |
| 두 번째 반복 | `1 >= 1`; `'-'`를 꺼낸 뒤 `'\0'` 확인 | `123*-` | 5 | 0 |
| 반복문 나가기 | `0 >= 1`은 거짓 | `123*-` | 5 | 0 |
| 입력 연산자 저장 | `push('+')` | `123*-` | 5 | 1 |

표의 중간 출력은 그때까지 저장한 문자만 보여준다. 변환이 끝나기 전에는 널 종료 문자를 갖춘 문자열이라는 보장이 없다. 특히 변환을 반복하면 현재 개수 뒤에 이전 문자가 남아 있을 수 있다.

바깥 반복문이 마지막 숫자 문자 `'4'`를 복사하면 출력 개수는 6이다. 마지막 `while (!is_empty())`는 남아 있는 연산자를 모두 꺼낸다. 여기서는 `'+'`를 꺼내 `postfix[6]`에 저장한다. 그 결과 `postfix_size == 7`이고 `size == 0`이다. 이제 `is_empty()`가 1을 반환하고 `!1`은 0이므로 반복문이 멈춘다.

끝으로 `postfix[postfix_size] = '\0';`가 널 종료 문자를 저장한다. `postfix_size`는 증가시키지 않는다. 결과는 문자열 `123*-4+`다. 나중에 더 짧은 입력을 변환하면 앞당겨진 끝 위치에 널 종료 문자를 새로 저장한다. 따라서 뒤에 남은 이전 문자는 출력되지 않는다. 이 함수는 값을 반환하지 않는다. 결과는 전역 `postfix` 배열과 갱신된 `postfix_size`, 비어 있는 연산자 스택에 남는다. 저장할 때마다 범위를 검사하지는 않는다. 입력과 출력이 각 배열에 들어간다고 가정한다.

### 8. `calc`: 정수 연산 하나의 결과 반환하기

정수 피연산자 두 개가 준비되면 저장된 연산자로 계산해야 한다. `calc(int num1, int num2, int op)`는 왼쪽 피연산자, 오른쪽 피연산자, 연산자 코드의 복사본을 받는다. 계산 함수가 `char c`를 전달하면 문자값은 매개변수의 `int` 자료형으로 변환된다. 비교에는 여전히 `'+'`, `'-'`, `'*'`, `'/'`, `'%'`의 코드를 사용한다.

`switch (op)`는 값이 일치하는 `case` 레이블을 선택한다. 각 레이블은 계산 결과를 곧바로 반환한다. 이때 함수 전체의 실행이 끝난다. 따라서 각 반환문 뒤에 `break`가 필요하지 않다.

| 선택한 레이블 | 반환하는 식 | 예제 |
|---|---|---|
| `case '+'` | `num1 + num2` | `calc(-5, 4, '+')`는 -1을 반환한다. |
| `case '-'` | `num1 - num2` | `calc(1, 6, '-')`는 -5를 반환한다. |
| `case '*'` | `num1 * num2` | `calc(2, 3, '*')`는 6을 반환한다. |
| `case '/'` | `num1 / num2` | `calc(7, 2, '/')`는 3을 반환한다. |
| `case '%'` | `num1 % num2` | `calc(7, 2, '%')`는 1을 반환한다. |

일치하는 레이블이 없으면 `switch` 뒤의 `return 0;`에 도달한다. 제공된 코드에는 `default:` 레이블이 없다. 이때 반환하는 0은 오류 보고가 아니다. 0은 올바른 계산 결과일 수도 있다. 함수는 나누는 수가 0이 아니라고 가정한다. 나눗셈과 나머지 연산에서 필요한 몫을 포함해 모든 정수 결과를 자료형으로 표현할 수 있다고 가정한다.

### 9. `eval_postfix`: 지역 정수 스택으로 계산하기

수식을 계산할 때는 연산자 문자가 아니라 계산한 숫자를 저장해야 한다. `int values[10];`은 정수를 담을 지역 배열 열 칸을 확보한다. 전역 문자 배열과 달리 이 일반 지역 배열은 자동으로 0으로 초기화되지 않는다. 올바른 수식을 계산하면 사용하는 각 칸에 값을 먼저 저장한 뒤 읽는다.

`int value_size = 0;`은 사용할 수 있는 값의 개수를 0에서 시작한다. 사용 중인 칸은 `values[0]`부터 `values[value_size - 1]`까지다. 다음 값을 넣을 때는 `value_size` 위치에 저장한다. 값을 꺼낼 때는 `value_size`를 줄인 뒤 그 위치를 읽는다. 문자 스택과 같은 규칙이다. 이 지역 선언은 함수 안에서 전역 `value_size`를 가린다. 따라서 이 함수에서 `value_size`를 바꾸면 정수 스택에만 영향을 준다. 계산 함수는 전역 `push`나 `pop` 함수를 호출하지 않는다.

`for` 반복문은 `i`를 0에서 시작하고 `i < postfix_size`를 검사한다. 본문을 실행할 때마다 `i`를 증가시킨다. `char c = postfix[i];`는 출력 토큰 하나를 읽는다. 반복문은 널 종료 문자를 찾지 않고 저장된 개수를 사용한다. `postfix_size == 7`이면 인덱스 0부터 6까지 처리한다. 인덱스 7은 처리하지 않는다.

숫자 판별 조건은 변환 함수와 같다. 이번에는 `values[value_size++] = c - '0';`가 숫자 문자를 정수로 바꾸어 스택에 넣는다. `'3'`에서 `'0'`을 빼면 정수 3이 된다. 저장에는 증가하기 전의 `value_size`를 사용한다. 문장이 끝나면 `value_size`는 1 커진다.

숫자가 아니면 연산자이며, 사용 중인 값이 적어도 두 개라고 가정한다. `int num2 = values[--value_size];`는 `value_size`를 먼저 줄인다. 이전에 맨 위에 있던 값을 오른쪽 피연산자로 읽는다. `int num1 = values[--value_size];`는 `value_size`를 한 번 더 줄인다. 그 위치의 값을 왼쪽 피연산자로 읽는다. 각 선언은 별도의 문장이다. 따라서 오른쪽을 먼저 읽고 왼쪽을 읽는 순서가 명확하다.

`values[value_size++] = calc(num1, num2, c);`는 `calc`를 호출한다. 반환된 정수를 다음 빈 칸에 저장하고 개수를 1 늘린다. 사용한 피연산자 두 개는 결과 하나로 바뀐다. 값을 꺼내도 이전 칸은 지우지 않는다. 현재 사용 중인 앞쪽 구간만 의미가 있다.

`123*-4+`의 연산자 세 개는 다음 변화를 만든다. 개수의 변화는 시작할 때의 개수, 두 번 꺼낸 뒤의 개수, 결과를 넣은 뒤의 개수를 차례로 기록한다.

| 연산자 | 연산 전 사용 중인 값 | `num2` (오른쪽) | `num1` (왼쪽) | 계산 | `value_size`의 변화 | 연산 후 사용 중인 값 |
|---|---|---:|---:|---|---|---|
| `'*'` | 1, 2, 3 | 3 | 2 | `2 * 3 = 6` | 3 → 2 → 1 → 2 | 1, 6 |
| `'-'` | 1, 6 | 6 | 1 | `1 - 6 = -5` | 2 → 1 → 0 → 1 | -5 |
| `'+'` | -5, 4 | 4 | -5 | `-5 + 4 = -1` | 2 → 1 → 0 → 1 | -1 |

표의 뺄셈 행과 덧셈 행 사이에서 숫자 문자 `'4'`를 정수로 바꾸어 넣는다. -5와 같은 음수 중간 결과도 문자로 되돌리지 않고 정수 배열에 저장할 수 있다.

올바른 수식이라면 반복문이 끝난 뒤 `value_size == 1`이다. `return values[--value_size];`는 `value_size`를 0으로 바꾸고 `values[0]`을 읽어 -1을 반환한다. 함수 호출이 끝나면 지역 배열은 사라진다. 반환한 정수 값은 그대로 전달된다. 계산은 `postfix`, `postfix_size`, 전역 문자 스택을 바꾸지 않는다. 두 번째 호출은 새 지역 변수 `value_size`로 시작한다. 저장된 같은 수식을 다시 계산할 수 있다.

코드는 피연산자가 부족한지 검사하지 않는다. 결과가 정확히 하나 남았는지도 확인하지 않는다. 비어 있거나 형식이 잘못된 후위 표기 입력은 배열 밖을 읽게 할 수 있다. 위의 실행 과정이 성공하려면 앞서 제시한 수식 규칙과 산술 연산의 가정을 지켜야 한다.

### 10. 실행 예제: 정의를 공유하고 결과 출력하기

실습 코드는 보조 함수를 제공한다. 별도 소스 파일은 보조 함수를 호출할 프로그램의 시작점을 제공한다. 처음의 `/* ... */` 텍스트는 주석이다. 실행에는 영향을 주지 않는다. `#include <stdio.h>`는 출력에 쓰는 라이브러리 함수 `printf`의 선언을 제공한다.

`extern char infix[8];`, `extern char postfix[8];`, `extern int postfix_size;`는 저장 공간이 `lab.c`에 정의된 이름을 선언한다. 별도 배열을 만들거나 기존 값을 초기화하지 않는다. 두 소스 파일을 함께 빌드하면 링커가 이 참조를 정의에 연결한다.

`void infix_to_postfix(void);`와 `int eval_postfix(void);`는 실행 예제에서 호출하기 전에 함수를 선언한다. 이 선언들은 세미콜론으로 끝난다. 함수 본문은 없다. 앞의 자료형은 반환값을 나타낸다. 매개변수 목록의 `(void)`는 매개변수가 없음을 명시한다. 실습 코드의 이전 방식인 `()` 정의도 여기서는 인수 없이 호출한다. 그러나 C11에서 `(void)`와 같은 함수 원형 정보를 제공하지는 않는다.

`int main(void)`는 프로그램의 시작점을 정의한다. 먼저 `infix_to_postfix();`를 호출한다. 따라서 출력하는 문장을 실행하기 전에 변환 결과가 준비된다. 다음 세 번의 호출은 입력 문자열, 변환한 문자열, 토큰 수를 출력한다. `%s`는 널 종료 문자 바로 앞까지의 문자를 출력한다. `%d`는 정수를 출력한다. 각 서식 문자열 끝의 `\n`은 이후 출력을 새 줄로 옮긴다.

마지막 출력 호출은 `eval_postfix()`를 정수 인수로 전달한다. 수식 계산이 먼저 끝나고 -1을 전달한 뒤 `printf`가 결과 줄을 출력한다. 각 `printf` 호출 앞의 `(void)`는 출력 함수 자체의 반환값을 버리겠다고 명시한다. 출력을 막거나 표시할 인수를 버리는 것은 아니다.

`return 0;`은 프로그램이 성공했다는 상태로 `main`을 끝낸다. 이 0은 수식의 답인 -1과 별개다. 따라서 네 줄의 출력은 C 코드 절에 나온 대로 `1-2*3+4`, `123*-4+`, 7, -1을 보여준다.

저장소에서 빌드할 때는 `make lab-demo`로 기존 `lab.c`와 `lab_demo.c`를 함께 컴파일한다. 파일 하나로 코드를 읽고 실행해 보려면 C 코드 절의 여섯 C 코드 블록만 표시된 순서대로 이어 붙인다. 그 파일 하나만 컴파일한다. 앞에 나온 작은 저장 공간 예제는 선언이 중복되므로 다시 추가하지 않는다. 합친 파일에 이미 정의가 들어 있다면 `lab.c`를 함께 링크하지 않는다.

### 11. 상태 변화 확인하기

데모를 실행하기 전에 저장된 값으로 다음 질문에 답해 보자. 각 답은 코드의 특정 문장에서 나온다.

1. **문자 세 개를 넣은 뒤 `peek()`는 왜 `'C'`를 반환할까?**
   세 번 넣으면 `size == 3`이 되고 `stack[2]`에 `'C'`가 저장된다. `peek`는 `size`를 바꾸지 않고 `stack[size - 1]`을 읽는다.
2. **꺼낸 문자가 왜 배열에 남아 있어도 될까?**
   `pop`은 `size`를 줄인 뒤 그 위치에서 꺼낼 값을 읽는다. 사용 중인 앞쪽 구간에서 이전 칸이 제외된다. 따라서 그 칸을 지울 필요가 없다.
3. **새로 들어온 `'+'`는 왜 `'*'`와 `'-'`를 모두 꺼내게 할까?**
   두 연산자의 우선순위인 2와 1은 모두 `>= prec('+')`를 만족한다. 다시 확인한 빈 스택의 센티널은 우선순위가 0이다. 따라서 반복문이 끝난다.
4. **변환과 계산을 마친 뒤 `postfix_size`와 `size`는 왜 다를까?**
   전역 `postfix_size`는 후위 표기의 토큰 수인 7을 유지한다. 전역 `size`는 변환이 연산자를 모두 꺼낸 뒤 0이다. 지역 `size`는 사용할 수 있는 정수의 개수를 센다. 결과 하나가 남은 뒤 마지막 반환문이 그 값을 읽으면서 0이 된다. 이후 지역 변수는 사라진다.
5. **뺄셈은 왜 `6 - 1`이 아니라 `1 - 6`일까?**
   6을 먼저 꺼내 오른쪽 피연산자 `num2`에 저장한다. 1을 두 번째로 꺼내 왼쪽 피연산자 `num1`에 저장한다. `calc`는 `num1 - num2`를 계산한다.
6. **두 번째 출력이 더 짧아도 왜 이전 문자가 표시되지 않을까?**
   변환은 저장하기 전에 `postfix_size`를 초기화하고 새로운 끝에 `'\0'`을 놓는다. 널 종료 문자 뒤의 칸에는 이전 값이 남아 있을 수 있다.
