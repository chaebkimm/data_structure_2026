# 제4장. 마지막에 넣은 값부터 꺼내기

저장한 항목 중 가장 최신 항목만 읽거나 제거하는 규칙을 만들고, 그 규칙으로 수식의 계산 순서를 정해 보자.

## 논리적으로 생각해 보기

### 왜 꺼내는 순서를 따로 정할까?

스택은 저장된 항목 중 가장 최신 항목만 읽거나 제거하는 자료구조다. 항목을 추가하거나 제거할 때 다른 항목들은 제자리에 남는다. 가장 나중에 넣은 항목을 먼저 꺼내는 규칙을 **후입선출(last in, first out; LIFO)**이라고 한다.

리스트의 끝에 항목을 추가하고, 마지막 항목만 읽거나 제거하면 스택을 구현할 수 있다. 앞에 있는 항목들을 이동할 필요가 없다. 실습에서는 배열에 이 리스트를 저장하고, 저장된 항목 수로 현재 끝을 표시한다.

### 어떻게 저장할까?

실습에서는 다음 전역 변수로 스택의 상태를 나타낸다.

```c
int stack[10];
int capacity = 10;
int size = 0;
```

배열의 유효한 인덱스는 0부터 9까지다. `size`는 저장된 항목 수다. 인덱스가 0부터 시작하므로 이 개수는 다음 항목을 넣을 위치와 같다. 처음 값 `size == 0`은 스택이 비었다는 표시다. `push`는 `stack[size]`에 쓴 뒤 `size`를 늘리므로 첫 항목은 `stack[0]`에 들어간다. 다음 항목들은 인덱스 1, 2 순서로 들어간다. 스택은 인덱스가 큰 쪽으로 자란다.

`size == 3`이면 사용 중인 항목은 인덱스 0부터 2까지에 있다. 맨 위 항목은 `stack[size - 1]`, 즉 `stack[2]`이고 항목 수는 3이다. `size` 이상인 인덱스는 사용하지 않는 구간이다. 가득 찬 상태의 `size == capacity`는 배열 바로 뒤의 경계를 나타낸다. `stack[10]`은 써도 되는 칸이 아니다.

`capacity`는 가득 찬 상태를 검사할 때 사용한다. `stack[10]`이 확보한 칸 수인 10과 같아야 한다. `capacity`만 바꾸어도 배열의 크기는 바뀌지 않는다.

### 넣기, 읽기, 꺼내기는 상태를 어떻게 바꿀까?

저장할 일 세 개에 문자 `'A'`, `'B'`, `'C'`를 붙이자. 아래 목록에서는 맨 오른쪽 항목이 스택의 맨 위다. 들어온 순서와 배열 인덱스가 증가하는 순서가 같다.

| 요청 | 반환값 | 아래에서 위로 나열한 항목 | `size` | 사용 중인 인덱스 |
|---|---|---|---:|---|
| 시작 | — | 비어 있음 | 0 | 없음 |
| `push('A')` | 없음 (`void`) | A | 1 | 0 |
| `push('B')` | 없음 (`void`) | A, B | 2 | 0–1 |
| `push('C')` | 없음 (`void`) | A, B, C | 3 | 0–2 |
| `peek()` | `'C'` | A, B, C | 3 | 0–2 |
| `pop()` | `'C'` | A, B | 2 | 0–1 |
| `pop()` | `'B'` | A | 1 | 0 |
| `pop()` | `'A'` | 비어 있음 | 0 | 없음 |

`pop`은 먼저 `size`를 하나 줄인 뒤 `stack[size]`를 읽어 반환한다. `stack[--size]`가 이 순서로 동작한다. 배열 칸을 지우지는 않는다. `size`를 줄이면 이전 맨 위 칸이 사용 구간에서 빠진다. 다음 `push`가 그 칸에 새 값을 덮어쓸 수 있다.

### 가득 차거나 비어 있으면 어떻게 될까?

`size == capacity`이면 스택이 가득 찼고, `size == 0`이면 비었다. `is_full()`과 `is_empty()`는 각 조건이 참이면 1, 거짓이면 0을 반환한다. 배열과 개수를 바꾸지는 않는다.

`push`, `peek`, `pop`은 이 검사 함수를 호출하지 않는다. 호출자는 `size < capacity`일 때만 넣고, `size > 0`일 때만 읽거나 꺼내야 한다. 크기가 10일 때 넣으면 `stack[10]`에 쓰려고 한다. 크기가 0일 때 읽으면 `stack[-1]`을 읽으려고 한다. 같은 상태에서 꺼내면 `size`를 -1로 줄인 뒤 `stack[-1]`을 읽으려고 한다. 배열 범위를 벗어난 접근은 동작이 정의되지 않는다. 상태를 보존하면서 요청을 거부하거나 특별한 값을 반환하는 코드가 아니다.

빈 스택에서 읽거나 꺼내려는 요청을 **언더플로(underflow)**라고 한다. 뒤의 수식 변환은 지원하는 입력에서 이를 피하려고 바닥에 `'\0'`을 먼저 저장한다. 이렇게 특별한 역할을 맡긴 값을 **센티널(sentinel)**이라고 한다. 센티널은 실제로 저장한 항목이다. 빈 스택이 자동으로 반환하는 값이 아니다.

### 함수 호출과는 어떤 관계가 있을까?

한 함수가 실행을 잠시 멈추고 다른 함수를 호출하면, 실행 환경은 보통 이전 호출을 나중에 이어 가는 데 필요한 정보를 저장한다. 이를 **호출 프레임(call frame)**이라고 한다. 중첩된 호출은 후입선출 순서로 끝난다. 탐구 활동의 숫자 함수 ID와 이 장의 문자 표시는 그 순서를 나타내는 모형이다. 실제 호출 프레임은 아니다. 이 전역 정수 배열도 프로그램 실행 환경의 호출 스택 자체는 아니다.

### 두 스택으로 원래 수식을 어떻게 계산할까?

`1-2*3+4`를 왼쪽부터 읽으며 두 스택을 사용해 보자. 한 스택에는 기다리는 연산자를 저장하고, 다른 스택에는 숫자를 저장한다. 곱셈은 뺄셈과 덧셈보다 우선순위가 높다. `*`가 나오면 기다리던 `-`는 곱셈을 먼저 계산할 수 있도록 스택에 남아 있어야 한다.

새 연산자가 나오면 우선순위가 같거나 더 높은 대기 연산자를 먼저 계산한다. 계산할 때는 연산자를 꺼내고, 오른쪽 숫자를 먼저 꺼낸 뒤 왼쪽 숫자를 꺼내 계산한 결과를 다시 넣는다. 입력이 끝나면 남은 연산을 모두 계산한다. 아래의 각 목록은 스택의 아래에서 위 순서다. 오른쪽 끝이 가장 최신 항목이다.

| 입력 또는 동작 | 대기 연산자 | 숫자 | 이유 또는 계산 |
|---|---|---|---|
| `1` 읽기 | 비어 있음 | 1 | 첫 숫자를 저장한다. |
| `-` 읽기 | `-` | 1 | 기다릴 뺄셈 연산자를 저장한다. |
| `2` 읽기 | `-` | 1, 2 | 다음 숫자를 저장한다. |
| `*` 읽기 | `-`, `*` | 1, 2 | `*`의 우선순위가 더 높으므로 `-`는 기다린다. |
| `3` 읽기 | `-`, `*` | 1, 2, 3 | `*`에 필요한 두 숫자가 준비된다. |
| `+`를 넣기 전: `*`, 3, 2 꺼내기 | `-` | 1, 6 | `*`의 우선순위가 더 높으므로 `2 * 3 = 6`을 넣는다. |
| 계속 `+`를 넣기 전: `-`, 6, 1 꺼내기 | 비어 있음 | -5 | `-`와 `+`의 우선순위가 같으므로 `1 - 6 = -5`를 넣는다. |
| 새로 들어온 `+` 저장 | `+` | -5 | 더 이상 기다리는 연산자가 없다. |
| `4` 읽기 | `+` | -5, 4 | 마지막 숫자를 저장한다. |
| 입력 끝: `+`, 4, -5 꺼내기 | 비어 있음 | -1 | `-5 + 4 = -1`을 넣는다. 최종 답이다. |

이 과정은 원래 수식을 직접 계산하는 방법이다. 어떤 연산을 기다리고 언제 계산하는지 보여 준다. 실습의 C 프로그램은 같은 계산 순서를 두 단계로 나누어 사용한다. 먼저 수식을 다시 쓰고, 그 뒤에 다시 쓴 수식을 계산한다.

### 왜 연산자를 피연산자 뒤에 둘까?

위에서 숫자는 `1`, `2`, `3`, `4` 순서로 읽었다. 계산은 `3`을 읽은 뒤 `*`, `-` 순서로 했고, `4`를 읽은 뒤 `+`를 했다. 숫자의 순서는 그대로 두고 각 연산자를 계산할 시점에 쓰면 다음과 같다.

```text
1 2 3 * - 4 +
```

다시 쓴 수식에는 각 연산을 실행할 순서가 나타난다. 여기서는 토큰을 구분하기 쉽게 공백을 넣었다. 실습 코드는 `123*-4+`로 저장한다.

`2`처럼 계산에 쓰이는 값을 **피연산자(operand)**라고 한다. `*`처럼 수행할 계산을 나타내는 기호를 **연산자(operator)**라고 한다. `2*3`처럼 연산자를 피연산자 사이에 놓는 방법은 **중위 표기(infix)**다. `23*`처럼 연산자를 뒤에 놓는 방법은 **후위 표기(postfix)**다. 이 실습에서는 숫자 문자 하나가 피연산자 하나다. `23*`는 2와 3을 곱한다는 뜻이지, 수 23을 뜻하지 않는다.

프로그램은 두 단계로 나뉜다. 변환 단계는 전역 정수 스택에 기다리는 연산자의 문자 코드를 보관하고 `eq_re`에 문자열을 쓴다. 계산 단계는 같은 스택의 개수를 초기화한 뒤 정수 피연산자와 중간 결과를 저장한다. 두 단계는 차례로 실행한다. 변환 단계에서는 산술 계산을 하지 않는다.

### 바뀐 순서로 어떻게 계산할까?

문자로 적힌 수식을 계산하려면 숫자와 중간 결과를 보관해야 한다. `123*-4+`의 문자 일곱 개는 수식을 구성하는 단위인 토큰이다. 마지막 `'\0'`은 문자열의 끝을 표시하며 계산하지 않는다. `eval_postfix()`는 `size = 0;`으로 시작하고 전역 `int stack[10]`에 숫자를 저장한다.

사용 중인 인덱스는 0부터 `size - 1`까지다. 맨 위 값은 `stack[size - 1]`이다. 별도의 지역 값 배열이나 지역 개수는 필요하지 않다. 같은 저장 공간이 단계마다 다른 내용을 담는다.

| 단계 | 전역 `stack`의 내용 | 전역 `size`의 뜻 |
|---|---|---|
| 변환 | 바닥 센티널과 대기 연산자의 문자 코드 | 센티널을 포함한 사용 중인 항목 수 |
| 계산 | 정수 피연산자와 중간 결과 | 사용 중인 숫자 값의 수 |

숫자 문자는 `c - '0'`으로 정수 값으로 바꾼다. 연산자가 나오면 정수 두 개를 꺼내 계산한 뒤 결과를 다시 넣는다. 먼저 꺼낸 값은 **오른쪽** 피연산자 `num2`다. 두 번째로 꺼낸 값은 **왼쪽** 피연산자 `num1`이다. 뺄셈, 나눗셈, 나머지 계산에서는 이 순서에 따라 결과가 달라진다.

| 후위 표기 토큰 | 동작 | 아래에서 위로 나열한 값 | `size` |
|---|---|---|---:|
| `1` | 1 넣기 | 1 | 1 |
| `2` | 2 넣기 | 1, 2 | 2 |
| `3` | 3 넣기 | 1, 2, 3 | 3 |
| `*` | `2 * 3` | 1, 6 | 2 |
| `-` | `1 - 6` | -5 | 1 |
| `4` | 4 넣기 | -5, 4 | 2 |
| `+` | `-5 + 4` | -1 | 1 |

마지막 `return pop();`은 -1을 반환하고 `size`를 0으로 만든다. 중간 결과는 정수이므로 음수이거나 한 자릿수보다 클 수 있다. 계산 단계에서는 센티널을 넣지 않는다. 0도 계산할 수 있는 숫자다.

`calc`는 `+`, `-`, `*`, `/`, `%`를 구현한다. 나눗셈은 C의 정수 나눗셈이므로 `7/2`의 결과는 3이다. 나머지 연산은 정수 나눗셈 뒤에 남는 값을 구하므로 `7%2`의 결과는 1이다. 이 연산들은 소수 부분을 가진 실수 결과를 만들지 않는다.

### 중위 표기를 후위 표기로 어떻게 바꿀까?

숫자를 계산하지 않고도 다시 쓴 순서를 만들 수 있다. 정수 스택에 기다리는 연산자의 문자 코드를 저장한다. 두 스택으로 직접 계산할 때 그 연산을 수행했을 시점에 연산자를 출력한다.

#### 어떤 연산자를 먼저 꺼낼까?

기다리는 연산자와 새 연산자의 처리 순서를 비교하려고 우선순위를 숫자로 나타낸다. `prec`는 다음 값을 반환한다.

| 문자 | 우선순위 |
|---|---:|
| `+`, `-` | 1 |
| `*`, `/`, `%` | 2 |
| `'\0'`을 포함한 나머지 문자 | 0 |

숫자 문자는 후위 표기 출력에 바로 넣는다. 새 연산자를 스택에 넣기 전에는 우선순위가 같거나 더 높은 대기 연산자를 모두 꺼내 출력에 넣는다. 같은 우선순위도 꺼내므로 같은 단계의 연산은 왼쪽부터 처리한다. 이를 **좌결합성(left associativity)**이라고 한다. `8-3-2+1`은 `((8-3)-2)+1`이라는 뜻이다.

변환은 먼저 `size`를 초기화하고 `'\0'`을 넣는다. 센티널의 우선순위 0은 지원하는 모든 연산자보다 낮다. 대기 연산자를 모두 꺼내면 `peek()`는 저장된 센티널을 읽고 비교 반복이 멈춘다. 그때도 스택에는 항목 하나가 남아 있다. 빈 스택을 읽는 것이 아니다.

#### 예제는 어떻게 변환될까?

`size`를 0으로 초기화한 뒤 바닥 센티널을 넣고 시작하자. 스택 항목은 아래에서 위 순서로 나열한다. 센티널도 항목 수에 포함한다.

| 입력 또는 동작 | 지금까지 쓴 후위 표기 문자 | 아래에서 위로 나열한 스택 | `size` | `pos` |
|---|---|---|---:|---:|
| 센티널 넣기 | 없음 | `'\0'` | 1 | 0 |
| `1` 읽기 | `1` | `'\0'` | 1 | 1 |
| `-` 읽기 | `1` | `'\0'`, `-` | 2 | 1 |
| `2` 읽기 | `12` | `'\0'`, `-` | 2 | 2 |
| `*` 읽기 | `12` | `'\0'`, `-`, `*` | 3 | 2 |
| `3` 읽기 | `123` | `'\0'`, `-`, `*` | 3 | 3 |
| `+` 읽기: `*` 꺼내기, `-` 꺼내기, `+` 넣기 | `123*-` | `'\0'`, `+` | 2 | 5 |
| `4` 읽기 | `123*-4` | `'\0'`, `+` | 2 | 6 |
| 입력 끝: `+` 꺼내기 | `123*-4+` | `'\0'` | 1 | 7 |
| 입력 끝: 센티널 꺼내기 | `123*-4+` 뒤에 `'\0'` | 비어 있음 | 0 | 8 |

입력과 출력 배열은 각각 여덟 칸이다.

```c
char eq[8] = "1-2*3+4";
char eq_re[8] = "";
```

지역 변수 `pos`는 0에서 시작하며 다음 출력 위치를 나타낸다. 변환은 `i < 7`을 사용해 인덱스 0부터 6까지 정확히 일곱 문자를 읽는다. 마지막 반복은 센티널까지 모두 꺼낸다. 센티널을 `eq_re[7]`에 쓰고 `pos`를 8로 늘린다. 문자열의 끝을 나타내는 이 문자를 **널 종료 문자(null terminator)**라고 한다. 숫자와 연산자 토큰은 일곱 개다. 종료 문자는 여덟 번째 저장 문자이며 수식 토큰은 아니다.

호출할 때마다 새 `pos`를 만들고 전역 `size`를 초기화한 뒤 새 센티널을 넣는다. 올바른 일곱 토큰 입력이면 출력 배열의 여덟 칸을 모두 덮어쓴다. 이 반복문은 더 짧은 수식을 지원하지 않는다.

### 이 실습에서는 어떤 입력을 사용할까?

제공된 프로그램은 다음 순서로 된 정확히 일곱 문자의 입력을 가정한다. `digit`은 숫자 문자 하나이고 `operator`는 연산자 하나다.

```text
digit operator digit operator digit operator digit
```

피연산자는 한 자리 숫자다. 연산자는 `+`, `-`, `*`, `/`, `%` 중 하나다. 입력은 `eq[0]`부터 `eq[6]`까지 놓이고 `eq[7]`에는 `'\0'`이 놓인다. 공백, 괄호, 단항 연산자, 여러 자리 피연산자는 사용하지 않는다. 단항 연산자는 `-3`의 부호처럼 피연산자 하나에 적용하는 연산자다. 나눗셈과 나머지 계산의 오른쪽 피연산자는 0이 아니어야 한다. 산술 결과는 `int`로 표현할 수 있어야 한다. 이 조건을 만족하는 입력을 변환한 뒤 계산한다. 각 단계가 전역 스택을 직접 초기화한다.

이 조건들은 호출자가 미리 지켜야 하는 가정이다. 함수 호출 전에 지켜야 하는 조건을 **사전 조건(precondition)**이라고 한다. `lab.c`가 이 조건들을 검사하는 것은 아니다.

- 더 짧은 입력에 `'\0'`이 먼저 나와도 반복문은 일곱 위치를 처리한다. 지원하지 않는 문자의 우선순위는 0이다. 변환은 센티널을 꺼낸 뒤 `stack[0]`보다 앞쪽을 읽을 수 있다.
- 피연산자가 부족하면 계산 중에 `stack[0]`보다 앞쪽에서 꺼낼 수 있다. 피연산자가 너무 많아도 거부하지 않는다. 마지막에 남은 개수도 검사하지 않는다.
- 가득 찬 스택에 넣기, 빈 스택 읽기, 0으로 나누기나 나머지 구하기를 막지 않는다. 정수 자료형이 표현할 수 있는 범위를 벗어나는 **정수 오버플로(integer overflow)**도 검사하지 않는다. 함수들은 오류 상태를 따로 알려 주지 않는다.

`calc`에서 어느 `case`에도 해당하지 않아 0을 반환하더라도 입력을 안전하게 검사한 것으로 해석하면 안 된다. 피연산자를 읽는 동작은 이미 끝났다. 문자와 수식 형식 검사, 피연산자 수 검사, 배열 범위 검사, 산술 오류 보고 기능은 확장 과제다. 제공된 코드에 이미 구현된 기능이 아니다.

### 각 연산은 어떤 규칙을 지켜야 할까?

연산을 정상적으로 마친 전역 정수 스택은 다음 조건을 만족해야 한다. 앞 장에서 배운 불변식을 이 스택에 적용한 것이다. 사용 중인 항목은 배열의 앞쪽에 연속해서 모인다. 이 범위를 **사용 중인 앞쪽 구간(active prefix)**이라고 부르자. `capacity`는 확보한 칸 수인 10이다.

```text
0 <= size <= capacity
사용 중인 인덱스: 0부터 size - 1까지 (size == 0이면 없음)
사용 중인 항목 수: size
size > 0일 때만 stack[size - 1]을 읽는다.
size < capacity일 때만 stack[size]에 새 항목을 쓴다.
```

호출자는 검사 없는 연산을 실행하기 전에 경계를 지켜야 한다. `push`의 `stack[size++]`는 증가 전 개수로 인덱스를 정하고 개수를 늘린다. `pop`의 `stack[--size]`는 먼저 개수를 줄이고 그 위치를 읽는다. `peek`는 `stack[size - 1]`을 읽지만 `size`를 바꾸지 않는다. 어느 연산도 기존 항목을 이동하거나 사용하지 않는 칸을 지우지 않는다.

변환은 인덱스 0부터 7까지 출력하고, 종료 문자를 저장한 뒤 `pos`는 8이 된다. 센티널은 마지막에 남은 항목을 모두 꺼낼 때까지 바닥에 남는다. 계산 중에는 `size`가 사용할 수 있는 피연산자와 중간 결과의 수다. 연산자 하나에는 값 두 개가 필요하고, 올바른 수식은 마지막 `pop` 직전에 값 하나를 남긴다. 계산 함수는 이 사실들을 검사하지 않고 성립한다고 가정한다.

## 효율 계산해보기

### 스택 연산 한 번에는 얼마나 많은 작업이 필요할까?

`push`는 한 칸에 쓰고 개수를 한 번 바꾼다. `peek`는 한 칸을 읽는다. `pop`은 개수를 한 번 줄이고 한 칸을 읽는다. 상태 검사 함수는 개수를 한 번 비교한다. 어느 연산도 기존 원소를 이동하지 않는다. 따라서 각 연산의 시간은 `O(1)`이다.

### 수식의 두 처리 단계는 왜 선형 시간일까?

`1-2*3+4`의 변환은 토큰 일곱 개를 읽고, 연산자 세 개와 센티널 하나를 넣고, 그 네 항목을 꺼낸다. 새 연산자 하나 때문에 여러 번 꺼낼 수는 있다. 하지만 같은 대기 연산자를 두 번 꺼내지는 않는다. 입력 문자가 `n`개인 버전으로 확장하면 전체 읽기와 스택 작업 시간은 `O(n)`이다. 현재 반복문은 언제나 정확히 일곱 토큰을 처리한다.

계산 단계는 후위 표기 토큰 일곱 개를 한 번씩 읽는다. 숫자 문자 네 개가 정수 네 개를 넣는다. 연산자 세 개는 각각 정수 두 개를 꺼내고 결과 하나를 넣는다. 마지막 꺼내기가 최종 결과를 반환한다. 토큰마다 필요한 작업 수가 일정하므로 일반화한 계산 시간도 `O(n)`이다.

### 저장 공간은 얼마나 확보할까?

프로그램은 정수 열 칸의 전역 배열 하나와 문자 여덟 칸의 배열 두 개를 선언한다. 변환과 계산이 같은 정수 배열을 다시 사용한다. 지역 변수는 개수와 임시 값을 담을 몇 개뿐이다. 지역 숫자 배열은 없다. 배열 길이가 고정되어 있으므로 저장 공간은 `O(1)`이다. 현재 입력은 정확히 일곱 문자다. 입력에 맞추어 배열이 커지도록 일반화하면 후위 표기 출력만으로도 `O(n)` 공간이 필요하다. 지원하는 수식 형식에 따라 스택 공간도 커질 수 있다.

## 용어 정리

아래 용어는 앞의 예제에서 이미 사용한 생각에 이름을 붙인다.
단계 B의 용어 자료는 수업 전체에서 사용하는 더 넓은 범위의 용어를 다룬다.

| 용어 | 이 장에서의 뜻 |
|---|---|
| 스택; 후입선출 (Stack; LIFO) | 남아 있는 항목 중 가장 나중에 넣은 항목을 먼저 꺼내는 접근 규칙 |
| 맨 위 (top) | 항목을 넣고 꺼내는 쪽 끝. 비어 있지 않은 스택에서는 인덱스 `size - 1`이다. |
| 넣기, 읽기, 꺼내기 (push, peek, pop) | 맨 위에 항목을 추가하거나, 맨 위 항목을 읽거나, 읽고 제거하는 동작 |
| 사용 중인 앞쪽 구간 (active prefix) | 정수 배열의 0부터 `size - 1`까지인 인덱스 구간. `size == 0`이면 비어 있다. |
| 언더플로 (underflow) | 스택이 비었는데 항목을 읽거나 꺼내려는 요청 |
| 센티널 (sentinel) | 저장한 바닥 표시. 여기서는 `'\0'`이 우선순위 비교를 멈추고 마지막에 출력의 끝을 표시한다. |
| 불변식 (invariant) | `0 <= size <= capacity`처럼 유효한 연산이 유지하는 규칙 |
| 중위 표기; 후위 표기 (infix; postfix) | 연산자를 피연산자 사이에 쓰는 표기; 연산자를 피연산자 뒤에 쓰는 표기 |
| 피연산자; 연산자 (operand; operator) | 계산할 값; 값에 적용할 연산 |
| 우선순위 (precedence) | 연산자를 먼저 처리할 순서를 정하는 기준 |
| 좌결합성 (left associativity) | 우선순위가 같은 연산자를 왼쪽부터 처리하는 성질 |
| 널 종료 문자 (null terminator) | C 문자열의 끝을 표시하는 `'\0'`. 토큰 수에는 포함하지 않는다. |
| 호출 프레임 (call frame) | 멈춘 함수 호출을 이어서 실행하는 데 필요한 실행 중 정보 |
| 사전 조건 (precondition) | 함수가 실행되기 전에 호출하는 쪽이 만족해야 하는 조건 |
| 정수 오버플로 (integer overflow) | 계산 결과가 `int`로 표현할 수 있는 범위를 벗어나는 경우 |

## 코딩 계획

같은 예제를 두 단계로 구현한다. 단계 사이에 개수를 초기화하고 전역 정수 스택을 다시 사용한다.

1. **정수 저장 공간을 준비한다.** 전역 `size`를 0으로 시작한다. `stack[size++]`로 넣고 `stack[size - 1]`로 읽고 `stack[--size]`로 꺼낸다. `size == capacity`이면 가득 찬 상태, `size == 0`이면 빈 상태다. 상태 검사 함수는 조건만 알려 준다. 각 연산이 이 함수를 자동으로 호출하지는 않는다.
2. **우선순위와 문자열을 준비한다.** `+`/`-`의 우선순위는 1, `*`/`/`/`%`의 우선순위는 2로 정한다. `eq`와 `eq_re`에 토큰 일곱 개와 종료 문자 하나를 담을 공간을 확보한다.
3. **후위 표기로 변환한다.** 지역 `pos`를 0으로 만들고, `size`를 초기화하고, `'\0'`을 넣는다. 정확히 일곱 문자를 읽는다. 숫자 문자는 복사하고 대기 연산자는 우선순위에 따라 꺼내 쓴다. 마지막에는 센티널도 꺼내 출력의 끝을 표시한다.
4. **정수 계산을 정의한다.** 지원하는 각 연산자에 대해 `num1 op num2`를 계산한다. 호출하는 쪽이 산술 연산의 사전 조건을 만족해야 한다.
5. **후위 표기를 계산한다.** `size`를 0으로 초기화한다. 정확히 일곱 토큰을 읽고 같은 `push`와 `pop`을 사용한다. 숫자 문자는 정수로 바꾼다. 연산자마다 오른쪽 피연산자부터 꺼내 계산하고 결과를 넣는다. 마지막 값을 꺼내 반환한다.
6. **실행하고 근거를 모은다.** 별도의 실행 예제를 사용한다. 후입선출 규칙, 경계 검사 함수, 우선순위, 피연산자 순서, 유효한 일곱 문자 수식의 반복 변환을 확인한다. 검사 없는 연산의 사전 조건을 벗어난 호출은 하지 않는다.

## 새로운 C 문법 설명

프로그램은 수식의 문자를 저장하고, 배열의 사용 범위 경계를 옮기고,
수행할 산술 연산을 골라야 한다. 아래 문법은 각 동작을 코드에 연결한다.
앞 장에서 배운 문법을 새로운 상황에 적용하는 부분도 있다.

### 문자, 숫자, 끝이 표시된 문자열

수식은 먼저 숫자를 문자로 저장한다. 계산할 때 그 문자를 정수로 바꾼다.
`'3'`은 문자 상수이고, `3`은 정수 값이다. `"3"`은 문자 `'3'` 뒤에
`'\0'`이 붙은 문자열이다. 작은따옴표는 문자 하나를, 큰따옴표는 문자열을
표시한다. 널 문자 `'\0'`의 값은 0이다. 숫자 문자 `'0'`과는 다르다.

`char eq[8] = "1-2*3+4";`는 수식 문자 일곱 개와 종료 문자를 담을
문자 칸 여덟 개를 확보한다. `char eq_re[8] = "";`는 여덟 칸을 모두
0으로 초기화한다. `i < 7`은 입력의 정확히 일곱 위치를 처리한다.
변환은 저장된 센티널을 꺼내 `eq_re[7]`에 쓰면서 출력의 끝을 표시한다.

숫자임을 확인한 문자는 `c - '0'`으로 정수로 바꾼다. C는 숫자 문자의 값이
연속됨을 보장하므로 `'3' - '0'`은 정수 3이 된다. 비교식의 `'+'`는
작은따옴표로 감싼 연산자 문자다. `num1 + num2`에서 따옴표가 없는 `+`는
덧셈을 수행한다.

### 조건을 묶거나 뒤집기

같은 우선순위에 여러 연산자가 속할 수 있다. `op == '+' || op == '-'`의
`||`는 논리합이다. 두 비교 중 하나 이상이 참이어야 한다.
C는 왼쪽 비교가 거짓일 때만 오른쪽 비교를 검사한다.
앞에서 배운 `c >= '0' && c <= '9'`의 `&&`는 두 비교가 모두 참이어야 한다.
왼쪽 비교가 참일 때만 오른쪽 비교를 검사한다.

마지막에 남은 항목을 꺼내는 과정은 센티널을 포함해 스택에 항목이 있는 동안 계속해야 한다.
`!is_empty()`는 논리 부정을 사용한다. `!`는 피연산자가 0이면 1을,
그렇지 않으면 0을 만든다. 빈 스택에서 `is_empty()`는 1을 반환하므로
뒤집은 조건은 거짓이 된다. `size == 0` 같은 비교도 참이면 정수 1을,
거짓이면 0을 만든다.

### 인덱스나 개수 바꾸기

넣기와 꺼내기는 경계를 한 칸씩 옮긴다. 후위 증가는 현재 값을 사용한 뒤 저장된 개수를 늘린다. 전위 감소는 저장된 개수를 줄인 뒤 그 값을 사용한다.

끝에 항목을 추가하려면 증가 전의 빈 위치가 필요하다. `stack[size++] = data;`는 `size`가 3이면 `stack[3]`에 쓰고 문장이 끝나면 `size`를 4로 남긴다. `eq_re[pos++] = c;`는 `pos`가 3이면 `eq_re[3]`에 쓰고 `pos`를 4로 남긴다. 이 지역 출력 위치는 전역 스택의 개수와 별개다.

꺼내려면 마지막으로 사용 중인 위치가 필요하다. `return stack[--size];`는 `size`가 3이면 먼저 2로 줄인다. 그 뒤 `stack[2]`를 읽어 이전 맨 위 값을 반환한다. 계산 함수는 두 피연산자에 대해 `pop()`을 서로 다른 문장에서 호출한다. 따라서 오른쪽을 왼쪽보다 먼저 꺼낸다.

### `switch`와 `case`로 계산 고르기

계산 함수는 연산자 문자에 맞는 계산 하나를 골라야 한다.
`switch (op)`는 `op`의 값을 구한 뒤 일치하는 `case` 레이블에서 실행을 시작한다.
`case '+':`는 콜론으로 끝나는 레이블이며 덧셈을 수행할 분기를 표시한다.
문자 상수는 정수 매개변수 `op`와 비교할 수 있다.

제공된 각 분기는 `return`으로 끝난다. 반환문은 `calc` 호출 전체를 끝내고
계산한 정수를 호출한 곳에 돌려준다. 따라서 여기서는 `break`가 필요 없다.
`return`이나 `break`가 없으면 다음 분기로 실행이 이어질 수 있다.
일치하는 분기가 없으면 switch 뒤의 `return 0;`에 도달한다.
그때 0을 반환한다고 수식을 검증한 것은 아니다.

### 정수 나눗셈과 나머지

값 배열에는 정수를 저장하므로 `/`는 정수 나눗셈을 수행한다.
`7 / 2`의 결과는 3이다. 나눗셈은 소수 부분을 버려 0에 가까운 정수를 만든다.
따라서 `-7 / 2`의 결과는 -3이다. `%`는 나머지를 계산한다.
`7 % 2`의 결과는 1이고, `-7 % 2`의 결과는 -1이다.
여기서 `%`는 산술 연산자다. 출력 형식 문자열 안의 `%d`와 역할이 다르다.

`/`와 `%`의 오른쪽 피연산자는 0이 아니어야 한다.
산술 결과도 `int`로 표현할 수 있어야 한다. 실습 코드는 유효한 산술 연산을
가정한다. 조건을 어겼을 때 이 연산자들이 오류를 나타내는 값을 반환하지는 않는다.

### 다른 소스 파일의 정의 참조하기

실행 예제는 `student/lab.c`에 정의된 배열과 함수를 사용해야 한다.
`extern char eq[8];`는 기존 배열의 이름과 자료형을 선언해 실행 예제가
그 배열을 사용할 수 있게 한다. 두 번째 배열을 새로 만들지는 않는다.
`eq_re`도 같은 규칙을 따른다. 두 소스 파일을 모두 컴파일하고
하나의 프로그램으로 연결해야 한다.

`void infix_to_postfix(void);`는 본문을 정의하지 않고 함수를 선언한다.
맨 앞의 `void`는 반환값이 없다는 뜻이고, `(void)`는 매개변수가 없다는 뜻이다.
끝의 세미콜론은 선언을 마친다. 이 형식을 **함수 원형**이라고 한다.
함수 원형은 컴파일러가 호출을 검사할 수 있게 한다.
C11에서 실습 코드처럼 `()`를 사용한 정의는 호출하는 쪽에 같은 수준의
매개변수 검사를 제공하지 않는다.

### 문자열을 출력하고 반환값 버리기

실행 예제는 저장된 문자와 계산한 답을 표시한다.
`#include <stdio.h>`는 `printf`의 선언을 제공한다.
`%s`는 널 종료 문자를 만날 때까지 문자를 출력하고, `%d`는 정수를 출력한다.
`\n`은 출력을 다음 줄로 옮긴다.

`(void)printf("postfix: %s\n", eq_re);`의 `(void)`는 `printf`의 반환값을
명시적으로 버리는 형 변환이다. 호출은 그대로 실행되어 후위 표기 문자열을 출력한다.
함수의 매개변수 목록에 쓰인 `(void)`와는 다르다.
마지막 출력 호출의 인수인 `eval_postfix()`는 `%d`로 출력할 정수를 구하도록
실행된다. 이어서 `return 0;`은 `main`을 끝내고 정상 종료를 알린다.

읽기 전에 `'3'`(문자), `3`(정수), `"3"`(널 종료 문자가 있는 문자열)을 구분한다. 숫자인지 확인한 문자에 `c - '0'`을 적용하면 정수 값을 얻는다. `stack[size++]`는 증가 전의 삽입 위치를 사용한다. `stack[--size]`는 먼저 감소한 뒤 이전 맨 위를 선택한다.

### 정수 스택 연산

호출하는 쪽이 배열 경계를 지켜야 한다. 가득 찬 상태와 빈 상태를 검사하는 함수는 상태만 알려 준다. 넣기, 읽기, 꺼내기는 이 검사 함수를 호출하지 않는다.

```c
int stack[10];
int capacity = 10;
int size = 0;

void push(int data) {stack[size++] = data;}

int peek() {return stack[size - 1];}
int pop() {return stack[--size];}

int is_full() {return size == capacity;}
int is_empty() {return size == 0;}
```

### 우선순위와 수식 저장 공간

기다리는 연산자에는 처리 우선순위가 필요하다. 두 수식 문자열에는 각각 토큰 일곱 개와 종료 문자 하나를 담을 공간이 필요하다.

```c
int prec(char op) {
    if (op == '+' || op == '-') {
        return 1;
    }
    else if (op == '*' || op == '/' || op == '%') {
        return 2;
    }
    return 0;
}

char eq[8] = "1-2*3+4";
char eq_re[8] = "";
```

### 중위 표기를 후위 표기로 변환하기

변환은 새 출력 위치와 저장된 바닥 센티널로 시작한다. 지원하는 연산자의 우선순위를 비교할 때 센티널이 꺼내기를 멈춘다. 마지막에는 센티널을 꺼내 출력의 끝을 표시한다.

```c
void infix_to_postfix() {
    int pos = 0;
    size = 0;
    push('\0');
    for (int i = 0; i < 7; i++) {
        char c = eq[i];

        if (c >= '0' && c <= '9') {
            eq_re[pos++] = c;
        }
        else {
            char op = peek();
            while (prec(op) >= prec(c)) {
                eq_re[pos++] = pop();
                op = peek();
            }
            push(c);
        }
    }
    while (!is_empty()) {
        eq_re[pos++] = pop();
    }
}
```

### 정수 연산

각 계산은 왼쪽 피연산자와 오른쪽 피연산자 순서로 수행한다. 호출자가 산술 연산의 사전 조건을 지켜야 한다.

```c
int calc(int num1, int num2, int op) {
    switch (op) {
        case '+': return num1 + num2;
        case '-': return num1 - num2;
        case '*': return num1 * num2;
        case '/': return num1 / num2;
        case '%': return num1 % num2;
    }
    return 0;
}
```

### 후위 표기 계산

계산 함수는 같은 전역 스택을 초기화하고 정수를 저장하는 데 다시 사용한다. 각 연산자는 오른쪽 피연산자부터 꺼낸 뒤 왼쪽을 꺼낸다.

```c
int eval_postfix() {
    size = 0;

    for (int i = 0; i < 7; i++) {
        char c = eq_re[i];
        if (c >= '0' && c <= '9') {
            push(c - '0');
        }
        else {
            int num2 = pop();
            int num1 = pop();
            push(calc(num1, num2, c));
        }
    }

    return pop();
}
```

## C 코드 전체 설명 (Full C Code Explanation)

이 참고 설명은 C 코드 절의 여섯 블록을 따른다. 모든 선언과 함수를 설명하고, 각 문장을 예제 수식 `1-2*3+4`와 연결한다. 함수가 무엇을 반환하고 공유 저장 공간에서 무엇을 바꾸는지 각각 추적한다. 반환과 저장 공간의 변경은 서로 다른 결과 전달 방식이다.

### 1. 선언, 함수 호출, 공유 상태 읽기

호출 사이에 남는 저장 공간부터 찾자. `int size = 0;` 같은 선언은 변수를 만들고 자료형과 처음 값을 정한다. `size = 0;` 같은 대입은 기존 변수를 바꾼다. 세미콜론은 문장을 끝낸다. 중괄호는 함수, 조건, 반복문의 문장들을 묶는다.

함수 밖의 정의는 전역 저장 공간을 만든다. `stack`, `capacity`, `size`, `eq`, `eq_re`는 프로그램이 실행되는 동안 남는다. 초기화는 저장 공간을 준비할 때 일어난다. 보조 함수를 호출할 때마다 반복하지 않는다. 수식의 두 단계가 같은 `stack`과 `size`를 사용한다.

반환 자료형은 호출 결과로 무엇을 주는지 알려 준다. `push`와 `infix_to_postfix`는 `void`를 반환하며 공유 저장 공간을 바꾸어 결과를 남긴다. `peek`, `pop`을 비롯한 나머지 실습 함수는 `int`를 반환한다. `return stack[--size];`는 개수를 줄이고 칸을 읽어 그 정수 값을 반환한다. 저장한 문자 코드도 정수 값이다.

매개변수와 일반 지역 변수는 호출 하나에 속한다. `push(int data)`의 `data`는 인수의 복사본을 받는다. 변환의 지역 `pos`는 출력 위치를 센다. 변환의 `i`와 `c`는 계산 함수에 있는 같은 이름의 변수와 별개다.

함수를 정의해도 본문이 즉시 실행되지는 않는다. 실행 예제는 `main`에서 시작해 변환을 호출하고 문자열을 출력한다. 마지막 출력 값을 얻으려고 계산을 호출한다. 실습 함수 자체는 출력하지 않는다.

### 2. 정수 저장 공간: 빈 스택이 0에서 시작하는 이유

처음 선언들은 공간을 확보하고 사용 중인 칸을 나타낸다. `int stack[10];`은 인덱스 0부터 9까지 정수 칸 열 개를 확보한다. 명시적 초기값이 없는 전역 배열은 모든 칸이 0으로 시작한다. 칸의 내용이 빈 상태를 결정하지는 않는다. `size`가 결정한다.

`int capacity = 10;`은 `is_full`이 사용할 용량을 기록한다. 별도의 정수 값이며 배열 크기를 바꾸는 명령이 아니다. `stack[10]`이 확보한 칸 수와 같게 유지한다.

`int size = 0;`은 저장한 항목이 없음을 나타낸다. 첫 삽입 위치는 0이다. 세 항목이 있으면 사용 중인 칸은 0, 1, 2이고 맨 위 인덱스는 `size - 1`이다. 크기가 10이면 다음 삽입 위치는 배열 밖인 `stack[10]`이므로 호출자가 넣기를 해서는 안 된다. 함수가 그 쓰기를 막지는 않는다. `'A'`, `'+'` 같은 문자 상수는 정수 코드로 저장할 수 있다. 계산 단계에서는 같은 칸에 -5 같은 계산 값을 저장한다.

### 3. `is_full`과 `push`: 경계를 알리고 항목 넣기

호출자는 다음 항목을 넣을 자리가 있는지 검사할 수 있다. `is_full`은 `size == capacity`의 결과를 반환한다. 같으면 1이고 다르면 0이다. 저장 공간을 바꾸지 않는다. 나중의 넣기를 거부하거나 이미 잘못된 개수를 검증하지는 않는다.

`push(int data)`에는 `stack[size++] = data;`만 있다. 후위 증가는 이전 개수를 인덱스로 사용한다. 문장이 끝나면 `size`는 1 커지고 해당 칸에는 `data`의 복사본이 남는다. 반환 자료형은 `void`이므로 성공 여부를 반환하지 않는다.

| 호출 | 호출 전 `size` | 기록하는 칸 | 호출 후 `size` |
|---|---:|---|---:|
| `push('A')` | 0 | `stack[0] = 'A'` | 1 |
| `push('B')` | 1 | `stack[1] = 'B'` | 2 |
| `push('C')` | 2 | `stack[2] = 'C'` | 3 |

닫는 중괄호에 도달하면 호출한 곳으로 돌아간다. 매개변수는 끝난 호출에 속하지만, 복사한 정수는 전역 배열에 남는다. 기존 항목은 이동하지 않는다. 넣기에는 `0 <= size < capacity`가 필요하다. 함수는 쓰기 전에 `is_full`을 호출하지 않는다.

### 4. `is_empty`, `peek`, `pop`: 마지막으로 사용 중인 칸 찾기

항목을 읽거나 꺼내려면 스택이 비어 있지 않아야 한다. `is_empty`는 아무것도 바꾸지 않고 `size == 0`의 결과를 반환한다. `peek`와 `pop`은 이 검사를 자동으로 호출하지 않는다.

`peek`는 바로 `stack[size - 1]`을 반환한다. 세 번 넣은 뒤에는 `stack[2]`를 읽어 `'C'`의 정수 코드를 반환한다. `size`는 3으로 남는다.

`pop`은 바로 `stack[--size]`를 반환한다. 전위 감소는 배열 인덱스로 사용하기 전에 개수를 줄인다.

| 단계 | `size == 3`이고 `stack[2] == 'C'`일 때의 효과 |
|---|---|
| `--size` | `size`를 2로 바꾼다. |
| `stack[2]` | 인덱스 2에서 이전 맨 위를 읽는다. |
| `return` | 그 정수 값을 호출자에게 전달한다. |

이전 맨 위 칸에는 여전히 `'C'`가 남지만 사용 중인 앞쪽 구간에서 제외된다. 나중의 넣기가 덮어쓸 수 있다. `size == 0`이면 읽기는 인덱스 -1을 읽으려 한다. 꺼내기는 개수를 -1로 줄인 뒤 같은 위치를 읽으려 한다. 빈 상태 센티널을 자동으로 반환하지 않는다. 변환은 읽기를 사용하기 전에 센티널을 직접 넣어야 한다.

### 5. `prec`: 연산자를 우선순위 값으로 바꾸기

변환은 어떤 대기 연산자를 꺼낼지 정하려고 숫자로 된 우선순위가 필요하다. `prec(char op)`는 문자 하나를 받아 스택을 바꾸지 않고 우선순위를 반환한다.

첫 조건은 `op == '+' || op == '-'`를 검사하고 참이면 1을 반환한다. 다음 `else if`는 `'*'`, `'/'`, `'%'`를 검사하고 일치하면 2를 반환한다. 마지막 `return 0;`은 나머지 모든 문자를 처리한다.

예제에서 `prec('-')`는 1이고 `prec('*')`는 2다. 저장된 바닥 센티널의 `prec('\0')`은 0이다. 대기 연산자를 모두 꺼낸 뒤 읽기는 남은 센티널을 읽는다. 더 낮은 우선순위가 비교 반복을 끝낸다.

지원하지 않는 문자에 0을 반환해도 그 입력을 거부한 것은 아니다. 그런 문자는 센티널에서 `0 >= 0`을 만족할 수 있다. 센티널을 꺼낸 뒤 인덱스 -1을 읽으려고 할 수 있다. 정해진 일곱 문자 입력 형식만 사용한다.

### 6. 수식 저장 공간: 문자, 길이, 널 종료 문자

수식은 보이는 문자와 끝 표시를 모두 저장할 공간이 필요하다. `char eq[8] = "1-2*3+4";`는 다음 여덟 칸을 만든다.

| 인덱스 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| `eq` | `'1'` | `'-'` | `'2'` | `'*'` | `'3'` | `'+'` | `'4'` | `'\0'` |

`char eq_re[8] = "";`는 처음에 빈 문자열을 만든다. 여덟 칸 모두 0으로 시작한다. 출력 길이를 나타내는 별도 전역 변수는 없다. 변환은 다음 출력 인덱스를 지역 `pos`에 둔다.

변환은 숫자 문자를 복사하고 연산자의 순서를 바꾼다. `2 * 3`을 계산하지는 않는다. 끝나면 `eq_re[0]`부터 `eq_re[6]`까지는 `123*-4+`를 담는다. `eq_re[7]`에 꺼내 쓴 센티널이 문자열을 끝낸다. 지역 `pos`는 마지막 저장 문자까지 포함하므로 8에 도달한다.

### 7. `infix_to_postfix`: 숫자를 읽고 기다리던 연산자 꺼내기

변환은 현재 입력으로 새 출력을 만들어야 한다. `int pos = 0;`은 지역 출력 위치를 만든다. `size = 0;`은 기존 전역 스택의 사용 중인 항목을 모두 제외한다. `push('\0');`은 바닥 센티널을 저장하고 `size`를 1로 만든다. 호출자가 스택을 먼저 비울 필요는 없다.

`for` 반복은 `i`를 0으로 시작하고 `i < 7`을 검사한 뒤 본문 실행마다 `i`를 늘린다. `eq[0]`부터 `eq[6]`까지 정확히 일곱 문자를 읽는다. 입력의 종료 문자를 찾지 않는다. `char c = eq[i];`는 현재 문자를 복사한다.

`c >= '0' && c <= '9'`이면 `eq_re[pos++] = c;`가 이전 출력 위치에 숫자를 쓰고 `pos`를 늘린다. 첫 숫자는 `eq_re[0]`에 들어가고 `pos == 1`이 된다. 숫자 문자는 스택을 바꾸지 않는다.

그렇지 않으면 입력 가정에 따라 `c`는 지원하는 연산자다. `char op = peek();`는 기다리는 맨 위나 저장된 센티널을 복사한다. `prec(op) >= prec(c)`이면 `eq_re[pos++] = pop();`이 해당 연산자를 출력 뒤에 붙인다. `op = peek();`는 다음 비교 전에 지역 복사본을 갱신한다. 전역 스택이 바뀌어도 지역 복사본이 저절로 바뀌지는 않는다.

비교가 거짓이 되면 `push(c);`가 새 연산자를 저장한다. `>=`는 같은 우선순위도 포함하므로 이전 `-`는 새 `+`를 넣기 전에 꺼낸다. 같은 우선순위 연산자를 왼쪽부터 처리하는 순서가 유지된다.

입력 인덱스 5를 읽기 직전에 출력은 `123`이고 `pos`는 3이다. 스택에는 인덱스 0의 센티널, 인덱스 1의 `'-'`, 인덱스 2의 `'*'`가 있다. 개수는 센티널을 포함해 3이다.

| 단계 | 비교 또는 동작 | 지금까지 출력한 문자 | `pos` | 전역 `size` |
|---|---|---|---:|---:|
| 맨 위 읽기 | `op = '*'` | `123` | 3 | 3 |
| 첫 번째 반복 | `2 >= 1`; `'*'`를 꺼낸 뒤 `'-'` 확인 | `123*` | 4 | 2 |
| 두 번째 반복 | `1 >= 1`; `'-'`를 꺼낸 뒤 `'\0'` 확인 | `123*-` | 5 | 1 |
| 반복문 나가기 | `0 >= 1`은 거짓 | `123*-` | 5 | 1 |
| 입력 연산자 저장 | `push('+')` | `123*-` | 5 | 2 |

표는 지금까지 쓴 문자만 보여 준다. 특히 반복 변환 중에는 중간 출력이 널 종료 문자열이라는 보장이 없다.

마지막 숫자 `'4'` 뒤에 `pos`는 6이다. 마지막 `while (!is_empty())`는 `'+'`를 꺼내 `eq_re[6]`에 쓰고 `size == 1`, `pos == 7`을 남긴다. 센티널이 남았으므로 한 번 더 실행한다. 센티널을 꺼내 `eq_re[7]`에 `'\0'`을 쓰면 `size == 0`, `pos == 8`이 된다. 이제 `is_empty()`가 1을 반환하고 `!1`이 0이 되어 반복이 끝난다.

반복문 뒤에 별도의 종료 문자 대입은 없다. 이제 `eq_re[pos]`에 쓰면 배열 밖인 인덱스 8을 사용하게 된다. 함수는 값을 반환하지 않는다. 완성한 문자열은 전역 `eq_re`에 남고 지역 `pos`는 호출과 함께 끝난다. 올바른 반복 변환은 여덟 칸을 모두 쓴다. 입력 반복이 일곱 위치를 읽으므로 더 짧은 수식은 지원하지 않는다.

### 8. `calc`: 정수 연산 하나의 결과 반환하기

정수 피연산자 두 개가 준비되면 저장된 연산자로 계산해야 한다. `calc(int num1, int num2, int op)`는 왼쪽 피연산자, 오른쪽 피연산자, 연산자 코드의 복사본을 받는다. 계산 함수가 `char c`를 전달하면 문자값은 매개변수의 `int` 자료형으로 변환된다. 비교에는 여전히 `'+'`, `'-'`, `'*'`, `'/'`, `'%'`의 코드를 사용한다.

`switch (op)`는 값이 일치하는 `case` 레이블을 선택한다. 각 레이블은 계산 결과를 곧바로 반환한다. 이때 함수 전체의 실행이 끝난다. 따라서 각 반환문 뒤에 `break`가 필요하지 않다.

| 선택한 레이블 | 반환하는 식 | 예제 |
|---|---|---|
| `case '+'` | `num1 + num2` | `calc(-5, 4, '+')`는 -1을 반환한다. |
| `case '-'` | `num1 - num2` | `calc(1, 6, '-')`는 -5를 반환한다. |
| `case '*'` | `num1 * num2` | `calc(2, 3, '*')`는 6을 반환한다. |
| `case '/'` | `num1 / num2` | `calc(7, 2, '/')`는 3을 반환한다. |
| `case '%'` | `num1 % num2` | `calc(7, 2, '%')`는 1을 반환한다. |

일치하는 레이블이 없으면 `switch` 뒤의 `return 0;`에 도달한다. 제공된 코드에는 `default:` 레이블이 없다. 이때 반환하는 0은 오류 보고가 아니다. 0은 올바른 계산 결과일 수도 있다. 함수는 나누는 수가 0이 아니라고 가정한다. 나눗셈과 나머지 연산에서 필요한 몫을 포함해 모든 정수 결과를 자료형으로 표현할 수 있다고 가정한다.

### 9. `eval_postfix`: 전역 스택을 정수 계산에 다시 사용하기

계산에는 피연산자와 결과를 담을 정수가 필요하다. 전역 배열이 이미 `int`이므로 `size = 0;`으로 같은 공간을 계산에 사용할 준비를 한다. 센티널은 넣지 않는다. 사용 중인 앞쪽 구간만 의미가 있다. 올바른 계산은 사용할 각 칸에 숫자를 먼저 쓰고 나중에 읽는다.

반복문은 `i`를 0으로 시작해 `i < 7`을 검사하고 본문마다 늘린다. `char c = eq_re[i];`는 출력 토큰 하나를 읽는다. 인덱스 0부터 6까지 정확히 처리한다. 인덱스 7의 종료 문자는 계산하지 않는다.

숫자이면 `push(c - '0');`가 문자를 정수로 바꾸어 다음 스택 칸에 넣는다. `'3' - '0'`은 정수 3이다.

연산자는 사용 중인 값이 적어도 두 개라고 가정한다. `int num2 = pop();`이 맨 위를 오른쪽 피연산자로 꺼낸다. `int num1 = pop();`이 그다음 값을 왼쪽 피연산자로 꺼낸다. 별도 문장이므로 순서가 정해진다. `push(calc(num1, num2, c));`가 계산한 결과를 같은 스택에 넣는다. 피연산자 두 개가 결과 하나로 바뀐다.

`123*-4+`의 연산자 세 개는 다음 변화를 만든다.

| 연산자 | 연산 전 사용 중인 값 | `num2` (오른쪽) | `num1` (왼쪽) | 계산 | `size`의 변화 | 연산 후 사용 중인 값 |
|---|---|---:|---:|---|---|---|
| `'*'` | 1, 2, 3 | 3 | 2 | `2 * 3 = 6` | 3 → 2 → 1 → 2 | 1, 6 |
| `'-'` | 1, 6 | 6 | 1 | `1 - 6 = -5` | 2 → 1 → 0 → 1 | -5 |
| `'+'` | -5, 4 | 4 | -5 | `-5 + 4 = -1` | 2 → 1 → 0 → 1 | -1 |

뺄셈과 덧셈 사이에는 숫자 `'4'`를 정수 4로 바꾸어 넣는다. -5 같은 음수 중간 결과도 정수로 남는다.

올바른 수식은 반복문 뒤에 `size == 1`을 남긴다. `return pop();`이 개수를 0으로 줄이고 `stack[0]`을 읽어 -1을 반환한다. 전역 배열은 남지만 모든 칸이 사용 중인 구간에서 제외된다. `eq`와 `eq_re`는 바뀌지 않는다. 다시 호출하면 개수를 초기화하고 같은 저장된 출력을 계산할 수 있다.

코드는 피연산자가 부족한지 검사하지 않는다. 결과가 정확히 하나 남았는지도 확인하지 않는다. 이 함수를 호출하기 전에 일곱 토큰 형식과 산술 연산의 가정을 지켜야 한다.

### 10. 실행 예제: 정의를 공유하고 결과 출력하기

실습은 보조 함수를 제공한다. 별도 소스 파일은 그 함수를 호출할 시작점을 제공한다. 처음의 `/* ... */`는 주석이며 실행에 영향을 주지 않는다. `#include <stdio.h>`는 출력 함수 `printf`를 선언한다.

`extern char eq[8];`와 `extern char eq_re[8];`는 저장 공간이 `lab.c`에 정의된 이름을 선언한다. 새 배열을 만들거나 초기화하지 않는다. 두 파일을 함께 빌드하면 링커가 참조를 정의에 연결한다.

`void infix_to_postfix(void);`와 `int eval_postfix(void);`는 사용 전에 함수를 선언한다. 세미콜론으로 끝나며 본문은 없다. 앞의 자료형은 반환값을 나타낸다. `(void)`는 매개변수가 없음을 명시한다. 실습의 이전 방식인 `()` 정의도 여기서는 인수 없이 호출한다. 그러나 C11에서 같은 원형 정보를 제공하지는 않는다.

`int main(void)`는 시작점을 정의한다. 첫 호출은 변환을 수행한다. 다음 두 호출은 입력과 출력 문자열을 표시한다. `%s`는 널 종료 문자 직전까지 출력하며 종료 문자 자체는 출력하지 않는다. 마지막 호출은 `eval_postfix()`에서 정수를 얻어 `%d`로 출력한다. 각 `\n`은 새 출력 줄을 시작한다.

각 `printf` 앞의 `(void)`는 그 함수의 반환값을 명시적으로 버린다. 호출을 막거나 출력할 인수를 버리지 않는다. `return 0;`은 정상 상태로 `main`을 끝낸다. 수식 결과 -1과 별개다. 세 줄은 `1-2*3+4`, `123*-4+`, -1을 표시한다.

저장소의 `make lab-demo`는 `lab.c`와 `lab_demo.c`를 함께 컴파일한다. 파일 하나로 읽고 실행하려면 C 코드 절의 여섯 C 블록만 표시된 순서대로 이어 붙여 그 파일만 컴파일한다. 앞에 나온 작은 저장 공간 예제를 더하면 정의가 중복된다. 합친 파일에 정의가 이미 있으면 `lab.c`도 함께 링크하지 않는다.

### 11. 상태 변화 확인하기

데모를 실행하기 전에 저장된 값으로 다음 질문에 답해 보자. 각 답은 코드의 특정 문장에서 나온다.

1. **세 번 넣은 뒤 `peek()`는 왜 `'C'`를 반환할까?**
   개수는 3이고 `stack[2]`에 `'C'`가 있다. 읽기는 개수를 바꾸지 않고 `stack[size - 1]`을 읽는다.
2. **꺼낸 값이 왜 배열에 남아 있어도 될까?**
   꺼내기는 먼저 `size`를 줄이고 그 위치에서 이전 맨 위를 읽는다. 해당 칸은 사용 중인 앞쪽 구간 밖이므로 지울 필요가 없다.
3. **새로 들어온 `'+'`는 왜 `'*'`와 `'-'`를 모두 꺼내게 할까?**
   우선순위 2와 1이 모두 `>= prec('+')`를 만족한다. 남아 있는 저장된 센티널은 우선순위가 0이므로 비교를 멈춘다.
4. **변환이 왜 `pos == 8`, `size == 0`으로 끝날까?**
   토큰 문자 일곱 개와 종료 문자 하나를 썼다. 마지막 반복이 연산자와 센티널을 모두 꺼냈다. 계산 중에는 같은 `size`가 정수의 개수를 세고 마지막 결과 꺼내기 뒤에 다시 0이 된다.
5. **뺄셈은 왜 `6 - 1`이 아니라 `1 - 6`일까?**
   첫 꺼내기가 6을 오른쪽 피연산자 `num2`에 넣는다. 두 번째가 1을 왼쪽 피연산자 `num1`에 넣는다. `calc`는 `num1 - num2`를 계산한다.
6. **다른 일곱 문자 입력이 왜 이전 출력을 바꿀 수 있을까?**
   변환은 새 지역 `pos`를 만들고, `size`를 초기화하고, 새 센티널을 넣는다. 출력의 여덟 칸을 모두 쓴다. 더 짧은 입력은 반복문의 고정 길이 사전 조건을 만족하지 않는다.
