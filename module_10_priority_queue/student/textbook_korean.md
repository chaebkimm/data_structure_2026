# 10장. 우선순위에 따라 선택하기

큐는 데이터가 들어온 순서대로 처리한다. 때로는 우선순위가 가장 높은 데이터가 필요하다. 이를 위한 간단한 자료구조를 구현해 본다. 예제로 유저들의 접속 계획을 보고 모두 접속해 있을 가장 이른 시간을 찾아본다.

## 논리적으로 생각해 보기

### 우선순위가 가장 높은 데이터를 먼저 처리하려면 어떤 자료구조가 맞을까?

큐나 스택과 비슷한 자료구조가 맞다. 데이터가 들어와 기다리다가 하나씩 나온다. 다음에 꺼낼 데이터를 정하는 규칙만 달라진다. 이제는 우선순위가 가장 높은 데이터가 먼저 나온다.

### 간단한 자료구조를 어떻게 구현할까?

이제 들어온 순서가 다음에 꺼낼 데이터를 정하지 않는다. 데이터를 우선순위 순서로 저장하면 맨 앞의 데이터가 항상 다음에 꺼낼 데이터가 된다.

### 현재 데이터의 위치는 어떻게 나타낼까?

기다리는 데이터는 배열에 우선순위 순서로 저장되어 있다. 우선순위가 가장 높은 데이터는 `front`에, 가장 낮은 데이터는 `rear`에 있다. 데이터를 꺼내면 `front`가 증가하고, 새 데이터를 넣으면 `rear`가 증가한다.

### 빈 자료구조의 위치는 어떻게 나타낼까?

기다리는 데이터가 하나뿐이면 `front`와 `rear`는 같은 위치다. 그 데이터를 꺼내면 `front`가 증가하므로, `front`가 `rear`보다 한 칸 뒤에 있으면 자료구조가 비어 있다.

### 새 데이터가 들어갈 자리는 어떻게 찾을까?

새 데이터보다 우선순위가 낮은 데이터는 모두 새 데이터의 오른쪽에 있어야 한다. 따라서 그 데이터들을 한 칸씩 오른쪽으로 옮기고, 비워진 위치에 새 데이터를 넣는다.

### 우선순위가 가장 높은 데이터는 어떻게 꺼낼까?

우선순위가 가장 높은 데이터는 `front`에 있으므로, 그 데이터를 꺼낸다.

### 각 유저의 로그인과 로그아웃 계획이 주어지면 언제 모두 미팅할 수 있을까?

모든 유저가 로그인했고 아직 아무도 로그아웃하지 않은 시간에 미팅할 수 있다. 각 유저는 여러 번 로그인하고 로그아웃할 계획이며, 모두 접속해 있을 가장 이른 시간을 찾는다.

### 문제를 풀려면 어떤 핵심 정보를 추적해야 할까?

각 유저의 로그인과 로그아웃을 한 쌍씩 살펴보며, 첫 번째 쌍부터 시작한다. 이 중 가장 늦은 로그인 시간과 가장 이른 로그아웃 시간을 추적하려고 한다. 가장 늦은 로그인 시간이 되면 모두 로그인했고, 가장 이른 로그아웃 시간 전까지는 아무도 로그아웃하지 않았다. 가장 이른 로그아웃 시간이 가장 늦은 로그인 시간보다 늦으면, 가장 늦은 로그인 시간을 미팅 시간으로 정할 수 있다.

### 각 유저의 현재 로그인과 로그아웃으로 미팅할 수 없으면 무엇이 바뀔까?

시간이 흐르면 로그아웃 시간이 가장 이른 유저가 로그아웃한다. 그러면 그 유저의 다음 로그인과 로그아웃 계획으로 넘어간다. 가장 이른 로그아웃 시간과 가장 늦은 로그인 시간을 갱신하고 다시 비교한다.

### 가장 늦은 로그인 시간은 어떻게 갱신할까?

로그인 시간이 가장 늦은 유저는 다음 계획으로 넘어가는 유저일 수 없다. 같은 유저라면 가장 늦은 로그인 시간이 가장 이른 로그아웃 시간보다 빨라서 이미 미팅할 수 있었을 것이다. 따라서 가장 늦은 로그인 시간은 여전히 현재 살펴보는 로그인 중에 있다. 새 로그인 시간과 비교해서 더 늦은 시간만 고르면 된다.

### 가장 이른 로그아웃 시간은 어떻게 갱신할까?

로그아웃 시간이 가장 이른 유저가 다음 계획으로 넘어갔으므로, 이제 어느 유저의 로그아웃 시간이 가장 이른지 찾아야 한다. 유저들을 로그아웃 순서로 저장해 두면 다음으로 가장 이른 로그아웃을 바로 알 수 있다. 이를 위해 앞에서 자료구조를 만들었다.

## 효율 계산해 보기

### 새 데이터를 넣는 작업량은 얼마나 될까?

데이터가 n개 기다리고 있다고 하자. 새 데이터의 우선순위가 가장 높으면 n개 모두와 비교하고 n개 모두를 옮긴다. 따라서 데이터를 넣을 때 최대 n번 비교하고 n개를 옮기며, 작업량은 기다리는 데이터의 양에 따라 늘어난다.

### 데이터를 꺼내는 작업량은 얼마나 될까?

일정한 양의 작업만 필요하다. 우선순위가 가장 높은 데이터가 이미 `front`에 있으므로, 기다리는 데이터가 아무리 많아도 비교하거나 옮기는 데이터는 없다.

### 가장 늦은 로그인을 찾는 작업량은 얼마나 될까?

계획에 있는 각 로그인 시간은 가장 늦은 로그인 시간과 최대 한 번 비교한다. 첫 로그인들은 시작할 때 비교하고, 그 뒤의 로그인은 해당 유저가 다음 계획으로 넘어갈 때 비교한다. 따라서 작업량은 계획에 있는 로그인 하나당 최대 한 번의 비교다.

### 가장 이른 로그아웃을 찾는 작업량은 얼마나 될까?

계획에 있는 각 로그아웃 시간마다 해당 유저를 자료구조에 최대 한 번 넣는다. 그때마다 비교하고 옮기는 횟수는 유저 수보다 적다. 따라서 작업량은 최대 계획에 있는 로그아웃 수에 유저 수를 곱한 만큼이다.

### 저장 공간은 얼마나 필요할까?

`front` 앞의 위치는 다시 사용하지 않으므로, 유저를 넣을 때마다 새 위치를 사용한다. 한 번에 기다리는 유저는 최대 전체 유저 수만큼이지만, 배열에는 계획에 있는 로그아웃 시간마다 한 칸씩 필요하다.

## 용어 정리

### 우선순위

다음에 꺼낼 데이터를 정하는 기준이다. 미팅 문제에서는 더 일찍 로그아웃하는 유저의 우선순위가 더 높다.

### 우선순위 큐

들어온 순서와 관계없이 우선순위가 가장 높은 데이터가 다음에 나오는 자료구조다. 이 장에서 말하는 ‘자료구조’가 바로 우선순위 큐다.

### 넣기 (Enqueue)

큐나 우선순위 큐에 새 데이터를 넣는 것이다. 여기서는 우선순위 순서에 맞는 자리에 새 데이터를 넣는다.

### 꺼내기 (Dequeue)

큐나 우선순위 큐에서 데이터를 꺼내는 것이다. 우선순위 큐에서는 우선순위가 가장 높은 데이터를 꺼낸다.

### Front

다음에 나올 데이터의 위치다. 여기에는 우선순위가 가장 높은 데이터가 있다.

### Rear

마지막으로 기다리는 데이터의 위치다. 여기에는 우선순위가 가장 낮은 데이터가 있다.

### 접속 회차

한 유저에 대해 현재 살펴보는 로그인과 로그아웃 쌍의 번호이며, `0`부터 센다.

## 규칙

### 기다리는 데이터에 대해 항상 참인 것은 무엇일까?

기다리는 데이터는 우선순위 순서로 저장되어 있다. 어떤 데이터도 그 앞의 데이터보다 우선순위가 높지 않다. 처음에는 데이터가 없으므로 이 규칙이 참이다. 데이터를 넣을 때는 우선순위가 같거나 더 높은 모든 저장된 데이터 뒤에 새 데이터를 놓으므로 이 규칙이 유지된다. 데이터를 꺼낼 때는 맨 앞의 데이터를 없애도 나머지는 순서대로 남으므로 이 규칙이 유지된다. 따라서 데이터가 기다리고 있을 때 우선순위가 가장 높은 데이터는 항상 `front`에 있다.

### front와 rear에 대해 항상 참인 것은 무엇일까?

기다리는 데이터는 정확히 `front`부터 `rear`까지의 위치에 있다. 따라서 `front`는 `rear`보다 한 칸을 넘어서 뒤에 있지 않는다. 둘 다 증가하기만 한다. 데이터를 넣으면 `rear`가 증가하고, 데이터를 꺼내면 `front`가 증가한다. 두 가지 가정이 이 규칙을 유지한다. `rear` 다음에 빈자리가 있을 때만 데이터를 넣고, 데이터가 있을 때만 꺼낸다.

### 로그아웃 시간이 바뀌어도 순서가 유지되는 이유는 무엇일까?

유저의 로그아웃 시간은 그 유저가 다음 계획으로 넘어갈 때만 바뀌며, 그때는 이미 그 유저를 꺼낸 뒤다. 아직 기다리는 유저들의 로그아웃 시간은 바뀌지 않으므로 순서가 유지된다.

### 미팅 시간을 찾는 동안 항상 참인 것은 무엇일까?

가장 늦은 로그인 시간 전에는 미팅할 수 없다. 처음에는 그 시간 전에 마지막으로 로그인하는 유저가 아직 로그인하지 않았으므로 이 규칙이 참이다. 한 유저가 다음 계획으로 넘어가면, 그 유저는 가장 이른 로그아웃 시간부터 새 로그인 시간까지 로그아웃해 있다. 따라서 새 로그인 시간 전에도 미팅할 수 없다. 그러므로 가장 이른 로그아웃 시간이 가장 늦은 로그인 시간보다 늦으면, 가장 늦은 로그인 시간은 단지 미팅할 수 있는 시간이 아니라 미팅할 수 있는 가장 이른 시간이다.

## 코딩 계획

### 우선순위 큐에는 어떤 데이터가 필요할까?

기다리는 데이터를 담을 배열과 두 위치 `front`, `rear`가 필요하다. 배열에는 계획에 있는 로그아웃 시간마다 한 칸씩 필요하다. 각 데이터는 유저 전체다. 유저 번호, 현재 살펴보는 로그인과 로그아웃 쌍의 번호, 그리고 그 두 시간을 담는다.

### 우선순위 큐를 초기화하려면 무엇을 해야 할까?

`front`를 `0`, `rear`를 `-1`로 설정한다. 첫 데이터는 `0`번 위치에 들어가야 하고, 데이터를 넣으면 `rear`가 증가하므로 `rear`는 `-1`에서 시작한다. 큐는 빈 상태로 시작하며, `front`가 `rear`보다 한 칸 뒤에 있으면 비어 있으므로 `front`는 `0`에서 시작한다.

### 새 데이터를 넣으려면 무엇을 해야 할까?

배열의 `rear` 다음에 빈자리가 있다고 가정한다. `rear`에 있는 데이터부터 새 데이터와 비교한다. 새 데이터의 우선순위가 더 높으면 저장된 데이터를 바로 다음 위치로 옮기고, 그 앞의 데이터로 넘어간다. 저장된 데이터의 우선순위가 같거나 더 높으면 멈춘다. 또는 `front`에 있는 데이터까지 지나면 멈추므로 `front` 앞의 위치까지 찾아가지 않는다. 비교하기 전에 `front`를 지났는지 확인한다. 그러면 데이터가 하나도 없을 때 첫 비교 전에 탐색이 멈추고, 비워 둔 위치는 `rear` 바로 다음의 빈자리가 된다. 비워 둔 위치에 새 데이터를 넣고 `rear`를 증가시킨다.

### 데이터를 꺼내려면 무엇을 해야 할까?

꺼낼 데이터가 있다고 가정한다. `front`에 있는 데이터를 꺼내고 `front`를 증가시킨다. 꺼낸 데이터가 있던 위치는 큐를 다시 초기화하기 전까지 사용하지 않는다. 따라서 배열에는 한 번에 기다리는 데이터뿐 아니라 들어오는 모든 데이터를 담을 공간이 필요하다.

### 미팅 문제에는 어떤 데이터가 필요할까?

유저마다 한 행씩 두고, 각 행에 그 유저의 로그인과 로그아웃을 쌍으로 묶어 시간순으로 담은 계획 표가 필요하다. 큐에 있는 각 유저는 자신의 번호, 현재 살펴보는 쌍의 번호, 그리고 그 쌍의 복사본을 담는다.

### 우선순위 큐에는 어떤 규칙을 줄까?

더 일찍 로그아웃하는 유저의 우선순위가 더 높다. 따라서 여기서는 시간이 가장 작은 유저의 우선순위가 가장 높다. 규칙은 두 유저를 받아 각 유저가 담고 있는 로그아웃 시간을 비교한다.

### 미팅 시간 찾기를 시작하려면 무엇을 해야 할까?

우선순위 큐를 초기화하고, 계획의 첫 로그인과 로그아웃을 담은 모든 유저를 넣는다. 어떤 시간보다도 작은 `-1`에서 시작해 큐에 있는 모든 유저의 로그인 시간을 비교하여 가장 늦은 로그인 시간을 찾는다. 유저 하나를 꺼낸다. 그 유저의 로그아웃 시간이 가장 이르다.

### 미팅할 수 있는지는 어떻게 확인할까?

가장 이른 로그아웃 시간이 가장 늦은 로그인 시간보다 늦으면, 가장 늦은 로그인 시간이 미팅 시간이다.

### 미팅할 수 없는 동안에는 무엇을 해야 할까?

로그아웃 시간이 가장 이른 유저의 다음 로그인과 로그아웃 계획으로 넘어간다. 다음 계획이 없으면 미팅할 수 있는 시간도 없으므로 끝낸다. 새 로그인 시간이 가장 늦은 로그인 시간보다 늦으면, 그 시간이 가장 늦은 로그인 시간이 된다. 유저를 다시 넣고 다음 하나를 꺼낸 뒤 다시 확인한다.

## 새로운 C 문법 설명

### 구조체 안에 다른 구조체를 어떻게 담을까?

구조체의 멤버도 구조체일 수 있다. 유저는 현재 로그인과 로그아웃을 하나의 `struct Session`으로 담는다. `out.now.logout`처럼 점 두 개를 써서 시간에 접근한다.

```c
struct Session {
	int login;
	int logout;
};

struct User {
	int id;
	int epoch;
	struct Session now;
};
```

### 구조체를 대입하거나 전달하면 어떻게 될까?

`int`와 마찬가지로 값 전체가 복사된다. 유저를 `compare`나 `enqueue`에 전달할 때, `dequeue`나 `next_epoch`에서 반환받을 때, 그리고 `u.now = plans[u.id][ep];`를 실행할 때 모두 복사본이 만들어진다. 이 중 어느 것도 계획 표를 바꾸지 않는다.

### 구조체를 만들 때 일부 멤버만 어떻게 설정할까?

점으로 각 멤버의 이름을 지정한다. 지정하지 않은 멤버는 `0`이 된다.

```c
struct User u = {.epoch = 0};
```

## C 코드

### 우선순위 큐 구현

#### 유저와 현재 로그인 및 로그아웃

```c
enum { IDS = 3, EPOCHS = 3 };

struct Session {
	int login;
	int logout;
};

struct User {
	int id;
	int epoch;
	struct Session now;
};
```

#### 우선순위 큐

```c
/* Slots are never reused: one slot for every enqueue, one per session */
struct User pq[IDS * EPOCHS];
int front, rear;
```

#### 우선순위 큐 초기화하기

```c
void init_pqueue(void) {
	front = 0;
	rear = -1;
}
```

#### 더 일찍 로그아웃하는 유저의 우선순위가 더 높다

```c
/* Nonzero if x has higher priority; strict <, so ties keep arrival order */
int compare(struct User x, struct User y) {
	return x.now.logout < y.now.logout;
}
```

#### 우선순위 큐에 데이터 넣기

```c
void enqueue(struct User user) {
	int i = rear + 1;
	/* Test front first, so pq[i - 1] is never read once front is passed */
	while (i > front && compare(user, pq[i - 1])) {
		pq[i] = pq[i - 1];
		i--;
	}
	pq[i] = user;
	rear++;
}
```

#### 우선순위 큐에서 데이터 꺼내기

```c
struct User dequeue(void) {
	return pq[front++]; /* the data at front, then front moves on */
}
```

### 미팅 시간 문제

#### 접속 계획

```c
struct Session plans[IDS][EPOCHS] = {
	{{5, 6}, {8, 9}, {11, 13}},
	{{2, 5}, {7, 8}, {12, 15}},
	{{1, 3}, {5, 7}, {9, 14}}
};
```

#### 한 유저의 다음 로그인과 로그아웃으로 넘어가기

```c
struct User next_epoch(struct User u) {
	int ep = ++u.epoch;
	/* After the last session, epoch is EPOCHS and now is left as it was */
	if (ep < EPOCHS) {
		u.now = plans[u.id][ep];
	}
	return u;
}
```

#### 첫 로그인과 로그아웃을 담은 모든 유저 넣기

```c
void init_meeting(void) {
	init_pqueue();
	struct User u = {.epoch = 0};
	for (int i = 0; i < IDS; i++) {
		u.id = i;
		u.now = plans[i][0];
		enqueue(u);
	}
}
```

#### 가장 늦은 로그인 시간 찾기

```c
/* Called once, right after init_meeting(), while every user is queued */
int latest_login(void) {
	int latest = -1; /* smaller than any time */
	for (int i = front; i <= rear; i++) {
		int cur = pq[i].now.login;
		if (cur > latest) {
			latest = cur;
		}
	}
	return latest;
}
```

#### 모두 로그인할 때까지 로그아웃 시간이 가장 이른 유저를 다음 계획으로 옮기기

```c
int meeting_time(void) {
	init_meeting();
	int t = latest_login();
	struct User out = dequeue();

	/* A user who logs out at t has already left, hence >= */
	while (t >= out.now.logout) {
		out = next_epoch(out);
		if (out.epoch >= EPOCHS) {
			return -1;
		}
		if (out.now.login > t) {
			t = out.now.login;
		}
		enqueue(out);
		out = dequeue();
	}
	return t;
}
```
