# 자료구조 - 요약

12주차 – 우선순위 큐 컨셉

## 목차

- 복습 - 큐: 추가된 순서대로 꺼내기
- 데이터가 우선순위를 갖는 큐
- 우선순위 큐에 데이터 추가, 삭제하기
- 접속 계획을 보고 미팅 시간 정하기

## 복습 - 큐: 추가된 순서로 꺼내기

- 큐는 시작 데이터와 마지막 데이터를 관리한다. 
- 큐에서 데이터를 꺼낼 때는 시작 데이터를 꺼낸다.
- 큐에 데이터를 추가할 때는 마지막 데이터 다음에 추가한다.

## 우선순위를 갖는 큐

- 데이터를 꺼낼 때 우선순위 순서로 한다.
- 큐에서처럼 시작 데이터 위치와 마지막 데이터 위치로 관리한다.
- 데이터를 우선순위 순서로 저장하는 방식으로 구현해본다.
- 같은 우선순위면 순서가 상관없다.

## 우선순위 큐에 데이터 추가

- 가정: 배열 뒤쪽에 저장할 공간이 있다.
- 마지막 데이터부터 차례로 비교해 추가할 위치를 찾는다.  
- 동시에 기존 데이터를 이동해 자리를 마련한 뒤 데이터를 추가한다.
- 마지막 데이터 위치를 업데이트 한다.

## 우선순위 큐 데이터 꺼내기

- 가정: 저장된 데이터가 존재한다.
- 우선순위가 가장 높은 데이터는 처음 데이터이므로, 처음 데이터를 꺼낸다.
- 처음 데이터 위치를 업데이트 한다.
- 꺼낸 자리는 다시 쓰지 않으므로 배열이 충분히 커야 한다.

## 문제 - 전체 미팅 시간 정하기

- 유저들이 각자 계획한 시간에 로그인과 로그아웃을 여러 번 반복한다.
- 미팅을 언제 할지 결정하기 위해 모든 유저가 접속할 가장 이른 시간을 찾는다.

## 미팅 시간을 찾는 아이디어

- 미팅 시간에는 모든 유저가 로그인을 했고, 로그아웃을 안 했어야 하므로, 마지막 로그인 시간과 첫 로그아웃 시간을 구해야 한다.
- 제일 늦게 오는 유저가 로그인을 할 때 먼저 가는 유저가 동시에 또는 이미 로그아웃을 했다면, 미팅을 할 수 없기 때문에 먼저 가는 유저가 다시 로그인하는 시간과 다음에 로그아웃 할 시간을 알아봐야 한다.
- 다시 돌아오는 유저의 로그인 시간과 기존에 제일 늦게 오는 유저의 로그인 시간을 비교해서 누가 제일 늦게 오는지를 업데이트한다.
- 누가 제일 일찍 가는지는 매번 새로 구해야 하므로 우선순위 큐를 쓴다.

## 미팅 시간 정하는 절차

1. 로그인 시간 기준 미팅 시간 제시
2. 먼저 가는 유저 찾기
3. 미팅 때까지 로그아웃 안 했으면 확정
4. 미팅을 못 했으면 먼저 간 유저가 언제 돌아오고 로그아웃 하는지 시간 정보를 업데이트하고 3.을 다시 반복

## 미팅 시간 제시 세부내용

- 모두 접속해 있어야 하므로 제일 늦게 오는 유저에 맞춘다.
- 한 번 미팅 시간을 정해 놓은 다음에는, 누군가 먼저 갔다가 돌아오는 시간하고만 비교해 보면 된다.

## 먼저 가는 유저 찾기 세부내용

- 처음에는 큐에 모든 유저를 저장한다. 
- 큐의 우선순위를 로그아웃 순서로 해서 먼저 가는 유저가 큐에서 나오게 한다.
- 큐에 유저의 번호를 저장해도 된다. 비교할 때는 그 번호로 유저의 로그아웃 시간을 찾아본다.

## 미팅 시간 확정하는 세부내용

- 미팅 시간이 로그인 시간 기준으로 계산해서 제시되었으므로, 로그아웃 시간만 확인하면 된다.
- 먼저 가는 유저가 미팅 시간 후에 로그아웃 하면 미팅 시간을 확정한다.

## 돌아오는 유저 업데이트 세부내용

- 먼저 가는 유저가 다시 돌아올 계획이 없으면 미팅을 못 한다.
- 돌아온 유저가 미팅 시간 후에 오면 미팅 시간을 새 로그인 시간으로 바꾼다.
- 돌아온 유저는 큐에 다시 추가하고, 큐에서 먼저 가는 유저를 새로 꺼낸다.
