# 진행자 전용 정답 기준

학생에게 미리 공개하지 않아요. 아래 기준의 결과와 이유를 자기 말로 모두 포함하면 `2`예요. 일부만 맞거나 이유가 빠지면 `1`이에요. 5장의 5번만 선택 문제예요.

## 1장. 배열이 모자라면 옮겨요

1. 읽는 위치는 `0, 1, 2`, 즉 `0`부터 `size - 1`까지예요. 3부터 7은 목록의 값이 아니에요.
2. `NULL`이 `data`를 덮어 기존 공간의 주소를 잃어요. 기존 값을 읽거나 공간을 해제할 수도 없어요.
3. `realloc`이 목록을 다른 공간으로 옮길 수 있어요. 확장 전 내부 주소는 새 목록의 칸을 가리키지 않아요.
4. 두 배 확장이라 복사는 가끔만 일어나요. 여러 `append`에 전체 작업을 나누면 한 번당 일정한 범위에 머물러요.

### 바꾼 예

`[7, 8, 9, 10]`, `size=4`, `capacity=4`인 목록에 12를 붙여요. 성공과 공간 요청 실패 뒤의 상태는 무엇인가요?

- 성공: 값은 `[7, 8, 9, 10, 12]`, `size=5`, `capacity=8`이에요.
- 실패: 기존 값, 주소, `size=4`, `capacity=4`가 모두 그대로예요.

## 2장. 주소로 계층을 만들어요

1. 부모·자식 관계는 배열에서 가까운지가 아니라 `left`와 `right`에 저장한 주소가 정해요.
2. 연결 하나의 가까운 조건만 확인해요. 부모가 둘인 노드, 긴 순환, 도달할 수 없는 노드 같은 전체 문제는 따로 검사해야 해요.
3. 60은 루트 50의 왼쪽 부분 트리에 있으면서 50보다 커요. 왼쪽 부분 트리의 모든 키가 50보다 작아야 한다는 규칙이 깨져요.
4. 노드는 호출한 쪽이 만든 고정 배열의 일부예요. 따로 할당한 공간이 아니고 `TreeArena`도 소유하지 않아요.

### 바꾼 예

루트 60의 왼쪽 자식은 40이고, 40의 오른쪽 자식을 70으로 두어요. 트리 모양과 BST 규칙은 각각 어떻게 되나요?

- 부모가 하나이고 순환이 없다면 트리 모양은 맞을 수 있어요.
- 70은 60의 왼쪽 부분 트리에 있으면서 60보다 커서 BST는 아니에요.

## 3장. 여러 방향의 관계를 저장해요

1. 방향 간선은 한쪽 방향만 나타내요. `1→0`은 별도 간선이 있어야 해요.
2. 전체 정점 수 6을 따로 저장해야 해요. 고립 정점 5는 간선 목록에 나타나지 않아요.
3. 무방향 간선은 양쪽에서 쓸 수 있으므로 `[u][v]`와 `[v][u]`가 같아야 해요.
4. 간선 하나는 정해진 칸만 봐요. 전체 검사는 사용 중인 `V×V`칸을 살펴요.

### 바꾼 예

정점 다섯 개인 빈 무방향 그래프에 `{1,4}`를 넣어요. 바뀌는 행렬 칸과 정점 1, 4의 차수는 무엇인가요?

- `[1][4]`와 `[4][1]`이 `true`가 돼요.
- 두 정점의 차수는 각각 1이에요.

## 4장. 마지막에 넣은 값을 먼저 꺼내요

1. 비어 있지 않은 스택의 마지막 데이터는 `stack[top]`이에요. `peek`는 그 값을 읽고 상태를 바꾸지 않으며, `pop`은 그 값을 읽은 뒤 `top`을 1 줄여요. 예전 칸의 비트는 남아도 논리 데이터는 아니에요.
2. 용량이 10일 때 유효한 상태는 `-1 <= top < capacity`예요. 데이터 수는 `top + 1`이에요. `is_full`과 `is_empty`는 상태만 알려 줘요. 호출자가 가득 찬 `push`와 빈 `peek`·`pop`을 피해야 해요. 현재 코드는 잘못된 호출을 거부하지 않아요.
3. 100, 200, 300을 차례로 넣으면 `top == 2`이고, 세 번 꺼낼 때 300, 200, 100 순서로 나와요. 마지막에는 `top == -1`이에요.
4. `1-2*3+4`는 `123*-4+`로 바뀌고 -1이 돼요. 변환과 계산은 같은 정수 배열을 다시 써요. 각 단계는 `top = -1`로 시작해요. 두 반복문은 문자열 끝에서 멈추므로 `1+2*3`처럼 짧은 식도 가능해요. 문법과 연산 범위를 검사하지 않아요.
5. `infix_to_postfix_parentheses()`는 `1+(2+3)`을 `123++`로 바꿔요. `(`는 기다리는 연산의 경계이고, `)`를 만나면 그 경계까지 연산자를 꺼낸 뒤 `(`를 버려요. 결과는 6이에요. 입력은 균형 잡힌 괄호를 포함해 최대 일곱 문자이고, 그 뒤에 널 문자가 필요해요.

### 바꾼 예

`4*2+3`을 숫자 스택과 연산자 스택으로 계산해요. `+`를 읽을 때
무슨 계산이 먼저 일어나고, 마지막 결과와 두 스택의 최종 상태는
무엇인가요?

- `+`를 읽으면 기다리던 `*`의 우선순위가 더 높으므로 `4*2`를 먼저 계산해 숫자 스택의 4와 2를 8로 바꿔요.
- 이어 `+`와 3을 넣고 입력 끝에서 `8+3`을 계산해요. 결과는 11이고, 숫자 스택에는 11 하나만, 연산자 스택에는 아무것도 남지 않아요.
- 실제 `lab.c`는 변환과 계산을 분리해요. `42*3+`를 만든 뒤 계산하고, 마지막 결과까지 꺼내 반환하므로 `top == -1`이 돼요.

## 5장. 한 갈래를 끝까지 따라가요

1. 노드를 기록하는 줄의 위치만 달라요. 전위는 두 호출 전, 중위는 두 호출 사이, 후위는 두 호출 뒤예요.
2. 50의 호출은 나중에 오른쪽 70으로 갈 위치를 기억해요. 30의 호출은 나중에 오른쪽 40으로 갈 위치를 기억해요.
3. 자식 주소가 부모 안에 있어요. 부모를 먼저 해제하면 자식 주소를 안전하게 읽을 수 없어요.
4. 시간은 노드 `n`개를 한 번씩 처리해 `O(n)`이에요. 동시에 남는 호출은 한 경로의 `h+1`개라 추가 공간은 `O(h)`예요.
5. **선택:** 오른쪽을 먼저 넣고 왼쪽을 나중에 넣어야 스택에서 왼쪽이 먼저 나와 전위 순서가 돼요.

### 바꾼 예

다음 트리의 전위, 중위, 후위 순서를 적어요.

```text
    8
   / \
  3  10
   \
    6
```

- 전위: `8, 3, 6, 10`
- 중위: `3, 6, 8, 10`
- 후위: `6, 3, 10, 8`

## 6장. 그래프에서 길을 잃지 않는 법

1. 스택에서 기다리는 동안 다른 간선이 같은 정점을 또 넣지 못하게 해요. `push` 성공 뒤 표시해야 해요.
2. 이미 발견한 1이 다시 들어가거나 처리되어 결과가 중복돼요. 순환을 따라 같은 작업이 반복될 수도 있어요.
3. 0에서 화살표를 따라 5까지 가는 경로가 없어요.
4. 연결 요소는 무방향 그래프에서 서로 오갈 수 있는 무리예요. 방향을 무시하면 원래 그래프와 다른 질문이 돼요.

### 바꾼 예

다음 그래프를 0부터 스택으로 탐색해요. 나가는 간선은 큰 도착점부터 확인해요. 방문 순서와 4의 포함 여부는 무엇인가요?

```text
0→2  0→3  2→1  3→1  1→2
4는 고립돼요.
```

- 방문 순서는 `0, 2, 1, 3`이에요.
- 4는 0에서 갈 수 없어 들어가지 않아요.
- 1은 2에서 넣을 때 표시하므로 `3→1`에서 다시 넣지 않아요.

## 7장. 배열 노드를 연결하고 빈 칸을 다시 써요

현재 `module_07_linked_list/student/lab.c`를 기준으로 확인해요.
연결 스택과 연결 큐를 리스트의 응용 예로 확인하고, 큐는 8장에서 그대로 재사용해요.
선형·원형 배열 큐 비교와 BFS는 8장 범위예요. `malloc`/`free` 포인터 목록과
DSU는 이 장의 필수 기준이 아니에요.

1. 실제 저장 위치는 배열의 칸이고 논리 순서는 정수 `next` 연결이 정해요.
   `-1`은 끝이며 배열 위치로 읽지 않아요.
2. `init_lnodes_pool()`는 열 칸을 `0→1→…→9→-1`로 잇고 `free_head=0`으로
   두어요. 사용 중인 연결이 없을 때 준비해야 해요.
3. `new_lnode(data,next)`는 빈 연결의 첫 칸을 떼고 전달한 두 값을 저장해요.
   빈 노드가 없으면 `-1`을 돌려주고 풀을 바꾸지 않아요.
4. `link_lnode`는 삽입할 노드에 기존 후속 위치를 먼저 저장해요.
   `delete_next_lnode`는 연결만 우회하고 뺀 노드의 옛 `next`를 남겨요.
   `free_lnode`는 그 `next`를 빈 연결의 머리로 바꾸므로 필요한 후속 위치를 먼저 보존해요.

### 바꾼 예

아무 노드도 사용하지 않는 상태에서 다음 코드를 실행해요.

```c
init_lnodes_pool();
int a = new_lnode(40, -1);
int b = new_lnode(60, -1);
int c = new_lnode(50, -1);
link_lnode(a, b);
link_lnode(a, c);
int removed = delete_next_lnode(a);
```

`a`에서 시작하는 연결, `removed`, 그 노드의 `next`, `free_head`는
어떻게 되나요? 이어 `free_lnode(removed)`와 `new_lnode(90,-1)`을
차례로 부르면 어느 칸이 재사용되고 살아 있는 연결은 어떻게 되나요?
연결에서 빼는 일과 빈 노드로 돌려놓는 일을 나눠 설명해요.

- `a=0`, `b=1`, `c=2`예요. 삽입 뒤 연결은 `0→2→1→-1`이에요.
- 삭제 뒤 `a`에서 시작하는 연결은 `0→1→-1`이고 데이터는 `40,60`이에요.
  `removed=2`, `lnodes[2].next=1`, `free_head=3`이에요.
- `free_lnode(2)` 뒤 빈 연결은 `2→3→…→9→-1`이에요.
- `new_lnode(90,-1)`은 위치 2를 다시 받고 그 칸을 `data=90,next=-1`로
  만들어요. `free_head=3`이고 살아 있는 `0→1→-1` 연결은 그대로예요.

### 공유 풀과 연결 스택

새 풀에서 A는 0번 노드의 값 17, B는 1번 노드의 값 23을 각각 첫 노드로
가지고 있어요. A가 자기 첫 노드를 분리하고 반환한 뒤 B가
`new_lnode(8,first_b)`로 받아 맨 앞에 붙여요. 두 시작 위치, B의 연결,
`free_head`는 어떻게 되나요? A가 옛 인덱스 0을 계속 읽거나 쓰면 왜 안 되나요?

- A의 시작은 `-1`, B의 시작은 0이고 B의 연결은 `0(8)→1(23)→-1`이에요.
  `free_head=2`예요. 두 리스트는 같은 풀의 가용 칸을 나눠 쓰지만 활성 노드는 겹치지 않아요.
- 옛 인덱스 0은 이제 B의 노드예요. A가 읽으면 옛값 17 대신 8을 읽어요.
  A가 그 칸의 값이나 연결을 쓰면 B를 바꿔요. 범위 안의 인덱스여도 A의 노드는 아니에요.

별도의 새 풀에서 `first=-1`로 시작해요. 17,23,31을 각각
`new_lnode(value,first)`로 받고 성공을 검사한 뒤 `first`를 바꿔요.
첫 노드만 차례로 제거하면 어떤 순서로 값이 나오나요? 제거 전에 무엇을
검사하고 어떤 값과 연결을 보관하나요? 풀 소진 시 `first`는 어떻게 해야 하나요?

- 연결은 `2(31)→1(23)→0(17)→-1`이고 출력은 31,23,17이에요.
- 제거 전에 `first != -1`인지 확인해요. 옛 첫 인덱스, 그 값과 다음 위치를 보관하고
  `first`를 다음 위치로 바꾼 뒤 옛 노드를 반환해요. 반환 뒤 그 칸에서 결과를 읽지 않아요.
- `new_lnode`가 `-1`이면 `first`를 바꾸지 않아요. 풀과 기존 연결도 그대로예요.
  별도 스택 API를 가정하지 않고 기존 노드 함수와 호출자의 변수로 설명해요.

### 연결 큐 응용 예

별도의 새 실행에서 `init_lnodes_pool(); head=tail=-1;`로 준비해요.
`enqueue(17)`, `enqueue(23)`, `enqueue(31)`을 차례로 부르고 각 반환값을
확인해요. 첫 `dequeue()`의 반환값과 남은 `head`, `tail`, `free_head`는
무엇인가요? 이어 `enqueue(41)`은 어느 풀 칸을 재사용하나요?
남은 값의 처리 순서와 마지막 삭제 뒤 두 끝은 어떻게 되나요?
공개 `dequeue()` 뒤에 호출자가 다시 `free_lnode`를 부르면 왜 안 되나요?
저장한 값이 `-1`일 때 빈 큐와 그 값을 어떻게 구분하나요?

- 처음 세 값은 풀 위치 0, 1, 2에 저장돼요. 첫 공개 삭제의 반환값은 위치 0이 아니라 값 17이에요.
- 공개 삭제 안에서 위치 0을 재활용하므로 `head=1,tail=2,free_head=0`이에요.
  그 칸의 `next`는 빈 연결의 다음 위치인 3으로 바뀌어요.
- `enqueue(41)`은 위치 0을 재사용해요. 활성 연결은 `1→2→0→-1`이고
  남은 값의 순서는 23,31,41이에요. 세 값을 모두 꺼내면 양 끝은 `-1`이고 빈 칸 열 개가 돌아와요.
- 호출자가 다시 반환하면 같은 칸을 두 번 재활용하게 돼요. 공개 함수가 이미 처리했어요.
- `enqueue(-1)`도 성공할 수 있고 비어 있지 않을 때 `dequeue()`가 `-1` 값을 돌려줄 수 있어요.
  빈 상태는 반환값 대신 `is_empty_queue()`로 확인해요.
- 열 칸을 모두 쓴 큐의 다음 공개 삽입은 `false`를 돌려주고 기존 연결을 보존해요.
  삽입 호출 자체를 `assert` 안에 넣으면 `NDEBUG` 빌드에서 실행되지 않으므로 결과를 먼저 저장해 검사해요.

## 8장. 배열 큐를 비교하고 같은 연결 큐로 BFS를 해요

### 큐 복습과 배열 표현 비교 — 필수

1. 연결 큐에서 처음 넣을 때 `head`와 `tail`이 같은 노드가 돼요.
   마지막 노드를 꺼내면 둘 다 `-1`이에요. 공개 `dequeue()`는 값을 반환하며
   노드를 자동 재활용해요. 원시 `dequeue_lnode()`만 풀 칸을 돌려줘요.
2. 선형 큐는 `rear`가 24에 도달하면 앞에서 값을 꺼냈어도 새로 쓰지 못해요.
   빈 상태는 `front == rear + 1`이에요.
3. 원형 큐는 위치를 25로 나눈 나머지로 갱신해요. 빈 상태는
   `front == (rear+1)%25`, 가득 찬 상태는 `front == (rear+2)%25`예요.
   따라서 활성 값은 최대 24개예요. 현재 코드는 `size` 필드를 쓰지 않아요.
4. 상태 함수는 잘못된 호출을 막지 않아요. 배열 비교의 독립 실행은
   `front=0; rear=-1;`로 준비해요. 트리·미로 BFS는 다른 사용자가 없는
   풀을 `init_lnodes_pool(); head=tail=-1;`로 준비해요. 둘은 다른 저장 표현이에요.

### 큐 바꾼 예

새 원형 큐를 `front=0; rear=-1;`로 준비하고 1부터 24까지 넣어요.
두 번 꺼낸 뒤 25와 26을 넣어요. `queue[25]`의 물리 칸, `front`,
`rear`, 논리 순서, `is_full_circular()`의 결과는 무엇인가요?
남은 옛값과 현재 큐 값을 어떻게 구분하나요?

- 처음 넣은 뒤 `front=0,rear=23`, 두 번 꺼낸 뒤 `front=2,rear=23`이에요.
- 25와 26을 넣으면 `front=2,rear=0`이에요. 위치 24를 쓴 뒤 위치 0으로 돌아와요.
- `queue[0]=26`, `queue[1]=2`, `queue[2..23]=3..24`, `queue[24]=25`예요.
  위치 1의 2는 남은 옛값이며 활성 값이 아니에요.
- 논리 순서는 `3,4,…,24,25,26`이고 24개예요.
  `(rear+2)%25=2`이므로 `is_full_circular()`는 참이에요.

### 트리 BFS — 필수

1. 원래 Module 2 트리의 루트는 F이고 처리 순서는 `F,A,G,B,C,D,E`예요.
   연결 큐 노드의 `data`에 정수 위치 `5,0,6,1,2,3,4`가 들어가요.
   큐 풀의 칸은 이 트리 노드 위치와 별개예요. 공개 `dequeue()`가 위치를
   반환하고 내부에서 큐 칸을 돌려놓은 뒤 BFS가 자식 작업을 넣어요.
   원래 예는 최대 세 대기 칸을 사용해요.
2. F 뒤 대기는 A,G이고 A 뒤에는 G,B,C예요. 새 자식은 앞서 기다리던
   노드 뒤에 들어가므로 더 깊은 노드가 앞지르지 못해요.
3. 한 부모만 갖고 순환이 없는 트리에서는 각 도달 노드가 한 번 들어가요.
   `tree_bfs`는 깊이를 저장하지 않고 `order`에 처리한 노드 위치를 적어요.
4. 루트 `-1`이면 0을 돌려줘요. 비어 있지 않은 입력은 유효한 최대 열 노드
   트리여야 하며 `order`에는 열 칸이 필요해요. 잘못된 트리를 거부하는 상태 반환은 없어요.

### 트리 바꾼 예

다음 트리의 루트 위치는 0이에요. 왼쪽 자식을 먼저 넣어
`tree_bfs(0, order)`로 탐색해요. `order`의 활성 부분, 반환한 수,
각 노드의 깊이, 가장 많이 기다린 노드 수는 무엇인가요?
큐 안에 저장한 정수는 노드의 위치인가요, 깊이인가요?

```text
0
├─ 1
│  ├─ 3
│  └─ 4
└─ 2
   └─ 5
```

각 노드는 한 부모만 갖고 순환은 없어요. 실행 전에 다른 사용자가 없는 풀을
`init_lnodes_pool(); head=tail=-1;`로 준비해요. 큐 풀 칸과 그 안의 노드 위치를 구분해요.

- `order[0..6)`은 `0,1,2,3,4,5`이고 반환값은 6이에요.
- 깊이는 `0,1,1,2,2,2`예요. 큐에는 깊이 대신 노드 위치만 저장해요.
- 1을 처리한 뒤 `2,3,4`, 2를 처리한 뒤 `3,4,5`가 기다리므로 최대 세 개예요.

### 미로 그래프 BFS — 필수

1. 처음 발견한 통로의 거리를 큐에 넣기 전에 기록해요. 다른 갈래가 그 통로를
   다시 보아도 이미 발견한 거리를 알아 중복해서 넣지 않아요. 공개 `enqueue`는
   풀 소진 때 `false`를 반환해요. BFS는 삽입을 실행한 뒤 저장한 성공 여부를 검사해요.
   이 BFS 자체는 실패 상태를 반환하지 않으므로 제시한 용량 조건을 만족해야 해요.
2. 이웃 거리가 현재 거리보다 크지 않으면 건너뛰어요. 정확히 하나 크면
   같은 최단 거리로 도착한 것이므로 선행 칸만 추가해요. 아직 25이면 거리와 선행 칸을 적고 넣어요.
3. 원래 시작 `{1,1}`에서 목표 `{5,5}`의 거리는 8이에요. 바로 전 칸은
   `{5,4}`, `{4,5}` 순서이고 완전한 최단 경로는 세 개예요.
4. 선행 칸을 따라가면 거리가 하나씩 줄어요. 출발점까지 거꾸로 모은 뒤
   뒤집으면 최단 경로 하나예요. 선행 칸 전체로 갈라져야 모든 경로를 복원해요.
5. 공개 `dequeue()`는 데이터 ID를 읽고 큐 칸을 재활용한 뒤 값을 반환해요.
   BFS가 이웃을 추가할 때는 그 칸을 다시 쓸 수 있어요.
   원래 `{1,1}` 실행은 20개 통로를 처리하지만 동시에 기다리는 항목은 최대
   네 개예요. 원래 미로의 모든 시작점은 최대 여섯 칸, 완전히 열린 5×5
   내부의 모든 시작점은 최대 열 칸이에요. 다른 그래프는 새 용량 근거가 필요해요.
6. 격자의 0은 벽이고 1은 통로예요. `distance=25`는 아직 경로가 기록되지
   않았다는 뜻이에요. 좌표의 열·행 `{x,y}`는 배열에서 `[y][x]`로 읽어요.

### 미로 바꾼 예

원래 7×7 미로를 유지하고 이번에는 `{5,5}`에서 시작해요.
다른 사용자가 없는 풀에서 `init_lnodes_pool(); head=tail=-1;`로 준비하고
`init_info()`를 불러요. 공개 `dequeue()`가 돌려준 데이터 ID로 현재 칸을 찾아요.
큐 칸은 함수 안에서 이미 재활용되므로 직접 반환하지 않고 다음 이웃을 넣어요.
목표 `{1,1}`의 거리, 모든 바로 전 칸, 복원 경로 하나는 무엇인가요?
출발점의 거리와 `prev_size`, 벽 `{0,0}`의 거리는 무엇인가요?
출발점을 바꿔도 두 통로 사이의 최소 이동 수가 같은 이유를 설명해요.

- 목표 `{1,1}`의 거리는 8이고 바로 전 칸은 `{1,2}` 하나예요.
- 경로 하나는 `{5,5}→{5,4}→{5,3}→{4,3}→{3,3}→{3,2}→{2,2}→{1,2}→{1,1}`이에요.
- 출발점 거리는 0이고 `prev_size=0`이에요. 벽 `{0,0}`은 거리 25예요.
- 통로 연결은 양방향이므로 기존 최단 경로를 뒤집으면 반대 방향의 같은
  길이 경로예요. 더 짧은 역방향 길이 있다면 원래 방향에도 더 짧은 길이 생겨 모순이에요.

## 9장. 연결된 후보에서 합을 만들 두 수를 찾아요

현재 `module_09_hash_table/student/lab.c`를 기준으로 확인해요.
예전 여덟 칸 선형 조사와 삭제 표시는 필수 확인 대상이 아니에요.

1. `hash_func`는 C의 `value % 10`이 음수일 때 10을 더해요.
   `12`, `22`, `-8`은 모두 버킷 2를 골라요. 버킷이 같아도 숫자는 다르므로
   연결된 후보의 값을 각각 비교해야 해요.
2. `save_data`는 새 노드를 버킷 머리에 붙여요. 기존 데이터와 같은 값을
   저장해도 다른 노드를 만들어요. `find_data`는 선택한 연결에서
   `lnodes[node].data`가 요청한 값과 처음으로 같은 노드 위치를 돌려줘요.
3. `init_lnodes_pool()`가 첫 할당 전에 빈 노드 연결을 준비해요.
   `init_hashtable()`은 버킷의 각 연결 꼬리를 기존 `free_head`에 이은 뒤
   그 연결의 머리를 새 `free_head`로 삼고 버킷 머리를 `-1`로 바꿔요.
   사용 중인 노드 풀이 다시 초기화되면 노드 소유가 겹칠 수 있어요.
4. `two_sum_ht`의 노드에는 숫자가 있던 이전 위치 `j`를 저장해요.
   따라서 필요한 숫자 `j_num`과 비교할 대상은 `nums[j]`예요.
   현재 위치를 저장하기 전에 찾아야 같은 위치를 두 번 쓰지 않아요.
   원래 배열과 목표 0에서는 두 방법 모두 위치 `{5,4}`, 숫자 `1,-1`을 찾아요.
5. 해시 계산과 머리 삽입은 일정한 수의 작업이에요. 길이 `k`인 연결 찾기는
   최대 `k`개 노드를 봐요. 잘 퍼진 값과 제한된 버킷당 후보 수가 있어야
   짧은 연결을 기대할 수 있어요. 원래 코드는 버킷과 노드가 각각 열 개이며
   자동으로 늘어나지 않아요. 완전 탐색의 최대 비교 수는 45번이에요.

### 바꾼 예

비어 있는 `hashtable`과 `init_lnodes_pool()`로 준비한 노드 풀에서
12, 22, -8을 차례로 `save_data(hash_func(value), value)`로 저장해요.
버킷 머리, 노드 연결, `free_head`는 어떻게 되나요?
`find_data(2,22)`와 `find_data(2,32)`는 어느 노드를 보고 무엇을 돌려주나요?
이어서 `init_hashtable()`을 부르면 반환한 노드들은 남은 빈 노드들과
어떻게 이어지나요?

원래 `nums`를 유지하고 `two_sum_ht(0)`을 불러요. 반환한 두 위치와
그 위치의 숫자는 무엇인가요? 저장한 위치 `j`를 그대로 비교하지 않고
`nums[j]`를 읽는 이유는 무엇인가요?

- 저장한 노드 위치는 차례로 0, 1, 2예요. `hashtable[2] == 2`이고
  연결은 `2(data=-8)→1(data=22)→0(data=12)→-1`이에요.
  다른 버킷 머리는 모두 `-1`이고 `free_head == 3`이에요.
- 22 찾기는 노드 2, 1을 보고 1을 돌려줘요.
  32 찾기는 노드 2, 1, 0을 본 뒤 `-1`을 돌려줘요.
- 초기화는 노드 0의 `next`를 이전 빈 노드 머리 3으로 바꿔요.
  모든 버킷 머리는 `-1`이고 빈 노드 연결은

- 이어서 실행한 `two_sum_ht(0)`의 답은 위치 `{5,4}`예요.
  `nums[5] == 1`, `nums[4] == -1`이에요. 노드 데이터 4는 이전 위치이므로
  숫자 -1을 확인하려면 `nums[4]`를 읽어야 해요.
- 맞는 쌍을 찾은 시점에는 현재 위치 5를 아직 저장하지 않았어요.
  이전 위치들의 노드는 남고, 다음 `two_sum_ht` 호출이 그 노드들을 반환해요.

   정렬은 위치를 바꾸므로 원래 기록의 인덱스와 구별해요.
3. 삽입 정렬은 더 큰 값만 밀고, 병합은 같을 때 왼쪽 기록을 먼저 골라요.
   이 규칙이 `17A`와 `17B`의 처음 상대 순서를 보존해요.
4. 병합 정렬의 임시 배열은 입력과 겹치지 않는 쓰기 가능한 `n`개 정수
   저장 공간이에요. 길이는 0부터 64이고 빈 호출은 원소를 읽지 않아요.
5. 구조 선택은 정렬 한 번의 비용, 반복 조회, 갱신, 순서 요구, 메모리를
   함께 비교해요. 모든 작은 조회에서 이진 탐색이 더 빠르다고 단정하지 않아요.

### 바꾼 예

배열 `[9,4,9,-1]`에서 선형 탐색의 첫 9는 인덱스 0이에요.
정렬 결과는 `[-1,4,9,9]`이고 첫 9는 인덱스 2예요.
정렬한 위치를 원래 기록의 위치로 바로 쓰지 않아요.

4를 넣은 직후 삽입 정렬 상태는 `[4,9,9,-1]`이에요.
안정적인 최종 기록 순서는 `[-1,4,9A,9B]`예요.
정수 출력 `[-1,4,9,9]`만으로 두 9가 뒤바뀌었는지는 알 수 없어요.

갱신이 드문 목록의 반복 조회는 정렬 비용을 한 번 낸 뒤 이진 탐색을
반복할 수 있어요. 갱신이 잦은 정확한 키 조회는 해시 테이블을,
정렬된 범위가 필요하면 AVL을 비교해요. 입력 크기와 메모리 조건도 적어요.

## 14장. 모든 정점을 가장 싸게 이어요

### DSU 확인

2. 경로 줄이기는 실제로 지난 `H→G→E→A`의 노드만 바꿔요.
3. 번호가 더 작은 대표 뿌리를 골라요.
4. D와 H는 이미 같은 묶음에서 이어져 있어요. 새 무방향 간선과 기존 길이 순환을 만들어요.
5. DSU는 같은 묶음인지 말할 뿐 실제 경로, 최단 경로, 신뢰, 권한은 알려주지 않아요.

### 바꾼 예

0–5에서 `union(4,5)`, `union(2,3)`, `union(4,2)` 뒤 `find(5)`를 해요. 대표와 5의 부모는 무엇인가요?

- 같은 크기에서 작은 뿌리 2가 이겨요.
- `5→4→2`를 따라 대표 2를 얻고 `parent[5]`도 2가 돼요.

### 최소 신장 트리

1. MST는 선택한 모든 간선의 합을 줄여요. 한 출발점에서 각 정점까지의 길이는 최소화하지 않아요.
2. `key[v]`는 현재 트리에서 v로 들어오는 간선 하나의 비용이에요. `dist[v]`는 출발점부터의 누적 비용이에요.
3. 두 끝점이 이미 이어져 있어 새 간선을 넣으면 순환이 생겨요.
4. 동률 간선으로 다른 신장 트리가 나올 수 있어요. 모두 연결되고 순환이 없으며 최소 합이 같아야 해요.
5. 트리의 간선 하나가 끊기면 연결도 끊겨요. 고장 뒤 돌아갈 길이 필요하면 여분 간선을 둘 수 있어요.

### 바꾼 예

간선이 `AB2, AC2, BC1, BD4, CD4`예요. 서로 다른 최소 신장 트리 두 개와 합은 무엇인가요?

- 예: `{BC,AB,BD}`와 `{BC,AC,CD}`
- 둘 다 모든 정점을 순환 없이 잇고 합은 7이에요.
