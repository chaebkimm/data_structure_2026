# 합성 참여자 응답 A

실제 참여자가 아닌 초보 학습자 모의 응답이에요. 응답 방식은 글이에요. 각 선행 답은 해당 장 교재를 열기 전의 첫 답으로 잠갔다고 가정했어요.

## 1장

### 선행 확인

1. 결과: 읽을 수 있는 위치는 `0, 1, 2, 3`이고 값은 네 개(`3, 5, 7, 9`)예요. 이유: 길이가 4인 배열의 위치 번호는 0부터 시작해서 3에서 끝나기 때문이에요.
2. 결과: 몸체는 네 번 실행되고 마지막 실행 때 `i`는 3이에요. 이유: `i`가 `0, 1, 2, 3`일 때만 `i < 4`가 참이고, 4가 되면 멈추기 때문이에요.

### 확인 문제 2번

- 문제: `realloc`의 결과를 `data`에 바로 넣으면 실패할 때 무엇을 잃나요?
- 첫 답(결과): 기존 공간의 주소를 잃어서 기존 값에 다시 접근하거나 그 공간을 해제할 수 없게 돼요.
- 판단 이유: 실패한 `realloc`은 `NULL`을 주므로 그 값을 `data`에 바로 쓰면 원래 주소가 덮이기 때문이에요.
- 근거: 「실패해도 이전 목록을 지켜요」의 “새 주소를 임시 변수에 먼저 받아요.”

### 바꾼 예

- 문제: `[7, 8, 9, 10]`, `size=4`, `capacity=4`인 목록에 12를 붙여요. 성공과 공간 요청 실패 뒤의 상태는 무엇인가요?
- 첫 답(결과): 성공하면 값은 `[7, 8, 9, 10, 12]`, `size=5`, `capacity=8`이에요. 공간 요청이 실패하면 값은 `[7, 8, 9, 10]`, `size=4`, `capacity=4`인 이전 상태 그대로예요.
- 이유: 꽉 찬 공간을 두 배로 늘린 뒤에만 12와 새 필드를 확정하고, 공간 요청이 실패하면 임시 주소가 `NULL`인지 확인한 뒤 아무 필드도 바꾸지 않기 때문이에요.

## 7장

### 선행 확인

1. 결과: `size`는 지금 목록에 들어 있는 값의 수이고 `capacity`는 현재 공간에 넣을 수 있는 최대 값의 수예요. 이유: 만들어진 칸이 있어도 아직 값이 들어오지 않은 칸은 `capacity`에는 포함되지만 `size`에는 포함되지 않기 때문이에요.
2. 결과: 실패 전의 원소와 순서, 크기 같은 관리 값, 호출자가 맡긴 출력이 그대로 남는다는 뜻이에요. 이유: 실패한 연산이 중간까지만 자료를 바꾸면 다시 시도하거나 이전 자료를 사용할 수 없기 때문이에요.

### 확인 문제 4번

- 문제: 가득 찬 큐에 90을 넣지 못했을 때 무엇이 그대로 남아야 하나요?
- 첫 답(결과): 물리 배열 `[62, 5, 47, 19]`, `head=2`, `size=4`, 용량 4와 논리 순서 `47, 19, 62, 5`가 모두 그대로 남아야 해요.
- 판단 이유: 가득 찬 큐는 새 값을 거부하며 실패한 `enqueue`는 기존 필드와 배열 칸을 바꾸지 않기 때문이에요.
- 근거: 「코드의 약속」의 “실패한 `enqueue`는 모든 필드와 배열 칸을 보존해요.”

### 바꾼 예

- 문제: 용량 5인 큐에 `10,20,30,40`을 넣고 두 번 꺼낸 뒤 `50,60,70`을 넣어요.
- 첫 답(결과): 물리 배열은 `[60, 70, 30, 40, 50]`, `head=2`, `size=5`이고 논리 순서는 `30, 40, 50, 60, 70`이에요.
- 이유: 두 번 꺼내면 30이 있는 2번 칸이 머리가 되고, 새 값은 `(head + size) % 5`로 구한 4번, 0번, 1번 칸에 차례로 들어가기 때문이에요.

## 12장

### 선행 확인

1. 결과: 경로에 들어 있는 모든 간선의 비용을 더해요. 이유: 가중 그래프의 경로 비용은 지나간 간선 수가 아니라 각 간선 가중치의 합이기 때문이에요.
2. 결과: 도착점에서 `predecessor`를 따라 출발점까지 거꾸로 적은 뒤 그 순서를 뒤집어요. 이유: 각 `predecessor`는 현재 정점 바로 전에 온 정점을 가리키기 때문이에요.
3. 결과: 가장 먼저 처리할 최소 기록은 힙의 뿌리에 있어요. 이유: 최소 힙은 부모 기록이 자식 기록보다 크지 않게 두므로 가장 작은 기록이 뿌리에 있기 때문이에요.

### 확인 문제 2번

- 문제: B의 비용이 9에서 4로 줄어도 `B/9`를 바로 지우지 않는 이유는 무엇인가요?
- 첫 답(결과): `B/9`는 힙에 남겨 두고, 나중에 꺼냈을 때 현재 `dist[B]=4`와 다르므로 오래된 기록으로 건너뛰어요.
- 판단 이유: 기존 힙 기록을 찾아 고치는 대신 더 싼 `B/4`를 새로 넣는 게으른 중복 방식을 쓰기 때문이에요.
- 근거: 「가장 싼 대기 기록부터 꺼내요」의 “꺼낸 비용이 현재 `dist[B]`와 다르면 옛 기록이에요.”

### 바꾼 예

- 문제: `A→B 7, A→C 2, C→B 3, B→D 1, C→D 8`에서 A부터 D까지를 구해요.
- 첫 답(결과): 최소 경로는 `A→C→B→D`, 비용은 `2+3+1=6`이에요. 오래된 기록은 `B/7`과 `D/10`이에요.
- 이유: C를 거치면 B의 비용이 7에서 5로 줄고, 이어 B를 거치면 D의 비용이 10에서 6으로 줄어요. 그래서 나중에 `B/7`과 `D/10`을 꺼내면 각각 현재 거리 5와 6에 맞지 않아 건너뛰어요.

## 16장

### 선행 확인

1. 결과: 꺼낸 기록을 오래된 기록으로 보고 그 정점의 간선을 살피지 않고 건너뛰어요. 이유: 현재 `dist[v]`와 다른 비용은 이미 더 좋은 기록으로 바뀐 예전 값이기 때문이에요.
2. 결과: 새 무방향 관계는 순환을 만들어요. 이유: 대표 뿌리가 같다는 것은 두 끝점 사이에 이미 같은 묶음 안의 길이 있다는 뜻이기 때문이에요.
3. 결과: 논리 간선 ID는 같은 끝점을 가진 평행 간선도 서로 구별하고 실제로 어느 입력 간선을 골랐는지 기록하는 데 필요해요. 이유: 끝점만으로는 서로 다른 간선을 하나씩 식별하거나 같은 간선을 중복 선택했는지 확인할 수 없기 때문이에요.

### 확인 문제 4번

- 문제: 프림과 크루스칼의 선택 간선이 달라도 둘 다 맞을 수 있는 조건은 무엇인가요?
- 첫 답(결과): 두 결과가 모두 모든 정점을 순환 없이 잇고 최소인 같은 합을 가지면 둘 다 맞을 수 있어요.
- 판단 이유: 같은 비용의 간선이 있으면 서로 다른 간선을 골라도 각각 올바른 최소 신장 트리가 될 수 있기 때문이에요.
- 근거: 「모든 간선을 싼 순서로 살펴요」의 “같은 비용의 간선이 있으면 두 알고리즘이 다른 간선을 골라도 돼요.”

### 바꾼 예

- 문제: 간선이 `AB2, AC2, BC1, BD4, CD4`일 때 서로 다른 최소 신장 트리 두 개와 합을 구해요.
- 첫 답(결과): 하나는 `{BC1, AB2, BD4}`, 다른 하나는 `{BC1, AC2, CD4}`이고, 두 트리의 합은 각각 `1+2+4=7`이에요.
- 이유: `BC1`과 비용 2인 간선 하나로 A, B, C를 가장 싸게 이을 수 있고, D를 잇는 가장 싼 비용은 4예요. 비용 2와 4에서 각각 동률인 간선이 있어서 서로 다른 두 선택이 같은 최소 합 7을 만들어요.
