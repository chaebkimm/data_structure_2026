# 진행자 전용 선행 확인 기준

진행자가 지정한 절만 사용해요. `N장 전`은 해당 장을 열기 전에 묻고, `학습 중`은 적힌 부분을 읽은 뒤에만 물어요. 아직 배우지 않은 현재 장 개념을 진입 조건으로 쓰지 않아요.

학생에게 정답을 보여주지 않아요. `H0`–`H2`의 첫 결과와 이유로 판정하고, 교정은 첫 응답을 잠근 뒤에 해요.

## 1장 전

1. int values[4] = {3,5,7,9};에서 읽을 수 있는 인덱스와 값의 수는 무엇인가요?
   - 기준: 인덱스는 0–3이고 값은 네 개예요.
2. for (i=0; i<4; i++)의 몸체는 몇 번 실행되고, 마지막 몸체 실행에서 i는 얼마인가요?
   - 기준: 네 번 실행하며 마지막 i는 3이에요. i가 4가 되면 조건이 거짓이에요.

## 2장 전

1. size=3, capacity=5인 고정 배열 리스트에서 현재 값의 인덱스는 어디까지인가요?
   - 기준: 0–2예요. 3–4도 배열 칸이지만 현재 목록의 값은 아니에요.
2. 배열 인덱스와 그 칸에 저장된 값은 무엇이 다른가요?
   - 기준: 인덱스는 칸의 위치이고 값은 그 칸의 내용이에요. 같은 값이 여러 위치에 있어도 위치는 달라요.
3. 고정 배열이 가득 찼을 때 거부한 삽입은 기존 값과 size, 용량을 어떻게 바꾸나요?
   - 기준: 바꾸지 않아요. 이번 배열 리스트는 저장 공간을 자동 확장하지 않아요.

## 3장 전

1. nodes 배열에서 물리적으로 붙어 있는 두 칸이 자동으로 부모와 자식이 아닌 이유는 무엇인가요?
   - 기준: left/right에 저장된 자식 인덱스가 관계를 정해요.
2. 이진 트리에서 순환이나 한 자식의 두 부모를 허용하면 왜 안 되나요?
   - 기준: 자식 링크를 따라 같은 노드로 돌아오거나 위쪽 관계가 둘이 되어 한 root의 트리 조건이 깨져요.

## 4장 전

1. int values[5]에서 size=3이면 현재 값의 위치와 다음 삽입 위치는 어디인가요?
   - 기준: 현재 값은 0–2이고 끝에 넣을 위치는 3이에요. 3–4는 아직 현재 값이 아니에요.
2. 작업량이 O(1)인 경우와 O(n)인 선형 탐색의 최악 경우는 입력 수에 따라 어떻게 달라지나요?
   - 기준: 정해진 인덱스 읽기의 작업량은 입력 수와 관계없이 일정해요. 없는 값을 찾으며 모든 n개를 검사하는 선형 탐색은 입력 수만큼 작업이 늘어요. 메모리 비용은 별도로 세어요.

## 5장 전

1. 이진 트리의 root, 왼쪽·오른쪽 자식, leaf는 무엇인가요?
   - 기준: root는 시작 노드, 자식은 저장된 자식 인덱스로 연결한 바로 아래 노드이고 leaf는 자식이 없는 노드예요.
2. 스택에 A,B,C를 차례로 넣으면 어떤 순서로 꺼내나요?
   - 기준: C,B,A예요. 마지막에 넣은 값부터 꺼내요.

## 6장 전

1. 무방향 간선은 adjacency list의 어느 정점에 저장하나요?
   - 기준: 양 끝 정점의 목록에 서로를 이웃으로 저장해요. 한 간선에 이웃 항목 두 개예요.
2. 같은 DFS에서 visit_num, parent, back_num은 무엇을 기록하나요?
   - 기준: 발견 순번, 첫 발견을 이끈 부모, 그 DFS의 자식 경로와 조상 간선으로 되돌아갈 수 있는 최소 발견 번호예요. 독립 탐색의 번호를 섞지 않아요.
3. postorder 작업은 자식 호출과 비교해 언제 실행하나요? 스택은 어느 항목을 먼저 꺼내나요?
   - 기준: 두 자식 호출이 끝난 뒤 현재 노드의 postorder 작업을 해요. 스택은 마지막에 넣은 항목을 먼저 꺼내요.

## 7장 전

1. 배열 리스트 중간에 값을 넣으면 뒤의 활성 값은 어떻게 되나요?
   - 기준: 자리를 만들려고 뒤에서부터 한 칸씩 오른쪽으로 옮겨요.
2. 배열의 물리적 칸 순서와 트리의 논리적 연결 순서는 어떻게 다를 수 있나요?
   - 기준: 칸은 움직이지 않아도 정수 자식 인덱스로 다른 순서의 관계를 만들 수 있어요.

## 8장 전

1. 별도의 새 실행에서 new_lnode()를 처음 부르면 어느 칸을 얻나요? 이후 init_lnodes_pool()를 다시 부르면 사용 중인 풀은 어떻게 되나요?
   - 기준: 첫 호출이 풀을 한 번 준비하고 위치 0을 돌려줘요. 이후 초기화 호출은 아무것도 바꾸지 않아요. 데이터를 새로 설정하는 일은 호출자 몫이에요.
2. simple_delink_next_lnode_from_prev(prev)가 돌려준 노드와 free_lnode의 역할은 무엇이 다른가요?
   - 기준: 분리는 next=-1인 노드 인덱스를 돌려주고 풀에 반환하지 않아요. 필요한 값을 읽고 어떤 활성 연결도 참조하지 않는지 확인한 뒤 호출자가 한 번 재활용해요.
3. 7장의 큐에서 17,23,31을 넣은 노드들을 차례로 꺼낼 때 어떤 값부터 읽나요? dequeue_lnode() 자체의 반환값과 마지막 두 끝을 말해요.
   - 기준: 17부터 읽어요. 원시 삭제는 데이터가 아닌 분리된 노드 인덱스를 돌려줘요. 호출자가 값을 읽고 노드를 반환해요. 마지막 삭제 뒤 qhead와 qtail은 -1이에요.
4. 트리 노드의 깊이는 무엇이며, 그래프에서 이미 발견한 정점을 기록해야 하는 이유는 무엇인가요?
   - 기준: 깊이는 root에서 현재 노드까지 간선 수예요. 그래프는 여러 경로나 순환으로 같은 정점을 다시 만날 수 있어요.

## 8장 학습 중 — 배열 큐·값 어댑터를 읽은 뒤

1. 선형 큐와 원형 큐의 front, rear는 무엇이며 25칸 원형 큐의 활성 용량은 얼마인가요?
   - 기준: front는 다음 삭제 칸, rear는 마지막 삽입 칸이에요. 원형 큐는 빈 상태와 가득 찬 상태를 구별하려 한 칸을 비워 최대 24개예요.
2. 8장의 dequeue()와 7장의 dequeue_lnode()는 무엇을 반환하고 누가 큐 칸을 재활용하나요?
   - 기준: 8장의 값 어댑터는 data를 읽고 큐 칸을 내부에서 재활용한 뒤 값을 반환해요. 7장의 원시 삭제는 칸 인덱스를 반환하므로 호출자가 따로 재활용해요. BFS 호출자는 어댑터가 이미 반환한 칸을 다시 free_lnode하지 않아요.

## 8장 학습 중 — 트리 BFS를 읽은 뒤

1. 원래 F root 트리에서 F 처리 뒤와 이어 A 처리 뒤 대기 순서는 무엇인가요?
   - 기준: F 뒤 A,G이고 A 뒤 G,B,C예요. 새 자식은 기존 대기 뒤에 들어가요.
2. 한 부모만 갖는 트리와 달리 그래프에서 같은 정점을 여러 번 만날 수 있는 이유는 무엇인가요?
   - 기준: 여러 갈래가 같은 정점에 합류하거나 순환을 따라 이미 본 정점으로 돌아갈 수 있기 때문이에요. 아직 읽지 않은 미로의 거리 기록 순서는 여기서 묻지 않아요.

## 9장 전

1. lnodes[node].next가 -1이면 무엇을 뜻하고, 다음 노드로 이동할 때 어느 값을 인덱스로 쓰나요?
   - 기준: 연결의 끝이에요. 끝이 아니면 next에 저장된 노드 인덱스를 써요. -1로 배열을 읽지 않아요.
2. new_lnode()는 인수를 받나요? 반환값 -1과 성공한 칸의 data/next는 어떻게 다루나요?
   - 기준: 인수가 없어요. -1은 소진이며 배열 인덱스로 쓰지 않아요. 성공한 칸의 next는 -1이고 data는 남아 있던 값이므로 호출자가 쓸 값을 대입해요.
3. init_lnodes_pool()를 두 번째 부르면 활성 노드나 저장 데이터가 초기화되나요?
   - 기준: 아니에요. 첫 준비 뒤에는 아무것도 바꾸지 않아요. 주인이 가진 노드를 분리해 반환해야 가용 공간이 늘어요.

## 10장 전

1. FIFO 큐와 LIFO 스택은 다음에 꺼낼 값을 각각 어떻게 정하나요?
   - 기준: 큐는 먼저 넣은 값, 스택은 마지막에 넣은 값을 꺼내요.
2. 노드 풀이 모두 사용 중일 때 save_data(hash,data)의 반환값과 기존 상태는 무엇인가요?
   - 기준: 유효한 버킷으로 호출하면 -1을 돌려줘요. 버킷 머리, 노드 필드, free_head==-1은 그대로예요.
3. 배열의 예약 용량과 활성 원소 수는 무엇이 다른가요?
   - 기준: 용량은 준비한 전체 칸 수, 활성 수는 현재 데이터가 있는 논리적 범위의 크기예요.

## 11장 전

1. 그래프 adjacency list와 정점 인덱스는 각각 무엇을 저장하고 가리키나요?
   - 기준: 각 정점의 실제 이웃 인덱스를 저장하고, 정점 인덱스는 바깥 노드 배열의 칸을 가리켜요.
2. BFS에서 목표의 이전 칸들을 따라 경로 하나를 복원하려면 어떻게 하나요?
   - 기준: 목표부터 거리가 하나씩 작은 이전 칸을 출발점까지 따라간 뒤 순서를 뒤집어요.
3. 최소 힙의 다음 항목은 어디 있으며, ID 힙의 역위치 표는 swap 때 어떻게 바뀌나요?
   - 기준: 다음 항목은 위치 0에 있어요. 교환한 두 ID의 위치 항목을 함께 갱신해 활성 heap의 ID→위치 대응을 유지해요.

## 12장 전

1. nodes[i].left/right에는 문자 키와 자식 인덱스 중 무엇을 저장하나요? 없는 자식의 표시는 무엇인가요?
   - 기준: 자식 인덱스를 저장하고 없는 자식은 -1이에요. 문자 데이터와 인덱스는 달라요.
2. leaf의 높이와 root에서 가장 먼 leaf까지 간선이 세 개인 트리의 높이는 얼마인가요?
   - 기준: 간선 높이를 쓰므로 leaf는 0, 그 root는 3이에요.

## 13장 전

1. 활성 길이가 n인 배열에서 읽을 수 있는 인덱스 범위는 무엇인가요?
   - 기준: 0 <= i < n이에요. n==0이면 읽을 원소가 없어요.
2. 최소 힙의 부모·자식 규칙이 배열 전체를 작은 순서로 정렬하나요?
   - 기준: 아니에요. 부모가 자식보다 크지 않다는 규칙만 보장해요. 형제나 다른 가지 사이의 값은 전체 순서가 아니에요.
3. 해시 테이블의 정확한 키 찾기와 AVL의 키 순서에는 어떤 차이가 있나요?
   - 기준: 해시는 후보 버킷을 좁혀 정확한 키를 찾아요. AVL은 비교에 따른 키 순서를 보존하므로 순서나 범위가 필요한 경우도 비교할 수 있어요.

## 14장 전

1. 간선을 비용순으로 정렬하면 무엇을 알 수 있고, 두 끝점이 이미 연결됐는지도 알 수 있나요?
   - 기준: 값이 싼 간선부터 읽을 수 있지만, 정렬만으로 이미 연결됐는지는 알 수 없어요.
2. 무방향 그래프의 연결 요소와 순환은 무엇인가요?
   - 기준: 요소는 서로 오갈 수 있고 정점을 더 보탤 수 없는 무리예요. 순환은 다른 정점을 반복하지 않고 시작점으로 돌아오는 길이에요.
3. 데이크스트라의 인덱스 힙에서 기다리는 정점의 더 작은 비용을 찾으면 어떻게 하나요?
   - 기준: 그 정점의 거리를 낮추고 역위치 표로 기존 항목을 찾아 힙 순서를 복구해요. 같은 정점의 낡은 복사본을 따로 넣는 설계가 아니에요.

## 14장 학습 중 — DSU를 읽은 뒤, Kruskal을 읽기 전

1. DSU에서 find로 얻은 대표가 같은 두 끝점 사이에 새 간선을 더하면 어떻게 되나요?
   - 기준: 서로 다른 두 끝점은 이미 경로로 연결돼 있으므로 새 간선과 그 길이가 순환을 만들어요. 자기 루프도 받아들이지 않아요.
2. union by size와 경로 압축은 각각 무엇을 바꾸고 무엇을 유지하나요?
   - 기준: 크기가 작은 그룹의 root를 큰 root 아래에 붙이고 크기와 요소 수를 갱신해요. 압축은 찾던 경로의 부모를 root로 바꾸지만 그룹의 구성원과 root의 크기, 요소 수를 바꾸지 않아요.
