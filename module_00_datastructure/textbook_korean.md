# 0장. 데이터를 똑똑하게 저장하는 방법

## 논리적으로 생각하기

### 소셜 미디어 앱

새로운 소셜 미디어 앱을 만든다고 상상해 보자. 앱에는 유저들이 작성한 게시물이 있고, 게시물마다 댓글이 달리고, 유저들은 서로를 팔로우를 한다. 앱에서 이를 저장하는 방식은 기능에 따라 달라진다.

- 피드 (리스트): 유저가 앱을 열면 시간순으로 정렬된 게시물 피드가 보인다. 하나의 게시물 뒤에 다음 게시물이 차례로 이어진다.
- 댓글 창 (트리): 게시물을 클릭하면 댓글이 보인다. 유저 A가 댓글을 달면, 거기에 유저 B와 C가 답글을 달고, 각 답글에 유저 A가 다시 답글을 단다. 가계도처럼 뻗어 나가는 계층 구조다.
- 팔로워 네트워크 (그래프): 유저들이 서로 어떻게 연결되어 있는지 그려보면, 서로 얽혀있는 거미줄 모양이 된다. 유저 A가 유저 B와 유저 C를 팔로우하고, 유저 B는 유저 C를 팔로우하고, 유저 C는 유저 A를 맞팔로우하며, 유저 A, 유저 B, 유저 C 모두 어떤 연예인을 팔로우한다. 연결 관계를 통해 무한히 뻗어 나가는 네트워크 구조다.

### 프로그램은 어떤 정보를 저장할까?

프로그램은 사용자 이름, 게시물 내용, 작성 시간, 팔로워 수와 같은 정보를 처리하고 저장한다.

### 프로그램은 이 데이터를 어떻게 정리할까?

프로그램이 수행해야 하는 작업에 맞춰 저장된 정보를 정리한다. 게시물은 시간순으로 정렬된 목록 형태로 저장하고, 답글은 무엇에 대한 답글인지에 대한 정보를 같이 저장하고, 유저 정보에는 팔로워 정보를 같이 저장한다.

### 효율이란 무엇일까?

프로그램은 연산 자원과 메모리를 소비한다. 효율이란 특정 작업에 필요한 연산 횟수와 메모리를 평가하는 것이다. 보통 연산 횟수를 줄이기 위해 추가적인 메모리를 사용하는 경우가 많으므로, 두 자원을 항상 동시에 최소화할 수는 없다.

### 효율을 평가하는 방법

프로그램을 실행하려면 항상 기본적인 작업량과 메모리가 필요해서 데이터의 양이 적을 때는 어떤 방식을 쓰든 비슷해 보인다. 프로그래머들은 데이터 양이 증가함에 따라 필요한 작업 시간과 메모리가 어떻게 증가하는지를 분석하여 효율을 평가한다.

### 효율을 표기하는 방법

효율을 나타내기 위해 빅오 표기법을 사용한다. n을 입력의 양이라고 했을 때, O(1)은 작업량이나 메모리가 입력과 관계없이 일정하다는 것을 나타낸다. 반면 O(n)은 작업량이나 메모리가 입력의 양에 비례하여 늘어나는 것을 나타낸다.

## 용어 사전

### 데이터 (Data)

사용자 이름, 텍스트, 숫자, 비밀번호처럼 컴퓨터 프로그램이 처리하는 가공되지 않은 정보.

### 자료구조 (Data structure)

프로그램이 수행해야 할 작업에 맞춰 프로그래머가 저장된 정보를 정리하는 방식. 데이터의 형태(리스트, 트리, 그래프 등)에 따라 각기 다른 구조가 필요하다.

### 효율성 (Efficiency)

특정 워크로드에 필요한 처리 시간과 메모리의 척도. 연산 단계를 줄이는 것과 메모리 공간을 절약하는 것 사이의 트레이드오프(상충 관계)를 동반하는 경우가 많다.

### O 표기법 (Big O notation)

데이터의 양이 증가함에 따라 컴퓨터의 작업량이 어떻게 늘어나는지를 분류할 때 프로그래머들이 사용하는 표준 표기법.

### O(1)

"오 원(O of 1)"이라고 읽는다. 데이터의 양이 늘어나도 작업량은 증가하지 않는다는 의미다.

### O(n)

"오 엔(O of n)"이라고 읽는다. 데이터의 양에 비례하여 작업량도 늘어난다는 의미다.
