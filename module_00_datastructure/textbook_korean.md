# 0장. 데이터를 똑똑하게 저장하는 방법

## 논리적으로 생각하기

### 소셜 미디어 앱

새로운 소셜 미디어 앱을 만든다고 상상해 보자. 앱에는 유저들이 작성한 게시물이 있고, 게시물마다 댓글이 달리고, 유저들은 서로를 팔로우를 한다. 앱에서 이를 저장하는 방식은 기능에 따라 달라진다.

- 피드 (리스트): 유저가 앱을 열면 시간순으로 정렬된 게시물 피드가 보인다. 하나의 게시물 뒤에 다음 게시물이 차례로 이어진다.
- 댓글 창 (트리): 게시물을 클릭하면 댓글이 보인다. 유저 A가 댓글을 달면, 거기에 유저 B와 C가 답글을 달고, 각 답글에 유저 A가 다시 답글을 단다. 가계도처럼 뻗어 나가는 계층 구조다.
- 팔로워 네트워크 (그래프): 유저들이 서로 어떻게 연결되어 있는지 그려보면, 서로 얽혀있는 거미줄 모양이 된다. 유저 A가 유저 B와 유저 C를 팔로우하고, 유저 B는 유저 C를 팔로우하고, 유저 C는 유저 A를 맞팔로우하며, 유저 A, 유저 B, 유저 C 모두 어떤 연예인을 팔로우한다. 연결 관계를 통해 무한히 뻗어 나가는 네트워크 구조다.

### 프로그램은 어떤 정보를 저장할까?

프로그램은 사용자 이름, 게시물 내용, 작성 시간, 팔로워 수와 같은 정보를 처리하고 저장한다.

### 프로그램은 이 데이터를 어떻게 정리할까?

프로그램이 수행해야 하는 작업에 맞춰 저장된 정보를 정리한다. 게시물은 시간순으로 정렬된 목록 형태로 저장하고, 답글은 무엇에 대한 답글인지에 대한 정보를 같이 저장하고, 유저 정보에는 팔로워 정보를 같이 저장한다.

### 효율이란 무엇일까?

프로그램은 연산 자원과 메모리를 소비한다. 효율이란 특정 작업에 필요한 연산 횟수와 메모리를 평가하는 것이다. 보통 연산 횟수를 줄이기 위해 추가적인 메모리를 사용하는 경우가 많으므로, 두 자원을 항상 동시에 최소화할 수는 없다.

### 작업량은 어떻게 셀까?

배열에 사용자 ID 열 개를 저장하자. 원하는 위치를 알고 있다면 그 위치의 ID 하나를 읽는다. ID의 값만 알고 있다면 맨 앞부터 값을 비교하다가 일치하는 항목에서 멈춘다. 찾는 ID가 마지막에 있거나 배열에 없다면 열 개를 모두 확인한다.

이번에는 ID 백 개를 저장하자. 알고 있는 위치를 읽을 때는 여전히 ID 하나를 확인한다. 마지막에 있거나 없는 값을 찾을 때는 백 개를 확인한다. 먼저 확인하는 항목 수를 센 뒤, 입력이 늘어날 때 그 수가 어떻게 바뀌는지 살펴본다.

### 저장 공간은 어떻게 늘어날까?

ID 열 개를 저장하는 배열에는 정수 열 칸이 필요하다. 백 개를 저장하려면 백 칸이 필요하다. 두 찾기 방법 모두 현재 위치와 찾는 값 등을 기록하는 데 정해진 수의 추가 변수만 사용할 수 있다. 저장하는 입력은 늘어나지만 찾기에 필요한 추가 공간은 일정하다. 처리 작업량, 입력 저장 공간, 추가 공간을 따로 센다.

### 늘어나는 정도를 어떻게 표기할까?

저장된 ID 수를 `n`이라고 하자. `n`이 늘어나도 일정한 범위 안에 머무는 비용을 `O(1)`로 쓴다. 알고 있는 배열 위치를 읽는 작업량은 `O(1)`이다. 입력이 충분히 커졌을 때 `n`의 일정한 배수 이내로 제한되는 비용을 `O(n)`으로 쓴다. 모든 ID를 확인하는 작업량은 `O(n)`이다. 비용이 늘어나는 정도의 상한을 이렇게 나타내는 방법을 빅오 표기법(Big O notation)이라고 한다.

배열의 저장 공간은 `O(n)`이고, 찾기에 쓰는 추가 공간은 `O(1)`이다. 시간 비용은 작업량을 나타낸다. 공간 비용은 저장 공간을 나타낸다. 따라서 값을 차례로 찾는 작업은 시간이 `O(n)`이면서 추가 공간은 `O(1)`일 수 있다.

### 어떤 경우의 찾기 비용을 셀까?

첫 번째 ID가 일치하면 비교 한 번으로 찾기를 끝낸다. 가장 적은 작업을 하는 최선의 경우다. ID가 마지막에 있거나 없으면 `n`번 비교한다. 가장 많은 작업을 하는 최악의 경우다. 평균 비용은 실제 작업에서 각 경우가 얼마나 자주 나타나는지에 따라 달라진다.

비용을 말하기 전에 어떤 경우인지 밝힌다. 여기서 값 찾기의 최선 시간은 `O(1)`이고 최악 시간은 `O(n)`이다. 빅오 표기법은 선택한 비용의 상한을 나타낸다. 표기법 자체가 최악의 경우를 선택하지는 않는다.

## 용어 사전

### 데이터 (Data)

사용자 이름, 텍스트, 숫자, 비밀번호처럼 컴퓨터 프로그램이 처리하는 가공되지 않은 정보.

### 자료구조 (Data structure)

프로그램이 수행해야 할 작업에 맞춰 프로그래머가 저장된 정보를 정리하는 방식. 데이터의 형태(리스트, 트리, 그래프 등)에 따라 각기 다른 구조가 필요하다.

### 효율성 (Efficiency)

특정 워크로드에 필요한 처리 시간과 메모리의 척도. 연산 단계를 줄이는 것과 메모리 공간을 절약하는 것 사이의 트레이드오프(상충 관계)를 동반하는 경우가 많다.

### 빅오 표기법

입력의 양이 늘어날 때 작업량이나 저장 공간이 늘어나는 정도의 상한을 나타내는 표기법. 측정하는 자원과 입력의 경우를 따로 밝힌다.

### O(1)

"오 원(O of 1)"이라고 읽는다. 입력이 늘어나도 일정한 상한 안에 머무는 비용이다. 알고 있는 배열 위치 하나를 읽는 작업량이나 정해진 수의 찾기 변수를 위한 추가 공간이 여기에 해당한다.

### O(n)

"오 엔(O of n)"이라고 읽는다. 입력의 양 `n`에 비례하는 상한이다. 저장된 ID 전체를 확인하는 작업량과 ID `n`개를 저장하는 공간이 여기에 해당한다.
